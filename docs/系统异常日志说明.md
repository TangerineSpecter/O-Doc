# 系统异常日志

管理员在「系统设置 → 系统日志」查看本机异常。列表显示标题、时间、来源模块及异常类型，可按模块、时间和关键词筛选；明细显示模型、HTTP 状态、提供商错误码、操作、请求/任务/资源 ID 和脱敏堆栈。单条下载为 UTF-8 文本，批量下载为 ZIP。删除及清空需确认，不可恢复。

## 存储和部署

日志使用独立 SQLite 文件，不创建业务数据库模型，不参与 WebDAV 同步或业务备份。默认目录为项目 `runtime/system_logs/`，可用 `ODOC_SYSTEM_LOG_DIR` 指定专用目录。生产 Compose 已增加 `./deploy/runtime/system_logs:/app/runtime/system_logs` 持久化挂载；重新部署时应用该挂载，避免容器更新丢失日志。

默认保留 30 天、最大 100 MB，管理员可调整。写入、概览查询和后台维护时清理过期记录，超限按最旧优先清理；删除后执行 SQLite 空间回收。统计包含数据库及其辅助文件。降低保留期限或容量可能立即清理历史日志。

## 采集边界

后端 ERROR 日志、统一异常处理、系统业务错误响应、模型调用和前端请求/运行/渲染异常接入采集。文章润色、Agent 任务、图书分析增加资源/任务关联上下文。流式请求在迭代和读取失败时保留请求关联。正常校验错误、登录过期、预期权限错误和主动取消不作为系统异常上报。

模型错误保留实际 HTTP 状态、异常类和提供商错误码。余额不足仅依据明确的提供商代码；`insufficient_quota` 显示为额度不足，不推断为欠费。SDK 内部重试不会逐次暴露给调用方；保留可获得的重试上限，以及应用层显式重试次数。

模型调用及有界调用的每次请求使用独立标识，父请求和任务 ID 仍用于关联；同一异常向外传播时合并，独立调用的失败分别保留。合并优先保留提供商实际返回的 HTTP 状态，不以对用户返回的业务状态覆盖。SQLite 写入在事务内完成读取与合并，避免多进程同时上报同一异常时丢失记录或关联字段。

系统不保存异常的原始正文、模型响应或异常消息，因为提供商可能在其中回显文章和凭据。保留安全的错误分类说明和堆栈位置。前端上报不携带请求正文、认证头或异常消息。上报接口需要登录，限流 30 次/分钟；日志读取、下载、删除和策略调整仅超级管理员可用。日志 API 自身的错误不上报，避免递归。

采集队列上限 512 条，异常存储失败不影响原业务结果，恢复后记录中断情况。日志仅覆盖功能上线后采集到的异常，不补录旧控制台日志；完全离线的浏览器、后端完全不可用或进程崩溃前尚未落盘的事件无法保证收集。

## 接口与验证

管理接口前缀 `/api/system/logs/`：列表、`overview/`、`<id>/`、`download/`、`delete/`、`clear/`、`policy/`；`report/` 接收受限的浏览器事件。沿用项目成功/错误响应和 camelCase 字段转换。管理接口禁止缓存。

后端隔离测试：`.venv/bin/python -m unittest system_logs.tests`。测试以临时目录代替真实日志目录，不初始化项目后台调度器或操作用户数据库。

前端使用 Node 22，在 `frontend_react` 中运行 `npm run test:system-logs`、`npm run type-check` 和 `npm run build`。

浏览器验收脚本：`frontend_react/scripts/test-system-logs-browser.cjs`。启动独立 Vite 测试端口后运行，支持 `ODOC_PLAYWRIGHT_MODULE` 指定 Playwright、`ODOC_CHROMIUM` 指定 Chromium、`ODOC_LOGS_TEST_URL` 指定前端地址。脚本只使用模拟 API 数据，检查桌面/手机列表、详情、下载、关闭、删除、空状态和横向溢出；这不等价于真实提供商或生产部署验收。
