# Agent 世界结构化决策模型接入

2026-10-11 起市场、生活活动、社交和旅行有限候选选择可使用结构化决策连接；是否启用及排除场景由世界设置统一控制，关闭或不可用时仍回退普通文本模型。JEV 是内置连接并保持默认值，其他连接通过配置和协议适配器扩展。

## 决策连接与协议

连接目录在「AI 模型接入 → 决策模型连接」管理。每个自定义连接保存名称、协议、服务地址和模型 ID；API Key 按账号及连接 ID 保存在 `SystemSetting.system_decision_credentials`，与可同步的连接元数据 `SystemSetting.system_decision_connections`、当前世界选择 `LifeConfig.settings.decision_connection_id` 一起随 WebDAV 同步。

当前提供两个适配器：`systemone` 直接发送 TypeSafe System One `{state, questions}` 并读取 `answers`；`openai_chat_json` 按 OpenAI Chat Completions 外层调用 `/chat/completions`，把同一 `{state, questions}` JSON 序列化到 `messages[0].content`，从 `choices[0].message.content` 解析按问题 ID 返回的 choice JSON。内部统一校验候选、完整概率分布和置信度。JEV 使用 `systemone`；StartLux 可以直连原生 System One，也可以按已验证的 NewAPI Chat 包装选择 `openai_chat_json`。协议不同于这两种格式的服务须新增独立适配器，不要求改写市场业务逻辑。

接口：GET/PATCH `/api/settings/decision-models/` 继续管理 JEV 密钥；POST `/api/settings/decision-models/connections/` 新建连接；PATCH/DELETE `/api/settings/decision-models/connections/{id}/` 编辑或删除；POST `/api/settings/decision-models/connections/{id}/test/` 按该连接协议执行结构化选择测试。JEV 保留原来的 `/api/settings/decision-models/test/` 模型列表连接检测。测试不会提交市场交易。

## 配置与账号

「AI 模型接入 → 决策模型连接」提供 JEV 内置连接，以及自定义连接的新增、编辑、删除、密钥管理和连接测试。JEV 使用官方 `https://api.typesafe.ai/v1`、`jev-latest`，按 System One 协议连接并记录响应实际版本；协议见 [TypeSafe API](https://docs.typesafe.ai/api) 和 [模型说明](https://docs.typesafe.ai/models)。StartLux 经 NewAPI 时配置 `openai_chat_json`，模型 ID 使用已验证的 `startlux-decision`。

配置读取只返回连接信息和密钥是否已配置，不回传密钥。账号从认证用户取得；测试按所选协议校验结构化决策结果。

`SystemSetting.system_decision_credentials` 自 2026-10-16 起参与 WebDAV 快照、修订和恢复。配置读取接口只返回密钥是否已配置，不回传密钥；请求错误不记录凭证。API Key 会以快照字段进入远端存储，请确保 SFTP/WebDAV 目录访问受控。

`AgentTask.market_config` 的旧 `decision_enabled` / `decision_provider` 值继续随任务同步以兼容历史数据；当前实际开关、排除场景和连接选择由 `LifeConfig.settings` 统一管理。连接元数据、世界选择和 API Key 使用已有 `SystemSetting` / `LifeConfig`，无新增数据库列或迁移。

## 执行与回退

市场机会认领保留在 `market_runner`，共享生命周期、截止时间和工具执行在 `market_model_execution`；结构化决策循环与可行候选分别位于 `market_decision_loop`、`market_decision_candidates`。所有修改继续通过原交易、预算和种植队列服务提交。

结构化决策模型先查看可行操作摘要，再选择进入或等待。进入后「购买、回收出售、上架、管理自己的挂牌」作为同层动作，只提供有实际候选的动作，不强制买卖；动作摘要每类最多3项示例，标明可行数量和是否还有更多，选中后每页20项完整查询，不静默丢掉候选。摘要保留回收金额、挂牌现价及品质，避免动作选择只看购买需求。种子、肥料、饲料沿用既有不可回收/挂牌规则；农产、畜产、美食可回收或挂牌，纪念品只可挂牌，探索材料和闲置装备沿用冒险回收规则。

结构化决策模型随后选择商品和数量；管理挂牌直接选择具体挂牌的改价或撤回，不再询问数量。候选保留价格、品质、来源、库存、回收值、版本及相关需求，由代码根据实时余额、后续预留、商品格、建筑容量和采购额度计算可买上限。可前后翻页和返回动作选择；每一步保留等待、离场和其他方案入口，数量支持1、所需量、当前上限及其他数量。单次 Choice 不超过255项。

结构化决策模型选定上架物品/数量或改价挂牌后，文本模型只补自由定价并提交这一个操作；工具集合与执行入口同时限制选定操作、物品、数量、版本和请求键，不能改买其他商品。版本或库存冲突返回失败事实，刷新后由所选连接重新选择；未提交操作不当作成功。撤回由结构化决策模型选择后直接执行原服务。复杂预算调整、种植队列或候选外方案仍调用任务覆盖模型或居民默认文本模型。复杂子流程查询后仅完成一个成功修改，立刻结束并刷新真实状态，再回结构化决策模型；失败修改不算完成。重复请求继续沿用原幂等校验。结束摘要区分实际买卖与上架、改价、撤回，上架不计作已成交收入。

缺密钥、认证失败、超时、服务错误、结构或候选 ID 无效时，本次剩余部分永久转文本模型。复用同一机会键、记录、会话及真实资产，携带成交事实和剩余额度，不重复入场扣体力或重放已成交交易。置信度只记录，不作为未经验证的回退阈值。

报价跨小时、挂牌版本和库存冲突刷新后重新选择；条件未变化的重复失败结束。停止、解绑、过期及调用上限也直接结束。两类模型共用5分钟、20次市场调用及24次工具执行限制；结构化决策请求超时不超过20秒、无自动重试，额外有限选择轮次上限为64，防止只翻页而无业务进展。结束摘要直接取成功操作事实，不追加摘要模型调用。

维护进程确认原市场执行进程已经退出后，会关闭会话并一并结束任务机会、执行记录（含居民子记录）、居民活动及仍在运行的模型请求；旧版本遗留的已关闭会话也会补齐终态。已提交成交、库存、余额和入场体力事实不重放；未知用量仍为空，计数保留。耗时按会话实际关闭时间计算，动态显示「市场会话中断」，不会当作居民主动离场或心理解释。不新增模型或同步字段，状态修订沿用既有同步机制。存活 runner 的正常离场、限时和停止仍由原流程收尾。

## 上下文与完整细节

`market_model_context` 构造模型私有投影：初始只保留身份、经营偏好、相关记忆、生活目标、预算、库存首屏及市场/农场需求摘要，消除生活大快照与市场快照的重复。稳定规则放在系统前缀。

市场买卖输入只提供想买卖什么、已有多少、商品作用、价格、库存、可买数量及现有需求。种子候选不带逐作物施肥组合、星级概率或收益试算；肥料保留库存、当前报价、品质增益及增产效果；动物保留已有数量、建筑要求、产物和生产周期。现有队列保留真实项目、缺货数量和采购额度，不发送其收益估算。买种子不强制触发队列修改；没有当天队列时不提供修改队列工具，存在队列且确需调整时仍使用真实计划 ID/revision。

初始农场摘要直接提供空地数、已成熟作物数、种子库存总量及「一轮地块数减现有种子」的备种参考量。田满或没有当天播种安排不限制提前采购；结构化决策和文本流程都说明备种参考不是强制目标，居民结合预算与偏好决定品种和数量。种子数量候选增加受现有库存、预算及采购额度限制的备种参考量，不自动购买、收获或新建种植计划。

`observe_market_detail` 按 topic/page/search 查询库存、逐批价格、挂牌价格历史、种子库存与肥料作用、农场畜牧、装备物资、食谱、生活目标/日程及历史经历。每页20项且明确 total/has_more；物品/挂牌按指定 ID 查询；生活详情从原始数据分页，不继承初始快照的20/50项截断。市场模型私有详情不提供作物概率、施肥方案及收益估算，工具结果投影也过滤这些字段，避免后续每轮继续携带。农场原始计算、业务数据、市场展示 HTTP 和外部 MCP 契约保持不变；本次仅修改运行时投影，无新增数据库或 WebDAV 同步字段。

食谱列表先返回名称、ID、材料数量与已有库存、等级及可制作状态；具体食谱完整详情通过 `topic=recipe` / `recipe_id` 读取，避免每次为购物携带全部食谱说明、制作预览及估算。已知状态不重复查询，没有食材采购或成品出售需求时无需读取食谱或历史成交。

文本工具循环刷新同一查询时，把旧工具结果替换成最新结果引用，保留 assistant/tool 配对；错误、实际成功写入和必要决策记录保留，旧初始快照在刷新后替换。输入减少依赖具体状态及查询行为，不承诺固定 Token 降幅。

关闭结构化决策连接或故障回退的文本流程也提供上述可行操作摘要，并明确保留/回收/挂牌的区别。刷新市场状态后移除旧初始动作摘要；真实操作继续使用原工具、库存和版本校验。所有摘要、候选及指定定价操作都是执行时投影，无新增数据库字段、迁移或 WebDAV 实体；成交和挂牌事实沿用现有同步记录。

买卖动作与采购简化回归：隔离数据库下的市场、JEV、会话恢复、农场、作物品质及用量测试共175项通过，包含 `test_market_intents` 的11项新增场景：实际回收、上架托管、改价、撤回、限定定价工具与参数、挂牌版本冲突重选、上架后 JEV 故障回退、完整挂牌分页、停止及第二十次调用收尾。额外核对模拟 JEV 的 HTTP 请求结构，入场、动作、商品、数量与离场各轮均不携带作物概率或施肥比较表。外部模型响应仍使用模拟，字符缩减不等同于实测 Token 或费用节省。

## 用量与验证边界

用量统计下钻的「任务执行记录」按该执行最后一次模型请求时间倒序，同一时间按执行ID稳定分页；居民、任务和其他调用排行榜继续按总Token降序。请求明细仍按请求时间倒序，避免新执行因用量较少被排在旧执行之后而误以为漏采集。

真实结构化决策请求接入 `Capture`，关联账号、居民、任务、执行、连接、实际版本、输入/输出和状态；各连接使用 `decision:<connection_id>` 稳定分类。阶段分别为 `决策模型市场选择`、`市场复杂操作`、`市场决策回退`；未知用量留空，失败不伪填零。JEV 连接测试不计入模型选择请求。

市场工具流程（含复杂单步与回退）在文本模型思考设置为「默认」且协议支持关闭时发送关闭参数；显式「开启/关闭」仍优先，不切换任务/居民模型，不修改模型配置或影响其他任务。不删除协议需要的思考历史。工具本地执行不直接产生模型用量；模型读取的工具定义、返回值、调用参数及思考均可能计入供应商统计，缓存输入仍属于总输入，费用需按供应商的缓存价格另算。

详情查询在既有执行步骤中记录中文主题、页码及序列化返回字符数，字符数不冒充 Token；不保存搜索正文、完整请求、响应或凭证。结束说明要求自然中文；含 `farm_queue`、`revision`、`request_id` 或「不可虚构」等内部规则的模型离场说明，以实际执行摘要替代，不推测居民心理。历史动态同样在读取时处理，不回写原始记录。以上均沿用既有步骤和说明字段，无新增数据库字段、迁移或同步实体。

该轮回归共196项通过（市场、JEV、会话恢复、农场、作物品质、用量及 `test_model_thinking`）：覆盖满田且无计划时实际购种但不修改农场、JEV可选择不买、受现有限额约束的备种数量、食谱列表/指定详情、查询大小诊断、旧动态文案及显式思考策略优先。真实模型仍为模拟，未修改本地业务数据库。

JEV 决策请求失败时，向本机「系统日志」记录固定错误分类（超时、连接失败、认证/权限、限流、HTTP 错误、JSON 解析、响应校验或适配错误）、失败阶段、异常类、HTTP 状态、耗时及代码栈位置；同时记录执行/任务/居民 ID。日志的 `model_request_id` / `usage_id` 与该次用量记录 ID 相同，没有用量归属时生成独立请求 ID，避免同一执行内的不同失败被合并。回退步骤显示具体类别、阶段和请求 ID，便于定位日志。密钥、请求/响应正文、原始异常消息及居民业务内容不写入日志。日志沿用本机 `system_logs` 存储，不参与 WebDAV 同步，不新增数据库字段；历史泛化错误不能补回原始原因。

后端在隔离测试数据库模拟外部响应，覆盖关闭/开启、等待、缺密钥、部分成交后回退、复杂修改后回 JEV、调用结束、候选翻页、私有完整详情、工具协议压缩、账号隔离、恢复保留密钥及原市场/用量/同步回归。浏览器使用隔离账号和数据库，核对实际保存请求与回显、清除密钥提示、公共 Select Portal、桌面和390px窄屏；连接检测在该验收环境模拟。

本次未调用付费 JEV、未部署、未修改生产数据库。真实对照需显式启用，分别记录费用、Token、耗时和决策质量；真实多设备接续仍沿用先停旧设备再开启新设备的边界。
