# 需求：文章双向链接一期

- 状态：可领取规格（P1）；建议排在 `003` 导出之后，可与 `006` 并行
- 规划来源：`docs/功能规划文档.md` P1「双向链接与反向链接」第一期（文章 ↔ 文章）
- 对照现状：HEAD `b2852e9`。编辑器是 textarea + 斜杠菜单，阅读用 `ArticleMarkdown`（`remark-gfm`）。无 `[[标题]]` 解析，无反链面板。标题只在 `(author, coll_id)` 内唯一，跨文集可以重名
- **一期不要新模型、不要改同步协议、不要升应用版本。** 链接只存在于 Markdown 正文里

## 1. 要解决的问题

文章之间只能靠普通 URL 或口头记忆互指。个人知识库里「这篇提到了那篇、那篇被谁引用」看不见，和规划里的知识网络差一截。

不要一上来做图数据库、闪念互链或 RAG「可能相关」。先让 `[[...]]` 能点、能插入、能在被链文章上看到反链。

## 2. 目标

登录用户在 Markdown 文章里用 wiki 链接指向自己的其它 Markdown 文章；阅读时能跳转；被引用的文章能列出反向链接。

## 3. 范围

### 做

- 仅 `content_format=markdown` 且 `is_valid=True` 的文章（与 `get_visible_article_queryset` 同一可见范围）
- 语法（正文里的源码，代码块和行内代码**不解析**）：
  - `[[标题]]` — 手打、按当前可见文章的标题解析
  - `[[显示名|art_xxx]]` — 斜杠菜单 / `[[` 搜索选中后的**写入形式**（稳定主键，改标题、换文集仍能跳）
- 阅读页把合法链接渲染成站内跳转：`/article/{collId}/{articleId}`
- 编辑器：输入 `[[` 弹出文章搜索；斜杠菜单增加「双向链接」
- 阅读页（以及编辑器可选）展示「反向链接」列表：哪些文章链到了本文

### 不做

- 闪念、白板、HTML 笔记、图书、资源
- `[[闪念:...]]`、块引用、嵌入预览、图谱页
- 改名时自动改写全库入链（一期保留字面量；稳定形式靠 `art_` id）
- 关系表 / 图数据库 / 新同步模型
- 版本历史、导出、分享链接、模板三期

**不要解析** `[[OD_IMAGE_*]]`、`[[OD_CODE_*]]` 等导入占位符（前缀 `OD_`）。

## 4. 产品规则

1. 只能链到当前用户能看见的 Markdown 文章。链到别人的私密文、已删文、HTML 笔记 → 失效链接，不 404 整页。
2. 解析顺序：
   1. `[[显示名|art_xxx]]`（`art_` + 现有 10 位字母数字）按 `article_id` 查
   2. `[[标题]]` 在可见 Markdown 文章里按标题精确匹配
   3. 0 条 → 失效样式，点击 toast「找不到这篇文章」
   4. 1 条 → 直接跳转
   5. 多条（跨文集重名）→ 弹出选择层，列出文集名、更新时间，选完再跳；编辑器里选中后应改写成 `[[显示名|art_xxx]]`，避免以后每次歧义
3. 同一篇里链到自己：允许，但反链列表排除自身。
4. 反链检索：当前用户可见 Markdown 文章的 `content` 中出现 `[[当前标题]]` 或 `[[...|当前articleId]]`。一期允许简单包含匹配，不要求完美跳过所有代码块；不要全表扫成前端把所有正文拉下来。
5. 公开读者：能打开文章就能点文内已解析的链接（目标文仍按原权限）。反链列表面向**作者**，游客和公开读者默认不展示，避免泄露私密文标题。
6. 删除或进回收站的目标：入链变失效，不必级联改正文。
7. 不引入独立 TODO。

## 5. 界面要点

- 有效链接：正文里橘色下划线文字，hover 显示目标标题 + 文集；走现有站内路由，不要新开标签（除非用户中键）
- 失效链接：slate 删除线或虚下划线，不做成红色大报错
- 反链：阅读页 TOC 附近一块「反向链接 N」，列表为标题 + 文集名；空状态「还没有文章链到这里」，不要插画
- 编辑器搜索层：复用现有白底圆角、`orange-50` 选中；键盘 ↑↓ Enter Esc；窄屏全宽
- 斜杠菜单新项：label「双向链接」，desc「插入 [[文章]]」
- 主色仍是橘子

## 6. 同步与实现约束（给阿尼亚）

- 链接是正文的一部分，随现有 `article` 快照走。**不要**为反链建表，否则必须进 `TARGET_APPS`、升版本、写同步说明
- 反链用查询接口，例如 `GET /article/backlinks/{articleId}`，服务端过滤可见 Markdown 文章
- 解析放纯函数（可前后端共用思路）：输入 Markdown + 解析上下文，输出链接节点；单测覆盖：id 形式、标题唯一、标题重名、代码块、`[[OD_IMAGE_1_0001]]` 不解析、改标题后 id 形式仍有效
- 阅读渲染加在 `ArticleMarkdown` 的 remark 插件或等价预处理，不要破坏划线批注、KaTeX、GFM
- 编辑器继续是 textarea，不要为了双链换成 TipTap
- 搜索接口尽量复用文章列表，按标题模糊、限制条数（例如 20）

## 7. 验收

- 写入 `[[显示名|art_xxx]]` 后，阅读页能跳到目标文（换文集、改标题后仍能跳）
- 只写 `[[唯一标题]]` 也能跳
- 两个文集里同名文章，点击 `[[同名]]` 出现选择层，不会随机跳
- 目标删除后，链接可见但失效，toast 说明找不到
- 源文保存后，目标文反链出现源文标题；去掉链接再保存，反链消失
- 作者能看见反链；未登录读者看不见反链面板
- fenced 代码块里的 `[[标题]]` 仍是代码
- `[[OD_IMAGE_1_0001]]` 不变成文章链接
- 无新模型、无迁移、无应用版本提升
- 不 commit（由人类决定）
