# 需求：文章版本历史一期

- 状态：可领取规格（P0）；建议排在回收站一期之后
- 规划来源：`docs/功能规划文档.md` P0「文章版本历史与快照回滚」
- 对照现状：HEAD `1b44b3c`；工作区另有未 commit 的自定义模板（localStorage）
- 新模型必须进 WebDAV v2，并更新 `docs/数据同步逻辑说明.md`

## 1. 要解决的问题

文章没有历史。下面这些操作都会把上一份正文盖掉，且无法回看、无法回滚：

- 编辑器手动保存（`ArticleUpdateView` 直接写 `content`）
- 编辑器「AI 润色」：先改本地正文，用户再保存后同样覆盖
- 网页导入后的后台润色（`ArticlePolisher` **不经用户点保存**，直接写库）

回收站解决的是误删；版本历史解决的是误改。两刀不要绑在一起。

## 2. 目标

登录用户可以查看自己某篇 Markdown 文章的历史版本，对比当前正文，并从某一版恢复。恢复前先把当前正文再存成一版，避免回滚本身不可逆。

## 3. 范围

### 做

- 仅 `content_format=markdown` 且 `is_valid=True` 的文章
- 新模型（建议名 `ArticleVersion`）落在 `article` app，使用**稳定字符串主键**（与现有 `article_id` 一类，禁止自增整数主键）
- 快照字段：标题、正文、文集 `coll_id`、分类、标签、`post_summary`、字数、操作者、来源、创建时间
- 触发：文章更新且标题/正文/文集/分类/标签/摘要相对库中旧值有变化时，先把**旧值**写入一版，再保存新值
- 后台 `ArticlePolisher` 写库前同样先快照旧值（来源标 `polish`）
- 列表：时间、来源（保存 / 润色 / 恢复 / 导入）、操作者、字数变化
- 只读预览该版 Markdown；可与当前正文做标题+正文对比（简单行级即可）
- 恢复：先快照当前，再把该版字段写回文章；`mind_map` 清空；`is_rag_synced=False`

### 不做

- 原样 HTML 笔记（恢复 Markdown 还原不了 HTML 包；一期直接排除）
- 闪念、白板、图片、图书、资源
- 编辑器未保存的本地润色（尚未写库，不必建版本）
- 按键级自动快照、完整 Git diff、三方合并 UI
- 批注偏移自动迁移（恢复后划线可能错位，一期用文案提示即可）
- 自定义模板、回收站（见 `001`）

## 4. 产品规则

1. 只有文章所有者能列出、预览、恢复历史。公开读者看不到版本入口。
2. 无变化不建版本（避免空点保存刷历史）。
3. **每篇文章最多保留 20 个历史版本。** 超出则淘汰最旧一版（走同步墓碑，不要只在本机 DROP，否则他端合并会把旧版带回来）。
4. 创建文章不强制写「第 0 版」；第一次产生历史是首次有变化的更新或后台润色。
5. 恢复必须二次确认，文案写明：当前内容会先存成新版本。
6. 软删进回收站的文章：历史记录随文章保留，但一期回收站 UI 不必展示版本。彻底删除策略与 `001` 一致时，版本行一并墓碑。
7. 不引入独立 TODO。

## 5. 同步（这一刀的硬约束）

`article` 在 `SyncManager.TARGET_APPS` 里，新模型会进入 v2 快照。必须同时做到：

- 主键跨设备稳定；版本行按 `模型:主键` 三方合并，不要把「一篇文章的全部历史」当成单个 blob
- 提升应用版本，让未升级客户端拒绝写回（沿用现有「旧客户端必须升级」机制，参考 HTML 笔记 0.9.8）
- 更新 `docs/数据同步逻辑说明.md`：版本是业务数据、随文章走、保留上限、淘汰用墓碑
- 不要把版本正文再复制进 `sync-v2/blobs`（正文已在 JSON 字段里）；也不要指望「WebDAV 有 10 份同步快照就不做产品版本历史」——那是整库备份，用户不能按文章回滚

旧快照没有该模型时：新设备视为「尚无历史」，不要把缺失当成删除。

## 6. 界面要点

- 入口：文章阅读页与编辑器各一处「历史」（编辑器可放侧栏或顶栏，不要塞进设置页）
- 列表默认最近在上；当前正文不是列表里的一项，或单独标「当前」
- 预览用现有阅读 Markdown 样式；对比页桌面可左右、窄屏可上下
- 主色仍是橘子；恢复是高风险操作，确认框用现有 `ConfirmationModal`
- 空状态：还没有历史时说明「保存或 AI 润色之后才会出现」

## 7. 验收

- 保存改写正文后，历史多一条，内容是保存前的标题+正文
- 编辑器润色后若不保存，历史不增加；保存后增加一条
- 导入后台润色完成后，历史里有润色前的正文，且能恢复回去
- 恢复后当前正文等于所选历史；再打开历史能看到恢复前那一版
- 第 21 次变化后，最旧一版从列表消失
- HTML 笔记没有历史入口
- `docs/数据同步逻辑说明.md` 已写明该模型；有迁移；未 commit（由人类决定）

## 8. 实现提示（给阿尼亚）

- 在 `ArticleUpdateView` / `ArticlePolisher` 写库前取旧实例建版本，不要在前端单独 POST 一份「可能与库不一致」的快照
- 标签存快照时用名称列表或 id 列表需固定一种，恢复时解析不到的标签跳过并保持其余
- 有子文章/换文集时只快照字段，不改树规则
- 测试至少覆盖：无变化不建版、润色写库建版、恢复先建版再写回、超过 20 条淘汰

## 9. 与其它需求的关系

- 排期：人类若尚未 commit 自定义模板，先不要在脏工作区上开这一刀
- 与 `001`：可先做回收站（尽量不新模型）；本刀必须新模型 + 同步，切片更大
- 模板三期（变量）和把自定义模板改成云端同步，都不是本刀
