# 需求：回收站一期（文章 Markdown + 闪念）

- 状态：代码已实现，人工已验收
- 规划来源：`docs/功能规划文档.md` P0 回收站
- 对齐：模板二期（自定义、localStorage）已落地未 commit，本刀范围不变
- 不改范围外代码；新字段必须核对 WebDAV 同步

## 1. 要解决的问题

删除目前对用户表现为「没了」。实际上：

- Markdown 文章、文集、闪念删除多是 `is_valid=False`，记录还在库里
- 没有入口列出已删内容，也没有恢复
- 原样 HTML 笔记删除会清理专属资源，界面写明「不可恢复」
- 资源库删除写明「永久删除」
- 编辑器里的 AI 润色会直接改写正文；没有版本历史时，误删比误改更不可逆，回收站是最小安全感

## 2. 目标

登录用户可以把**自己的**已删 Markdown 文章和闪念放进回收站，支持按类型筛选、恢复、彻底删除。恢复后出现在原来的文集/闪念流中（文集仍有效时）。

## 3. 范围

### 做

- 文章：`content_format=markdown` 且 `is_valid=False`，包括用户可删除的 Agent 文集帖子
- 闪念：`is_valid=False`
- 列表、筛选（文章 / 闪念）、恢复、彻底删除（二次确认）
- 删除确认文案从「不可恢复」改为「将移入回收站」（仅本范围内类型）
- 入口：设置页新标签，或资源库附近的「回收站」页（二选一，优先 `/recycle` 独立页，避免设置页更挤）

### 不做（二期或明确排除）

- 原样 HTML 笔记：维持现有清理与「不可恢复」，**不要**在一期假装可恢复
- 文集、图片、白板、图书、资源库文件、通知
- 版本历史、单篇导出、自定义模板
- 新的同步协议或快照格式升级

## 4. 现状（实现时不要再发明一套删除）

| 对象 | 现有删除 | 同步 |
| --- | --- | --- |
| Markdown 文章 | `ArticleDeleteView` 置 `is_valid=False`，有子文拒绝删，并删 RAG 向量 | 在 v2 快照内，软删随快照、删除走墓碑 |
| 闪念 | `MemoDeleteView` 置 `is_valid=False`，并删闪念向量 | 当前已在 v2 快照内；软删/恢复随快照同步，物理删除由墓碑传播 |
| 文集 | `AnthologyDeleteView` 只把文集 `is_valid=False`，不级联改文章 | 在快照内。文章仍可能以 `coll_id` 挂着，但可见性跟有效文集走 |
| HTML 笔记 | `delete_html_note` 清理专属资源 | 源/预览删除随墓碑；文件清理不可当回收站 |

列表可见性：`get_visible_article_queryset` 已要求 `is_valid=True` 且文集有效。回收站接口必须**另查**当前用户的无效记录，不能复用这篇可见查询。

没有 `deleted_at` 字段。一期用软删后的 `updated_at` 作为「删除时间」即可，避免为了展示时间先加同步字段。若以后要保留「删除前的更新时间」，再加 `deleted_at` 并写入同步说明。

## 5. 产品规则

1. 只有所有者能看见、恢复、彻底删除自己的回收站条目。
2. 恢复 Markdown 文章：`is_valid=True`，刷新文集计数，按需提示重新同步 RAG（不要在恢复时强制长耗时同步阻塞）。
3. 若所属文集已无效：恢复失败并说明「请先恢复文集」（一期无文集回收站，则文案改为「所属文集已删除，暂无法恢复」）。
4. 恢复闪念：`is_valid=True`；向量可事后再同步。闪念业务记录随当前 v2 快照同步，RAG 向量仍由本机重建。
5. 彻底删除：二次确认，物理删除记录；`post_delete` 同步跟踪器为文章、闪念及其同步关联记录写入粉碎墓碑。在支持该规则的同步客户端间，粉碎胜过并发编辑；普通删除仍保留原有的编辑优先规则。
6. 有子文章的文章本来就不能删进回收站（现接口已拦）；不必在回收站处理树冲突。
7. 不引入独立 TODO。

## 6. 界面要点

- 列表：标题/闪念摘录、类型徽标、删除时间、原文集名（文章）
- 空状态：说明回收站是安全网，不是永久备份
- 危险操作按钮用现有红色体系（`red-50` / `red-600`），主色仍是橘子
- 桌面与窄屏都要能完成恢复 / 彻底删除
- 不要做营销风空状态插画

## 7. 验收

- 删除一篇 Markdown 文章后，目录与搜索不再出现；回收站能看到；恢复后回到仍有效的原文集；粉碎后同步墓碑生效
- 删除一条闪念后，闪念流不再出现；回收站能恢复；粉碎后同步墓碑生效
- 删除 HTML 笔记仍走原确认文案，**不出现**在回收站
- 只有所有者可以列出、恢复和粉碎自己的文章/闪念；筛选支持文章与闪念
- 无新同步格式；若未加字段，则不必改 `TARGET_APPS`
- 不 commit（由人类决定）

## 8. 给开发的同步提醒

- 文章和闪念已经在快照范围内。恢复通过模型 `save()` 把 `is_valid` 扳回 True；粉碎通过模型 `delete()` 由同步信号记录带标记的墓碑，包括级联删除的关联记录。
- 一期不新增同步字段、模型或快照协议。
- HTML 资源清理逻辑不要在一期改成「延后删除」，除非单独开切片。
