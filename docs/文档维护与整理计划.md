# 文档维护与后续整理计划

目标：从 `AGENTS.md` 按任务进入目录和当前业务说明，保留足够的实现线索，减少旧方案、重复规则和阶段记录对当前开发的干扰。以下状态基于 2026-10-16 的静态文档与代码检查。

## 当前文档的写法

当前业务说明按“适用范围 → 当前规则与流程 → 数据/同步边界 → 代码入口 → 已知限制”组织。文首写核对日期和范围；实现已存在、规划待做、生产待验收分别说明。

- 一项持续演进的业务保留一个当前入口，阶段更新直接修订现行说明。历史方案与验收记录带日期并链接回该入口。
- 目录只给任务线索和短描述，避免复制业务正文。长文先提供主题导航，当前规则摘要与历史推演按用途拆开。
- 数值、默认目录和接口字段已有明确代码来源时，写规则含义与来源；完整表格只有在确需人工维护时保留。
- 文档与代码冲突时追查实际读写和执行路径；无法确认的状态标为待核对，不把旧建议写成当前事实。
- 重命名或删除前用 `rg` 检查路径引用、生成脚本和运行时读取；更新入口后检查本地链接。

## 运行资源边界

`docs/` 不全是说明文字。`system_settings/builtin_skills.py` 读取 `docs/config/` 的四份 Skill 原文；`travel_seed.py` 读取旅行种子 CSV；`scripts/combat_design/` 生成并读取 `docs/data/combat/`。这些路径的调整需要同时处理代码、生成及打包引用。

当前业务说明、历史验收与部署状态分别核对；静态文档检查不能证明正式数据库已迁移、外部模型效果或多设备同步已验收。
