# 模型输入上下文优化规范

适用范围：项目中调用语言模型、决策模型、Embedding/RAG 或带工具的模型请求。目标是在保留完成当前任务所需事实、约束和证据的前提下，减少每次请求的输入 Token；不以“越短越好”代替正确性，也不把输入精简等同于减少请求次数。

本规范中的“必须/禁止”用于正确性、安全和数据边界；“应/优先”表示默认实施方式；“建议”允许按具体场景取舍。

Agent 各任务的阶段清单、信息与工具矩阵、当前覆盖状态及后续实施批次，统一维护于[Agent 场景输入与工具治理方案](./agents/Agent场景输入与工具治理方案.md)。本文提供通用约束；方案中标为待实施的内容不能视为已有代码行为。

## 1. 基本原则

每个模型请求只应包含能影响**本次输出**的资料。一个字段的保留理由应能说明：它影响哪项判断、生成哪部分内容，或由哪个后续校验/执行步骤消费。解释不出用途的字段先移除或改为按需加载。

精简顺序：

1. 先定位真实消耗最大的请求阶段，再沿调用链确认模型当时实际收到什么。
2. 先删除无关字段、重复内容和不需要的历史，再压缩仍然相关的内容。
3. 将原始明细改为能支持当前决策的摘要；如果摘要会掩盖风险、例外或边界，则保留那些必要证据。
4. 把可确定的规则、计算和合法性检查交给代码；把模型留给确实需要语义判断、选择或自然语言生成的部分。
5. 用真实请求用量和代表性场景确认收益与质量，不凭字符数或单次成功响应推断效果。

输入应覆盖足够的信息以回答当前问题，不应携带为了“以防万一”而收集的整份领域上下文。压缩后如需模型猜测缺失的时间、数量、来源、单位、权限或业务规则，说明压缩过度，应补回最小必要信息。

## 2. 优化前先还原完整请求

### 2.1 以一次实际模型请求为单位

Token 统计应按请求用途、阶段、模型和真实请求 ID 拆分。完整输入不只包括业务 JSON，还可能包括：

- system/developer 指令、角色提示词及固定策略；
- 用户指令、序列化上下文、历史消息；
- 检索出的记忆、文档片段或示例；
- 工具定义、参数 Schema、工具结果和多轮状态；
- 格式修复、超时重试或失败重试时再次发送的内容。

不要看到一次执行的总 Token 高，就假定某个大 JSON 是唯一来源；也不要只优化上下文对象，却忽略重复的角色提示词、工具 Schema、记忆和重试请求。应区分“单次请求输入大”和“多次请求累积多”。

### 2.2 追踪字段的来源与消费者

沿实际代码路径阅读输入构造器、请求调用、输出解析、领域校验和最终执行者。为候选字段记录：

| 字段 | 来源与时效 | 影响的判断/生成 | 下游消费者或校验 | 保留条件 |
| --- | --- | --- | --- | --- |
| 例如：可用库存 | 当前库存快照 | 是否选择该商品、数量上限 | 服务端库存校验 | 决策需要库存，或输出受库存约束 |
| 例如：星级概率数组 | 目录估算 | 只有风险偏好或质量阈值判断才会用到 | 通常无直接消费者 | 若只比较平均收益，改为期望收益等摘要 |

字段间接影响人物偏好、风险承受或内容风格时，也可以保留，但要写清这种关联。字段“来自数据库”“以后可能用到”或“原先就一直传”本身不是保留理由。

## 3. 如何构造最小充分输入

### 3.1 按决策阶段分层

把一个复杂流程拆成模型确实需要分别做出的判断。前一阶段只得到后一阶段所需的选择结果，再按需加载后续上下文。例如：

```text
活动选择（角色偏好、近期经历、时段、可用活动）
  → 预算分配（已选付费活动、余额、相关的其他资金预留）
  → 领域计划（该领域的当前状态、候选、必要边界）
  → 服务端验证和执行
```

活动未选定前，不传完整农场、旅行、市场或创作细节；不需要预算的活动，不单独调用预算规划；领域计划阶段不重复注入完整角色卡和无关长期记忆。只有下一阶段真的依赖前阶段资料时，才传必要结果或短摘要。

阶段拆分可能增加请求数。设计时要同时比较每阶段输入和**完成同一业务任务的总请求数、总 Token 与质量**，不可只展示某个单次请求变小。

### 3.2 按需投影，而不是直接序列化大对象

在模型调用边界构造专用的、只读的输入投影。优先从已有权威数据派生，不把 ORM 对象、API 全量响应、整个角色/农场/背包状态或内部快照直接序列化给模型。投影应有明确字段、单位、状态含义和数据时点，不修改源对象，也不为了提示词新增持久字段。

有多个可选动作或执行分支时，按本次开放能力装载对应上下文、输出字段和规则；未开放的能力不应查询其附属资源。模型投影与提交、并发复核所需的完整服务端快照分开构造，压缩模型输入不能削弱服务端校验。

优先检查并去除：

- 本次决策不涉及的背包物品、活动类型、页面展示字段、建筑、动物、配置和工具；
- 无库存、不可选、未启用、已过期或已被规则排除的候选项；
- 与当前时间窗口无关的历史记录和未来安排；
- 同一事实在角色卡、用户上下文、记忆和工具状态中的多份副本；
- 已在调用指令中说明的固定规则，再次作为大段数据传入的重复说明；
- 对当前输出没有作用的 `null`、默认值和内部追踪元数据。

只有在“缺失”和“明确为空/未知”含义不同、或下游依赖显式状态时，才保留相应 `null`、空数组或状态字段。不要为了少几个 Token 把这些状态合并。

### 3.3 选择摘要粒度，避免搬运原始明细

模型要做的是哪种判断，就传能支持该判断的统计量：

| 任务 | 通常够用的输入 | 只在确有需要时提供 |
| --- | --- | --- |
| 比较平均收益 | 期望数量、期望收益、增量成本/净收益 | 完整概率分布、每种结果的枚举明细 |
| 判断风险是否超过阈值 | 超阈概率、分位数、最坏情况或风险区间 | 与阈值无关的全部采样/概率行 |
| 安排生产队列 | 可用数量、生长时间、当前占用与剩余时间、截止时间 | 与当前可种候选无关的全部作物目录和历史收成 |
| 选择文本证据 | 与问题相关的片段、来源与日期 | 整本书、整条历史或未命中的全部文档 |
| 从固定候选中分类/选择 | 合法候选、必要属性和区分信息 | 候选背后的整份配置或已可由代码计算的规则 |

如果概率分布只用于比较平均收益，应将它转换为期望值和必要的增量指标，不要要求模型阅读并解释每个概率点。如果判断依赖尾部风险、低概率高损失或达标概率，必须提供对应的风险摘要或最小相关分布；不能因为“概率表很长”就删掉关键风险证据。

对数字摘要要同时给出单位、比较基线和重要假设。例如 `expected_revenue`、`incremental_cost`、`net_gain` 应明确单位和是否包含随机事件/税费。避免传一个没有业务语义的数字，让模型自行猜测。

### 3.4 合并和去重重复信息

同一事实应有一个清晰的权威表示。重点排查：

- 角色提示词既完整放进 system，又以 `role` 字段放入 JSON；
- 同一条日程同时重复传活动、时点、完整意图、预算和理由，而当前阶段只需要其中一部分；
- 当前状态已包含在工具结果中，又重复附上产生该状态的全部历史工具调用；
- 一项偏好同时出现在角色卡、长期记忆摘要和近期经历原文；
- 指令、输出 Schema 说明和字段注释重复讲同一条固定规则。

去重时不能丢掉必要的来源、时间、稳定 ID 或置信/新鲜度信息。优先保留权威值及最短的必要出处，而不是把两份内容拼成一份更长摘要。

### 3.5 让代码和模型各做适合的事

代码应负责可精确验证的算术、日期/时段比较、库存上限、合法候选过滤、权限、预算硬边界、幂等和事实写入。尽量预先生成合法候选供模型选择，不让模型从无关目录中重建规则或猜测是否可执行。

模型输入仍应包含它要比较的真实依据；模型判断不能代替服务端校验。压缩或重构提示词后，服务器端不变量、交易边界、输出 Schema 和失败处理不得仅靠模型遵守。

输入中的稳定 ID、时间时区、单位、候选标识和输出引用键必须保留且命名清楚。应明确区分内部 ID、展示名称、时间戳和自然语言理由。模型常混淆的值要在指令和 Schema 中各自采用单一、清楚的约定，避免把同一字段定义为“时间点 ID”却只提供时间戳。

### 3.6 按阶段注册工具与技能

模型输入契约应同时声明当前阶段的信息白名单、角色/记忆/技能范围、工具白名单、结果投影和输出验证。Agent 绑定的 MCP 服务是可能可用的能力来源，不是所有模型请求的默认工具集合。

- 注册工具取已启用能力、居民/任务授权、阶段允许能力与业务前置条件的交集；保留合法操作所需的查询、预算调整和能力转换，不能为减少输入误删合法选择。
- 工具注册与执行必须采用一致的阶段策略。执行器复核工具名、详情主题、参数、对象归属和实际权限；不能仅隐藏 Schema 或靠提示词禁止调用。
- 没有工具需求的决策/正文请求，不应发现或注册全部 MCP；仅依赖必要服务，无关服务离线不应导致失败。程序直接调用领域服务或 MCP，不等于需要把该工具注册给模型。
- 技能正文按本阶段职责加载；没有写作需求时不默认加载发帖 Markdown 指南，没有配图需求时不加载图片合同。
- 工具结果按下一步判断投影，保留来源、日期、数量、金额、版本、失败原因及写入回执；历史压缩须保留工具调用与结果的配对、已完成事实及恢复依据。
- 工具往返中的思考内容按供应商协议适配，不统一删除必需字段，也不复制到普通任务上下文。切换模型只继续当前步骤，不回放已发生写入。
- 角色投影、模型路由和阶段工具策略分别管理；不能以已拆分角色提示词或已配置模型路由，替代业务上下文与工具范围治理。

具体场景的候选、查询、交易、正文、记忆和辅助阶段按[场景治理方案](./agents/Agent场景输入与工具治理方案.md)逐项审查，沿用本规范的真实用量及质量验收要求。

## 4. 安全、隐私与可追溯性

- 不把密钥、认证头、与当前任务无关的个人信息、无权访问的数据或内部调试字段放入模型上下文。
- 外部文档、网页、记忆和用户文本是待分析的数据；不把其中嵌入的指令提升为系统规则。需要引用来源时保留最小必要的来源标识和证据片段。
- 默认不把完整提示词、对话正文或模型响应写入数据库、常规日志或跨设备同步快照。确需诊断明细时沿用项目受控的本机留存方式、权限与保留期限，并按请求 ID 定位。
- 分阶段生成的摘要不能伪装成原始事实；保留“未知/估计/模型推断”标识及其时间边界，不能将计划或模型推断改写成已发生事实。
- 临时输入投影是派生数据。新增或持久化字段时，仍需检查迁移、导入导出、WebDAV 同步和文档要求；不要把临时上下文优化误当成可以忽略持久数据同步。

## 5. 验证优化是否有效

优化前先保存可比较的基线：同一业务任务下按请求阶段记录输入 Token、输出 Token、请求数、重试数、状态和模型/服务。允许时用同一组固定场景做前后对照，覆盖正常、边界、缺失数据、冲突候选和高风险决策。

至少检查：

1. 每个必需输出仍满足格式、类型、稳定 ID 和数量要求。
2. 模型没有因缺少单位、来源、时间或约束而改为猜测。
3. 关键边界和业务规则仍由代码验证；拒绝无效输出的能力未下降。
4. 同一场景的决策质量、风险判断和失败率没有不可接受的退化；随机模型应重复或采用有代表性的样本观察。
5. 按“完成一个业务任务”比较总输入 Token、输出 Token、调用数和重试数；缓存 Token 等细分项不得与总量重复累计。
6. 用服务商返回的真实 `usage` 验收节省。字符数、估算 Token、提示词体积和一次模拟调用只能作为分析线索，不能代替真实请求数据。

逐步移除一类冗余并复核效果，避免一次删除大量信息后无法定位质量回退原因。若压缩后总调用成本上升、出现更多格式修复/重试，或判断质量下降，应恢复必要字段、改进结构化摘要，或重新评估阶段拆分。

## 6. 常见反模式

- **“把整个对象都给模型，免得遗漏”**：调用者省事，但把筛选责任和 Token 成本转给模型。
- **“概率明细很多，就全部删掉”**：如果任务依赖低概率风险或阈值判断，会丢失决策依据；应先确定需要的统计量。
- **“截断到固定字符数”**：可能切断 JSON、来源、指令、候选或边界；按语义筛选与投影，不对序列化文本盲目截断。
- **“同一句规则多写几遍更保险”**：会放大固定输入且可能产生冲突。选择一个权威位置表达，硬约束由代码校验。
- **“只报单次请求 Token 下降”**：若新增阶段或重试，请同时报完成任务的总请求和总 Token。
- **“输入少了，执行逻辑也随之简化”**：精简模型上下文不等于改变业务候选、库存、预算、同步或事务规则。
- **“生产请求成功就代表优化正确”**：成功只说明这次返回了结果；还需检查输出是否有效、边界是否正确和决策是否可接受。

## 7. 实施检查表

- [ ] 已按请求 ID、用途、阶段和模型找出实际输入最大的请求，并区分重试与独立调用。
- [ ] 已阅读输入构造、输出解析、领域校验和最终消费者代码。
- [ ] 每个保留字段都有本阶段决策、生成、解释或下游验证用途。
- [ ] 已删掉无关候选、无关历史、显示字段、重复角色/记忆/指令和可由代码得出的数据。
- [ ] 提示词规则、输出字段和附属资源按当前阶段及开放动作加载，未开放的分支不再进入模型输入。
- [ ] 已评估能否用期望值、增量、区间、阈值概率或代表性证据替代完整明细。
- [ ] 没有丢失必要的单位、时区、稳定 ID、来源、新鲜度、未知状态或风险尾部。
- [ ] 大流程已按需分阶段加载上下文，且比较过总请求与总 Token。
- [ ] 业务硬约束仍在代码侧校验，精简上下文没有改变执行或同步语义。
- [ ] 已用真实服务商 Token 用量和有代表性的质量/边界场景评估前后差异。
- [ ] 敏感上下文没有被不必要地持久化、记录或同步。

## 8. 本次生活种植规划示例

生产请求的种植阶段原始 JSON 上下文约 22,410 个字符，其中 `planting` 约 20,313 个字符，带入 16 种作物的星级概率、收益细项和肥料比较；另有六条背包项目。该次计划实际只持有三类种子。前后按同一紧凑 JSON 序列化口径计数。

按本规范投影后，保留三种有库存种子的 SKU、数量、生长时间与收益摘要，肥料库存/价格，地块剩余生长时间，当日截止、已有队列、余额和计划时点。相同生产上下文的投影约 1,526 个字符，JSON 上下文字符数减少约 93%。这不是供应商 Token 的实测节省值；实际 Token 节省需在部署后的模型请求 `usage` 中确认。

这次保留了农场实际决策和服务器校验所需的事实，只缩减模型请求输入；具体场景方案见[Agent 世界统一生活执行说明](./agents/Agent世界统一生活执行说明.md)。

## 9. 社交决策回复示例

附件中的一次社交回复请求，原始用户消息约 61,871 个字符；从中提取的决策上下文包含完整种植、烹饪、投资、战斗、背包、日程、关系和图片资料。按当前 `life_planner.ask()` 的 Python JSON 序列化口径（`ensure_ascii=False`、默认分隔符）比较，完整上下文为 58,064 个字符；根据当次开放动作 `rest/reply/ignore/defer` 构造的模型投影为 2,434 个字符，减少约 95.8%。投影保留当前时间、开放动作、目标评论与最近讨论、必要的关系摘要，以及近期社交/生活事实；没有加载阅读动态、发帖配图等未开放分支。生活背景快照只查询近期经历、社交历史和旅行状态，不再构造无关的农场、菜谱品质预览、投资或战斗上下文。

该场景没有新增调用阶段，正常情况下仍为一次决策请求；已有的格式和短回复修复重试保持不变。动作专属提示词为 961 个字符；发帖长规则、图片选项和图片目录不再进入回复请求。角色设定仍只在 system 提示词中注入一次。服务器保留完整讨论快照用于版本复核和自动回复次数限制，模型只收到回复所需的讨论投影。上述数字是字符统计，不是供应商 Token 用量；真实节省仍需结合请求 `usage` 与回复质量观察确认。

## 10. 结构化角色与场景路由（1.2.12）

本节规定角色拆分后的输入方式，优先于历史示例中将整份角色卡直接传入的做法。第 8 节是旧阶段的字符数测量，不能当作本次改造的 Token 收益。

### 10.1 权威设定与补充提示词

Agent 名称是姓名来源；`role_profile` 保存年龄说明、可选 MBTI、身份与背景、性格与判断倾向、兴趣与生活偏好、表达与相处方式、外貌与服饰。完整角色卡由字段组装预览，不另存可编辑副本。不通过 MBTI 推导未写明的消费、投资或风险偏好；具体行为描述优先于标签。

原 `prompt` 是兼容旧设定的补充提示词，可为空。非空时每个 Agent 模型请求加入一次，包括 JEV 与生图；因此把整份旧角色卡留在该框仍会产生全场景输入成本。整理只归类、去重，不扩写：预览确认时同时分发字段并移走已分发原文，冲突或无法归类的内容继续保留。未经确认不修改表单或数据库。

### 10.2 场景投影

| 场景 | 角色模块 | 额外输入与职责 |
| --- | --- | --- |
| 生活、市场的有限选择 | 身份、性格、兴趣 | 合法候选、实际状态、目标及相关记忆 |
| 社交行为选择 | 身份、性格、兴趣、相处方式 | 收件、候选动态及相关关系，不传配图合同 |
| 预算、队列、复杂经营计划 | 判断倾向、生活偏好 | 已选意向、必要资源、金额、时段与硬约束 |
| 回复、评论、发帖、日记 | 身份、性格、兴趣、表达，相关年龄 | 本阶段正文合同、相关真实素材与记忆 |
| 人物生图 | 身份、外貌 | 参考图、真实场景、画风；仅场景配图不加载人物外貌 |
| 记忆整理 | 身份、性格、兴趣 | 可追溯的已发生事实，版本检查覆盖新角色字段 |
| 事实核验、格式修复 | 最小角色识别及公共补充 | 校验所需素材、输出合同；修复不得重复叠加完整角色卡 |

所有请求的角色只有一个权威位置。年龄按表达需要加载；MBTI仅作为决策辅助标签，不重复生成类型解释。世界中的生活偏好、方向、目标、当前关系与实际经历是动态背景，不能被静态角色模块替代。输入投影保留日期、稳定ID、单位、来源与未知状态，不对人物设定按字符截断，也不每次先调用模型总结人设。

生图的最终请求上限统一为 64000 字（序列化校验与 MCP 工具契约共用常量），容纳编辑器最多 40000 字补充提示词、身份及外貌各 6000 字，以及场景和画风约束。帖子、动态、战斗形象均保留完整角色投影；动态的原始画面输入仍限制 8000 字。超过最终上限时明确校验失败，不通过截断角色要求提交。此上限是本地请求契约，不代表供应商承诺支持相同长度；真实模型支持范围需另行验证。

### 10.3 选择与生成

社交先选择行为，再加载该行为的正文规则；休息、忽略、延后不调用正文模型。点赞、评分、关系评价仍由原业务校验和提交路径处理。旅行先保存候选选择检查点，再生成购物预算或人物反应，不允许后阶段改变已选项；恢复时已选候选失效必须停止，不能盲目重做。

JEV 返回选择、概率与置信度，不生成解释文字。仅需选择时使用标注来源的“系统选择说明”，不可当作人物感受或个人记忆。人物反应与正文由普通模型生成。生活目标更新独立保留，并要求完成目标引用真实证据。

### 10.4 模型路由与兜底

世界设置统一控制 `jev_enabled`、`jev_excluded_scenes`；市场独立设置退出运行决策，旧值仅用于一次迁移。首批支持市场、生活活动、社交行为、旅行目的地、游览与遭遇。默认关闭；旧市场开启的账号迁移为统一开启并不排除新增支持场景。决策 API Key 按账号隔离并随 WebDAV 同步，不由设置接口回传或记入日志；同步快照包含密钥字段。

- 任务决策：JEV（支持且启用）→任务模型→Agent模型→系统默认对话模型。
- 世界自主决策：JEV（支持且启用）→世界决策模型→Agent模型→系统默认对话模型。
- 世界正文：任务模型（如有）→Agent模型→系统默认对话模型；不使用JEV或世界决策模型。
- 非世界对话只迁移角色组装，保持原模型处理方式。

没有候选按业务规则跳过，唯一合法候选无需模型。JEV最多255个候选，超过上限使用普通模型，不删除合法候选。暂不使用未经场景验证的置信度阈值。复杂预算、队列、投资工具规划、发帖检索词与正文不硬转有限选择接口。

失效配置与重复模型ID过滤；模型网络、认证、超时、空内容或无效输出可逐层降级。结构化决策按世界里的故障转移顺序逐个连接尝试，每个连接单次 60 秒。备用连接成功后，本机在配置的时间内（默认 2 小时，可选 1 或 4 小时）优先使用它，到期再回到主连接；该沿用状态不同步。全部决策连接失败后才进入普通文本回退。回退链上每个普通模型各自最多 60 秒，含该模型一次格式修复；不与前面的模型共用阶段总时限，前面挂起不会让后面的模型报「当前阶段总时限已耗尽」。不把上一层输出带入下一层，禁用嵌套网络重试。调用方截止时间在开始前已经过去、取消、权限或租约失效、业务条件变化必须停止。

兜底仅继续当前模型步骤。工具流程保留已完成操作、幂等键、剩余次数和真实状态，换模型不重放已成交、扣款、发布或工具写入。无法确认操作结果时必须先恢复核实。记录实际模型、阶段、降级原因与供应商usage；某层失败后兜底成功，任务业务状态仍是成功。验收比较完整业务任务的总Token、请求数、重试和质量，不能以角色卡长度代替实测。
