# 系统性能监控

核对日期：2026-11-06。状态：本地实现与隔离验证；未发布到生产，未启用生产数据库扩展或进行真实业务负载验收。目标规格与实施顺序见[需求规划](./requirements/008-系统性能监控.md)。

## 使用入口

超级管理员打开「系统设置 → 性能监控」（设置路径的 `?tab=performance`）。首次安装默认暂停，在「采集设置」开启。支持最近 1 小时、24 小时、7 天，页面可见且上一轮请求结束后每 30 秒刷新；详情、设置和清空均使用弹窗。

概览、排行、样本与原生数据库状态独立请求。翻页只读取样本；切换操作类型不重新请求概览，数据库状态仅在 SQL 页读取。每类资源最多缓存 8 组查询条件，只展示当前条件匹配的缓存，首次查询及新条件失败不会展示另一筛选的旧数据。同条件刷新保留已有结果并提示失败；清空会取消在途请求并清除所有查询缓存，避免旧响应或旧分页重新出现。

分页区分普通接口、流式响应、SQL、模型调用、后台任务与外部调用，分别查看次数、累计/平均/最大耗时、近似 P95/P99、慢比例与错误比例。错误率包含同类全部结果，4xx/取消不计服务端错误。平均耗时趋势按时间分桶，有采样缺口时断开，不填充零。当前页面提供近似 P95，P99 同样由接口返回，暂未单列于页面。

慢操作、失败、包含慢子阶段的操作，以及约 1% 正常操作保留样本；聚合覆盖进入队列且成功落盘的全部事件。静态资源、健康检查及 `/api/system/` 诊断 API 排除。每次查询最多读取 20,000 个分钟聚合桶、返回 100 个排行；超限明确显示数据不完整，应缩短时间范围。

新聚合桶在维度 JSON 中保存直方图格式版本及完整桶边界，桶结构变化后另建聚合键。没有该元数据的历史桶按固定的首版边界读取，不套用升级后的边界。只有结构一致且计数有效的分布可以合并；不兼容或损坏时 P95/P99 返回未知并注明原因，次数、累计耗时和错误率仍可用。不通过补零或截断数组修复分布，避免产生错误百分位。

## 三层采集

- **接口**：Django 中间件计时，以路由模板分组；响应对象返回与流式迭代结束分开。流式记录服务端首个非空响应块，正常、失败、取消和关闭只结算一次；同步/异步包装均关闭原始迭代器，异步响应从关闭线程调用时回到所属事件循环清理，不声称测到了浏览器实际收到时间。
- **SQL**：Django 执行包装统计次数、累计调用耗时与单次慢执行。嵌套操作复用包装，SQL 全局只计一次，根操作保留包含关系。当前仅保存语句类型、结构指纹和有界代码位置，**不保存 SQL 模板或参数**；指纹用 sqlparse 做结构归一化后哈希，不把它当作可安全导出 SQL 正文的认证器。驱动后续取数、ORM 对象构造、锁等待原因和执行计划未单独采集。
- **AI/后台任务**：复用既有模型/任务诊断入口，记录执行时间、已观测首个有效内容或思考输出、取消/失败和可见重试尝试数。未暴露的 SDK 重试、任务排队等待显示未知，不以零补齐。后台操作与跨线程模型网络调用保留父子关系。

外部 HTTP 挂在 requests 默认 HTTPAdapter、HTTPX 默认同步/异步 HTTPTransport，统计每次传输层响应返回的耗时，避免重定向的外层与内层重复计算；不含完整流式正文消费，不保存 URL、请求头或正文。自定义 Transport、其他客户端、独立进程及尚未埋点的后台任务不保证覆盖。

HTTP 全局包装与采集线程仅在已识别的运行服务进程启用：Django runserver 的实际服务进程（含 `--noreload`），以及 Gunicorn、uWSGI、Uvicorn、Daphne 启动入口；重载父进程和 migrate、check、shell、测试等管理命令不自动安装。自定义启动器需要补充识别。代码位置解析使用每进程最多 4,096 条路径缓存，包含项目外路径的排除结果；行号仍取当前栈帧，SQL 包装复用一次策略快照。

当前任务接入包括：已有 `diagnostic_operation` 的 Agent 周期任务/居民子阶段、图书分析、文章处理；Agent 世界 `execute_item`；RAG 手动/定时同步；WebDAV `sync_v2`、强制下载与本地备份导入。已有 `model_operation` 覆盖的通用模型、生图与直接模型调用接入；有界模型调用额外记录可观测尝试与首输出。尚未逐一运行真实外部模型/WebDAV 验收，不能据此宣称所有后台路径已覆盖。

在途记录约 5 秒更新。超过 20 秒未更新时标记「心跳中断」，耗时停在最后一次心跳；5 分钟后隐藏，由维护任务分批删除。面板按类型、操作及心跳状态分别显示数量和最长耗时，最多展示最近 100 条。在采集线程收到完成批次时，即使预算不足以写入统计，也会清理对应在途记录。请求在路由解析后即显示路由模板，解析前或未匹配路由的请求显示「尚未匹配路由的请求」。当前只记录操作实际开始，尚未接入业务可运行时刻或调度队列，不提供任务排队等待分析。进程强杀前未落盘的数据不能恢复。

## 诊断报告与修复

在样本详情点击「导出诊断报告」，下载包含 `report.md`、`evidence.json`、`manifest.json` 的 ZIP。报告可以离线阅读并交给代码助手；无需访问原监控页面。包含发生时构建版本、模块/函数/相对路径及行号、耗时和父子阶段、SQL 指纹与次数、模型/HTTP 证据、规则线索和已知缺口。选择子事件时附已保存的根样本，缺失则注明。

同类基线按同操作、构建身份、策略、方法及模型/提供商选择；同结果数据用于耗时对照，全结果总体用于错误率与慢比例。结果中保留各自样本量和范围。基线可能包含目标记录，不能称为独立正常对照；它是时间邻域聚合，不保证业务输入、并发或数据规模一致。

异常关联只读访问既有本机日志，通过已知关联键指纹命中 `event_correlations`。日志是同日同类异常聚合，因此只附分类、聚合 ID、次数与首末时间，**不把代表请求、任务、耗时或堆栈当作本次独立证据**。未匹配可能是关联键未采集、未落盘、过期或清理，不证明本次没有异常。导出不会创建 SQLite 文件或修改日志。

报告不收集提示词、模型正文、SQL 参数、原始请求/响应、认证信息、用户主机路径，不自动调用 AI、重跑业务、远程取证或执行 EXPLAIN ANALYZE。SQL 次数偏多只是排查线索，不能直接认定 N+1、缺索引或网络故障。修复应先核对报告 commit 与实际源码，再按同一数据规模、并发和采集策略复测；资料不足时补采，不能只凭一个耗时值保证根因或优化效果。

报告在内存即时生成，不保存服务端副本。完整包解压后不超过 2 MiB；样本采集本身最多 100 个子阶段、64 KiB，截断内容无法靠导出恢复。目标已清理返回 404；关联信息缺失则保留报告并标记缺口。只允许管理员导出，响应禁止缓存。

## PostgreSQL 原生查询统计

后台每分钟检查 `pg_stat_statements`，未安装时显示「未启用」，不会自动安装、修改 preload 或重启数据库，应用侧 SQL 仍可用。安装需按 PostgreSQL 16 说明核对已有 preload、安排重启、在目标库安装扩展和配置读取权限。

当前保存累计耗时前 1,000 个指纹的只读快照，不读取原始 query 文本。可计算相邻快照的次数/总耗时差值，首次、超过 120 秒缺采、统计重置/淘汰或数据库重启时重建基线。原生累计快照与应用统计不合并。当前页面展示累计快照与缺口说明，区间差值由接口返回；不将累计最大耗时相减充当区间最大值。

原生统计包含数据库所见的监控语句，目前无可靠模板分类时不擅自隐藏；非累计耗时前 1,000 的查询和单次采样间重置后重新累计的情形存在诊断边界，不能当作完整 SQL 审计。生产扩展启用和真实重置场景仍需环境验收。

## 数据、本机边界与维护

新增 Django app `system_performance`，独立 PostgreSQL 表由 `0001_initial` 管理。策略、桶、样本、批次去重、在途与原生快照均不参与 WebDAV、同步修订及业务备份；导入也过滤该 app 的记录，避免外部备份覆盖本机策略。整库 pg_dump 和数据库卷备份仍可包含这些表。

每进程队列上限 2,048 条/8 MiB，单批最多 200 条；低流量约 5 秒刷写，达到 200 条立即唤醒，有积压时连续处理各批，不再逐批等待 5 秒。策略和在途心跳独立约 5 秒刷新；没有在途操作时不执行心跳事务或获取策略行锁。批次只对锁竞争、事务重试、语句超时及连接故障最多尝试 3 次；同一批次 ID 防止提交状态不明时重放计数。连接、锁及语句有界，监控写入在独立后台线程连接中完成，业务事务不会等待它落盘。容量不足、数据库故障或队列满时允许丢弃；页面健康数字是当前服务进程所知，不代表全体 worker 的精确丢失量。

策略读取、批次写入、在途心跳、维护和原生数据库采样分别记录安全错误分类与累计失败次数，不保存异常正文。`failed_batches` 只累计批次写入失败，成功不清零；连续失败次数在对应阶段成功后重置。单次心跳/维护故障及短暂锁竞争不关闭采集，维护失败至少退避 5 秒再尝试。策略读取或写入连续失败至少 3 次且当前错误不是锁竞争等短暂类型时，暂时关闭进程缓存中的采集，后续成功读取本机策略可恢复；不改写管理员保存的启用开关。真实数据库不可用期间仍可能丢失事件。

每进程每日最多跟踪约 2,048 个原始聚合维度，超限进入按类型/状态/策略分组的「其他」。保留策略默认样本 7 天、统计 30 天、数据库快照 7 天、批次凭据 24 小时、过期在途 5 分钟；每分钟分批清理。活跃诊断数据预算默认 200 MiB，以 JSON 文本字节的两倍加每行 2 KiB 开销预留估算，覆盖样本、桶、快照、批次凭据与在途记录。预算计量与压力状态保存在本机策略 JSON，由策略行锁串行管理；首次计量和维护会在短语句超时内仅扫描性能表重新核对。写入前先预留聚合与去重批次空间，再尝试保留样本；空间不足时限制新明细，聚合/去重也放不下时跳过整个新批次并计数，不继续无限增长。快照与在途新记录同样受预算约束。压力下连续分批清理最旧的样本、快照和桶，每轮有时间上限，直到低于约 85% 预算后恢复明细写入；不为腾空间删除 24 小时内的去重凭据。若下调预算已低于受保护元数据占用，则保持限流直到空间可用或调高预算。正常退出尝试有界刷写；突发、进程终止与数据库故障仍可能丢记录。该预算限制活跃数据的保守估算量，不能当作 PostgreSQL 库文件硬配额；空页、索引膨胀、WAL 和物理空间回收仍存在独立边界。

暂停保留已开始操作的结束信息。清空提高代次，拒绝旧代次队列与在途回写；策略保留。新策略在操作结束时按当前进程缓存版本应用，SQL 按单次执行结束时版本记录，跨 worker 约 5 秒刷新。当前不提供每模型/任务类型单独阈值、worker 版本确认面板或导出历史。

## 代码入口与验证

后端：`system_performance/` 按采集上下文、队列、存储、指标、数据库快照、查询、报告、API 分工。路由 `/api/system/performance/` 下为 `overview/`、`rankings/`、`samples/`、`samples/<id>/`、`samples/<id>/report/`、`database/`、`policy/`、`clear/`。

前端：`components/Settings/PerformanceMonitor/`、`hooks/usePerformanceMonitor.ts`、`hooks/usePerformanceResource.ts`、`api/performance.ts`、`types/performance.ts`；mock 为 `mocks/performance.ts`，经 `mocks/local.ts` 分派。设置页只注册入口；沿用项目橘色品牌和卡片规范。

纯 local 模式每类初始提供 24 条样本，可验证每页 20 条的分页；聚合、排行和详情来自同一组记录。清空后持续为空，旧 ID 的详情/报告返回 404，不按定时器恢复历史。性能页顶部「模拟新采集」仅在采集启用且非空场景时生成新时间、新 ID 的记录；暂停时不生成，阈值仅影响新记录。该按钮不发送真实业务请求；刷新整页会重置内存 mock。

- `.venv/bin/python -m unittest system_performance.tests`：29 项无数据库单元测试，覆盖同步双向排除、统计分母、SQL 脱敏、流式关闭、报告安全投影、队列刷写，以及启动入口识别、路径缓存、直方图兼容、心跳/维护故障隔离和连续失败计数。
- 先确认已有 PostgreSQL 容器健康，再运行 `.venv/bin/python scripts/test_performance_postgres.py`：加载 `deploy/.env` 或 `ODOC_DEV_ENV_FILE`，在现有数据库的随机事务 schema 内验证 8 项持久化/API、容量压力、维度溢出与历史/损坏直方图测试。只操作该 schema 的新表，结束后回滚并检查 schema 不存在；不创建替代数据库、不读取业务表、不启动真实调度器。
- Node 22：`npm run test:performance` 的 6 项测试验证 mock 分页/统计、清空后新代次、暂停/恢复、阈值、实际 ZIP 与路由边界。
- Node 22：`npm run type-check`、新增文件定向 ESLint、`npm run build`；构建仍有现有的大包提示。
- `ODOC_DEV_FRONTEND_PORT=5298 sh dev.sh local`：纯 mock 页面检查 1440/768/390 宽度、明细、设置、实际 ZIP、空/加载/错误，无横向溢出与未匹配 API 的 501；另检查分页仅请求样本、新筛选失败不混用旧结果，以及清空后显式新采集/暂停行为。不代表真实后端或真实提供商验收。

生产尚未发布。正常容器启动脚本会执行 Django migrations；发布后先确认新表与健康状态，再由管理员开启采集。未启用生产扩展、未做真实业务长时间并发/CPU/内存/磁盘开销对照，初始 P95 增幅 ≤5% 与内存增幅 ≤30 MiB 仍是待验证目标。停用可关闭采集或设置 `ODOC_ENABLE_PERFORMANCE_WORKER=false` 后重启应用，不自动删除表或卸载扩展。
