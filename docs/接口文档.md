# 接口导航与通用约定

本页用于定位当前接口和调用契约。2026-10-16 已静态核对总路由、认证配置和前端请求封装；具体字段、权限与错误状态继续沿领域代码阅读。旧版逐接口汇总见[历史记录](./archive/development/旧接口汇总记录.md)。

## 查找顺序

1. 从下表找到领域与后端路由。
2. 阅读对应 View/Serializer 和前端 API/类型，确认请求、响应、权限、分页及副作用。
3. 涉及业务规则时阅读领域说明；涉及持久数据时阅读[同步说明](./数据同步逻辑说明.md)。

接口总挂载在 [`o_doc/urls.py`](../o_doc/urls.py)。前端通用请求的 `baseURL` 是 `/api`，传入模块 API 的路径应与该前缀组合；各路由是否带结尾 `/` 按实际定义保留。

## 通用请求与响应

- 登录接口为 `POST /api/auth/login`。普通前端受保护请求携带 `Authorization: Token <token>`；后端默认启用 DRF Token 与 Session 认证，具体公开范围由各 View 的权限规则决定。
- 普通 JSON 响应使用 `{code, msg, data}`，成功业务码为 `200`。前端[请求封装](../frontend_react/src/utils/request.ts)成功时直接返回 `data`，调用方按模块类型读取。
- HTTP 状态与业务码都要检查：既有业务错误可能保留 HTTP 200，也有接口显式返回 400/403/409 等状态。公共错误码见 [error_codes.py](../utils/error_codes.py)，异常包装见 [exceptions.py](../utils/exceptions.py)。
- 默认 JSON Parser/Renderer 负责驼峰转换；具体例外以接口实现为准。文件附件、流式响应和 MCP 不能直接套用普通 JSON 的解析方式。
- `FormData` 上传由浏览器设置 multipart boundary；Blob/ArrayBuffer 下载由前端请求封装直接返回文件内容。
- 权限、稳定业务 ID、分页、取消请求、幂等键和同步范围按领域契约处理；不根据前端隐藏按钮推断后端已授权。

## 维护方式

新增或修改接口时，更新所属领域的 API、类型和业务说明。本页只维护通用约定和路由导航；完整字段样例优先写在领域文档，避免在总表和各业务说明中重复维护。响应与架构规则见[代码规范](./代码规范文档.md)。
