# O-Doc AI 读书：情节回顾与知识图谱

## 产品与边界

入口：书架每本书的「AI 导读」，地址 `/books/:collId/guide/:bookId`。

- 故事模式：默认情节流程，一个节点对应一个事件；可切换关系图谱、叙述顺序 / 故事时间、故事线与章节回顾。人物、时间、地点、线索均可打开详情与关联。
- 知识模式：章节总结、重点、重点问答、概念图谱、章节 / 整书思维导图、学习启发。学习启发明确标为 AI 延伸建议。
- TXT、普通 EPUB、文字 PDF 可分析；扫描 / 页眉文字 PDF、严重混合扫描、加密 / 无有效正文文件拒绝 AI 分析。MOBI 提示转换为 EPUB、TXT 或文字 PDF，不接入 OCR。
- 保留原有书架与阅读功能；分析基于可提取文字，不理解图片、图表、公式。小说默认允许整书剧透。
- 图谱独立于双链文章；每本书一套节点和明确关系，多视图共享数据，不部署专用图数据库。

## 使用流程

1. 「检测可用内容」执行文件完整性、正文与目录检测，不调用 AI。
2. 根据书名、目录、正文样本推荐故事 / 知识模式，开始前可修改。无须填写图书分类。
3. 显示字数、章数和范围后手动开始；超过 100 章默认先分析 20 章，可自选范围或选择全部章节。
4. 正文按有界段落完整处理，完成章节即可查看。原文、节点、关系和摘要均保留，不因上下文长度直接截掉尾部。
5. 可停止、重试续跑、重新生成选定范围和独立重建检索。局部重生成保留其他章节的成果。Embedding 失败后可点击顶部「重试向量化」或警告区「立即重试向量化」；正常状态按钮为「重建向量检索」。仅重建已发布范围的原文向量，不重新抽取情节、生成导读，已保存的向量继续复用。
6. 原文入口：TXT 定位偏移并寻找摘录所在页，PDF 定位页码，EPUB 定位正文文件。没有可靠目录时明确标为自动分段，章节可改名、拆分和向后合并。
7. 人工说明、别名、同类型节点合并及关系修改独立保存；重新分析保留修正。新增关联标记为用户补充，关系删除使用隐藏修正。
8. 当前发布版不被旧任务覆盖；重新生成保留历史版，版本菜单显示最近 50 版并提供只读查看。旧正文 / 章节定位不再匹配时不能自动跳到当前原文。
9. 分析控制区展示「执行记录」：等待后台、模型请求开始 / 首个输出 / 接收进度 / 返回、实际提供商与模型角色、字符数、耗时、输出预算、JSON / 引用 / 原文证据校验、显式网络重试 / 参数兼容回退 / JSON 修复、分段保存、章节导读和范围总结、向量索引批次及终态。每 3 秒随状态查询更新，等待耗时每秒刷新；新记录自动滚动，向上阅读时暂停跟随，支持加载更早记录与复制当前诊断。字符进度来自真实流式响应（最多每 2 秒记录），不展示未经校验的正文输出、内部推理或密钥。

### TXT 章节识别与规则升级

标题按单行识别，禁止空白匹配跨行；包含句号、引号等正文特征的行不作为章节标题。整书优先使用重复出现的大章标题族，有明确章标题时，章内纯数字小节和下级节标题保留在正文中，不另建大章。仅有纯数字标题时，要求至少三个从 1 连续递增的编号；无法可靠判断时使用有提示的自动分段。

检测结果记录 `parser_version` 和 `custom_boundaries`，随分析设置 JSON 同步，无需新增数据库字段。规则升级后点击「重新检测」，旧自动目录会重新生成并使原分析版本失效；人工改名、拆分或合并的目录保留。旧版无标记的手动布局根据区域定位和缓存标题检查保守保留，缓存缺失时也不贸然覆盖。

《白夜行》用户提供的 TXT 已以只读方式验证：347,029 字，13 个明确章标题加 1 个「书前内容」，不再误切正文中的「第一部影片」和第五章内的小节「6」。所有章节拼接与解码后的全文完全一致，TXT 偏移逐章校验通过，原文件哈希未变化；原书及摘录未作为测试样本提交。书前声明 / 导读当前仅单独标识，尚未自动剔除。

## 领域与数据

后端 `book_analysis/`：

| 模块 | 职责 |
| --- | --- |
| parsers / chapter_detection / inspection | 正文检测、单行及层级标题识别、目录、原文定位、边界修正与恢复 |
| extraction | 结构化抽取、类型 / 引用 / 连续证据校验、分层汇总 |
| graph | 图谱持久化、局部投影、关系变化和人工修正 |
| jobs / scheduler | 数据库认领、租约、取消、断点、版本校验 |
| execution | 本机执行事件、受限诊断字段、租约及历史分页 |
| retrieval / ask_views | 独立书籍 Chroma 集合、关键词 / 证据回退、带来源 SSE 问答 |
| access / serializers / views | 权限、请求校验与统一响应 |

同步模型：BookAnalysis、Chapter、Revision、ChapterResult、GraphNode、GraphEdge、NodeSource、Correction。字符串 ID 跨设备稳定；节点 canonical_id 不随分析版本改变，事件没有明确既有对象引用时按出处区分。

节点：事件、人物、地点、时间、线索 / 物品、概念、观点、方法、案例。关系有类型、方向、来源和章节上下文；盟友与敌对等历史关系同时保留。节点事实区分 explicit / inferred / user，不将模型自报置信度当成准确率。连续摘录必须能在当前原文段落定位，悬空对象或无证据关系校验失败，修复重试一次；仍失败不发布该分段结果。

未知时间保留原文说法；排序日期只接受原文明示 ISO / 年月日。情节流程保留 640px 高度画布，采用固定尺寸的内容卡片节点（事件名称标题、简介、来源、故事时间与故事线），逐行从左到右，不使用蛇形或重复的情节编号栏。支持拖动卡片、背景平移、滚轮缩放及重置；换行顺序线绕开卡片。虚线箭头仅表示当前排列顺序，不代表只有一条故事线；保留接口已有顺序与因果边，橙色因果线仅来自有证据的 causes 关系。故事线、搜索、类型及顺序控件合并在同一工具栏，小屏自动换行。关系图谱使用逐节点拖动与动态力导向布局，初始及重置视图适配实际节点范围，不重启物理布局；结合原生 labelLayout 与 SVG 标签边界避让，在布局变化、缩放及拖动后隐藏冲突标签。悬停不使用白底标签，突出紫色关联线及关联节点，弱化无关内容，优先显示当前及关联标签。人物详情固定高度并内部滚动，按基础信息（姓名、别名、年龄、职业、介绍）、人物关系、关联内容、原文证据与修正排列；年龄与职业只从已加载明确记录保守整理，未知显示未明确，保留章节来源。自动事件合并依赖模型明确引用已有事件，不凭标题相似进行身份猜测；不确定对象可手动合并。

自动推荐和扫描判定为启发式检测，不等于对所有文件或抽取语义正确性的保证。来源校验验证出处与结构，不能证明模型概括必然正确；请保留人工回看原文的路径。

## 性能、版本与部署

- 当前实现书内串行 AI 请求（低于最多两个的上限），全局仅一项任务执行。数据库租约 180 秒，每 15 秒续约，执行检查必须持有有效认领 token。
- 服务进程自动启动工作线程，可用 `ODOC_ENABLE_BOOK_ANALYSIS=false` 禁用。沿用项目服务进程检测，开发需标准自动重载 runserver；`runserver --noreload` 不自动启动。
- 分段抽取优先简易模型，没有配置则回退默认模型；章节 / 整书分层汇总与问答使用默认模型。
- 抽取与汇总采用独立有界请求能力 `utils/bounded_completion.py`，不改变普通对话、工具调用及问答的原有请求方式。单次调用硬时限 120 秒，覆盖建连、流式接收、一次显式网络重试与 JSON 参数兼容回退；SDK 重试为 0，静默超时不自动再等 120 秒。取消 / 租约失效主动取消异步连接，网络线程不写数据库；关闭资源后任务变为 failed / cancelled，保留完成成果。
- 抽取上限 6000 token，摘要汇总上限 4096 token；正文抽取精简为最多 12 节点、16 关系、240 字摘要和短证据。达到生成上限或声明 overflow 时均衡二分完整正文，最多递归 4 层；仍失败保留可重试状态，不发布截断成果。无效 JSON 修复传入实际错误候选，并将其视为不可信数据，不记录候选原文。
- 优先发送 JSON 模式，仅在 400 / 422 明确说明 response_format / json_object 不支持时回退提示词约束；其他参数 / 模型 / 认证错误不盲目兼容重试。当前抽取缓存版本为 `book-v2-bounded`，旧分段缓存不复用，已完成章节不因升级而删除。
- 有界图书请求按已核验参数关闭 Qwen、DeepSeek 及 MiniMax M3 的思考；MiniMax M2.x 不宣称关闭，其他 / 自定义提供商保留默认并在面板说明。参数依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[MiniMax OpenAI SDK](https://platform.minimax.io/docs/api-reference/text-openai-api)。只有正文输出字符数、正常结束标记和可用的用量统计进入诊断，不记录 reasoning 内容。
- 简易模型仍为可选；已配置但认证失败不会自动切换到主模型。任务认证失败提示显示失败请求实际使用的角色（简易模型 / 主对话模型）、提供商及模型名称，不显示 API Key 或提供商原始响应；简易模型未配置时，抽取失败正确标为主对话模型。图书页面与设置页面均说明这一选择规则。
- 图谱一次最多 200 节点；流程 / 时间线和章节列表最多 50；节点事实 50 条分页，图谱摘要每节点最多 3 条事实。详情按需加载。
- 向量使用独立 `book_analysis/embeddings.py`，每次仅提交一段不超过 1500 字符的字符串，与 memo 的兼容接口输入方式一致。建索引单次硬时限 180 秒，问答向量检索 30 秒快速降级；无隐式重试，停止 / 租约失效主动取消连接。每段完成立即写入 Chroma，重建时按稳定 ID 复用已有向量；逐条记录输入字数、模型、超时和返回耗时，验证索引、数量、有限数值与维度。整个索引过程固定模型配置，集合名包含书籍与模型身份，过滤书籍 / 章节 / 分析版本。向量失败不阻塞导读；无本机正文时可使用同步的图谱证据回答。这些改动不增加同步字段，向量和执行事件仍为本机派生数据。
- 原文 hash、模式、设置版本及抽取版本确定缓存有效性；更换正文或边界后旧成果失效，旧版本仍可查看。
- 上线前执行 `uv run manage.py migrate` 并重启服务。开发测试未迁移用户数据库。
- 所有同步设备须升级到包含 book_analysis 的版本再使用此功能，避免旧客户端不能识别新模型。

## API

均位于 `/api/book-analysis/books/<book_id>`，沿用 code / msg / data 与驼峰转换：

| 路径 | 方法 / 行为 |
| --- | --- |
| 基础路径 | GET 检测信息、状态、概要及最近历史版本；可传 revisionId |
| /inspect | POST 检测文件、缓存章节 |
| /chapters | GET 50 项分页，revisionId 可查看旧版已完成章节 |
| /chapters/<id> | GET 导读、定位、正文预览，可传 revisionId |
| /chapters/<id>/boundary | PATCH rename / split / merge |
| /runs | POST mode、start、end、force、kind(analyze / index)，返回任务 ID |
| /runs/<id>/cancel 或 /retry | POST 停止 / 续跑 |
| /runs/<id>/events | GET 执行记录，before 为事件数字游标，每次最多 80 项，按发生顺序返回 |
| /graph | GET chapterId、kind、query、center、thread、view、order、page、limit、revisionId |
| /nodes/<canonical_id> | GET 节点事实与关联，可传 page、revisionId |
| /nodes/<canonical_id>/correction | PATCH name、description、aliases、mergeInto、hidden |
| /relations | POST source、target、kind、label，创建用户关系 |
| /relations/<id> | PATCH 关系说明 / 类型；DELETE 隐藏关系 |
| /ask | POST question、chapterId、nodeId；SSE sources / answer / error / done |

只有所有者能启动分析或修改。具备阅读权限的用户能查看已发布成果；所有章节、节点、版本和任务必须属于该书。公开图书可匿名读结果，昂贵问答限流 30 次 / 小时；未发布构建版不开放。

## 同步与恢复

分析成果和 Correction 自动加入现有 WebDAV / FTP / SFTP 快照及修订追踪。

SourceCache、SegmentCache、AnalysisRun、WorkerLease、ExecutionEvent 为本机派生数据，明确排除同步；Chroma 也不同步。换设备后可直接查看导读、图谱和来源。需要全文检索时从书架恢复正文，再重建检索；自定义章节定位保存原始区域列表，可重建拆分 / 合并后的 PDF、EPUB 和 TXT。

执行记录受图书阅读权限保护，任务 ID 必须属于该书；只保存白名单元数据与已通过校验的简短摘要，不保存 API Key、完整提示词、无效模型原始响应或内部推理。启动本次版本前须执行迁移 `0004_executionevent`；旧任务的历史不会补造，仅后续执行步骤产生记录。租约是否有效及最近续约时间用于排查重启 / 线程中断，不代表模型有输出，也不是独立的任务总时限。
