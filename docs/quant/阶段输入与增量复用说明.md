## 当前规则

当前普通首次研究使用工作流41；新跨源码研究使用42，继续/指定重跑既有任务保持原版本。历史输入和成果不改写；恢复执行使用当前兼容的响应解析和纠错，实际输入不同时按既有指纹规则重新计算。42沿用28的组件方案4及阶段输入复用规则，并使用[源码算法提取](./源码因子算法提取说明.md)合同。跨源码基准须显式选择同材料已完成研究，不能按名称跨研究借用结果。

41/42 的源码输出目录不再跳过循环、复合赋值后将初始化值当成完整算法；受影响输出转由模型提供完整 Python。31–40 重建历史模型输入时仍用原目录规则；v28 评分提示保持其冻结原文，新评分指令仅用于31及之后的算法工作流，避免旧快照输入哈希变化。

## 分析步骤与故障恢复（2026-10-31）

| 步骤 | 产出 | 恢复方式 |
| --- | --- | --- |
| 整理来源 | 保存源码、作者说明和来源快照 | 保留已取得的资料 |
| 识别资料 | 名称、类型、计算用途 | 输出格式错误反馈给模型纠正 |
| 参数与静态检查 | 源码默认参数及中文解释 | 唯一定位的默认值由源码目录直接填入，不因模型抄写错误阻断 |
| 研究分析 | 做什么、怎么算、关键公式、参数、使用方法 | 按既定阅读结构生成，已有采用正文不被续跑覆盖 |
| 提取因子 | 中文名、稳定标识、入参、公式、完整实现 | 格式、引用或明确的返回类型错误自动纠正；不执行上传代码 |
| 修订候选定义 | 必要的计算定义补充 | 无修订目标时直接沿用原提取结果 |
| 检索比对 | 当前库及历史实验的相关记录 | 指定重跑评价时沿用此前比对范围 |
| 评价与审查 | 五维评分和依据 | 失败保留算法，标记未完成并可单步续跑 |
| 设计实验 | 数据准备、参数比较、输出检查步骤 | Python 算法给出 Python 运行方案，本机表达式方案只绑定可执行算法 |
| 发布报告 | 当前文档或待采用更新 | 已有文档进入更新对比，不增加并排的独立报告入口 |

响应解析先去除完整的前置思考块及外层 JSON 围栏，不改写代码字符串。JSON 转义损坏、字段错误等向模型反馈具体位置和上次响应，在既有调用与时间预算内最多自动纠正一次；输出截断另有一次压缩完整输出的重试，不占格式纠正机会。继续失败时记录明确原因。参数、提取、评价和规划均使用该路径，已完成步骤保留。

源码引文允许换行符等价，归一后仍回写实际源码片段；有真实引文时不让额外说明文字使整个算法失效，全部无依据的引文仍返回具体原因。参数默认值只按唯一源码声明修正，参数名必须对应原始声明。评分按原始源码评价结构、时序与可解释性，不因没有运行回测就把静态质量全部置空。评分单次上限180秒，提取和规划300秒，仍受总预算限制。

评分和规划的系统降级不计入完成百分比。页面每个失败/部分完成步骤提供“从这一步继续”，执行预算、词表和沿用说明默认折叠。后台异常日志记录任务、阶段、字段原因和对应研究路径，可回到研究处理。诊断日志沿用本机日志保留策略，不进入 WebDAV；业务输入、成果及当前采用状态按既有已确认同步范围保存。

代码入口：`quant/workflows/model_response.py`、`runner.py`、`quant/algorithms/python_output.py`；页面入口 `ResearchWorkflow.tsx`。生成输出检查只判断能静态确定的字典列表与标量序列矛盾，不声称完成任意 Python 的运行或原平台等价验证。

28在识别、参数、研究、提取、候选修订、审查及实验设计阶段，保存**实际模型提示全文的哈希**、JSON输出/长度合同及已有模型配置身份。来源与全部依赖哈希仍按原样记录，独立于这个模型输入指纹。只在同版本、同阶段、同模型配置、实际提示完全相同，且原阶段成功、当前未要求重跑时，尝试沿用结果；不是按摘要相似、函数同名或模型自行声称未受影响来复用。确定性阶段和组件解读保持自己的合同。

沿用前在当前来源上重新校验阶段输出、引文、参数、候选及词表；修订参数的系统来源身份重新绑定当前来源，before/after哈希和变化字段重新计算。原AI摘要、推断及引文不改写，不把出处哈希的变化冒充新模型研究。复核失败就进入正常模型路径，不能因为完整快照也恰好相同而跳过失败的校验；发布仍要求全部阶段有效。显式指定重跑的阶段及后续步骤继续强制执行，优先于输入相同。

模型输入构造达到现有上限或未通过检查时，先记录受阻输入和失败阶段，保留前序成果；没有可用指纹，不复用或调用模型。旧合同没有本次指纹，不能事后补造后用于跳过模型。复用结果不产生新模型用量，未知用量不记0；缓存静态意见不增加实证等级，不代表平台执行或真实模型质量重新通过。

## 候选修订的分析范围

原修订阶段重复读取全部来源与局部意见，任何无关源码改变都触发模型。本版只在以下条件下提供选中候选及其声明依赖正文：组件方案完整可用，所有源码引文唯一定位到已提供的组件，组件静态依赖无疑点，且候选与来源没有尚待解释的外部依赖声明。多项选中候选的正文取并集，不通过相似名称猜测关联。

提供候选完整定义、参数/默认/约束、原引文、局限、提取说明、修订检查和词表；保留完整说明/网页与平台配置。源码保留原行号；只省略未选组件和系统来源哈希，后者由服务端重新绑定。缺依赖、动态/间接调用、重复引文、找不到组件、组件预算省略影响覆盖、其他语言等情况退回完整来源。完整来源分支仍读取完整代码与原上下文。

这种有界视图用于**定义修订假设**，不是运行时依赖完整性或原平台等价证明。材料不足须返回unresolved，不猜测未提供正文。修订引文须属于当前确实提供的连续正文范围，不能借用未提供的源码；相邻范围可引用连续原文，跨省略区间不允许。参数或关联代码改变会改变实际输入，重新修订；相同候选与依赖下，仅独立函数变化时可以沿用修订。

全局识别、参数、研究、提取和评分继续读取完整来源。新完整源码就是这些阶段的相关输入，变更后重审是必要行为；不会为了减少调用强行复用旧评分。组件及实际阶段输入已形成有界增量路径，不能据此宣称求解了任意程序运行时语义。
