# 依赖源码补交与重新分析

核对日期：2026-10-25。应用1.5.44、quant schema47；没有新增表或数据库迁移。本文描述来源补充与AI重分析，原平台依赖安装、编译和实际运行仍须单独验证。总入口见[量化研究库](./量化文集一期说明.md)，完整目标见[重构规格](../requirements/007-AI量化研究系统重构.md)。

## 当前使用流程

研究报告页选择材料当前源码快照，点击“补充依赖源码”。可粘贴或上传`.py/.pine/.mq4/.mqh/.tdx/.txt`正文，填写与源码引用一致的相对文件名和补充原因，支持中文文件名及路径。上传可自动识别UTF-8/UTF-16，也可选择GB18030等读取编码。每次1–4份文件，单份最多100000字符，整份主源码及依赖最多150000字符（含定位标记），总数最多8份；同材料最多64层补充。空输入、越界路径、仅大小写不同的重复文件、覆盖主源码及全部未变化的提交均拒绝。

补交默认自动排队分析。标题、原理、参数、问题、候选、研究评分及实验建议继续由既有AI工作流生成。没有可用模型或当前执行预算不允许排队时，补充来源仍保存并显示原因；稍后可手动分析。归档成功不代表报告已完成或依赖已在原平台运行。

同名依赖以新来源版本替换，原始文件、旧来源、旧报告与原评分不改写。打开表单时固定父快照；其他标签页或设备已更新材料时，旧提交返回409，须刷新选定当前快照。相同请求重试返回同一来源，不重复付费排队；修改内容需新请求标识。保存后可直接查看每份原文、文件SHA-256及AI引文对应的全局行号。

## 文件、模型与来源边界

新`SourceRevision.payload`标为`source_supplement / bundle_version=1`，保存父来源ID/hash、原始文件清单、提交原因及文件增替记录。主源码逐字沿用父来源；新依赖标为用户提供。重新组装的`code`只供定位和分析，文件标记不属于原始源码，解码后的源码文本另行保存，SHA按该文本的UTF-8编码计算；原上传字节、BOM和原文件编码不冒充为此hash所验证的对象。CRLF、单独CR及Unicode字符串分隔符按编辑器物理行规则定位，不反复嵌套旧文件标记。

AI读取本次完整的主源码与依赖正文、文件范围和补充原因。文件名、注释与原因都是待研究材料，不赋予执行工具或安装权限。不同文件没有在本机合并执行；同名函数/文件不能证明实际导入或终端EX4同版。能从正文解释的计算可形成带出处的候选定义；缺失、无法证明的时序/运行配置及原生依赖继续未知，不能用收盘价猜测替代不可得算法。

原URL和已保存网页正文沿用父来源，依赖补交不会重新抓取网页或丢掉文件包。新报告绑定新来源，可与旧报告比较；它的静态分数不表示原平台验证或收益。修订定义仍按[现有AI修订规则](./AI定义修订与问题闭环说明.md)保存独立候选，原始源码事实、修订假设和实证结果分开。

## 同步与实现

按用户已确认的全部量化业务资产范围，文件正文、父来源、提交、文件hash/行号、变更及新报告继续随WebDAV/FTP/SFTP同步。均使用既有SourceRevision、AIRun、Workflow和ResearchReport；凭据、模型/实验执行队列、租约与向量仍留本机。所有同步设备须支持schema47后再交换新记录。

恢复重新从同材料父来源及提交构建完整文件包，核对主源码、文件增替、hash、全局行号、请求身份和有界无环谱系。改了行号或文件hash后再重算外层hash仍拒绝；恢复不安装依赖、运行代码、调用模型或重新授权分析。旧来源和报告合同保持。

后端：`quant/research/supplements/{contracts,services,views,sync}.py`；API为`POST /api/quant/:collection/entries/:entry/sources/:source/supplements/`，沿用所有者权限和集合锁。工作流文件上下文在`quant/workflows/contracts.py`，采集跳过已冻结包在`research/acquisition.py`。

前端：`sources/SourceSupplement.tsx`、`SourceBundlePreview.tsx`、`hooks/useQuantSourceSupplement.ts`、`types/api/quantSourceSupplement.ts`；独立local路由位于`mocks/quant/sourceSupplements.ts`。默认自动分析可关闭，错误保留表单，上传及保存期间禁用关闭；未保存内容纳入现有离开保护。沿用项目Modal/Select/CodeEditor及视觉规范。

## 真实模型单案例

从此前[MQ4缺依赖指标报告](./多平台真实模型验收记录.md)接续：原指标通过`iCustom`引用`MissingVendor`，旧报告保留算法未知、研究分40。通过正式新API补交一份原创候选`MissingVendor.mq4`正文，按Period窗口计算`close/mean−1`；明确它不是厂商认证文件，无法确认与实际EX4同版。

使用本机已配置的deepseek-flash，6次真实调用、约297.66秒，自动发布新报告，研究分48；旧报告hash不变。模型从新文件第35–40行解释计算，提取一个带`mean>0`条件的SMA偏离表达式，分别保留主/依赖的Period、ShowSignal及内部状态。它没有把默认14当成实际或最优参数。

新报告仍记录EX4同版、iCustom加载、数组方向和当前柱变化等未知；没有编译/运行/回测。未自动生成可执行实验方案：提取定义仍声明需要明确映射的`rates_total`，且数据/时间/平台语义待核对。该结果证明模型能结合补交正文继续研究，不表示已完整解决原生依赖、候选合同或正式验证晋级。
