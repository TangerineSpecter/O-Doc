# 源码问题清单与严重度

核对日期：2026-10-25，应用 1.5.38、量化同步 schema 46。当前新源码工作流为 14，跨源码增量工作流为 15。问题清单用于静态研究报告；实验解读和外部反馈仍使用各自现有合同。完整流程见[量化研究库](./量化文集一期说明.md)。

## 当前规则

AI 在既有“评价与审查”模型调用中，同时生成五维研究质量评分、问题清单及审查范围说明，不增加模型请求预算。问题清单每项包括标题、严重度、类别、影响、建议、涉及评分维度及逐字原文依据。没有具体问题也必须明确审查范围和未检查项，空清单不表示源码正确或没有风险。

严重度为严重、高、中、低、提示。严重用于直接破坏该对象研究或使用前提的问题，例如把未来收益当作当时可用的交易信号；高用于重大依赖、实现或执行风险。类别覆盖时点泄漏、重绘、依赖、实现、执行、风控、参数、无依据主张及其他问题。模型需结合因子、指标、策略/EA 类别判断，不能因指标没有下单或止损函数而报错，也不能把本机表达式缺算子当作原平台缺陷。

`source_fact` 表示 AI 判断原文明示了事实，`hypothesis` 表示影响仍需验证。两者都不是平台编译、运行、收益或独立证据状态。对重绘、平台语义等未验证影响，应按假设表述。引文存在校验只保证引用绑定原始材料，不能证明模型的自然语言判断正确；质量基线和人工复核见[报告质量评测](./研究报告质量评测说明.md)。

## 页面与人工修改

报告在五维评分之前展示独立问题清单，严重/高影响问题另有明显提示，研究总分不能被读作通过结论。列表按严重度排序，可展开每条原文依据，原始引文保留换行。总分继续按照原始五维规则计算，不用程序悄悄改写 AI 分数；严重度单独展示，避免平均分掩盖问题。

问题清单与原始评分来自不可变 AI 原稿。用户仍可编辑、删减正文并保留修订历史，编辑正文不会改写原稿清单；原稿及修订均可查看。重新审查或修订源码生成新报告，不把新结论追写到旧报告。历史工作流 0–13 不追加新字段，页面明确标为历史报告尚未提供独立问题清单，原风险文字保持可读。

## 契约、持久化与同步

静态报告 JSON 扩展为 `source_findings_version=1`、`source_findings_note`、`source_findings`。最多 20 项，每项最多 5 处依据；字段和受影响维度有固定枚举及长度限制，维度不能重复，同一标题/类别/依据的重复问题拒绝计数。依据的 `field` 只能是 code、description、web_markdown，quote 必须逐字存在于该来源快照，不能用编造的行号或另一份来源代替。

新工作流审查阶段缺少清单、没有范围说明或引用不存在时，阶段失败，不发布残缺报告。原始源码、旧评分、候选和已有报告仍保留，可恢复到审查阶段继续。新清单通过工作流版本绑定；恢复会重建阶段输出、报告内容及 Markdown 并校验哈希。旧工作流不能追加清单，新工作流不能删除清单标记后冒充历史合同。

这些业务事实按用户已确认范围进入 WebDAV/FTP/SFTP 同步，复用现有阶段、AIRun、ResearchReport 的 JSON 字段，无新数据库迁移。版本提升到 schema 46 和应用 1.5.38，用于阻止旧客户端错误恢复新合同。同步不触发模型、实验或平台运行，本机执行权限和队列不恢复。

代码入口：`quant/research/findings.py` 维护合同、原文校验、提示和 Markdown；`quant/workflows/` 冻结新阶段合同；研究发布、worker 和同步校验版本边界；前端 `SourceFindings.tsx` 展示独立清单，`mocks/quant/findings.ts` 仅为明确标注的纯 local 演示，不声称解析或运行真实源码。

本地验证：545 项量化/同步/共享向量后端全量回归及最后 16 项问题清单/质量工具定向回归通过；97 项前端测试、类型检查、定向 lint、构建、迁移一致性和差异空白检查通过。浏览器纯 local 验证了新报告严重提示、逐字依据展开、旧报告未审查提示及桌面/手机换行。真实模型的严重度判断、原平台编译运行、正式部署和远端双设备交换尚未验收；这些本地结果不代表完整重构目标已完成。
