## 当前规则与流程

1. 默认入口为“收集并分析”；顶部“收集批次”支持多文件和多份材料的独立归档与顺序分析，详见本文“批量收集与自动分析”。单份入口：粘贴代码、作者说明或来源网址，可留空标题，由分析完成后命名。先归档不可变来源，再排队分析；无模型或队列不可用时仍保留资料并提示重新分析。网址在分析任务开始后尝试获取公开静态正文，保存独立快照。登录、验证码、动态渲染或网络失败不会被伪装成正文；只给链接且获取失败时不调用模型，同时提供代码/说明时继续分析已提供材料。主页面默认展示 AI 研究报告，手工内容放在“补充笔记”。
2. 同一研究可保存多个 Python、Pine、MQL4 实现，每个实现保存名称、语言版本、依赖、参数和当前代码版本。每次保存或恢复历史创建新版本；代码及来源快照不可覆盖，验证说明可单独补充。不同设备新建版本使用稳定字符串 ID，不共用版本序号作为身份。
3. 原平台回测可在外部执行，在文集中手工记录标的、周期、时间区间、参数、费用假设、自填指标和结论。可关联本研究的具体代码版本，也可暂时为空并显示“代码版本未知”。空指标不补零、不推算收益，也不按不同测试条件自动排名。
4. 附件可以挂在研究、实现、版本或回测上，所有目标必须属于同一研究。同时关联回测与代码版本时，两者的明确版本必须一致；编辑回测不能改为与已有附件冲突的版本，需要先移除冲突的附件关联，系统不会静默改写附件证据。回测或附件未指定版本时仍可保存。普通文本脚本 `.py/.pine/.mq4/.mqh` 可读取成代码草稿，读取限制为 1 MiB；其他文件只保留原件。Notebook、第三方回测报告不自动解析；历史行情 CSV 使用独立的“实验行情”导入入口，附件不会自动转为行情。上传和下载不会执行代码；图片通过鉴权资源接口预览，其他附件下载。
5. AI 提供结构化研究分析、代码解释和转换。分析任务冻结来源快照，生成原理、公式、参数、评价及验证计划；报告自动保存。用户选择已保存的来源版本、模型、转换目标和补充要求，系统冻结该版本后提交任务；不发送整个研究库或自动读取附件。任务可以查询、取消或显式重试，重复请求标识只对应同一个输入。每个文集最多同时保留 4 个有效任务；提交新任务前会回收该文集中所有研究的过期或缺失租约，并把旧任务标记为中断，不会重新派发。本机执行器仍持有任务时，跨文集排队超过初始 3 分钟不会误判中断；进程退出后由操作系统释放排队标记，原租约过期后即可回收。开始执行后仍使用 3 分钟续期租约和单次 120 秒模型调用时限。普通新资料分析为10阶段、最多7次模型调用／840秒；跨源码局部研究为11阶段、最多8次／960秒；没有修订目标时跳过额外模型调用，失败可继续已保存阶段，已结束任务可指定阶段重跑；具体规则见本文“分阶段研究与恢复”。重复提交旧请求标识只返回原任务及恢复后的状态；重试中断任务必须由用户明确提交新请求标识。
6. 转换完成后先展示候选代码、差异、假设、依赖和限制，用户采用后新增实现，初始验证状态均为“待验证”。重复采用不重复创建。解释结果由用户主动加入说明草稿并保存，不能直接覆盖原文。
7. 编译、运行、结果核对由用户分别记录，系统不自动确认语义等价。失败、取消、超时或输出截断不产生正式代码版本。研究和文集采用逻辑删除，历史附件引用继续保护原文件；移除附件引用不删除文件。

## 数据与同步边界

用户已确认全部研究内容进入现有 WebDAV/FTP/SFTP 同步：`quant.Entry`、`Implementation`、`CodeVersion`、`Backtest`、`Attachment`、`AIRun`、`WorkflowStep`、`WorkflowOutcome`、`SourceMaterial`、`SourceRevision`、`ResearchReport`、`ReportRevision`、`FactorCandidate`、`FactorRevision`、`FactorQualification`、`FactorEvidenceLink`、`FactorRelation`、`FactorComparison`、`FactorMerge`、`FactorMergeWithdrawal`、`MarketDataset`、`ExperimentRequest`、`ExperimentCheckpoint` 和 `ExperimentResult` 是业务事实；源代码及结构化结果进入数据库快照，附件沿用 `Asset` 媒体清单与 Blob。手工验证记录和采用来源也随所属业务记录同步。

`quant.Job` 的执行租约、取消状态、阶段预览、临时上下文只留本机，不同步。排队存活标记是系统临时目录中的进程文件锁，不新增业务持久字段，也不进入同步；任务完成、队列 Future 取消或提交失败时释放标记。恢复会清除本机 Job 并将未完成 AIRun 标记为中断；需要用户显式重试，不会从快照重新授权模型调用。模型凭据沿用现有模型配置，不复制进量化请求或日志。

快照携带 `quant_schema_version=46`、记录清单和业务哈希；恢复前校验文集私密性、所属用户、实现与版本、回测、附件和 AI 来源引用。量化完整性错误不能由放宽 Agent 世界校验跳过。没有量化域的旧快照可以读取；同步仍遵循现有整库覆盖或三方合并语义。应用版本升级用于让旧客户端拒绝新快照，参与同步的设备应一同升级。

## 代码入口与 API

- 后端 `quant/`：models/serializers 表达数据与契约，services 处理版本、附件和候选采用，worker 管理有界模型请求，locking 协调写入与同步恢复，sync 管理快照校验及本机执行撤销。
- 页面 `/quant/:collId`、`/quant/:collId/entries/:entryId`；`QuantPage` 编排领域组件、Hook、API、类型和纯逻辑。编辑器使用 CodeMirror 6，提供行号、缩进、查找、撤销和代码保存，不承担编译检查。Python、MQL4、Pine Script 和通达信均提供语法高亮；Pine 使用本地词法解析，区分注释、字符串、关键字、类型、函数、内置变量和数值，编辑、版本预览及 AI 候选共用同一配置，不代表编译或语义校验通过。
- `/api/quant/<collId>/entries/` 下提供条目 CRUD、实现及版本、验证、回测、附件及脚本文本读取、AI 任务及取消/采用；全局 `/api/quant/models/` 返回可用对话模型和默认模型。遵循通用 `code/msg/data` 与驼峰接口约定。
- 请求先完成认证和文集归属预检，再取得文集锁及事务；锁内重新读取文集归属和研究有效性。未登录或无权访问的请求不会创建任意文集 ID 的锁文件，等待锁期间的删除或归属变化也不能绕过校验。
- 资源库通过显式 `quant_references` 识别研究引用，展示量化来源并阻止误删，包括已软删条目的历史证据。量化附件不能经旧 `/media/` 静态路径绕过鉴权。

## 预算内连续研究（2026-10-25）

可从资料分析或实验解读中的 AI 方案启动连续研究：选择按点击顺序排列的 1–5 条历史行情，配置最多 1–5 轮、1–160 次候选尝试、1–300 秒计算和 30–1200 秒总耗时。启动时解析默认模型并固定其 ID，每轮最多创建一次受控解读。数据每条记录使用一次，未预选更多行情时停止，不自行循环旧记录。不同记录仍可能区间重叠，也可能不满足模型文字中的市场/周期要求；本阶段不会自动证明独立性，成果仍标为研究证据。

每轮复盘冻结剩余总轮数、候选/计算上限预留后的额度、剩余总耗时，以及后续同文集预选行情的标的、周期、长度和区间元信息，不传后续价格值。超长元信息整项省略，缺失显式保留；要求下一方案匹配可用数据与预算，无轮数/预算时proposal=null。模型文字判断不能替代代码预算检查、数据条件审查或独立性审计。该输入使用现有requirements字段同步，入口为 `experiments/campaigns/review_context.py`。两轮真实运行、独立数值核对和恢复记录见[本地验收](./真实连续研究与预算停止验收记录.md)。

本机协调器顺序执行“冻结并启动本轮实验 → 等待计算完成 → 创建并绑定本轮解读 → 等待完整报告与方案 → 校验预算与下一条行情 → 下一轮”。连续研究的实验禁用普通完成回调中的自动解读，避免重复模型调用。只有完整完成的计算与解读能进入下一轮；部分完成、失败、中断、被停止或无有效方案都会结束。达到轮数上限或模型明确不提出方案为正常结束；候选/计算/总耗时预算不足、预选行情用完均保留具体停止原因。每轮按实际方案的 max_candidates 与 seconds 上限预留总预算，提前结束不返还，确保最坏上限不超过授权。总耗时包括排队、计算与模型等待，每次模型仍受已有 120 秒调用限制。

`ResearchCampaign` 保存不可变起点、行情顺序、模型与总预算；`ResearchRound` 绑定逐轮 ExperimentRequest，`ResearchEvaluation` 绑定该轮唯一 AIRun，`ResearchOutcome` 保存最终原因与轮数。原始 proposal 与每轮实际实验、解读、衍生因子继续独立保留，后续轮只采用前轮完成解读生成的方案，不用任意最新报告替换。重复启动标识幂等，不重新授予权限。停止连续研究会停止当前实验或取消当前解读，完成的尝试与报告保留；已有终态不被失败回调覆盖。

`ResearchCampaignJob` 为本机授权，最多 2 个协调线程、每文集最多 2 项活跃研究，子实验与模型仍复用各自有界队列。协调器每次推进在文集锁内复核所有者、私密权限、租约与期限，跨进程队列标识避免重复提交；读取只展示或回收失效状态，不创建下一轮。进程丢失后不自动重跑，原记录可查看；同步撤销协调任务和子任务权限，晚到回调不得生成新实验。

迁移 `0014` 与同步 schema 13 纳入 Campaign/Round/Evaluation/Outcome 四类业务事实。恢复前验证预算、顺序、确定性身份、请求及模型归属、逐轮输入等于对应提案、前轮完成才能衍生后轮、终态轮数/原因与本地不可变事实；ResearchCampaignJob 排除同步，恢复清理执行权限。沿用用户确认的 WebDAV/FTP/SFTP 范围，向量缓存/执行队列继续本机管理，模型配置沿用现有设置规则。

API 为文集下 `campaigns/`、`campaigns/<id>/`、`campaigns/<id>/cancel/`。后端入口 `quant/experiments/campaigns/`，前端 StartCampaign、CampaignPanel、useQuantCampaigns、quantCampaign 类型；样例路由 `mocks/quant/campaigns.ts` 仅人工模拟轮次，不计算行情也不调用模型。界面展示预留预算、模型调用次数、逐轮状态、停止原因，并可跳转到各轮实验详情。

## 来源分析直接提出首轮实验（2026-10-25）

## 跨来源研究与弱父代组合探索（2026-10-25）

当前新实验解读使用输入版本 v3，输出仍采用已兼容的规划 v2 契约。在创建任务时扫描同一私密文集最近最多 2,000 条其他来源候选，仅允许有效研究、明确声明默认数值/布尔参数或 v3 字符串枚举、可直接映射 OHLCV 的输入、受控表达式和当前引擎可组合类型。风险/执行/显示模块、未知映射/默认值、不同单位或没有表达式的候选不自动进入组合。本轮父代及衍生项完整保留，跨来源按完整结构契约去重；不声称跨平台语义等价。

候选按与基础父代共享的原始标签、机制类别及已有且投影修订仍匹配的语义关系评分排序。评分仅用于检索排序：共享标签数最多计 4，非 other 的相同类别计 2，语义余弦乘 4；同分按稳定 ID。选择最多 4 项，前三项取相关排序，最后一项在可用时保留不同机制类别的探索项，否则取下一相关项。不是每次新调 embedding，也不是完整全库相似搜索；语义关系来自已保存的索引，未提供关系时仍可按标签/类别和组合契约发现候选。

`AIRun.planning_context` 固定方法、扫描/合格数量、上下文省略数、原始选项、跨来源选项及出处/检索理由。跨来源候选序列化额外材料最多 32,000 字符；总投影仍不超过 160,000，必要时只移除新增选项并记录数量，不截断本次真实尝试或失败证据。排队后新增资料、标签修订或重复提交同请求都不改写当时材料。旧 v1/v2 输入与幂等指纹保持原样；本次上下文是同步的研究事实，任务权限仍只在本机。

AI 可以从所提供的原始/衍生/跨来源选项选择下一轮父代，引用 `library:<id>` 的真实出处，并说明可否证的组合假设；检索结果不是已经采用的方案，也不是收益、统计相关或互补性证据。新增候选基线为来源默认值，原始父代保留本轮实际参数；模型仍只能修改实际参与表达式的 signal 参数。多父代新方案至少 2 代，必须为组合留出候选预算。页面可展开本次报告使用的固定跨来源清单并打开候选及出处。

搜索引擎新请求使用 `quant-local-search-2`：当代数和预算允许时，第一代优先尝试已成功计算的所选原始父代组合，不因单独表现被训练 Pareto 淘汰就排除其组合潜力；之后继续训练筛选/验证选择。参数变体仍占用预算，预算不足会留下停止原因，并不保证遍历所有组合。引擎 v1 仍可按原规则执行旧冻结请求，历史结果的版本和检查点不改写。组合仍限定同类型的布尔 AND/OR 或同单位数值平均；这不是任意公式进化或新算子发现。

## 可执行参数约束（2026-10-25）

新 AI 分析可为参数补充 `domain.version=1`，有条件依赖时采用下述 `domain.version=2`，自动报告和候选详情展示“本机实验将检查”及逐字原文。支持数值闭区间、数值/布尔枚举、带明确起点的正步长，以及同一候选内另一参数的 `< / ≤ / > / ≥ / = / ≠` 关系；布尔只支持布尔枚举和相等/不等关系。只接受已识别的整数、数值、布尔类型。关系引用必须完整存在，不能丢弃依赖后假装可独立运行；大小写保留。引文须存在于固定来源，存在引文不等于证明模型解释正确。

`domain` 是从来源提取的声明约束，不是 AI 推荐区间，也不从默认值、SET 优化范围或历史表现倒推。未声明的上下限/步长保持 null；没有明确规则时省略 domain，页面说明文字约束尚不能自动检查。字符串枚举见下述 v3 合同，有界条件算术见 v4；任意函数或超出已启用条件合同的约束继续作为文字保留；本功能不等于完成全平台参数 schema。源码默认值与声明冲突时仍允许报告指出问题，但不能生成可执行首轮方案或偷偷更改默认值。

## 逐折重新搜索的滚动验证（2026-10-25）

准备实验可启用 `walk_forward` v1，使用 `quant-local-search-4`；也可采用 AI 首轮/反馈方案中给出的同一配置，实验解读后的方案完整继承。手动表单默认关闭，旧方案不自动启用。配置包含扩展/固定长度滚动训练、2–5 折、首折训练收益区间数（至少 20）、每折验证/测试收益区间数（至少 5），以及首个交易信号之前额外预热根数（0–2000）。最后一折测试截止于冻结行情末尾，前面的测试区间依次向前排列；相邻测试仅共享一个边界开盘价，不重复计收益区间。

每折从原始冻结父代重新运行完整参数/组合或公式演化搜索，训练指标决定 Pareto 与探索父代、验证指标完成本折选择，之后才计算本折测试。传入每折引擎的行情截断至该折测试末尾，候选计算进一步截断至验证末尾；滚动模式还截掉预热之前的旧历史。扩展模式保留首折训练起点，滚动模式保持训练长度。后续折可以使用已经过去的早期测试数据；所有测试只声明排除在**本折**选择之外，不能据此证明父代来源、历史研究或跨批次独立。

长度计数与 `simulate` 一致，表示开盘到下一开盘的收益区间。训练/验证与验证/测试之间分别跳过 `gap` 根边界后的 K 线，下一段起点为前段末尾加 `gap+1`。首个交易信号使用前一根已收盘 K 线，额外预热发生在该信号之前；预热不足仍传播缺失，不能抹掉失败尝试。最小所需行数为 `2 + warmup_bars + train_bars + validation_bars + folds*test_bars + 2*(gap+1)`，同时遵守至少 60 根和至多 20000 根的行情上限。数据不足直接拒绝，不静默缩短窗口。

整批仍最多 32 次尝试、4 代、60 秒。尝试额度按折平分，余数按先后各加一次；每折必须容纳全部基线、参数组及启用演化时至少一次额外尝试，否则在入队前拒绝。每折种子为 `(seed+折序号-1) mod 2^32`。所有折共用总计算截止时间，未用完的本折额度不转移，也不按测试表现重新分配。每次尝试都有全局连续 ID 与折号，父代只能指向本折此前尝试或原始来源。

结果保存每折窗口、计算起点、种子、预算、选择与测试结果；顶层选择和曲线对应最后一折，不比较不同折的 Pareto，也不按测试收益挑折。最多三个回库候选仅取最后一折训练/验证前沿。汇总展示完成测试折数、正收益折数、逐折收益算术均值、最差收益、最大回撤与基线均值。每折独立空仓开始、区间末平仓，因此这些描述不是连续组合净值、显著性或最优参数证明；无可用信号的折保留拒绝记录且测试为未评价。

取消/超时保留此前已完成折的结果和本折已写尝试，末折未完成的测试不发布。若最终发布前才收到取消，撤下最后一折测试并重算已完成折汇总；此前折仍保留。进程异常与失去授权按原任务机制保留已持久化的尝试检查点，不自动续算。AI 解读获得全部折的摘要、选择、失败和参数证据，不接收完整行情/曲线；单参数敏感度仅比较最后已启动折，禁止跨时间段拼接成稳定区域。

## 条件参数依赖（2026-10-25）

参数域 v2 在 v1 基础上增加 `conditions`：每条规则由 `when`（触发条件）与 `require`（必须满足的条件）组成。例如 `enabled = true` 时要求 `fast < slow`。支持参数与数值/布尔常量或另一参数比较，及嵌套“且、或、非”；布尔只能与布尔作相等/不等比较，数值不能与布尔混比。参数域保留 1–8 条条件规则，每个表达式最多 32 节点、6 层，且/或分别包含 2–8 个子条件，所有规则同时适用。不执行原文、函数、算术表达式或任意代码。

触发条件为假只跳过本条要求，不取消无条件的范围、步长、枚举或其他规则。所有分支中的依赖必须存在于同一参数清单；即使分支不触发，也检查依赖实际值的类型和完整性，不能用缺失值或 `0/1` 冒充布尔开关。相互引用是对同一个固定参数集合的断言，不进行求解、赋值或自动改值，因此不会递归计算参数。无可用值时须补充配置，不能猜测。

AI 仅能从原文明示条件提取，继续保留逐字来源证据，不把推荐范围、历史收益或 SET 优化配置推导为硬约束。报告指出冲突后仍可保存，但带违规默认值或参数组的首轮/后续方案不发布。手动实验基线入队前拒绝，违规变体保留为 rejected 尝试并展示具体触发条件。条件依赖参数可以在基线准备时填写；自动搜索仍仅修改实际参与计算的信号参数，不因它出现在约束中就扩充优化空间。

报告、候选和实验准备复用同一自然语言解释；组合及多层衍生重命名每个分支中的所有参数引用，保留条件原文，导出 manifest 同步映射名称。导出默认值经过检查，但目标平台改值后的条件执行尚未生成进所有平台代码，不能把 manifest 视为原平台运行验证。

## 时序排序与条件门控（2026-10-25）

受控表达式和演化策略 v2 新增 `ts_rank` 与 `gate`。新手动研究默认列出十个算子，AI 首轮方案可提出它们，实验解读与下一轮方案保留冻结配置。历史 evolution v1 仍只接受原八种算子；编辑旧方案时只有选择新算子才升级为 v2，不改写已保存的旧尝试。

`ts_rank(x,N)` 是单序列完整历史窗口的中点秩：`(小于当前值的数量 + 0.5 × 等于当前值的数量) / N`，包含当前已收盘柱；同值全相等时为 0.5，N=1 时也是 0.5。不足窗口或窗口含缺失则输出缺失；窗口为 1–2000 整数，仅接受数值序列，输出无量纲。不是横截面排名。排序值落在 0–1 内，原来的零阈值通常不再起过滤作用；系统保留明确的实验阈值，不自动猜测交易规则。

`gate(signal,condition)` 要求第二父代为布尔序列；仅条件为 true 时保留第一父代，false 或缺失时输出缺失，保留第一父代的数值/布尔类型和单位。不可用乘零代替屏蔽：在负信号阈值下零可能产生持仓，而缺失在本机模拟器按空仓处理。`missing_signals` 也包含主动屏蔽，不应全部解释为行情质量问题。

两种变换参与实际计算、类型/复杂度拒绝、分代预算、尝试检查点与训练/验证选择；留出不参与候选生成。衍生候选保留双方参数、条件依赖和父代记录，按分支重命名参数，合并相同 OHLCV 输入，可再次成为实验父代。local 样例同步覆盖门控组合回库和再次排序，全部指标明确为人工演示。

四平台导出当前使用 `quant-indicator-export-3`（排序语义沿用 v2）：Python 直接计算同一中点秩；Pine/MQL4 用逐窗口比较；通达信用显式历史 REF 比较并分块求和，常量窗口展开 N 项，可调窗口展开至 2000 项，代码总量超过 1 MB 时拒绝导出。通达信不使用末柱常量代替各柱当前值。导出 manifest 保存算子语义与边界，仍标为原平台编译和等价待验证；展开公式的原平台长度和性能限制尚需验收。参考 [Pine 历史循环说明](https://www.tradingview.com/pine-script-docs/language/loops/)，生成契约和本机数值对照不能替代原平台运行。

## 参数条件算术（2026-10-25）

参数域 v4 继承 v3 的声明范围、枚举、比较和布尔条件，数值操作数新增有界 `add/sub/mul/div/neg` 树。例如来源明确声明“启用过滤时，两个短周期加慢周期不能超过 80”，可表示为 `when: enabled = true`、`require: (lookback × 2) + slow ≤ 80`。只有逐字来源依据且能明确表达的规则才进入机器合同；AI 推荐范围不变成硬约束，单位或原文含义不明时保留文字，不推断参数间量纲一致。

比较的左右两侧可递归包含参数引用、常量、二元节点 `{operator:add|sub|mul|div,left:操作数,right:操作数}` 或一元节点 `{operator:neg,argument:操作数}`，整个比较至少引用一个已声明参数。字符串与布尔仍只支持同类型相等/不等，不参与算术；没有任意函数、幂运算或源码执行。每个 when/require 最多 64 个节点、8 层，包含比较、逻辑和所有操作数；每个域仍最多 8 条规则。旧 v1–v3 按原合同检查，不将其升级为新算术语义。

v4 数值操作数按 JSON 数字的十进制文本转为精确有理数，前端 BigInt、后端 Fraction 使用一致规则；`0.1 + 0.2 = 0.3` 可正确比较，不添加可能放过违约值的浮点容差。字面数值和全部被引用的实际数值必须有限且绝对值不超过 9007199254740991，避免 JavaScript 读入不安全整数后静默舍入；此界限仅用于 v4 条件的操作数和引用，不扩展到无关参数或旧版本。每一步中间结果分子/分母各不超过 4096 位、绝对值不超过 1.7976931348623157e308；除零或越界拒绝该次计算。
