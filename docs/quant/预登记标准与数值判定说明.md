# 预登记标准与数值判定

核对日期：2026-10-25。应用1.5.45、量化同步schema48。当前固定验证可在绑定新行情前冻结数值标准，由计算器逐项判定，AI解释判定与研究评分。这是有限范围的证据增量，完整重构目标仍未完成。

## 当前流程

在已完成实验中选择一份实际评价的尝试，点击“登记当前尝试的验证”。原有公式、实际参数、费用、策略规则、数据截止点和固定区间数量仍先冻结。可选启用数值标准，至少填一项，留空维度不增加要求；启用而全空会被拒绝。登记后不能修改，改变假设应新增计划并保留旧记录。

| 可选标准 | 计算口径 | 输入范围 |
| --- | --- | --- |
| 最低成本后收益 | 本次固定方案total_return | 小数-1至1000 |
| 最大回撤上限 | 本次固定方案max_drawdown | 小数0至1 |
| 相对同成本基线最低超额收益 | 固定方案收益减同区间基线收益；起止及bars须一致 | 小数-1000至1000 |
| 最低信号覆盖率 | 1－missing_signals/bars | 小数0至1 |
| 最少入场次数 | 本次固定方案entries | 整数0至100000 |

界面收益和覆盖率按百分数填写，超额按百分点填写，服务端和快照使用小数；次数不换算。不自动推荐阈值，不从旧结果反推标准。全部填写项使用AND；任一未满足则整体未满足，其余未知仍逐项保留。没有失败项但存在未知时为证据不足。取消、失败和缺失指标保留null，不能当作0。百分比类比较的固定绝对容差为1e-12（小数），次数精确比较；近似显示值相同时可展开精确数值，未满足但显示相同时自动展开。

导入后续行情、核对区间和预约执行沿用[固定验证规则](./固定方案新数据验证说明.md)。登记和下一次下载/导入的先后只证明本系统内的顺序，不证明外部此前未使用行情。

## 数值与资格分开

`criteria_assessment.status`由代码生成：met、not_met、insufficient，分别表示满足本次登记标准、未满足、判定证据不足。很弱的标准可能在亏损结果上满足，不能额外推断盈利。

`eligibility`另记发布时资格。仅当计算完整、所有已登记数值满足、fresh模式、登记后导入、预约和发布时审计均完整且没有已知冲突时，为`fresh_scope_criteria_met`。数值满足但普通复核、重用或审计不足时，为`criteria_met_reuse_or_audit_unknown`；失败和不足分别保留对应状态。

直接属于当前公式及实际尝试的因子证据，可在上述有限资格成立时增加`registered_criteria_met`，界面标为“发布时曾满足本次登记标准及已知新数据条件”。祖先和相似公式不继承。当前使用审计后来变化时，冻结判定不改写，详情另行提示现有资格变化。外部先前使用、原生平台等价、跨市场稳健性仍未知，`independent_validation=false`不改变。

这不是完整金融有效性晋级：嵌套验证、多重检验控制、原生依赖运行与等价核对、全局语义依赖增量，以及真实外部反馈、多设备远端同步和部署等仍有工作。

## AI、历史与同步

完整固定计算结束后自动创建AI解读；有登记标准的新成果要求`criteria_review`保留代码给出的status和eligibility，并引用fixed_validation。缺少或改写时报告拒绝发布，原始计算保留。AI仍负责解释各项表现、风险、参数边界和研究评分，不能自行晋级。报告正文可人工编辑，原始判定和报告原稿继续保存。

成功、失败与取消的登记判定进入[后续历史研究](./固定验证历史与后续AI研究说明.md)，仍属于已看历史。后续AI可据此提出新假设，不能拿历史达标作为新假设的独立验证。

无标准的历史plan/result保持v1；新登记标准使用plan/result v2，内含criteria和assessment各自v1。复用既有JSON持久化，无数据库迁移。按用户已确认范围随WebDAV/FTP/SFTP同步；恢复重建冻结方案、实际计算和判定，篡改阈值、容差、实测值、状态或资格会拒绝。旧记录不能事后补标准。所有参与设备须支持schema48，队列、租约、密钥和执行授权不恢复。
