# 因子结构检查与验证证据

核对日期：2026-10-25。本规则从应用 1.5.32、量化 schema 40、迁移 `quant.0022` 引入，结构策略 v1 继续使用；当前自动修订扩展见[AI定义修订](./AI定义修订与问题闭环说明.md)。本文描述当前实现；完整研究目标见[重构规格](../requirements/007-AI量化研究系统重构.md)，总入口见[量化文集](./量化文集一期说明.md)。

## 当前流程

AI 提取、人工公式修订和实验衍生的新候选，都会保存独立的确定性结构检查。候选详情先展示检查结果，再展示属于该公式版本的直接实验、固定样本对照与用户反馈。因子库支持按“结构可复用／待补齐／尚未检查”筛选，关键词与混合检索使用同一条件。结构状态和已有观察分开展示，不按祖先表现、标签或人工工作版选择授予验证结论。

结构上下文从工作流 v6/v7 引入，当前 v14/v15 继续使用：继承 v4/v5 的冻结词表，在“评价与审查”和“设计实验”的既有调用中加入有界结构检查摘要，无额外模型调用。AI 能看到具体缺失引用、类型问题、缺少默认值及需要明确映射的输入；应区分原始代码问题与提取定义的问题。摘要最多 22,000 字符，省略数明确记录；旧 v1–v7 各按原输入合同继续，不向历史报告追加新依据。

## 结构检查的范围

策略 v1 只检查受控表达式及其已声明合同：

- 输入、参数与树节点引用完整，表达式符合现有深度、节点和算子限制。
- 数值、布尔和字符串枚举比较类型一致，窗口参数明确为整数，窗口符合本机上限，输出与声明类型相符。
- 默认配置单独检查类型、声明参数域和条件约束；缺少值会阻止自动实验就绪，但不会把完整的参数化公式判成不可复用。
- 自动输入映射只识别 OHLCV 名称；其他输入必须提供实际映射，不使用收盘价猜测替代。
- 保存逐节点依赖、输入引用和原始可得时点／缺失规则声明。原平台库依赖仍标为声明、待核实。

这不是原平台依赖安装或修复，也不证明单位、可得时点、缺失处理与真实数据一致。原平台语义等价、经济有效性、原生代码编译和执行仍须独立验证。没有受控表达式的原平台片段继续作为候选保留，不运行上传源码或生成虚拟收益来补齐检查。缺失正文可使用[依赖源码补交与重新分析](./依赖源码补交与重新分析说明.md)；新定义仍须满足输入、类型与数据映射条件，不自动继承父版本验证。

## 直接证据及参数

`FactorEvidenceLink` 固定目标对象与公式指纹，按确定性规则从原业务事实重建：

| 记录 | 当前版本可归入的内容 | 结论边界 |
| --- | --- | --- |
| 本机实验 | 明确种子本身及其参数变体；衍生候选只归入创建自己的那次尝试 | 展示实际参数、输入绑定、市场／周期、费用、滑点、隔离、训练／验证指标、失败及拒绝原因。组合和公式变异的收益不反授给祖先 |
| 留出与逐折观察 | 本版本的实际尝试被选中且存在对应留出结果；至少两个对应逐折观察才显示滚动观察 | 既往数据使用情况未核实，始终不标“独立验证”；展示已知同文集区间重叠，不能由未发现重叠推出全局独立 |
| 固定样本对照 | 左右侧明确匹配当前版本 | 保留实际参数、映射、共同有效行、差异行、容差及通过／反例／未知，只限本样本口径，不推导普遍或平台等价 |
| 用户观察 | 反馈显式关联当前候选 ID | 回测、模拟、实盘均显示“用户提供”；结构化算术核对与平台真实性分开，用户声明不授予已验证实盘层级 |

观察级别可并存，详情保留负面结果。失败但有检查点、无正式输出的实验只显示已保存尝试数量并提供完整实验入口，不推定计算成功。原研究质量评分不因多了一次实验、人工标签或合并操作自动提高。

新实验结束、实验衍生发布、对照结束和反馈归档时自动积累直接记录。旧候选可点击“归集已有证据与结构检查”：按实验／对照／反馈分别分页，默认每页扫描 20、最高 50，前端显示进度并可停止。操作只重建元数据，不调用模型、不计算行情、不启动队列；中断后可重跑且幂等。历史在归集期间继续增加时可再次归集，不声称一次分页扫描证明全历史穷尽。

## 数据、同步与恢复

`FactorQualification` 保存不可变策略版本、检查与内容哈希；`FactorEvidenceLink` 保存不可变的直接目标和完整范围；候选 `qualification_version=1` 要求对应检查存在。上述业务事实和新工作流输入继续按用户已确认范围进入 WebDAV/FTP/SFTP。向量、执行队列、租约、凭据与执行授权仍留本机。

恢复重新构建结构检查及每条直接证据，校验所属、目标、参数、哈希、稳定 ID 与原始事实。伪造后重算哈希、跨版本继承、冒充独立验证、遗漏新候选规定检查均拒绝。旧完整备份的候选显式补 `qualification_version=0`，不借用本机新检查或证据；显式归集不会修改旧候选不可变定义。恢复不授予模型或实验执行权限。

## 代码与验证入口

后端为 `quant/verification/` 的纯结构策略、证据投影、发布服务、提示输入、同步与 API；模型在 `quant/models.py`。API 为 `GET/POST /api/quant/:collection/factors/:candidate/verification/`，仅所有者可访问。GET 默认返回 20 条证据、最高 40；历史归集使用 POST 的种类与偏移。

前端组件在 `components/Quant/verification/`，请求和取消在 `hooks/useQuantVerification.ts`，严格解码在 `utils/quantVerification.ts`，local 样例在 `mocks/quant/qualification.ts` 与 `verification.ts`。local 指标是人工展示数据，界面单独标明，不能作为真实行情、模型或平台验收证据。

专项测试覆盖自动检查、实际计算与逐折的直接范围、参数、负面尝试、人工新公式不继承证据、旧记录幂等归集、旧快照恢复、伪造拒绝及新旧 AI 输入合同。完整原生依赖求解与修复、全局语义增量、独立验证晋级、完整策略／EA 执行、真实模型与市场、原平台及远端多设备同步和部署仍未完成。

本轮验证：478 项量化／共享同步与向量传输回归通过；补充参数名／输入映射断言后 9 项专项通过；85 项前端、类型检查、定向 lint、生产构建和迁移一致性通过。隔离后端生成的 6 份结构检查和 6 条实验／对照／反馈证据可由真实前端严格解码。纯 local 浏览器核对直接参数 20／15、拒绝参数 0、旧证据归集与刷新、空结果筛选、加载与接口失败恢复、20／25 固定对照的精确跳转，以及 390px／1440px 阅读。人工样例明确标注不作为实证；真实后端浏览器连接、正式迁移、真实模型／平台／市场与远端多设备同步尚未验收。截图位于 `/private/tmp/odoc-factor-verification.png`、`/private/tmp/odoc-factor-verification-390.png` 和 `/private/tmp/odoc-factor-verification-1440.png`。
