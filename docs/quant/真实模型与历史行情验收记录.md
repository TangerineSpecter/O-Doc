## 本地模型配置与首次真实调用

开发启动脚本 `dev.sh` 默认使用本机 PostgreSQL，模型配置存在其中；项目根目录的 SQLite 不是这次已配置模型的数据库。已通过只读查询确认 `deepseek-flash` 存在且有提供商凭据。凭据仅用于进程内配置，不写入报告或本记录；业务验收使用隔离内存数据库和临时媒体目录，后台调度关闭。

使用[固定质量语料](./研究报告质量评测说明.md)中的原创 Pine `pine_bands`，未向模型提供参考答案。首轮真实运行 workflow 14：来源识别、参数提取、研究分析通过，因子提取失败；共 4 次提供商调用，没有发布报告。失败保留，不能只导出后续成功结果。

定位到两个具体问题：提取阶段没有携带参数 domain 的完整说明，模型为固定常量创建了全空 domain；显示候选把中间量 `b` 展开为 `sma(close,N)`，但输入表只列 `b`，遗漏 `close`。已补齐同一参数合同、禁止空约束、展开后核对叶子依赖的提示，并要求复制已核对的参数记录、优先少量互补模块。校验继续拒绝这两类输出，不删除错误字段来强行发布。没有改变业务字段、报告合同、工作流版本或同步格式，也不改写旧报告。2 项最小化回归和受影响工作流、参数测试共 18 项通过。

第二轮真实运行的识别、参数、研究、提取、修订和库比对通过，审查阶段因引用错绑失败；共 6 次调用，没有发布报告。模型把 `source_structure` 和 `portable_qualification` 的工具观察误标成 `source.description`，而该来源的 description 实际为空。已明确限定只能引用 source 对应原文字段，工具覆盖和验证状态写入审查范围说明，继续拒绝错绑引文；新增最小回归验证这个边界。

第三轮真实运行完成全部阶段并发布[原始报告](./验收记录/2026-10-25-deepseek-flash-report.md)：7 次真实调用，250.87 秒；用量记录合计输入 93,805、输出 45,665、总计 139,470 tokens。报告有 6 个参数、6 个候选和 8 项源码问题，五维研究质量评分为 3/3/3/3/2、总分 56；这不是收益分或投资结论。6 个预期参数全部匹配，默认值与类别全部匹配，没有重复、额外参数或漏项；6 个候选的原文引用和报告章节检查通过。当前复杂策略缺少经确认的订单语义及可执行定义，首轮实验方案为 null 并说明原因，没有编造等价实验。

## 官方历史行情与独立数值核对

数据为 Binance 现货 BTCUSDT 的 2024 年 1 月小时 K 线，共 744 行，范围 `2024-01-01T00:00:00Z` 至 `2024-01-31T23:00:00Z`。[官方数据说明](https://github.com/binance/binance-public-data)给出归档和校验方式，[官方 K 线格式](https://developers.binance.com/en/docs/catalog/core-trading-spot-trading/api/rest-api/market)用于核对时间、OHLC 与基础成交量列。归档：[固定下载地址](https://data.binance.vision/data/spot/monthly/klines/BTCUSDT/1h/BTCUSDT-1h-2024-01.zip)。

- 归档 SHA-256：`cf873a185bd5b24b8e00034e49583fcb49928e0c3a45c6fc27a632a683655417`，与发布 `.CHECKSUM` 一致。
- 规范化 CSV SHA-256：`14b48319e5e446d15d8add8f3cc5d9728c0d96469591265f8e9efbe61eb05b68`。
- 固定归档先核对哈希，再解压；逐行核对 12 列、连续小时开盘时间、收盘时间与无损列转换。UTC 毫秒只做时间格式转换，价格及成交量文本保留。

运行范围为源码夹具定义的 `close / lag(close,N) - 1` 受控表达式：收盘信号决定下一根开盘做多或空仓，各分段从空仓开始、最后开盘平仓；每侧手续费 5 bps、滑点 5 bps。候选 N=5，另试 3、8、0；3 折 expanding，各折重新从相同种子搜索，总计 12 次尝试，9 次评价、3 次参数无效拒绝，全部形成检查点。训练 200 段起步、验证和留出各 80 段、预热 20 根、间隔 2。

独立参考账本仅用 Python Decimal（45 位精度）按原始文本价格逐笔计算，不调用产品表达式、分区或回测函数作为答案。已核对 18 组开发区间汇总指标、3 组留出完整净值与逐段收益、3 组同成本买入持有基线；数值绝对误差容差 `2e-11`。拒绝项及真实计算结果进入冻结的实验解读证据；快照导出、校验和恢复后，数据原文及结果哈希不变，执行授权没有恢复。

## 重复运行

下载是显式命令，普通测试不会联网。每次使用尚不存在的目录，验收输出采用独占创建以保留旧记录：

```bash
uv run --python 3.11 python -m quant.acceptance.market_bundle --output /tmp/quant-market-new
QUANT_MARKET_ACCEPTANCE_DIR=/tmp/quant-market-new uv run --python 3.11 python manage.py test quant.acceptance.market_case --settings=quant.test_settings --noinput
```

没有数据、固定哈希不一致或数值不一致均失败，不跳过后称通过。结果写入所选目录的 `acceptance-result.json`。下载器有 2 MB 上限和 20 秒网络超时，不读取模型配置、正式业务库或交易账户。入口为 `quant/acceptance/market_bundle.py`、`market_case.py` 和独立参考 `market_reference.py`。

验收输入、下载归档和命令输出是显式本机测试文件，不新增业务持久字段，不自动进入 WebDAV/FTP/SFTP。源码、业务报告和实验数据沿用已获确认的同步范围；本次只验证隔离快照恢复，未验证两台真实设备交换。
