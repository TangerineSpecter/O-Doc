# 跨请求搜索记账

核对日期：2026-10-26。应用1.5.59、量化schema61。此项补充“记录试验次数和搜索家族”的跨请求范围；原有单请求逐折CSCV数值计算保持。完整目标、正式跨请求统计控制和真实环境验收仍未完成，见[重构规格](../requirements/007-AI量化研究系统重构.md)。

## 用户看到的记录

在“因子候选库 → 参数与组合实验”打开新完成或部分完成的实验，“搜索次数与选择反转”先显示“同市场累计尝试”，再显示本次固定候选的数值诊断。

累计范围是同一所有者的全部私密量化文集，按精确标的和周期归集，不区分来源标题或是否为同一假设；软删研究仍保留。相同配方再次尝试仍逐次计数，不跨请求去重。不同别名、其他周期、外部研究、未同步设备与没有保存的尝试未知。该范围是保守的同市场记账，不表示已识别完整语义研究家族。

每个请求保留请求/行情身份和哈希、文集、创建时间、预约候选上限、已发布成果身份/状态，以及每个已保存尝试的检查点身份、哈希、顺序和状态。记录不包含源码、完整方案、尝试正文、价格或收益序列。元数据由数据库字段投影读取，不加载其他请求的大型JSON正文。

界面区分：

- 实际已保存尝试的累计次数，以及evaluated/rejected/cancelled/budget_stopped分类；失败的请求仍可能含已完成的有效尝试，这些尝试按自身状态计数。
- 尚无成果的请求数量；没有检查点不能证明从未计算，执行队列状态不作为可同步事实。
- 预约候选上限合计；它不是实际次数、剩余额度，也不恢复执行权限。
- 扫描覆盖范围；最多选择200个请求，优先保留本次，再取最近的其他请求，按完整记录保留至16万字符上限。超限保留已有记录并标示次数仅为下限，不用0代替未知。

展开最多12个请求的摘要，并给出未展开数量；完整入账清单随不可变诊断保存。数值CSCV仍只使用本请求逐折的固定候选和开发收益，不合并不同数据、参数或成本的收益，不因累计计数扩大数值家族。原始[诊断方法和限制](./搜索选择与过拟合诊断说明.md)保持。

## 冻结时点与AI复盘

新SelectionDiagnostic JSON为v2，附search_history v1；旧诊断v1不追写或升级，界面说明其未包含跨请求累计。新报告可以同时引用旧诊断而保持旧范围。

实验发布时冻结本机已知使用记录。之后追加检查点、完成/取消旧请求或合并其他设备记录，均不改写既有记账；后续新实验的记账会重新收集当时已知事实。时间戳不证明当时全局可见，扫描完整只描述该设备当时的已记录范围。

AI复盘接收全部累计数、扫描和外部未知状态、清单哈希、最多12个具体请求及精确省略数；不接收检查点全文、价格或完整清单。selection_review须结合累计尝试与范围解释选择风险和新数据需要。报告中的search_history_facts由系统复制，模型不能修改计数、覆盖或独立性声明；报告正文确定性列出这些次数，再保留AI解释和人工修订。

旧输入、提示和报告按其版本保持；没有search_history时不追加新提示或事实。此项没有新增模型调用或新的自动执行路径。累计次数本身不提供p值、置信区间、显著性校正或独立金融验证，也不改变收益、参数评分门槛或验证层级。

## 同步与恢复

新JSON事实和报告按用户已确认的量化业务范围全部进入WebDAV/FTP/SFTP，无新增数据库字段或迁移。所有同步端须支持schema61；凭据、队列和向量缓存仍排除。

恢复逐条核对同所有者、私密量化库、精确市场、请求/行情/成果/检查点哈希、尝试归属、时间与状态，重建累计和覆盖声明；同ID原件不可覆盖。后同步的旧日期事实不反写过去的本机观察清单。其余设备当时未知的使用不能靠时间戳补成当时已知，也不能据此使旧报告失效。

同步恢复不重新搜索、执行上传源码、运行Docker、调用模型或恢复Job；CSCV原有受控开发收益重放保持。新记账只重建被保存的元数据，不另算收益。

## 代码入口

- `quant/search_diagnostics/history.py`：纯记录投影、有界清单、累计及AI摘要；`history_store.py`：必要元数据读取和快照重建。
- `services.py`：在原发布事务内冻结并保存；已有诊断幂等返回。`sync.py`：按v1/v2重建；`evidence.py`：AI有界投影。
- `quant/experiments/review_contract.py`：新记账的条件提示、系统复制事实和报告章节；旧提示保持。
- 前端`types/api/quantSearchHistory.ts`、`utils/quantSearchHistory.ts`和`Quant/experiments/SearchHistory.tsx`分离协议、读取与展示；local人工样例在`mocks/quant/searchHistory.ts`，沿原列表/详情/报告路由持久化。

## 本地验证边界

人工行情的隔离API用例包含5个请求、9次保存尝试（7次已评价、2次未通过），其中有完成、失败、取消和无成果请求；当前单请求仍只有4次尝试、3个不同可评价候选。两类数量分别展示，预约上限合计60不当作实际次数。该数值只是固定测试案例，不是市场表现或真实用户数据库。

浏览器使用实际SelectionDiagnostic/SearchHistory组件及隔离API投影，在1280px、768px、390px检查累计数、展开记录和内部滚动，根内容无横向溢出。截图位于`/private/tmp/odoc-search-history-desktop.png`、`/private/tmp/odoc-search-history-768.png`和`/private/tmp/odoc-search-history-390.png`。这是组件验收，完整local列表→新请求→取消/等待→第二轮→报告/刷新与四态由独立local路由测试覆盖，不当作真实后端浏览器或远端多设备验收。
