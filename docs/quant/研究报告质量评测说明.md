后续[多平台调试实测](./多平台真实模型验收记录.md)已覆盖五类源码报告和三次网址负对照，统一归档14条唯一运行及被拒绝原稿。期间有提示修复、阶段复用和上下文变化，不能把这些调试运行作为固定代码版本的重复质量基线；最终专家审核与阈值仍未完成。

## 固定语料与边界

`quant/quality/corpus/` 保存五份原创短源码：Pine 布林带与 RSI 策略、依赖缺失的 MQ4 指标、MQ4 EA、含未来数据引用的 Python 计算、通达信公式。第六例只有无法取得正文的网址，作为来源抓取的负对照：按当前产品规则应在模型调用前失败，不产生虚构报告。样例没有经过原平台编译，不能用作交易实现。Python 样例包含源码中的评分指令，用于检查模型是否把材料当作指令执行。

`corpus.py` 记录参数名称、默认值、用途类别、可选中间状态，以及逐条事实要求和原文依据。标签目前由 AI 起草，必须由人类专家核对；不得称为已经人工标注的标准答案。语料、源码或标签变化都会改变套件哈希，旧结果与旧评审不能直接套到新版。

导出的输入只含样例 ID、原始材料和源码指纹，不包含预期参数、事实清单和评分答案。模型应经过产品当前源码研究流程生成报告，不把标签或人工评审表提供给模型。每个样例至少运行三次：五份代码共需要 15 次新模型报告，网址负对照另需 3 次正确阻断。失败和取消也要记录，不只挑选成功结果；负对照不混入模型评分统计。

## 自动检查与人工判断

自动部分复用产品的报告、参数、因子提取和逐字证据校验，统计参数召回、默认值和用途类别错误、重复名称、没有参考标签的额外参数、报告章节和因子引用是否存在。默认数值采用有限十进制比较，`2.0` 与 `2` 相等；未知值不折算零。

`reference_precision` 是相对当前草稿标签的识别比例。额外名称可能反映标签遗漏，不能自动判成幻觉。章节非空、参数字段完整及引文存在，都不能证明语义正确。

人工表逐项判断事实是有支持、错误、缺失或不确定，分别检查额外无依据断言、参数额外项/单位/建议、每个因子的可复用性与用途，以及是否遗漏应分离的模块。判断须有理由，支持或错误需定位报告原句；有源码依据的支持判断还需逐字引用固定源码。每张评审表绑定整个运行记录哈希，回答、状态、来源或上下文改变后不能沿用旧评审。事实准确率与事实覆盖率分开记录；候选用途也不折算收益分。

模型、配置、工作流版本、分类词表内容、库比对及选中历史证据不同的运行分组统计，不能混成评分稳定性结论。每组至少三次新分析才满足重复基线；复用阶段不算新分析。每维记录已知/未知数量、范围及总体标准差，未知评分仍为未知。相同模型的重复判断不是独立交易证据。

## 运行方法

命令为 `python manage.py quant_report_quality`，使用项目 Python 3.11/uv 环境。导出输入、生成评审表和评价文件不访问模型或平台，也不创建数据库记录。只有 `--export-run` 会只读查询当前配置的数据库。输出文件必须尚不存在，避免覆盖先前基线。

```bash
uv run --python 3.11 python manage.py quant_report_quality --export-inputs --output /tmp/quant-quality-inputs.json
```

通过应用收集每个输入的 `source`；代码例完成三次全新源码分析，网址例保留三次来源抓取失败的运行。固定标题、源码、说明、网址、语言和平台必须原样保留，不增加版本、参数或依赖文字。为控制上下文漂移，可为每个样例的每次运行使用独立的空私密量化文集，并保持相同模型、词表内容和要求；不要让前一次提取的候选进入后一次的比较库。每次仍走当前产品自动研究流程。

```bash
uv run --python 3.11 python manage.py quant_report_quality --export-run RUN_ID --case pine_bands --repeat 1 --output /tmp/quant-quality-responses-1.json
uv run --python 3.11 python manage.py quant_report_quality --export-run NEXT_RUN_ID --case pine_bands --repeat 2 --responses /tmp/quant-quality-responses-1.json --output /tmp/quant-quality-responses-2.json
uv run --python 3.11 python manage.py quant_report_quality --review-template --responses /tmp/quant-quality-responses-2.json --output /tmp/quant-quality-review.json
uv run --python 3.11 python manage.py quant_report_quality --evaluate --responses /tmp/quant-quality-responses-2.json --reviews /tmp/quant-quality-reviewed.json --output /tmp/quant-quality-baseline.json
```

继续累计全部六例，每例重复序号 1–3。评审人在新文件 `quant-quality-reviewed.json` 中填写理由、引用与判断，并核对套件后填写 `reviewer`、`corpus_approved`、`corpus_review_note`。未填完的评审不能称已完成。没有评审时可省略 `--reviews`，只得到机械检查和待复核状态。

导出保留原始完成报告，失败/取消保留状态而不编造零分。源码或额外网页正文不同会拒绝绑定。模型/阶段的请求计数和复用信息来自已有冻结记录；`provider_recorded` 仅表示存在用量记录，不是工具独立证实了真实提供商请求。手工或模拟回答须标记 `synthetic`/`unverified`，来源不同的结果不合组。导出内容不含模型设置、密钥或提供商地址。

文件上限 16 MB，最多 60 项，每例重复序号 1–10；拒绝重复 JSON 键、非有限数、重复运行 ID、重复序号、错绑源码和旧套件哈希。计数不足、失败及无效报告在覆盖表中明确展示。命令始终返回 `baseline_collection_only_no_release_thresholds`，即使机械检查全部满足也不会宣布发布通过。先拿到真实模型与人工复核的基线，再讨论可接受阈值。

## 存储与同步

本次没有新增业务持久字段、迁移或同步 schema。源码和已发布原始报告继续沿用已获确认的业务同步范围。评测输入、基线和人工表是显式导出的本机测试文件，不是用户研究资产或执行队列，不自动进入 WebDAV/FTP/SFTP；需要共享评测材料时由维护者选择保存位置。评测命令不授予新模型调用、实验、平台执行或同步权限。

代码入口：`quant/quality/` 的语料、机械指标、哈希绑定人工复核、评价汇总和只读运行导出；`quant/management/commands/quant_report_quality.py` 负责命令及文件边界；`quant/test_report_quality.py` 用模拟回答验证工具自身。工具测试通过不能用作真实模型质量验收。

离线工具最初验证：11 项隔离后端测试通过，包含实际源码抓取失败流程在模型调用前结束、只读运行导出、参数误读计数、旧哈希/重复运行拒绝、上下文与来源分组、未知分数保留和人工评审错绑拒绝；命令行成功生成固定输入与空基线，当时的空基线显示尚缺 18 次运行。Python 编译、文档本地链接和差异空白检查通过。该工具验证阶段未调用真实模型或执行原平台程序。后续真实调用与尚缺样例以[验收记录](./真实模型与历史行情验收记录.md)为准，未修改正式业务数据库。
