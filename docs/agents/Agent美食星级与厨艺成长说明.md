# Agent 美食星级与厨艺成长

> 本文说明仓库当前实现中的美食制作规则。生活日程和执行总入口见[Agent 世界统一生活执行说明](./Agent世界统一生活执行说明.md)；持久数据、恢复和迁移见[数据同步逻辑说明](../数据同步逻辑说明.md)。一期和二期的详细实施记录已移入[历史归档](../archive/README.md)。

## 当前范围

- 固定 20 个稳定 ID 的食谱；图鉴支持查看、配置现有食谱和维护图片，不提供新增或删除食谱的入口。
- 食谱默认解锁等级为 1～10；当前规则允许配置等级 1～99。每份基础产量为一个成品，材料限规则中指定的作物、普通鸡蛋和普通牛奶；基础调味料、水及小麦、水稻、大豆、向日葵的基础处理不额外扣库存。金色畜产品不能替代普通产品。
- 制作由内置生活活动执行。模型只能在服务端给出的可制作食谱中选择食谱、份数、用料策略并填写理由；不能决定价格、经验或产量。存在可制作候选时必须至少选择一道；没有可执行候选时不制作。
- 每次活动最多选择三道不同菜谱，每道1～10份，总计最多30份。没有直接制作 HTTP 操作入口。手动制作复用相同的三轮候选选择逻辑。

## 用料与计划

每道食谱可选择 `low_stars_first`（低星优先，日常制作）或 `high_stars_first`（高星优先，精品制作）；相同星级按库存创建顺序和稳定 ID FIFO。仅使用所选居民自己的背包，不读取其他居民或市场托管库存。

日程选中美食后，先从真实库存扣除其他未结束美食安排的未制作需求，生成等级、材料和体力满足的菜谱；超过十种时按当前时段和轮次稳定随机抽十种。先选菜谱，再选1～可制作最大份数（上限十份），再选择用料策略；两种策略分配相同时代码直接确定。第二、第三轮前选择是否继续，重新按剩余材料过滤并排除已选菜谱，输入保留已选菜谱与份数。

确认的配方规则、份数、策略和材料需求保存到版本化 `LifeItem.context.cooking_plan`，随日程同步。这里仅预留规划材料，不扣背包。后续时段和手动美食按未被其他计划占用的材料规划；取消或结束释放未执行部分，部分失败重试只保留未完成份数。执行时按保存计划分配全部份数的真实材料和体力，并冻结品质规则、材料记录、价格批次及材料基础价值，不重新请求制作选择。基础价值取确认计划时农牧场目录中的作物或普通畜产品回收基础价；实际消耗价值按被冻结的库存价格批次计算。高星材料提高高星概率，但不保证加工盈利；挂牌溢价不计入保证收入。

每份制作开始时重新检查居民授权、执行锁、旅行状态、等级、材料批次和体力。原料扣除、一个成品入库、经验、体力及制作事实在同一事务内提交；失败不会拆开提交。相同操作键返回原结果，不重抽品质或重复奖励。材料变化后停止未完成份数，不自动替换；此前成功份数保留。每份结算后更新等级，后续份数使用当时等级。

日程规划和手动制作的各轮选择均包含美食任务配置的制作偏好，同时保留居民生活偏好。执行冻结材料时再次扣除其他未结束计划的预留，排除当前日程自身；同一库存格的前序价格批次已被预留时，只冻结并扣除可用批次，保留预留批次的数量和成本。

## 星级、价格与经验

普通鸡蛋和普通牛奶按一星计算。材料平均星级按“数量 × 计划确认时的基础价值”加权：

`A = Σ(数量 × 基础价值 × 材料星级) / Σ(数量 × 基础价值)`

居民等级为 `L` 时，四次独立伯努利试验的成功率为：

`p = 0.04 + 0.46 × ((L−1)/98)^0.8 + 0.25 × ((A−1)/4)`

成品星级为 `1 + Binomial(4, p)`，范围 1～5 星。每份使用稳定操作 ID 和品质规则版本生成确定性结果，计划预览不会抽取结果，重试或恢复不会重抽。

| 星级 | 基础回收价倍率 | 基础经验倍率 |
| --- | ---: | ---: |
| 1 星 | 1.0 | 1.0 |
| 2 星 | 1.2 | 1.1 |
| 3 星 | 1.5 | 1.2 |
| 4 星 | 1.8 | 1.3 |
| 5 星 | 2.2 | 1.4 |

一星保留食谱基础回收价；二至五星单价按倍率向上取整，再乘成品数量。经验按倍率向下取整，每份只结算一次。旧库存和已确认计划使用原价格与规则快照，不因后续编辑追溯重算。

## 厨艺成长

厨艺经验绑定稳定居民 ID；居民改名不重置成长。等级上限为 99，满级继续累计经验。

- Lv.1～9 的逐级门槛为 `200L−100`。
- Lv.10～98 的逐级门槛为 `1900 + 10x + ceil(x²/2)`，其中 `x = L−10`。
- 到达 Lv.10 需要累计 8,100 经验；到达 Lv.99 需要累计 331,904 经验。
- 食谱要求等级、基础经验和体力均可单独配置；改变要求等级不会自动改基础经验或体力。

## 背包、市场与同步

成品稳定 SKU 为 `dish.<recipeId>`，复用 Agent 世界共用背包、库存价格批次和市场交易。成品的 `source.stars` 为 1～5 星，与作物品质和畜产品金色品质分开；不同星级分格，托管、成交、购买、撤单和回收保留来源星级与价格批次。新规则不改写旧库存、历史事实或旧挂牌价格。

烹饪持久数据纳入 WebDAV；同步完整性版本为 `cooking_schema_version=3`。版本3增加美食日程计划清单及关联校验；兼容版本0～2的旧快照。版本 1 的旧快照先按旧规则验证，再兼容补一星并更新相关指纹；缺少新版关键数据的快照拒绝恢复。升级涉及迁移 `0056_dish_stars`，执行时机、备份要求和多设备升级顺序以[数据同步逻辑说明](../数据同步逻辑说明.md)为准。仓库规则不证明用户正式数据库已迁移或双设备同步已验收。
