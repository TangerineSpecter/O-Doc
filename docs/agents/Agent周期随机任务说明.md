# Agent 周期随机任务

在 Agent 任务分配中选择「定时任务 → 周期随机」，设置每天、每周、每月或每年的目标次数。固定时间和间隔任务继续使用原调度规则。

每周期目标次数允许 1 到 10000，避免单次配置生成无限量计划；串行 Agent 可分配 0 次。

## 次数规则

- 并行：设置 N 次表示每个 Agent 各成功 N 次；一轮一起开始，成功立即计数，失败的 Agent 单独补执行，补齐后进入下一轮。
- 串行：设置 N 次表示任务的总额度；默认平均分配，余数按 Agent 选择顺序分配，也可以手动调整。分配总和必须大于 0 且不能超过 N；未分配额度不执行。每次轮流执行一个 Agent，独立使用任务目标，不传递前一个 Agent 的上下文。
- 只统计带随机机会归属的主 Agent 成功结果；手动执行、失败、异常、中断、后续 Agent 和通知失败不增加或扣减次数。重复记录按机会和 Agent 去重。

## 时间与恢复

周期按 Django 项目时区（默认 Asia/Shanghai）计算，周一为每周起点；日、月、年从对应自然周期零点开始。每个周期分成与实际机会数相同的区间，每个区间随机选取一个时刻，可以在全天执行。新任务仅在当前周期剩余时间安排计划，之后每个周期重新生成。

计划和当期配额持久化，服务重启不重新抽取。任务暂停保留计划，恢复时依次补执行已经错过的机会；未到期的机会继续等待。失败依次等待 5、15、30、60 分钟重试，之后最多每小时尝试一次，到周期结束不再补旧周期次数。一次执行跨越周期边界时，成功仍归入启动时所属周期。

周期、目标次数、Agent 选择与执行模式的修改从当前周期结束后生效；本周期继续使用配置快照。关闭任务立即暂停。切换回固定调度也会等当前随机周期结束，任务卡片提示配置待生效。

## 接口与同步

任务 CRUD URL 保持 `/api/settings/agent-tasks/`。新增 `scheduleMode`（fixed/random）、`randomPeriod`（daily/weekly/monthly/yearly）、`randomCount`、`randomAllocations`（`{agentId, count}` 列表）。列表传输避免动态 Agent ID 被驼峰转换器修改；数据库存储仍为 Agent ID 到次数的映射。`randomProgress` 只读，返回当期边界、目标、各 Agent 成功进度、下次执行时间、状态及配置待生效标记。执行记录新增只读 `randomContext` 保存机会归属。

配置与记录同步，本机计划、退避和租约不进行同步，详见 `docs/数据同步逻辑说明.md`。多进程共享数据库时使用 10 分钟租约，每 30 秒续约，异常中断后认领过期机会并只补执行未成功的 Agent。同一任务应仅在一台设备运行；模型和外部工具的副作用不具备跨进程崩溃的严格恰好一次保证。

升级运行 `.venv/bin/python manage.py migrate system_settings` 应用 `0025_agent_random_schedule` 和 `0026_agent_random_cycle_snapshot`，然后重启后端。所有同步设备先升级到 0.9.24。

## 人工验收

1. 新建并行任务，每周 3 次，选择两个 Agent，确认各自目标为 3，并显示各自成功进度。
2. 新建串行任务，每月 10 次，分配 A=6、B=4；合计超过 10 或全部为 0 时拒绝保存，选择每年同样可用。
3. 并行任务模拟 A 成功、B 失败，确认 A 只计一次、补执行仅调用 B；手动立即执行不改变随机进度。
4. 重启、暂停恢复和修改周期，确认计划保持、错过机会可补执行、配置修改提示下周期生效。
5. 在任务页等待进度刷新，检查窄屏表单滚动、保存与重新编辑后分配值保持。

删除 Agent 后会记录不可执行的失败状态，跳过该 Agent 在本周期的剩余机会，其他 Agent 继续执行。跳过不增加成功次数，保留删除前的成功进度。
