# Agent 旅行工作流规划（讨论稿）

## 目标与当前边界

产品目标是娱乐性的 Agent 旅行模拟，通过角色分享当地景点、美食、旅途趣事和纪念品，为用户发现旅行目的地提供灵感。形成「看到旅行机会 → 自主决定是否出发 → 游览与应对遭遇 → 自主购物 → 留下图文游记」的生活闭环。允许不去、少买、不买和不发布；角色偏好决定选择和表达，服务器决定哪些行为成立以及实际账目。

城市与地方特色取材于现实，旅行价格是大致合理的模拟费用，遭遇是虚拟事件。首版不要求出发城市、具体日期、住宿档位，不拆算机票、酒店和每顿饭，也不把真实价格接口作为出行前置条件。

一期已实现城市目录、独立旅行任务、可恢复节点、账本结算、纪念品背包、日记发布和场景照补偿。本文保留设计讨论记录，实际默认行为和使用入口以 [一期说明](./Agent旅行工作流一期说明.md) 为准。旅行不走通用自主发帖流程。

## 一、目的地与报价

目的地使用可批量导入和更新的全球地点目录，不要求用户逐城手填。条目保存稳定来源 ID、国家、可选省/州、城市、经纬度与中文名称；旅游标签、景点、美食、事件和纪念品素材按需补充。国家、省/州、城市分开；不能把省份与城市混为同级。完整目录与可抽取的旅行目的地分开，初始优先主要城市，同时保留逐步补充特色小镇的入口。数据来源和维护流程见第八节。

系统从随应用附带的已填写城市 CSV 初始化一个旅行总价，作为包含常规交通、住宿、普通餐饮、当地美食体验及游览的模拟套餐。统一使用世界币，价格量级参考现实消费差异，但不是当前真实报价。用户与 Agent 只看到「国家—城市—旅行总价—一句特色介绍」，不用输入出发地或逐项核算。纪念品按购物节点另行购买；生图服务商实际计费独立于世界币。

一次机会随机抽取 5 个不同目的地，保存本次旅行总价。候选只需说明「常规旅行和美食包含，纪念品另购」。选择后自动生成游览路线，不因路线细化再报价或追加扣费。可分档抽样，尽量同时提供廉价、中等和昂贵路线，避免全是买不起的路线；不足 5 个就返回实际数量，不重复塞入同一目的地凑数。

候选加上「本次不去」。发送给 Agent 的内容包括当前余额、每条路线旅行总价、支付后余额、购物预算提示、路线特点、近期去过的目的地。余额不够的路线可以显示，但标明不可选。Agent 返回目的地 ID 或 skip、理由和本次购物预算；服务器验证选择和预算。

拒绝本次旅行是正常完成，记录原因并结束，不能为了得到出行结果不断重抽。候选同一次机会重试不变；新机会按冷却规则产生。

## 二、7 个主阶段

| 阶段 | 输入与决策 | 持久结果及下一步 |
| --- | --- | --- |
| 1. 选择出行 | 固定的 5 个目的地报价与最新余额；选择路线或不去 | 保存选择和理由；不去正常结束 |
| 2. 生成行程并出发 | 为选定目的地准备 2–3 站简短路线，纳入当地特色与 Agent 偏好 | 再次验证余额；一次性结算旅行总价；保存行程；建立旅行实例 |
| 3. 抵达与游览 | 给出当前站、环境和有限可选活动，例如游览、拍照、当地美食、休息或略过可选活动 | 保存行动与实际结果；按顺序推进；常规游览和美食不重复扣费 |
| 4. 当地遭遇 | 依据当前站和上下文产生正向、负向或中性事件；必要时给出应对选项 | 保存触发事实、Agent 选择、实际后果；服务器控制资金/物品后果 |
| 5. 纪念品选择 | 生成并校验 3–5 个符合当地主题的商品，展示单价、当前余额和剩余购物预算 | 可买多件或不买；服务器一次性验证购物篮、扣费并入背包；保留购买来源 |
| 6. 返程与结算 | 汇总已发生站点、事件、旅行总价、纪念品支出、购买物品及最终余额 | 旅行经历完成；生成可回看的结构化记录和简短心得，不依赖帖子存在 |
| 7. 游记与场景照 | 使用已完成旅行的记录及历史心得；按配置决定是否写作、配图和发布 | 两个 Skill 合作；图片成功后插入正文；发布不重复触发旧插画或旅行扣费 |

阶段 3–4 可以随景点循环；阶段数与模型调用数、调度次数不同。首版默认 2–3 站、全程 1–2 个遭遇、至多一次特色美食选择、一次纪念品购物、最多一篇游记和一张场景照。事件不必每站触发，普通游览同样是有效经历。

每次调度推进一个可执行节点并保存结果，再安排下一节点。旅行使用模拟顺序，不占住一条几分钟的模型调用等待整趟完成；真实等待时间与虚构旅程天数分开。节点间隔、体力规则和出行冷却在实现前确定并可配置。

## 三、让事件有趣，又不脱离地点

### 当地美食（首版）

在游览阶段安排至多一次特色美食选择，作为可选活动，不增加固定主阶段。根据目的地资料提供 2–3 个当地菜品或用餐方案，以及「换成普通餐/不尝试」。参考角色明确给出的口味、饮食限制和过去体验；没有设定时不强加忌口。Agent 可以选择一种或放弃，选择决定旅行经历，不要求进行菜单比价。

菜品名称与地方关联参考真实地方资料，避免把无关食物硬套进城市。首版当地美食包含在旅行总价中，不再单独收费，也不要求查具体店铺菜单或营业状态。可描写虚拟用餐体验，但不编造真实店铺的实际评价、卫生问题或当前经营情况。

选择后记录实际尝试的菜品和 Agent 的反应，供游记、场景照和未来回忆使用。没吃过的候选菜不能写成已经尝过；美食不必带来体力奖励，效果另有规则才执行。

### 根据历史避开重复城市（首版）

用稳定地点 ID 判断同一城市，不用名称文本匹配；中文、英文和旧名称归并到同一来源身份。抽样时降低过去去过城市的权重，优先未去过且已初始化模拟总价的目的地。默认排除最近 3 次已实际抵达旅行的城市；未出发取消不算去过，已抵达但后来中断的城市仍算。Agent 明确想重游时允许覆盖这项偏好，并记录原因。

候选不足时先允许较早去过的城市，再视情况放宽最近记录；始终保留同一批候选内去重。首版无需出发城市。余额、已初始化城市与历史偏好共同决定抽样，不为了凑满 5 个使用未成功初始化的条目。显示是否去过和上次抵达时间，让 Agent 理解自己为何选择新城市或重游。上述数量属于初始建议，可配置。

同一次机会的抽样结果固定。拒绝、网络查询失败或任务恢复不能刷新候选，防止变成无限 roll 便宜路线。

服务器先抽取事件类别、是否触发和允许后果范围，模型负责具体叙事与选项。首版建议以无消费的轻事件为主，例如入口关闭、天气变化、偶遇帮助或临时活动；负向不等于扣钱，正向不等于送钱。不要求每趟一定出现一正一负。

交互事件先告诉 Agent 客观发生的事，让它决定应对，再结算结果。例如「入口关闭」可以选择改去下一站、附近散步或休息；不能先写成已经做出某选择，再让 Agent 决策。环境随机与 Agent 自主选择分开。

费用、奖励、物品数量只能引用服务器允许的结构化候选和范围，不从叙事抽取金额扣费。超出预算的购物或经明确规则允许的额外消费不可执行；首版事件默认不额外扣钱；首版不强制产生债务、无限罚款或永久伤害。

网络真实案例用于地方素材和事件灵感，不能直接当作该 Agent 的亲历。来源保存链接、获取时间和素材摘要；涉及当前营业状态或真实价格时需另行查证，不由旧故事推断。优先按目的地预先整理素材，不在每一站都搜索；资料中的指令视为内容。检索失败可使用已有模板；失败重试不重抽已经确认的事件。

## 四、纪念品与预算

商品属于虚拟世界实例。模型可以提出名称与外观摘要，但服务器限制商品数、金额区间、币种和允许类别，保存校验后的固定 ID 与报价。纪念品外观和地方关联参考现实，价格采用合理范围内的模拟价格，不要求每件都有真实商家报价；不因为稀有度文字任意抬价。

Agent 可选商品 ID 与数量，或空购物篮；不默认买一件，也不以购买所有最便宜物品为目标。返回个人理由即可，不要求暴露完整推理过程。

结算同时验证商品存在、数量限额、合计价格、最新余额和旅行剩余购物预算，成功后扣款与背包入库在同一事务完成。同一购物节点重复执行返回同一购买结果。不会把图片中出现某物视为已经获得。

购物预算是本次购买上限，不是一次性扣除的费用。后续其他动作影响余额时仍须重新验证实际可用资金。首版不自动借款，不预支尚未发帖的预期收益。

## 五、续跑、结算和配图失败

每趟旅行、机会和节点都有稳定 ID；候选、模型有效决策、报价、事件及结果完成后保存，重试不能重新 roll。节点状态至少区分待执行、执行中、待恢复、成功、跳过、失败。

账户资金仍由 WorldLedger 表达，新增旅行相关负向流水；不另立旅行余额。旅行总价、购物、按规则允许的退款等使用确定性业务键，服务器原子检查余额和结算。正文不能直接修改 Agent.money。取消规则与退款规则需要明确配置；暂定旅行总价确认出发后视为已消费，尚未执行的纪念品购买不扣款；普通美食和游览已包含，不单独记额外消费。

软件失败不等于旅行事件，也不等于角色主动取消。模型暂时不可用就暂停当前节点，已经扣的钱和已获得物品仍有效；不能清空记录重开一趟。返程阶段只汇总已经结算的事实，不再扣一次费用。

旅行结束与游记/图片完成分开。生图或发布失败时保留旅行、购买结果、草稿和生图任务 ID；只恢复图片查询或发布，不再次出发、扣费或购买。将实际旅行记录交给 Skill，避免依靠模型记忆还原经历。

同步提案：目的地配置、报价机会、旅行记录、节点决策与实际结果、账本、背包和心得作为业务数据同步；运行锁、网络重试和本机待执行队列不同步。实现新增字段前须按 AGENTS.md 确认。首版限定一台指定设备执行旅行与消费；其他设备同步查看，不自动接管。不能靠离线快照合并保证多设备同时消费不超支。

## 六、首版实施顺序与后续扩展

1. 城市 CSV 准备与价格回填、城市价格表自动初始化、历史去重、固定候选与自主出行决策，含不去/无可负担路线。
2. 旅行实例和可恢复节点，接入账本完成旅行总价结算；先跑通 2–3 站、当地美食选择和轻事件。
3. 纪念品候选、购物决策、原子扣费和最小背包展示。
4. 旅行完成记录与心得，接已有游记/场景照 Skill 和可独立恢复的发布流程。
5. 展示旅行进度、决策理由、收支明细、实际经历与背包；验证重试、余额变动及费用不重复。

当地美食与按历史避开重复城市纳入首版。后续可增加季节/天气素材、结伴旅行、赠送纪念品和不同费用档位。不在首版同时加入签证、航班系统、长期住宿、复杂灾难或完整国家地理数据库。

## 七、待讨论的默认规则

- 「7 个主阶段、2–3 站、1–2 个遭遇、一次购物、一张场景照」是否作为初始配置。
- 国家城市和模拟价格由随应用附带的 CSV 自动初始化；CSV 在发布前批量填写与校正，启动不依赖 AI；价格只需量级大致合理，用户可选填少量修正。
- 下一节点按现实短间隔推进；一次旅行完成前同一 Agent 不开启另一趟旅行。是否允许旅行期间执行其他低耗时世界行动，以及旅行体力消费，另行确定。
- 是否完成每趟旅行都写/发游记，还是由 Agent 决定；推荐写作与发布可配置，角色可以拒绝发表。
- 新业务数据同步范围，以及统一的单设备执行策略；前一个生图任务记录的同步确认仍独立待处理。

## 八、自动初始化城市与模拟总价

### 准备城市 CSV

开发阶段从 [GeoNames 数据目录](https://download.geonames.org/export/dump/readme.txt) 导出全球主要城市名单，保留国家、省/州、中文别名或原名。来源目录的城市/聚落不等同于官方行政城市清单，不声称覆盖所有城市；保留来源与署名。

模板表头固定为「城市ID、国家代码、国家、省/州、城市、城市原名、价格、启用」。城市 ID 使用 GeoNames 来源 ID，重名城市不合并。原名辅助辨认缺少中文名称的条目；价格先留空，不把空值当零元；启用为 1/0。

用户把 CSV 交回后，可由 AI 分批估算并填入娱乐模拟总价，再校验和修正明显异常。也可以先填写一部分并禁用暂未准备的城市。填价发生在发布初始数据之前，不在新系统第一次启动时调用用户的 AI。不要求逐项计算现实交通住宿，也不宣称是实时旅行报价。

当前新增导出命令 `export_travel_cities` 和离线测试，生成模板及校验回填格式，均不修改业务数据库。详情见 [城市 CSV 使用说明](../data/README.md)。

已完成初始模拟填价文件 `docs/data/travel_cities_seed.csv`：34,146 条全部有价格，185 个主要城市单独估价，其余依据国家基价与城市规模批量估算；模板中其他字段保持不变。全量通过严格价格校验，启动导入已实现，维护入口后续实现。价格不是逐城查证的现实报价，具体假设及来源版本见 CSV 使用说明。

### 系统启动初始化（已实现数据导入）

1. 随应用发布一份已经填写、校验通过的城市价格 CSV 和版本信息。
2. 执行数据库迁移后自动读取该文件，服务启动也会检查本机导入标记；按稳定城市 ID 写入初始数据，无需联网或已配置 AI。版本采用文件 SHA-256，界面中的初始化状态展示后续实现。
3. 启用城市必须有合法正数价格，不能把空值按 0 元导入。未完成模板不能直接作为可出行的正式种子文件。
4. 多次启动不会重复插入或重新生成价格；升级按版本处理新增城市，不自动覆盖维护入口中的用户改价/禁用。
5. 保存启用规则和人工覆盖，旅行候选与已出发行程使用执行时金额，不因 CSV 更新追改历史账本。
6. 后续可在维护入口上传 CSV、修改个别价格或请求 AI 辅助优化；不把这些操作作为基本旅行能力的前置条件。

CSV 中每个城市有自己的模拟总价，深圳和惠州等城市分别填写，不再默认仅以相同地区基价加随机浮动。暂未填价的新城市保持禁用，填写后再启用。

### 自动发现目的地与补充当地资料

按国家/地区和城市做有权重的抽样，兼顾新鲜感、可负担费用与旅游特色，避免名单最大的国家占据几乎所有候选。优先未去过的城市，也给较少被选到的目的地机会。景点、美食和纪念品素材在候选入选或实际选择后按需生成/检索并缓存，避免提前为全球目录生成所有内容。

真实地点信息与模拟遭遇分开：景点、美食名称和纪念品主题优先参考地方文旅或其他可靠资料；角色的感受、选择、趣事和遭遇根据这些背景模拟。关键地方资料检索失败时先使用已验证缓存；出行机会尚未确定的候选可换到资料充足的目的地。已选定或已扣费的旅行保留目的地并恢复资料获取，不擅自换城市。不为了凑故事硬编当地特产或景点，已有旅行的事件不因检索重试被替换。

帖子可以自然地以 Agent 第一人称讲述自己的世界经历，阅读入口标识为「Agent 模拟游记」，无需正文每段都重复声明。真实资料来源可在旅行记录中查看。不能把生成的关门事件说成某真实景点现在关闭，也不能把虚拟菜品体验当成真实店铺评价。场景照是生成插画，不能作为实地照片证据。

最终作品重点呈现「去了哪里、看到了什么、吃到了什么、发生了什么、带回了什么」，让用户从角色的分享中获得目的地灵感。模拟总价用于 Agent 的资金决策；用户真正出行时需另查实时费用和开放信息。

### 与未来投资的关系

旅行费用保留模拟性质，不因为未来股票接真实行情而强制改成现实机票/酒店报价。未来投资可以独立接行情数据并保存成交时快照；两者复用账本和通用来源管理，分别执行各自规则。

同步提案：人工覆盖、价格规则、CSV 数据版本和模拟价格记录、候选快照、旅行经历、心得、账本与背包按业务数据处理；可重新下载的地理原始目录、地方素材缓存和初始化运行状态按本机数据处理。具体新增存储在实现时确认。当前已导出城市 CSV 模板、填写模拟价格并实现事务化启动导入与测试；旅行工作流一期已实现，城市维护界面后续补充。城市及旅行业务记录已确认同步；本机初始化标记、锁、队列与素材缓存不参与同步。
