下文区分用户明确要求与设计默认值。用户要求构成边界；其余规则由本轮补全为一期默认方案，可随反馈调整。第 1～18 节不是当前生产内容包的逐项配置清单；涉及实际数值时，以版本化内容和代码为准。设计目录见[战斗数据目录说明](../data/combat/README.md)，当前仓库内容包位于 `system_settings/agent_world/combat/data/`。

## 1. 已确定的范围与边界

- 战斗职业与当前「职业管理」独立，不属于同一种职业。一个 Agent 可以同时拥有现有职业和战斗职业。
- Agent 参与探索出发决策与准备；达到转职等级时在安全回合点暂停探索并参与职业选择，完成后自动继续。普通战斗回合仍由代码执行，不调用模型。
- 探索采用回合制，角色与怪物轮流执行；一分钟一轮不再作为确定规则，新的回合间隔待验证。
- 地牢没有层数，持续按概率遭遇怪物；有 Boss 的地牢会按本次击败怪物数增加首领遭遇概率；新手区域不设首领。
- 探索消耗现有世界体力，并纳入统一生活日程的活动选择。
- Agent 展示穿戴装备、战斗属性、技能与战斗职业。每次探索无论完成还是中途失败，都保存可回顾的事件。
- 出发时选择目的地、探索时长和探索风格，检查携带药剂与是否更换装备。
- 目的地配置等级区间、怪物、掉落材料和装备；怪物配置等级范围和掉落规则。
- 装备采用白装、蓝装、金装，分别具有 1、2、3 条随机词条。武器有基础攻击。
- 新手职业没有技能；10 级一转、30 级二转、50 级三转，职业存在分支。
- 当前冒险等级上限为 99 级，升级节奏偏慢，经验不能按短时探索快速满级设计。
- 省略手动加点与技能加点选择，技能到对应等级自动学习。
- 基础属性包括力量、敏捷、智力、体质、精神和运气。精神影响治疗量与魔法防御；运气一期只影响暴击率，不影响掉落。
- 炼金本期不做。未来作为类似美食制作的独立生产系统，消耗掉落材料制作药剂或其他商品，可自用、在市场出售或卖给其他 Agent。
- 当前掉落的装备和材料需要有价值，并可直接出售给商店。
- 新增业务数据全部参与现有 WebDAV 同步；运行锁和临时状态仅保留本机。

当前阶段先确认设计，不以本文表示功能已经交付。

## 2. 探索流程

整体循环为：日程选择 → 准备与出发 → 持续概率遇怪与自动战斗 → 掉落、经验和升级 → 达转职门槛时暂停选择并续跑 → 正常返回或中途失败 → 保存探索事件 → 留用装备或出售物品。没有楼层进度与通关目标，正常结束称为完成探索。

### 2.1 出发决策与准备

Agent 判断今天是否进行迷宫探索，并决定：

| 项目 | 内容 |
| --- | --- |
| 目的地 | 选择探索区域，参考等级区间、危险程度、怪物与目标掉落 |
| 时长 | 例如 30 分钟、1 小时、2 小时 |
| 探索风格 | 一期选择均衡、强攻、谨慎、技能偏好或节约 |
| 装备 | 检查当前装备及背包装备，决定是否更换 |
| 药剂 | 选择此次携带的药剂种类与数量 |

**设计建议：** 后端校验出发条件，并保存此次探索计划。携带药剂从共用背包转入本次探索物资，结束后返还剩余药剂，避免同一物品同时被市场或其他活动消耗。已穿戴装备在探索期间锁定，不能更换或出售，新掉落装备返回后再选择穿戴。

### 2.2 时间与回合

**已确定：** 角色与怪物轮流行动，探索有预设时长。一分钟一轮已撤回为待讨论方案。

**新建议：** 先以 15 秒一轮做模拟，一轮包含角色行动一次、怪物行动一次。角色先行动，若击败怪物，则怪物不再行动；倒地后停止推进。30 分钟、1 小时、2 小时对应最多 120、240、480 轮时间刻度，但不能把每个刻度都视为一次掉落机会。

每次战斗结束后，间隔 30 秒触发下一次遭遇抽样。普通怪、精英与 Boss 的概率规则见第 4 节，战斗回合本身不触发新怪。若平均战斗耗时 60 秒，加上遭遇间隔，约为每小时 40 次击杀；这是新的吞吐基准，不是已验证结果。

出发时立即生成首个遭遇，15 秒后开始第一轮。击杀后等待 30 秒生成下一遭遇，生成后再过 15 秒执行其第一轮。例如四轮击杀：0 秒生成、15/30/45/60 秒行动并击杀；90 秒生成下一怪、105/120/135/150 秒行动并击杀，两次击杀相差 90 秒。

每个提交刻度先提交有效时间增量与自然日预算归属，生成并截断每 5 分钟的物品机会，以及按出发时职业缩短比例调整后的装备判定机会，再检查时限，未到期才执行持续效果、动作及击杀结算。装备判定间隔最短 1 秒，最多暂存 1 次，并在下一次击杀时处理；普通/精英未中立即消费装备判定。物品机会仍最多保留 2 次。1800 秒正常结束仍获得并保留终点新机会，但不执行该刻度回合或奖励未击败怪物。暂停和终止也先提交此前真正推进的有效时间，不能靠终止删掉已应得机会。

到达时限后不再开新战斗，当前未结束战斗终止，不给未击败怪物奖励。时间边界与回合同时到达时，不补发一个越界回合。

### 2.3 逃跑与提前结束

**新建议：** 一期取消随机逃跑动作，避免角色因为抽中某个动作就突然结束探索。谨慎风格通过更早治疗、使用护盾或防御体现，不再提高逃跑概率。探索时限到达正常返回，生命为 0 则失败返回。

用户主动召回可作为明确操作，结束探索并保存原因；「出发前设定条件撤退」保留为后续候选，不纳入本轮随机动作公式。逃跑成功率与此前逃跑系数因此不再适用。

建议中途失败保留已完成击杀的经验和掉落，不删除已经成立的业务事实；未击败怪物不结算。返回恢复规则与休整期见体力日程章节，暂停和系统故障须与战斗倒地区分。

## 3. 探索风格与随机行动

### 3.1 一期探索风格

最初的激进、谨慎、技能狂魔只是举例。一期默认开放以下五种风格；本轮取消随机逃跑后，风格只影响战斗行动和资源使用，不会随机结束探索。

| 风格 | 主要倾向 | 主要取舍 |
| --- | --- | --- |
| 均衡 | 兼顾普攻、技能、治疗与防御 | 默认方案，平衡输出与消耗 |
| 强攻 | 普攻和伤害技能权重高，更晚治疗、较少防御 | 更快输出，但更容易倒地 |
| 谨慎 | 更早治疗，提高防护技能与防御权重 | 生存更稳，但可能消耗更多药剂、减少击杀 |
| 技能偏好 | 更常选择有效技能，更早回蓝 | 职业技能表现明显，法力与药剂消耗更高 |
| 节约 | 弱敌多用普攻，强敌再用技能，减少不必要用药 | 更省补给，但可能输出较慢或因保守用药倒地 |

风格独立于职业。没有技能的新手也能选择风格，但不能凭风格生成技能。风格不直接加攻击、经验或掉落率，击杀效率差异通过实际战斗自然产生。

### 3.2 状态输入与参数

以下为可配置的初始算法草案，尚未实现或平衡。

```text
h = 当前生命 / 最大生命
m = 当前法力 / 最大法力（最大法力为 0 时取 0）
t = clamp((怪物等级 - 角色等级) / 10, 0, 1)
c = clamp((0.35 - h) / 0.35, 0, 1)
```

t 是基于等级差的威胁近似，后续应考虑 Boss、预计承伤与装备。c 表示低血线危险程度，不是直接伤害加成。

| 风格 | 普攻权重 A | 技能权重 S | 治疗起始血线 H | 回蓝起始比例 M | 防御系数 D |
| --- | ---: | ---: | ---: | ---: | ---: |
| 均衡 | 100 | 60 | 65% | 35% | 1.0 |
| 强攻 | 150 | 80 | 35% | 30% | 0.6 |
| 谨慎 | 80 | 50 | 85% | 40% | 1.8 |
| 技能偏好 | 60 | 150 | 65% | 65% | 1.0 |
| 节约 | 120 | 50 | 45% | 20% | 1.0 |

### 3.3 动态权重与抽样

```text
w普攻 = A
w技能 = S × max(q技能)
w治疗药剂 = 150 × clamp((H - h) / H, 0, 1) × (1 + t + c)
w回蓝药剂 = 100 × clamp((M - m) / M, 0, 1)
w防御 = 20 × D × (0.2 + t) × (0.3 + c)
P动作 = w动作 / 所有有效动作权重之和
```

伤害技能 q 基础取 1；纯治疗/持续治疗 q = 2 × (1-h) × (1+t+c)，满血为 0；防护技能 q = (0.3+t+c)，已有同组效果为 0；纯减益 q = 0.6+t，敌人已有同组效果为 0。兼具伤害或治疗与状态的技能取有效类别 q 的最大值，不相加；无效类别不贡献 q。谨慎对有效防护技能 q 乘 1.5，强攻对伤害技能 q 乘 1.3。

节约风格对耗法力伤害技能 q 额外乘 `clamp(0.35 + 0.65 × t, 0.35, 1) × (0.5 + 0.5 × m)`，不将该惩罚用于保命治疗。技能类型整体权重取最大 q，避免技能数量多就天然增加技能概率；抽中技能后，再按各技能 q 选择具体技能。

先过滤不可执行动作：无药剂则对应权重为 0；法力不足、冷却中、目标无效的技能不参与抽样；满血不纯治疗；满蓝或无耗蓝技能不使用回蓝药剂。未受威胁时使用上述低防护 q；复合技能仍可因伤害或治疗类别参与，但不重复叠加其无效状态类别。药剂类型抽中后优先选择满足当前缺口且浪费较少的携带药剂。

归一化后按累计权重区间随机选择。若所有动作均不可执行，记录为控制导致的行动跳过；普通攻击通常是无消耗兜底。每轮使用当前状态重算，不保存固定概率表。抽样和结果与回合事实一起提交，恢复不重抽。

例如剩余生命 50%、法力 80%、敌我同级，有药剂和伤害技能：均衡治疗概率约 17.7%，谨慎约 31.9%，强攻尚未到治疗血线，治疗概率为 0%。没有药剂时治疗权重归零，其余动作重新归一化。本示例不包含当前可用治疗或防护技能。

动作概率子模型见数值评估；谨慎与节约的真实成本、技能收益和 Boss 存活率必须在完整战斗引擎实现后模拟，不能仅由这张参数表判断平衡。

## 4. 区域与怪物

### 4.1 区域配置

区域需要配置等级区间、怪物池、装备池和材料池。

**设计建议：** 进一步配置推荐等级、进入条件、怪物出现权重、采集事件、危险程度、精英与 Boss 规则。需区分推荐等级与强制进入门槛。

### 4.2 怪物配置

怪物需要配置名称、等级范围、基础属性及成长、行为或技能、经验奖励、材料掉落和装备掉落。

**设计建议：** 每次遭遇生成实际怪物等级与属性。同一怪物模板可以用于不同区域，但不同区域可限制其生成等级。怪物行为同样由代码执行。

### 4.3 掉落规则

| 奖励 | 配置内容 |
| --- | --- |
| 材料 | 材料种类、掉落概率、数量区间 |
| 装备 | 装备模板、掉落概率、装备等级范围、品质权重 |
| 经验 | 怪物经验及等级差修正规则 |

**设计建议：** 掉落表明确区分「每项独立判定」与「一组内抽取一项」，避免概率含义混淆。奖励结算保存实际结果，而不是查看记录时重新随机。

首批区域、怪物与掉落方向见下节；装备模板、数值与概率见第 6 节及配置目录。

新芽草甸仅出现普通怪物，不设置精英或 Boss；其他有首领的区域保留原有首领遭遇机制。裂隙领主保留为精英，Boss 另设。Boss 属于持续探索中的概率遭遇，不是楼层终点或通关要求。精英提高高品质装备掉落权重，不保证每次掉落金装。

掉落建议绑定到具体怪物：每种怪物主要提供自身对应材料，装备通过对应等级的公共装备池抽取，避免所有怪物独立维护一套重复装备。普通怪与精英都可以配置白、蓝、金装概率，准确分布待平衡。

武器等级限制建议采用 `实际装备等级 ≤ 怪物实际等级`，并受区域装备池限制；怪物不足以掉落某个模板最低等级时，先排除该模板再抽样。所有部位均使用同一等级限制，Boss 专属吊坠另需满足其模板最低等级。

### 4.5 普通与精英遭遇及 Boss 概率

非 Boss 遭遇按区域怪物池权重抽取。初始建议每个区域两种普通怪权重 60、35，精英权重 5；实际等级使用第 16.5 节的角色等级 ±2 后按关联区间限制规则。不同区域可修改权重，不能把攻击回合误当成遭遇抽样。

| 地牢 | Boss 候选 | Boss 等级范围 | 战斗特色 |
| --- | --- | --- | --- |
| 苔石洞窟 | 苔冠巨兽 | 10～12 | 护体与重击 |
| 废弃矿坑 | 深矿巨像 | 22～25 | 高物防、破甲攻击 |
| 迷雾林地 | 迷雾树王 | 32～35 | 中毒与自疗 |
| 沉没遗迹 | 潮汐祭司 | 47～50 | 魔法输出与护盾 |
| 灰烬堡垒 | 灰烬领主 | 65～70 | 灼烧与冷却爆发 |
| 星蚀裂隙 | 星蚀主宰 | 95～99 | 物魔混合输出与减益 |

Boss 初始等级建议为 `clamp(角色等级 + 2, Boss等级下限, Boss等级上限)`。低等级角色去低级区域也可能遭遇显著更强的 Boss，出发信息必须展示这一风险。

设 n 为本次探索已击败的普通与精英怪数量，在下一次遭遇时先判断 Boss：

```text
n < 12：Boss 概率为 0
n ≥ 12：P(Boss) = min(0.25, 0.01 × (n - 11))
同一次探索已经遭遇 Boss：后续 Boss 概率为 0
```

例如击败 12、20、30、40 只后，下一次遭遇 Boss 概率分别为 1%、9%、19%、25%。抽不到 Boss 时仍正常抽普通或精英，下一次在更高 n 下再次判断，所以累计探索越久、击杀越多，遇到 Boss 的机会越大；角色倒地或时限到达仍可能从未遇到 Boss。

一次探索最多遭遇一次 Boss，击败后继续普通探索；开始新探索时 n 归零。Boss 数量限制与概率只是初稿，掉落额度跨探索累计，不能通过反复开启探索重置奖励额度。

### 4.6 怪物属性基线草案

以 M 为怪物实际等级，先计算普通怪参考属性：

```text
生命 = floor(40 + 18 × M + 0.5 × M²)
法力 = floor(20 + 8 × M)
主攻击 = floor(6 + 4 × M + 0.10 × M²)
物理与魔法防御基线 = floor(4 + 1.8 × M)
命中值 = 0.95；闪避值 = 0.04；暴击率 = 0.05；暴击倍率 = 1.50
```

模板明确普攻伤害类型。物攻型使用主攻击为物攻，魔攻可为 0；魔攻型反之；混合型分别配置，不能同时默认获得两份满额主攻击。

厚甲怪可生命乘 1.4、物防乘 1.8；敏捷怪可生命乘 0.8、主攻击乘 1.1、闪避值设为 0.15；法术怪可物防乘 0.7、魔防乘 1.3。配置中保存最终模板系数。

精英在模板基线上生命乘 2、攻击乘 1.15、防御乘 1.2；Boss 生命乘 6、攻击乘 1.25、防御乘 1.3，并配置特色技能。每个怪物一次行动仍只选一个动作，Boss 不额外多行动。

普通怪建议普攻与特色技能权重 80:20、精英 65:35、Boss 50:50，技能不可用时回到普攻；纯普攻怪不建无意义技能。怪物技能使用同一效果引擎，消耗、冷却与动作结果进入战报。上述数值还需实战模拟，尤其法师生存与 Boss 战斗时长。

### 6.6 战斗速度与掉落额度分离

回合变快不按击杀数线性增加物品产出。建议增加按实际已提交探索时间获得的掉落额度，进度以居民为单位跨探索累计：

- 每累计有效探索 5 分钟，获得一次物品掉落结算机会；未消耗机会最多保留 2 次。
- 装备判定按 `equipment_interval_seconds × (1 - 出发时职业缩短比例)` 累计，基础间隔为 5 分钟、最短 1 秒；未遇到可结算击杀时最多暂存 1 次。普通/精英装备判定未中时立即消耗本次机会，不保留重抽。
- 在击败怪物时，物品机会和装备判定分别处理；没有任何机会时只获得经验，不创建掉落。
- 普通或精英的装备判定以 20% 基础概率抽装备；未中时，仍按现有物品机会结算材料。职业掉落率加成按百分点叠加。装备命中且同时有物品机会时占用一次材料机会；没有物品机会时，命中可独立获得装备。
- 每次材料奖励 1～2 件；装备奖励一件，品质建议普通白/蓝/金权重 80/18/2，精英 60/35/5。
- Boss 击败时优先消耗两次已获得物品机会；不足两次则只用已有机会。若首个物品机会带有装备判定机会且存在等级适配装备池，则保底生成一件装备并消费该机会，最多一件；剩余物品机会结算材料。Boss 品质建议 30/55/15，不额外无条件增发装备。

机会只按同一居民已提交的有效探索时间产生，包含正常遭遇间隔，但不包含准备、暂停、故障停机或等待其他活动。连续重开、改时长、切换地牢、同步与重启均不重置累计时间和消耗事实。尚未触发掉落结算的机会按第 16.5 节跨日保留，超过携带上限的新增机会截断并记账；已执行但未中的装备判定不保留。不能把自然经过的离线墙钟时间直接当作机会。

因此长期平均每小时最多获得 12 次物品机会；装备判定数量取决于职业缩短比例与实际探索时间，且最多暂存 1 次。普通/精英的装备命中仍按 20% 基础概率，判定次数不是装备件数保证。边界窗口可能使用此前剩余机会，应按累计探索时长计算上限。物品机会消耗但怪物无适用奖励时记录空掉落，不补抽。

此方案使长探索和更高击杀效率增加经验及遇 Boss 的机会，但物品总量主要受时间控制。装备判定机会提供概率抽取，不保证每次机会都掉装备。节奏规则须在出发说明与结果报告中可见，不做暗中削减。

### 6.7 回收价与收益基准

建议材料回收价为 `round_money(1 + 0.04 × 材料等级)`，材料等级与模板绑定，不由拾取者等级决定。装备回收价基础为 `10 + 0.5 × 装备等级`，白/蓝/金系数为 1/1.6/2.4。每条词条用实际值在该装备等级区间中的位置归一化为 0～1，固定区间取 0，各词条均值为 Q，价值再乘 `1 + 0.10 × Q`，最终在掉落时按分四舍五入固化。

按 99 级极端上界，材料每件 4.96、金装最高每件 157.08；长期每小时两件最高金装加 24 件材料约 433.20。这是刻意宽松、忽略两类占用同一机会的产出价值上界，不是平均实际收入，仍需扣药剂成本。已有库存集中出售可以产生单次大额收入，不将它误判为即时探索超额产出。

探索不直接掉金币，击杀不写金钱收入；只有出售给商店或真实交易才写世界账本。背包装备价值不等于 Agent 现金。暂不增加日常 NPC 收购需求和动态价格系统，若测试仍出现收益过高，再调整透明的价格或额度。

## 7. 冒险等级与分支转职

### 7.1 已确定的阶段

| 阶段 | 等级要求 | 职业选择 |
| --- | ---: | --- |
| 新手 | 初始 | 无职业技能 |
| 一转 | 10 | 选择基础战斗职业 |
| 二转 | 30 | 从当前职业的分支中选择 |
| 三转 | 50 | 从当前二转职业继续选择进阶分支 |

达到对应等级，触发 Agent 判断想转职成哪个职业。经验结算在门槛等级暂停，超出门槛的经验保留；Agent 完成转职后才按新职业继续成长并恢复当前探索。选择失败时探索保持暂停，不能手动跳过转职。

### 7.2 转职树示例

│  ├─ 剑士 → 剑圣 / 狂战士
│  └─ 守卫 → 圣骑士 / 盾卫

   ├─ 祭司 → 神官 / 审判者
   └─ 自然使 → 德鲁伊 / 守望者

### 7.3 转职处理建议

向 Agent 提供可选分支、职业特色、当前装备和探索经历，保存选择及理由。决策失败可重试，未完成前保留原职业；已成功的阶段不重复选择。

达到门槛后在击败魔物的安全回合点暂停当前探索；Agent 选定分支并完成转职后才恢复，不能把转职延迟到下一次出发。

冒险等级上限已确定为 99，经验曲线草案见第 9 节。转职补给、不可洗职业及延迟转职规则见第 16.2、16.4 节。转职分支尽量兼容前置装备，避免转职后没有可用武器。

## 8. 技能自动成长

**已确定：** 不提供手动技能加点，到指定等级自动学习技能；新手无职业技能。

**设计建议：** 不建立可分配技能点。已学技能到指定等级自动升级，例如 10 级学习、20 级升二级、30 级升三级，具体节点由技能配置决定。此处数值仅为示例。

- 主动技能由战斗代码从可用技能中选择。
- 被动技能直接影响属性或规则。
- 转职后保留前置职业技能，并增加新职业技能。
- 技能配置包括所属职业、学习等级、升级节点、效果、消耗、冷却、目标和使用条件。
- 冷却按回合计数。伤害、治疗、增益、减益见第 8.6～8.8 节；召唤一期作为持续伤害效果，无独立宠物单位。

下面给出技能清单、升级、叠加和治疗规则草案，具体数值尚未定稿。前置技能默认保留，各技能参数见第 8.6～8.8 节。

### 8.5 技能与探索风格的配合

技能偏好仍需按用途筛选：缺血才选择纯治疗技能，未受威胁时降低防护技能适用权重，已有不可叠加增益不重复施放。强攻提高伤害技能权重，谨慎提高治疗、防护技能适用权重，节约更重视法力成本。

第 3.3 节体现技能动作总权重与用途修正，具体技能还需要按有效治疗量、防护需求、冷却和资源消耗计算适用度，不能仅靠 S 参数表达全部职业行为。

### 8.6 主动技能数值草案

以角色等级 L、技能等级 R 为输入。建议技能最多 3 级：学习等级为一级，学习等级 +10 时二级、+20 时三级，超过 99 的最后节点改为 99；当前候选最晚 80 级学习，因此不会出现同级重复升级节点。

倍率、固定量和效果百分比在下表给出的一级值上乘 `s = 1 + 0.10 × (R - 1)`，每级增加一级值的 10%，不是连乘。持续时间与冷却不随 R 改变。减伤、命中、暴击等仍受全局上限限制。

耗蓝列的 a+bL 是展示公式，CSV 分别保存 cost_base=a、cost_per_level=b，最终 `ceil((a + bL) × (1 + 0.15 × (R - 1)))`。不从 CSV 执行表达式。HP、MP 成长不会改变技能耗蓝事实，但等级和技能等级会影响消耗。

| 技能 | 一级效果 | 一级耗蓝 | 冷却轮数 | 持续轮数 |
| --- | --- | --- | ---: | ---: |
| 重斩 | 1.35 倍物攻 | 4+0.4L | 2 | 即时 |

### 8.8 回合与状态时序建议

以 15 秒的逻辑轮次为单位。角色先行动，然后怪物；每次行动前先结算作用于该实体的持续伤害与持续治疗，若倒地则跳过该行动并结束相应战斗。随后处理冷却可用性、抽样动作、资源消耗、命中、伤害和附加效果，持续效果完成最后一次 tick 后移除；普通增益、减益和护盾的到期统一在全局刻度开始时处理。

对自身的持续治疗从下一次自身行动前开始；对敌人的持续伤害从下一次敌方行动前开始，可能在施加的同轮首次生效。持续 k 轮意味着在探索仍持续、目标存活且效果未被替换或清除时实际 tick k 次，而非随前端刷新次数减少。伤害先于治疗，持续伤害造成倒地后不再用同一阶段的持续治疗复活。

增益、减益和护盾从施加时立即有效，施加于全局刻度 r、持续 k 轮时，在 r+k 刻度开始前失效，覆盖 r 至 r+k-1；重启不延长。持续伤害/治疗另按剩余 tick 次数管理，不因普通增益到期而少 tick。

探索等待也推进 15 秒全局刻度：没有普通动作和怪物动作，但角色先结算自身持续伤害/治疗，再检查倒地；冷却和普通增益/护盾到期照常推进。怪物已经死亡，其状态清除，不产生等待期怪物 tick。没有探索外自然回血/回蓝。角色在等待期因残留毒伤倒地同样保存失败和已有奖励。例：第 5 刻度施放恢复祷言，第 6 刻度先恢复第 1 次再击杀，等待的第 7/8 刻度恢复第 2/3 次；第 8 刻度生成新遭遇，第 9 刻度开始下一战。使用冷却为 k 的技能后，最早在自身第 r+k 轮再次使用；例如 r=5 使用冷却 3，最早 r=8 可用。探索中冷却跨怪保留，短暂遭遇等待按逻辑时间推进冷却，不能遇新怪就重置。

毒刃的中毒为物理持续伤害，怪物毒孢为魔法持续伤害；伤害类型以效果行 damage_type 为准，不能按「中毒」名称推断。同类同目标效果不叠加，采用更强效果并保留较晚到期时间；不同毒伤来源若都属于中毒也只保留更强的一份，不能无限堆状态。护盾重施取当前剩余与新护盾中的较大值，不相加。同类减伤仍受全局上限限制。怪物死亡即清除其状态，角色增益按实际剩余轮次跨怪保留。

生产纯引擎及边界测试已经落地；逐项覆盖与完整引擎数值评估见一期实施与验收记录。

### 9.4 基础属性换算为战斗属性

以下 STR、DEX、INT、VIT、SPR、LUK 是角色永久基础属性与装备基础属性词条之和，再应用六维被动后的有效值；直接战斗属性加成另加，避免同一条词条重复计算。floor 向下取整。固定生命底值 44、固定法力底值 12 用于保持原初稿的 1 级上限，不再使用统一的每级生命、法力系数。

```text
生命上限 = floor(44 + 累计固定 HP 成长 + 12 × VIT + 直接生命加成)
法力上限 = floor(12 + 累计固定 MP 成长 + 6 × INT + 4 × SPR + 直接法力加成)
物理攻击 = floor(3 + 2 × STR + 0.4 × DEX + 武器物理攻击 + 其他直接物攻加成)
魔法攻击 = floor(3 + 2 × INT + 0.4 × SPR + 武器魔法攻击 + 其他直接魔攻加成)
物理防御 = floor(0.8 × VIT + 0.25 × STR + 装备与其他直接物防加成)
魔法防御 = floor(0.8 × SPR + 0.25 × INT + 装备与其他直接魔防加成)
治疗强度 = floor(2 × SPR + 0.5 × INT + 直接治疗强度加成)
```

在无装备与被动影响时，战士每级生命实际增加 `16 + 12 × 4 = 64`，法力增加 `2 + 6 × 1 + 4 × 1 = 12`；法师每级生命增加 `6 + 12 × 1 = 18`，法力增加 `14 + 6 × 4 + 4 × 4 = 54`。法师的 HP 持续增长，只是明显低于战士，MP 成长则明显更高。

独立职业成长与属性贡献是两个有意保留的来源，不是重复录入同一次成长。生命与法力上限从永久成长事实和当前装备重新计算，不把最终上限另一次累加后再套属性公式。

六维被动已在输入阶段计算；派生后再应用直接战斗属性被动与临时状态。百分比加成同类先相加，再乘一次，不按词条数量连乘；六维及攻击、防御的同类百分比合计限定在 -90%～+200%，使最终倍率在 0.1～3；命中、闪避、暴击、减伤使用各自公式上限。审判者等转换被动在明确阶段额外计算，转换使用未转换的输入，不能递归互相转化。

这些系数必须与怪物属性、装备成长一起平衡，不单独视为最终数值。怪物直接按怪物成长配置得到战斗属性，不强制按玩家职业六维公式生成。

### 9.5 命中与闪避

命中与闪避合并为一次命中判定，避免先命中再闪避两次抽样导致实际命中率被重复降低。角色与怪物使用相同判定规则。

```text
攻击者命中值 = clamp(0.95 + 0.10 × DEX攻 / (DEX攻 + 80) + 命中加成, 0, 1.10)
防守者闪避值 = clamp(0.03 + 0.25 × DEX守 / (DEX守 + 120) + 闪避加成, 0, 0.35)
等级修正 = -0.02 × max(0, L守 - L攻) + 0.005 × max(0, L攻 - L守)
最终命中率 = clamp(命中值 - 闪避值 + 技能命中加成 + 等级修正, 0.20, 0.98)
```

怪物无需有敏捷属性，可在成长配置里直接给出命中值、闪避值，再套最终公式。等级修正只作用于命中判定，不重复乘到伤害公式上。

伤害型普通攻击和技能默认都需要命中判定；魔法攻击也不天然必中。自疗、自身增益无需命中判定。特定技能若设计为必中，必须在技能配置中显式标记。未命中仍消耗本次行动、法力并进入冷却，不返还资源。

此处命中值与闪避值都是算法输入，前端不把角色静态命中值直接显示为「对任何怪物的命中概率」。对当前敌人的最终概率才包含对方闪避和等级差。

### 9.6 普攻、技能与防御伤害

普通攻击由武器指定伤害类型：物理武器使用物理攻击，法杖等魔法武器使用魔法攻击。无武器时暂按物理普通攻击。

```text
原始伤害 = 对应攻击属性 × 技能倍率 + 技能固定伤害
普通攻击：技能倍率 = 1，固定伤害 = 0
有效防御 = max(0, 对应防御 × (1 - 穿透比例) - 固定穿透)
防御尺度 K = 60 + 6 × 攻击者等级
防御减伤率 = clamp(有效防御 / (有效防御 + K), 0, 0.75)
状态减伤率 = clamp(防御动作减伤 + 技能减伤 + 其他同类减伤, 0, 0.60)
伤害浮动 = 在 [0.95, 1.05] 中随机取值
暴击倍率 = 暴击时使用暴击伤害倍率，否则为 1
最终伤害 = max(1, floor(原始伤害 × 额外增伤倍率 × (1 - 防御减伤率)
                      × (1 - 状态减伤率) × 伤害浮动 × 暴击倍率))
```

额外增伤倍率为 (1 + 技能缺血增伤) × (1 + 同类适用被动增伤之和) × (1 + 目标易伤)，全程纳入最终取整之前。狂怒击的技能缺血增伤 = 配置 value × (1-h)，猎杀标记进入目标易伤；对应持续伤害被动在施加时固化到持续伤害倍率，不逐 tick 重复叠加。同类增伤合计上限 200%，目标易伤上限 100%。无这些效果时额外增伤倍率为 1。

物理伤害使用物理防御，魔法伤害使用魔法防御。防御上限与状态减伤上限分别限制，再乘算；两项达到上限时总减伤为 90%，不是把 75% 与 60% 相加。穿透比例暂限制为 0～60%。

2026-10-18：combat-1.0.19 在上述通道伤害完成后再乘属性修正 `clamp(1 + 属性强化 − 属性抗性, 0.60, 1.50)`。属性只有水、火、土、风、光、暗，不用相克表；毒伤仍只走原来的防御，不进属性修正。角色抗性默认 0。通道伤害 100、修正 1.30 时，最终伤害是 130。

上述最小伤害 1 只适用于已命中、原始伤害大于 0 的有效伤害段；未命中或没有伤害效果时为 0，不能因套公式生成伤害。

结算系数采用定点数或精确分数，组合乘算后只在最终伤害处向下取整。未达到防御上限时直接使用精确的 `K / (有效防御 + K)` 减伤乘数，避免循环小数截断导致示例中的 100 被错误取整为 99；最终保存整数伤害。

防御动作本身不造成伤害，建议使下次受到的敌方伤害行动额外减伤 35%，结算后消失；多段攻击视为同一次敌方行动，所有段都受该防御效果。若敌人没有伤害行动，效果最多保留至角色下次行动开始，不能无限累积。防御与技能减伤按状态减伤上限合并。

护盾在减伤后吸收伤害，剩余才扣生命。物魔混合技能先分别计算两部分对应防御，再合并扣护盾与生命，不额外重复一次完整伤害。多段技能配置每段倍率，合计倍率才是整体输出，不能把整体倍率重复应用到每段。

每个独立直接伤害段各判定命中与暴击；混合伤害的同一段共享一次判定。附加敌方状态跟随其对应伤害段命中，多段技能的状态最多施加一次，不额外抽命中。无直接伤害的敌方复合效果共用一次行动级命中判定，例如衰败咒的持续伤害和减防一起命中或一起失败。自身效果不依赖敌方是否命中：森林结界自身减伤与圣盾生成必定成立。圣盾被伤害完全耗尽时追加一次圣光十字裁决，该伤害按普通魔法伤害规则判定。未命中仍扣法力和进入冷却。持续伤害需首次施加成功，此后按状态持续规则结算，默认不再抽命中、不暴击、仍经过对应防御与当时减伤，来源属性和技能倍率在施加时固化。状态叠加与回合顺序见第 8.8 节。

示例：物理攻击 100，技能倍率 1.5，对方物防 60，攻击者 10 级，无穿透、暴击，浮动取 1。K=120，防御减伤为 1/3，伤害为 100；对方防御动作减伤 35% 时，最终伤害为 65。

### 9.7 暴击与治疗

```text
暴击率 = clamp(0.05 + 0.30 × LUK / (LUK + 150) + 暴击加成, 0, 0.60)
暴击伤害倍率 = clamp(1.50 + 暴击伤害加成, 1.50, 3.00)
技能治疗量 = floor(治疗强度 × 治疗倍率 + 固定治疗量)
实际治疗量 = min(技能治疗量, 生命上限 - 当前生命)
```

暴击在命中后判断。治疗默认不暴击、不经过敌方防御，也不受伤害浮动影响；药剂按自身固定量或比例恢复，不受精神影响。疗效、减疗和护盾强度均需要明确效果配置，不能自动套伤害暴击规则。

一期运气只进入上述暴击率公式，不参与掉落与经验计算。

### 9.8 怪物经验与等级差

只有击败怪物才获得击杀经验，未完成战斗、采集和防御不会按回合发经验。经验与击杀事实一起结算，同一怪物只结算一次。

```text
普通怪基础经验 B(M) = floor(10 + 3 × M + 0.3 × M²)
精英经验系数 = 2.0；Boss = 3.0；普通怪 = 1.0
Δ = 怪物等级 M - 角色等级 L
```

| 等级差 | 经验系数 f(Δ) |
| --- | --- |
| -3～+3 | 1.0 |
| -4～-9 | 1 - 0.1 × (-Δ - 3)，即 0.9～0.4 |
| -10～-19 | 0.1 |
| ≤ -20 | 0.02 |
| ≥ +4 | 1 + min(0.2, 0.04 × (Δ - 3))，最高 1.2 |

```text
经验计算基数 = min(B(M), floor(1.25 × B(L)))
击杀经验 = max(1, floor(经验计算基数 × 怪物类型系数 × f(Δ)))
```

等级差与越级基数上限共同避免高等级怪物一次带来过多经验；精英有奖励，但其血量、输出与耗时也要增加。等级差取击杀结算前角色等级，不使用升级后的等级反算奖励。此规则适用于当前单人探索，未来组队需要另行设计经验分配。

材料价值、装备品质和运气均不提高经验。击杀数更多可以获得更多经验，但普通攻击次数和技能使用次数不额外发经验。

### 9.9 1～99 级升级经验

等级最高 99。回合缩短后，原先每小时 15 只的经验曲线不能继续原样使用，否则升级明显变快。本轮以每小时约 40 只同级普通怪为基准提高升级需求，保留较慢的成长节奏。

```text
E(L) = ceil(200 + 20 × L² + 1.6 × L³)，1 ≤ L ≤ 98
E(L) 表示从 L 升至 L+1 所需经验，不是累计经验
99 级没有下一等级
```

经验与击杀一起结算，够升级则扣 E(L)、逐级保存属性和 HP、MP 成长、技能解锁与转职待办，剩余经验保留。达到 99 级后不继续积攒升级经验；累计获得经验可以做历史统计，不用作未来开放等级的预存额度。

### 9.10 新节奏估算与平衡验收

以每小时 40 只同级普通怪、无精英与 Boss、无死亡和时间损失为基准，估算累计小时 `Σ[E(L) / B(L)] / 40`，不是完整战斗模拟。

| 从 1 级达到 | 每小时 40 只的累计探索时长 | 每小时 30～60 只的范围 | 每天有效探索 2 小时的基准天数 |
| --- | ---: | ---: | ---: |
| 10 级 | 约 7 小时 | 约 5～9 小时 | 约 4 天 |
| 30 级 | 约 61 小时 | 约 40～81 小时 | 约 30 天 |
| 70 级 | 约 333 小时 | 约 222～444 小时 | 约 166 天 |
| 99 级 | 约 665 小时 | 约 443～887 小时 | 约 333 天 |

每日 2 小时是日程预算建议，尚未实现，不可将表中日历天数当作保证。较高品质装备和不同职业可能显著提高击杀效率，Boss 经验也会改变结果；最终必须结合第 4.6 节怪物、第 6 节装备、第 8 节技能和第 10 节药剂做完整模拟。

验收同时检查每小时经验、倒地率、药剂消耗、Boss 遭遇率、实际材料数量、装备数量与商店净收入，不能只控制经验而忽略产出。经验曲线与物品额度分别调节，不增加未公开的经验扣除。

### 12.2 启动时如何对齐

当前项目的旅行目录已有 CSV 初始化能力，入口为 `system_settings/agent_world/travel_startup.py` 与 `travel_seed.py`，在迁移后或服务启动后执行，按文件哈希去重，并且只补缺失城市、不覆盖已存在数据。

战斗目录需要比「只补缺失」更明确的版本更新机制，建议流程为：

1. 全量读取配置包与版本清单，解析所有 CSV。
2. 在写数据库前校验全部字段、稳定 ID、外键、等级范围、概率、掉落模式、职业树、技能与效果码。
3. 比较当前已安装目录版本与内容哈希，无变化则直接跳过。
4. 持有跨进程导入锁，在同一事务中安装完整的新目录版本，并提交版本标记。失败则全部回滚，继续保留原可用版本。
5. 只在完整安装成功后切换新探索使用的目录版本；图鉴展示新的有效配置。

启动对齐放在数据库迁移完成后的服务初始化阶段，不在 `AppConfig.ready()` 中直接读写业务表。测试和其他普通管理命令不自动导入；迁移后初始化与显式安装命令可作为专门入口，用于只校验、预览差异和手动安装。

跨进程锁负责避免多个 Worker 或开发重载重复安装，进程内锁不能替代它。目录不可用或安装失败时，阻止新探索使用不完整内容，其他模块可继续运行并给出明确日志。

### 12.3 更新与删除边界

- CSV 维护内置配置，不覆盖角色成长、物品库存、穿戴关系、转职记录与探索奖励。
- 每次发布新的内容版本，按稳定 ID 安装新模板定义。改名不产生新身份。
- 从 CSV 移除一行不自动物理删除旧定义；停用通过显式 enabled 字段表达，并保留历史版本与引用。
- 已出发探索保存整次使用的配置版本，包括相关怪物、技能、成长、装备与掉落规则；升级目录后，进行中的探索继续使用原版本。
- 探索中的升级与自动学技能使用该探索关联的内容版本，不能混用新旧规则。达到转职门槛时在击败当前魔物后的安全回合点暂停；Agent 使用该探索关联的有效目录选择直接分支，转职事实和绑定补发装备均记录同一目录版本，成功后更新当前探索中的职业、装备与战斗属性并自动续跑。
- 已掉落装备、已有价值和已结算经验不因 CSV 更新重算。
- 若后续允许用户在界面改配置，采用独立覆盖层并参与同步；CSV 更新只改内置底稿，不用启动覆盖用户设置。内置参数与用户覆盖的有效值需在出发时固化。

### 12.4 与 WebDAV 的关系

CSV 文件是随应用发布的内容来源；安装到数据库的目录版本、定义和用户覆盖是持久业务配置，按已确认边界参与同步。导入锁和本机安装缓存不参与同步。

配置包需要明确的版本、发布时间、文件哈希和引擎兼容版本，不能用本机启动时间当作更高优先级的业务修订。内容版本不可变，同版本不同哈希应拒绝安装；已同步来的更高版本不能被本机旧 CSV 自动降级。

恢复后可以保留多个历史内容版本，当前引擎不认识的效果码不能默默执行或替换。参与探索的设备需更新到兼容版本；旧设备可以提示升级并停止推进该探索。同步合并与恢复必须按第 17～18 节的完整事实、身份和版本校验契约实现。

### 12.5 效果由代码执行

CSV 配置效果码与参数，例如物理伤害、魔法伤害、自疗、护盾、持续伤害、属性增益、属性减益。后端用固定注册表解释效果码，禁止从 CSV 执行 Python、JavaScript 或任意计算表达式。

新增已有机制下的怪物、技能、装备只需新增配置；新增一种战斗机制仍需要代码支持与对应校验。单纯维护 CSV 无法自动生成新的游戏机制。

## 13. 世界体力与统一生活日程

**已确定：** 探索消耗世界体力，是统一生活日程中的活动选项，不另建一套冒险体力。

当前世界体力实现上限为 100，每小时恢复 5，以成功消费事实重放余额。探索需沿用该机制，失败的探索也应保留已经发生的成功体力消费，不能因探索终态 failed 就把体力扣款隐藏。

### 13.1 体力消耗草案

建议入场扣 10 体力，每开始一个 5 分钟有效探索块再扣 2 体力。按完整时长，30 分钟、1 小时、2 小时分别消耗 22、34、58；5 分钟块按实际开始时扣一次，中途失败不退已开始块费用，未开始块不扣。

出发要求当前体力足以覆盖计划总成本，并保存体力预留承诺；真正扣费随探索推进。当前体力系统没有独立预留余额，实施时需设计活动承诺与可用余额校验，不能只写一张计划就宣称体力已经被扣除。

规划、手动活动和探索续跑均需尊重预留，推进前不足则记录「体力不足结束」，不创造负体力。角色忙碌可避免并发消费，但跨设备仍需一致性校验。自然恢复继续按现有世界规则计算，不新增探索中自动恢复 HP、MP。

### 13.2 日程选择与占用

建议默认每天有效探索预算 120 分钟，允许配置。总预算以居民、自然日和已发生探索时间计，不因切换地牢或失败重开重置；跨日按实际时间分别归属。

生活规划读取战斗等级、职业、装备、生命法力、携带药剂、可用体力、当前现金、目标、后续安排与近期失败事实，决定是否探索、地点、30/60/120 分钟时长和补给预算。没有装备或药剂时可先采购，采购不能突破现有生活预算和其他已预留承诺。

探索必须在后续安排前结束；空间不足时改短时长或选择其他活动。出发前准备由 Agent 处理，进入探索后不逐轮调用模型。正常探索期间角色状态为「探索中」，该角色不能同时执行旅行、农场、市场、投资等主动活动。

居民占用是业务状态，不长时间持有整个世界执行锁。模型准备与短事务各自申请已有执行许可，等待下一轮时释放全局执行位，其他居民仍能正常生活。

### 13.3 返回、恢复与停机

正常返回不免费恢复满血满蓝。建议非探索期间每 5 分钟恢复最大生命 5%、最大法力 10%，均以完整时间块计算；倒地后先休整 30 分钟，结束后生命恢复至 20%，再按普通恢复。休整期间不能再次探索，普通活动是否允许按各自条件判断。

世界体力按原有规则自然恢复，不因倒地额外扣金币或经验。已击杀奖励保留，未击败怪物不结算。恢复倍率、倒地休整时长使用上面的默认数值，不能通过出发再返回重置恢复计时。

已确定：停机、暂停期间不执行战斗、不增加有效时长、掉落额度、经验或消耗；同一后端恢复后自动检查接续。预计返回时间固定为实际出发时间加计划时长，暂停不延长结束点；恢复时已经到期则直接返回，仅保留已提交成果。尚未到期则按剩余墙钟时间核对日程、体力与每日额度，条件不满足时提前返回。返回会归还未用药剂、释放租约与生活安排占用，后续日程沿用生活调度规则继续；未扣的体力与预算释放，已消费物资和已结算奖励不回滚。

系统暂时异常可以先保留可恢复的中断状态；一旦决定终止则进入唯一终态。出发前校验失败也保存日程尝试原因，但不创建击杀或掉落。

## 14. Agent 冒险展示与操作

**已确定：** Agent 需要穿戴装备、属性、技能、战斗职业展示。建议在现有居民详情中增加「冒险」面板，避免把战斗职业塞进已有职业管理。

- 概览：冒险等级、经验条、当前战斗职业与转职路径，生命、法力、世界体力，当前探索或休整状态。
- 装备：六个槽位与当前穿戴物品，白/蓝/金标识；点击查看固定属性、词条、来源、回收价和职业限制，背包选择时提供更换前后属性对比。
- 属性：六维、HP/MP 上限、物魔攻击与防御、治疗强度、暴击等，区分永久成长、装备、被动与临时效果。对当前怪物展示最终命中率，不把静态命中值误当概率。
- 职业：当前职业、前置分支、下一次转职等级、待转职决策、选择理由与历史。
- 技能：已学技能等级、消耗、冷却、效果及下一升级节点；锁定技能显示学习条件，不提供加点按钮。
- 探索：地牢、风格、已用/剩余有效时间、当前怪物与 Boss、击杀数、Boss 遭遇概率、携带药剂与掉落额度；提供查看战报、主动召回。

穿戴展示一期先做装备槽与物品图标，不承诺自动将装备绘制到 Agent 全身立绘上；若需要视觉换装，另行确定素材层与渲染规则。手机端同样能查看、换装、打开技能和探索报告，遵循现有 Select、Modal 和隐藏内部滚动条规范。

### 14.1 探索观察窗口

**新增确定需求：** 探索是持续过程，用户需要随时打开简易窗口，观察当前正在做什么、战斗情况、已探索多久、击败哪些怪物以及获得哪些掉落。一期采用「探索观察」模态窗口，使用现有 Modal 视觉与交互规范。

居民冒险面板和每日活动中的进行中探索卡均提供「观察探索」入口，打开同一个 exploration_id 的窗口；已结束卡打开相同窗口的结果状态。入口卡简要显示地牢、当前阶段、已探索/计划时长与击杀数，具体战斗放在窗口内。关闭窗口不暂停探索，重新打开从后端读取最新状态，不依赖此前页面计时或缓存。

窗口从上到下包含以下四区，桌面适中宽度、移动端接近全屏；顶部身份、进度和底部操作固定，中部内容局部滚动且隐藏原生滚动条。

| 区域 | 展示内容 |
| --- | --- |

### 14.2 当前阶段与战斗动态

阶段文案由已提交业务状态派生，不让模型猜测。准备采购阶段显示在日程入口卡，成功创建探索后才进入本窗口的计时；准备耗时不计探索时长。

| 结算中 | 已停止探索，正在保存结果及返还物资；只展示已确认奖励 |
| 已结束 | 正常完成、倒地失败、主动召回、体力不足或系统中断结束，以及实际探索时长和固定结果 |

未遇 Boss 时展示「已击败普通/精英 N 只，下一次遭遇 Boss 概率 X%」；不足 12 只时提示还差几只达到概率起点。这里是下一次遭遇概率，不能标成整场成功率。无当前怪物时不提前展示尚未随机生成的名字或掉落。

战斗动态逐轮展示后端已确认结果，例如：

```text
12:15  遭遇 Lv.10 洞穴蝙蝠
12:30  第 1 轮：使用精准射击，造成 42 伤害；蝙蝠普攻，造成 11 伤害
12:45  第 2 轮：普通攻击未命中；蝙蝠使用闪身，获得闪避增益
13:00  第 3 轮：击败洞穴蝙蝠，获得 53 经验；获得蝠翼 ×1
13:00  寻找下一遭遇，预计 30 秒后继续
```

以上仅为展示文案样例，不用于验证技能数值。遇怪、每轮双方动作、持续伤害/治疗、用药、击杀、升级、掉落、暂停和结束均可查询。没有掉落时明确显示「本次击杀无掉落机会」或真实的空奖励原因，不能把未发生的奖励画进背包。命中、暴击、防御、护盾吸收和状态变化用短标签呈现，详细数值可展开，不堆满默认视图。

一期角色与怪物行动在一个回合事务中结算，因此窗口展示「最近一轮角色做了什么、怪物做了什么」和当前等待状态，不假装后端正在逐秒挥刀。轻量血条或结果动画只复现已确认变化，不改变轮次、伤害、时间或奖励。

### 14.3 掉落、击败记录与观察操作

「掉落」页材料按 SKU 合并数量、记录最近获得时间；装备逐实例显示图标、名称、等级、白/蓝/金品质和词条，点击打开物品详情。掉落统计只计本次探索所得，和出发前背包库存区分；回收参考价值标明为估值。进行中可查看，出售和换装仍按非探索状态与原有占用规则校验。

「击败记录」页按怪物模板合并普通/精英击杀次数，可展开实际等级、遭遇与击杀时间和经验；Boss 单列展示遇到、击败或尚未击败。累计击杀不包含当前未击败敌人，Boss 遭遇也不冒充 Boss 击杀。点击某次战斗可按 encounter_id 查看对应轮次。

打开窗口默认显示最近 50 条动态，向上加载更早记录。只有用户位于列表底部时自动跟随；阅读历史时保留位置，显示「有新动态」按钮，点击后回到底部。切换页签、切换居民或重新打开时，不拼接另一场探索的旧记录。折叠或隐藏窗口后不产生新用户事件。

窗口操作为「关闭」「查看完整战报」和探索进行中可用的「提前召回」。召回提交后显示处理中，成功读取终态才展示召回结果；与回合提交争用事务时，以后端成立事实为准，不在点击瞬间乐观撤销敌人、掉落或时间。默认不提供用户逐回合攻击、技能、换装或改风格按钮。观察窗口未新增暂停游戏能力，系统暂停状态沿用后端真实状态。

### 14.4 实时更新、数据契约与异常展示

一期使用轮询：窗口可见时每 2 秒读取一次轻量进度快照，版本不变时不重新请求战报；版本前进时按游标拉取新增动态。请求不并发堆积，页面不可见或窗口关闭即停止轮询，恢复可见时立即刷新。请求失败按 5/10/30 秒退避，正常成功后回到 2 秒；进入终态后取得固定结果与末尾动态即停止自动轮询。该频率仅影响观察延迟，不改变后端 15 秒战斗刻度。

快照必须来自同一已提交版本，至少包含 exploration_id、revision、as_of、status、phase、elapsed_active_seconds、duration_seconds、next_tick_at、当前遭遇及双方状态、击杀分类统计、经验/升级、掉落摘要、药剂剩余、体力已耗、奖励额度、Boss 判断状态、最新战报游标及终态原因。显示字段用现有 API 驼峰渲染，内部领域仍用 snake_case；next_tick_at 只是后端预计时间，不是执行保证。

详情接口按 exploration_id 与 encounter_id 分页，战报有稳定事件 ID、递增序号、有效探索时间偏移和真实提交时间，前端按 ID 去重。各区不能混用不同版本的累计统计；快照读取在短只读事务中保持一致。战报分页不越过本次快照确认的最新游标，新版本到达后再追加。

前端可显示距下一刻度的预计倒计时，但已探索时长、血量、击杀、经验和掉落以已提交快照为准，不通过本地秒表发奖或模拟伤害。快照长期无进展时展示最近确认时间，不仅因下一轮预计时间已过就宣称倒地或暂停；后端明确状态与客户端连接异常分开呈现。

网络断开显示「连接中断，当前展示截至某时刻」，保留最后快照并停止可信倒计时，不把网络故障写成探索失败。重连读取最新快照，按游标补齐动态；游标失效则重新获取当前摘要与最近记录。账号权限失效时关闭受保护内容，不继续展示另一账号的缓存。进入召回或终态不删除已有战报，刷新页面后仍能恢复同一场探索记录。

窗口本身的打开状态、页签、滚动位置、轮询计时和动画仅本机，不参与 WebDAV；窗口读取的探索、回合、击杀、消耗、掉落和结算仍属于此前已确认同步的业务事实。观察多个前端不增加执行者，也不发起第二套战斗调度。

## 15. 探索事件、战报与 Agent 回顾

**已确定：** 每次探索无论正常结束还是中途失败，都记录事件，供 Agent 回顾。此处事件是持久事实，不要求模型生成朋友圈帖子。

### 15.1 持久结果

每次探索有唯一稳定 ID，保存居民身份快照、归属、关联日程、出发理由、地牢、风格、计划时长、实际有效时长、规则版本、装备与携带物资快照。

过程保存已提交回合和关键变化：怪物生成、Boss 判断与遭遇、行动、伤害、治疗、药剂消耗、击杀、经验、升级与掉落额度消耗。最终结果包括：

- 终态与原因：正常完成、倒地失败、用户召回、体力不足、系统中断等分别表达，不混用「成功」。
- 击杀数量、精英与 Boss 结果、获得经验、升级和转职待办。
- 固定掉落清单、装备实例、材料数量、实际携带/消耗/返还药剂、体力成本。
- 终局生命法力、实际采购支出、掉落回收参考价值。掉落价值不写为现金收入。
- 最后完成阶段和真实异常摘要。不可恢复的信息不补造，Agent 删除后保留身份快照。

单次失败也保留前面已获奖励；失败没有掉落仍保存失败事件。探索返回、物资返还、释放预留和终态提交幂等，不能多创建一条结束事件。

### 15.2 每日活动与详细战报

复用每日活动时间线的只读投影方式：每次探索一张聚合卡，执行中显示状态，终态显示结果，点击打开详细战报；不把每个 15 秒回合单独刷进活动列表。跨日执行参考现有旅行聚合原则，按最新业务进展展示，结束后固定在终态日期，不复制同一探索。

逐笔商店出售继续进入世界账本和收支视图，探索报告只关联真实出售，不把尚未出售装备价值算成收益。探索事件与回合数据参与 WebDAV 同步，展示卡与聚合统计是派生结果，不另保存一份可能漂移的事件副本。

### 15.3 Agent 回顾输入

生活规划与出发准备读取近期探索摘要及必要的记录引用，例如「在灰烬堡垒因补给不足倒地，实际消耗 4 瓶药剂，保留 3 件材料」。Agent 可以据此选择更低等级地牢、调整药剂或更换装备，不在回顾时伪造未发生的经历。

是否自动写入长期记忆沿用现有记忆维护入口，避免战斗引擎直接把每轮日志写成长记忆。默认提供结构化摘要，按需要查询详细记录；不自动发布社交内容。终态事件必须先落库，模型总结失败不影响奖励或失败事实。

### 15.4 长期战报、存储与同步体积

15 秒一轮会产生长期累积数据。按每天 2 小时的上限，一个居民一年最多约 17.5 万个逻辑刻度；等待刻度不一定产生完整战斗行，但不能假设战报永远很小。

一期不按天数自动删除业务记录。探索摘要、成长、物资、击杀、奖励、出售与幂等操作事实永久保留；已结束探索的详细战报可转为不可变压缩归档，必须保留完整原始记录、稳定事件 ID、序号范围、结构版本和内容哈希。归档不得重新随机或重算，只改变存储表示。

归档和索引同样属于同步业务数据。实施时扩展现有快照协议，使恢复结果同时包括热记录与已校验归档；旧恢复器不支持归档版本时明确拒绝该版本，不能忽略文件后声称同步完整。归档转换先生成并验证，再原子切换索引；重复转换不创建两份业务记录，失败保留原热记录。

观察窗口只取当前快照与最近记录；一期旧战报永久保留热记录并分页读取；未来归档也不整包解压到浏览器，不把全部战报送给模型。同步体积按居民数和使用量测试，不能把压缩等同于零增长。压缩归档是实施时的存储优化；在快照与恢复协议支持前保留热记录，禁止先删后补同步。

## 16. 一期剩余规则的默认选择

本节补齐此前未展开的规则，属于设计默认值，不代表用户曾逐项确认。

### 16.1 内容目录与 Boss 奖励

采用第 7～8 节完整职业树，共 29 个职业含新手、74 个玩家技能。每个怪物和 Boss 的技能组合、动作权重、触发条件在 monster_actions.csv 中逐项列出；10 个怪物技能的倍率、耗蓝、冷却和状态效果同样进入技能等级及效果表，不通过名称猜测。

材料采用 24 个稳定 SKU：18 个普通/精英材料加 6 个 Boss 印记，每项有明确等级、回收价及来源怪物。每个怪物材料池目前只包含对应材料，数量 1～2，选择材料奖励后必定命中该项；扩展多材料时再按表内权重抽样。

普通与精英装备池覆盖武器、副手、头、身、手、脚、吊坠和戒指，不按击杀者职业限制掉落；装备穿戴权限仍由职业、精通和等级规则决定。角色不能穿戴的物品仍可保留、出售或后续交易。装备等级在区域下限至 min(怪物实际等级,区域上限) 中抽取；低于模板最低等级的装备不参与。材料等级固定，不能按拾取者等级抬价。

每个 Boss 有一个专属吊坠模板。Boss 获得装备奖励且有装备判定机会时，以 50% 选择对应专属吊坠、50% 使用区域通用池；专属仅限制掉落来源，不增加装备判定机会，价格继续用同一公式。没有装备判定机会时获得对应材料，不保证每次击败 Boss 都有装备，出发说明明确展示该规则。

Boss 的两次物品机会按「首次优先装备，后续材料」处理，不重复抽两件装备；不足机会时按实际可用次数结算。Boss 印记不兑换额外金币或免费装备，一期仅保留与回收。

### 16.2 装备权限与返回后处理

一转战士可用长剑、战斧，游侠可用长弓、匕首，法师可用单手法杖；祭司路线在学会圣杖精通后可用单手圣杖。精通装备只按已学精通判定，不附加职业白名单：元素师路线在 30 级学会双手杖精通后可使用双手杖；剑士在 30 级学会双手剑精通后，达到装备等级即可使用，剑圣继承；狂战士在 50 级学会双手剑精通后也可使用。二转弓手及其后继只用长弓，刺客及其后继只用匕首。通用训练木剑、头饰、吊坠与戒指全职业可用；类型防具、盾、圣杖、双手杖和双手剑须满足对应精通。双手武器占用副手，不能同时装备副手物品。穿戴要求为角色等级不低于装备等级。

新手可用一般物理武器及全职业通用的训练木剑。完成一转时若旧武器不兼容，给予一次对应基础白武器：固定 10 级、一个固定主属性 +1 词条、绑定、回收价 0。它是可重复请求但只提交一次的转职事实，不占随机掉落额度、不参与市场出售。二转沿同根已有武器切换，若从一转游侠转为另一种武器分支且没有兼容武器，补发一次对应 30 级绑定白武器。

返回后只完成奖励、物资返还和事件结算，不额外强制调用模型。换装由下一次出发准备中的 Agent 决策完成，服务端给出符合条件装备与换装后属性预览；用户也可在非探索状态手动换装。

默认不自动卖装备或材料。下一次市场活动由 Agent 决定出售，用户可以手动批量出售；穿戴中、探索占用、绑定或收藏锁定的物品不能出售。收藏锁定是同步业务字段；材料按 SKU 设置最低保留量，默认 0，但不代表自动出售。出售接口按实际库存与实例归属复核，不接受客户端自行填写价格。

穿戴更新为原子替换，旧装备回背包；装备总量不限，筛选支持部位、等级、品质、可穿戴与锁定。背包满仓惩罚、耐久和强化不在一期范围内。

### 16.3 药剂、日程与决策契约

基础药剂放在市场的常驻补给区，不占整点随机商品格，不依赖其他居民共享库存，按固定价格供应；单次采购最多 20 瓶，按真实未预留余额、角色归属和购买事实校验。装备、材料商店回收同样作为常驻能力，不依赖随机商品位。

采购与携带是两个步骤，超过携带上限的库存留在背包。一次探索出发计划固定包含 dungeon_id、duration_minutes、style_id、equipment_instance_ids、potion_quantities、可选采购和 reason，时长只允许 30/60/120。探索不预留生活预算；药剂采购按未被其他安排预留的真实余额校验，余额不足时减少或放弃采购，并按已有库存出发。服务端检查等级、物资、体力、时间窗口与权限。

| 4b | 蓝药数量 | 同上，并加入红药已选数量 | 0～`20 − 红药数量` 瓶 | 转成蓝药携带量与必要采购量 |
| 5 | 背包装备处理 | 性格、职业、等级和当前装备信息；不传地点、时长、风格或药剂 | 见下方装备规则 | 逐件穿戴或记录出售/挂牌意图 |

地点、时长、风格和药剂决策结果逐步累加到本次探索计划。背包装备按当前显示顺序逐件检查；只跳过等级高于角色的装备，不按职业过滤。等级符合但职业或精通不符的装备仍交模型判断出售/挂牌。可穿且槽位空置时直接穿戴；可穿且槽位已有装备时，将该槽位旧装备和候选装备一起交模型判断更换、出售或上架。选择更换后穿上候选装备，再单独判断被换下装备出售或上架。不可穿的装备只提供出售、上架选项。出售/挂牌判断写入同步的战斗事实，后续准备跳过已处理的背包装备；高等级跳过项不标记，以便角色升级后再判断。

选择出售或上架只记录意图，不在出发准备时执行市场写入。下次进入居民集市时，出售意图自动按装备商店回收价成交；上架意图再询问一次定价，提供商店回收价的 10%、20%、30%、40%、50% 五个选项，并创建现有居民集市挂牌。挂牌装备可由其他居民购买、改价或撤回；成交后装备归买家冒险档案。没有启用结构化决策模型时，挂牌价格由现有文本模型决定。装备挂牌和转移沿用市场交易事实及战斗装备事实链，并随 WebDAV 同步。

决策模型不可用时，不得因此阻止探索出发：地点、时长、风格和药剂使用代码定义的安全候选回退；装备问题本轮跳过且不标记，供后续准备重试。挂牌价格问题暂缓该件挂牌，不阻止其他市场操作。

用户测试记录：用 20 个药剂数量候选项调用 `startlux-decision`，响应选中“2瓶”，置信度约 `0.297556`，并返回候选概率分布；usage 报告 prompt 384、completion 0、total 384 tokens。共享有限选择入口最多接受 255 个候选项。

实现备注：装备出售/上架意图写入现有同步战斗事实；居民集市挂牌复用 `MarketListing`、`MarketTransaction` 和 `EquipmentInstance`，没有增加数据库列。新增装备所有权转移事实后，战斗同步元数据版本升至 6，旧版本客户端会拒绝写入新版本快照。

无效计划不消耗体力，允许最多两次纠正；仍无效记录日程失败。资料过期时重新读取真实资源，不用旧库存继续出发。休息也是有效生活选择，不能强制每个居民每天探索。

一天探索上限默认 120 有效分钟，计入手动与自动探索；已安排未出发也占日程承诺，取消后释放。每个 5 分钟块先复核预留并扣 2 体力，再推进该块，不因失败返还。探索不因生活预算不足而失败；药剂预算不足只影响可购买和携带的数量。

### 16.4 初始成长、转职与图鉴

现有 Agent 在首次启用冒险时幂等建立归属明确的 1 级新手档案，不按历史工作或发帖补经验。新建 Agent 同样从 1 级开始。初始化六维、HP/MP 和训练木剑采用稳定操作 ID；训练木剑引用 equip.training_sword 模板，固定为 1 级物攻 10、力量 +1、白色绑定实例，名称快照为训练木剑；同一模板也参与普通掉落。归属不明确时拒绝创建，不按名字合并居民。旧目录中的绑定新手木剑保留原模板快照，不改写实例。

当前无洗职业、跨树转职与降级。每个门槛在击败当前魔物后的安全回合点触发 Agent 决策；转职成功后永久保存，后续重试不重选。探索在决策期间暂停，成功后按新职业更新技能、属性与装备并自动续跑；调用失败或选项无效时保持暂停，用户可请求 Agent 重试，但不能手动跳过。经验只结算到门槛等级，剩余经验保留，后续升级使用新职业成长。完成转职时自动学习该路径中角色当前等级已满足的技能及最高合格等级，逐项幂等记录；不学习其他分支技能。历史档案连续错过多个门槛时按一转→二转→三转依次决策，不能直接跳到三转。

运气一期只影响暴击，不影响掉落。图鉴一期全部公开展示规则，个人另有「已遭遇」「已击败」「已获得」标记，从探索事实与物品事实派生，不做额外奖励解锁。

怪物与 Boss 先使用目录图标、品质色和可替换图片；装备使用物品图鉴图片入口。图片缺失显示固定部位或怪物占位图，不自动调用生图。私有资源沿用所属账号与资产权限。立绘视觉换装不在一期，穿戴采用九槽展示。

### 16.5 掉落累计、时间与恢复边界

物品机会和装备判定机会的累计时间跨探索、跨日保留，不在午夜清零，未使用上限仍为 2 次物品机会和 1 次装备判定机会。机会通过累计时间应得总次数减已消耗/已截断次数计算，不能用页面计时器发奖。普通/精英未中装备的判定已消费，不计入未使用存量。暂停、故障期间不累计有效时间。

遭遇怪物实际等级采用 clamp(角色等级 + uniform_integer(-2,2),区域怪物下限,区域怪物上限)，而非从整个区域跨度均匀抽取，避免高跨度区域每次随机落差过大。低于某怪最低等级时仍可能遭遇较强怪，进入界面展示风险。

正常结束、失败、体力不足、用户召回均返还未用药剂，保留已成立奖励。终态清除本次探索的临时增减益、护盾与持续效果，不结算未来 tick；保留当前绝对 HP/MP，按清除后的上限截断，不凭空回血。职业被动和装备保留。主动召回需服务端提交独立操作 ID，与回合提交争用同一个短事务锁；谁先提交谁决定最后已成立回合，终态之后不再推进。

非探索恢复只按完整 5 分钟块计算，保存上次恢复基准，不因读取接口或穿脱装备重置。倒地的 30 分钟休整不执行普通回血；到期把 HP 设置为上限 20%，MP 在休整期间可正常按规则恢复。休整到期之后再开始新的 HP 恢复块。

### 16.6 跨设备与配置升级

一期支持一个后端执行世界活动，多个浏览器访问同一后端。WebDAV 用于业务同步与恢复，不能被当成跨离线后端的实时执行锁。其他独立设备默认只读冒险结果，不自动恢复执行授权。

更换执行设备必须先在旧后端暂停新出发、正常结束或明确终止在途探索、同步成功，再在新后端恢复业务数据并授权新出发；旧探索不在另一设备接续。旧后端无法确认停止时不自动接管，不承诺两个离线后端同时写入的正确性。可恢复中断仅在同一后端继续，这是一期边界，不暗示运行锁参与同步。

规则升级不改已有永久成长、装备属性与结算结果。进行中的探索固定旧目录版本，返回后切换到新目录；已学技能以后使用新版本参数，保留学习与等级事实，回顾仍显示当时的旧技能参数。若新规则取消技能或收紧职业装备限制，必须专门迁移，不能启动时静默卸装或删除技能。

### 16.7 业务时区与调度延迟

时间持久化复用项目现有 `life_time.local_time/storage_time` 转换：当前 `USE_TZ=False`，数据库保存上海本地时间，不修改全局设置；接口返回带 `+08:00` 的 ISO 时间，同步沿用现有存储语义。自然日预算固定按 Asia/Shanghai 划分，不能采用浏览器或执行设备时区重置预算。探索记录出发时的业务时区及已发生时间归属，跨午夜区间按两天实际有效时间分配；暂停的墙钟间隔不归入任何一天的有效探索量。

一期不开放运行中修改业务时区。更换时区需停止新活动，结束在途探索，迁移当前日预算与未来日程承诺后整体切换；已发生历史按原时区保留，不因切换重复领取当日额度。只改变用户界面时间显示无需改变业务时区。

战斗刻度以执行后端计时，客户端修改时钟不影响进度。正常唤醒只提交当前一个到期刻度，不批量追赶多个漏掉的回合；若调度延迟超过两个回合间隔，进入可恢复「系统中断：执行延迟」，冻结进度，沿用停机恢复与日程复核流程。不能因为服务器卡顿后一次连续执行几十轮，突然击杀、消耗或发大量掉落。中断时只保留已提交有效时间，不把漏执行的墙钟时长补成探索量。

### 16.8 Agent 删除、停用与维护操作

探索、准备事务或转职事务进行中时，禁止直接删除 Agent、清空冒险档案、转移装备归属或重置成长；界面提示先提前召回或终止活动。结束事务确认物资返还、预留释放与固定结果成立后，再执行用户请求的删除，不使用级联删除抹掉已有奖励、交易与事件事实。

暂停 Agent 自动生活只禁止后续自动出发；已经开始的探索默认继续，由用户另行召回。暂停整个执行后端则使在途探索进入系统暂停状态，适用第 13.3 节。两类操作文案和效果必须区分，避免用户认为停止自动日程会自动回滚当前探索。

当前使用的地牢、怪物或装备模板被停用时，在途探索继续沿用绑定的旧目录，停用只影响下一次出发。删除后重建的居民拥有新身份，不继承旧等级、装备或额度；历史保留原身份快照，不按同名重新认领。绑定初始装备不进入市场，删除/重建不能形成现金收益。

## 17. 数据模型与接口实施契约

以下是设计契约；生产领域模型和 0062–0064 迁移现已实现。实际模型合并、API 操作入口与验证状态以[一期实施与验收记录](./Agent战斗探索一期实施与验收记录.md)为准。新增业务全部同步，沿用既有身份、库存、WorldAction 体力事实、WorldLedger 和生活日程。

| 领域模型 | 职责与约束 |
| --- | --- |
| CombatCatalogVersion 与定义记录 | 不可变配置版本、哈希与生效状态；安装全包事务化，缺引用拒绝 |
| CombatProfile | 归属、稳定居民 ID、等级、当前经验、永久六维、累计固定 HP/MP、当前生命法力、恢复基准、当前战斗职业；一居民一档案 |
| CombatGrowth / CombatPromotion / CombatLearnedSkill | 每次升级、转职和技能学习的唯一事实；记录版本与来源，不能只同步余额 |
| EquipmentInstance / EquipmentLoadout | 唯一装备、固定属性、词条、价值、绑定和收藏；九槽穿戴，同一实例不能重复占槽或被两个居民穿戴 |
| Exploration / ExplorationEncounter / ExplorationRound | 唯一日程关联、出发快照、时间、怪物生成、动作与随机结果、轮次、终态；同探索同轮次唯一 |
| ExplorationReward / ExplorationSupply / ExplorationEnergyBlock | 经验、掉落、携带与使用返还、分块体力操作；与回合或终态同事务提交 |
| ExplorationProgress | 每居民有效探索时间、跨探索掉落机会、装备判定机会、日预算使用与预留；从事实校验，避免任意覆盖余额 |
| CombatRuntime | 本机租约、唤醒时间、执行授权与重试，不同步，不据此产生业务奖励 |

材料与药剂复用现有 AgentInventoryItem 与 SKU 库存能力，装备独立实例与背包统一展示。Agent 现有 profession 不改名、不迁移、不绑定战斗职业。角色归属校验同时覆盖共用背包、日程和冒险档案，不允许不同账号认领同一居民。

建议接口前缀 `/api/settings/agent-world/combat/`，遵循既有认证、camelCase 渲染与响应协议：

| 接口 | 用途 |
| --- | --- |
| GET catalog、dungeons、monsters、equipment-templates | 图鉴与有效配置，支持分页与分类 |
| GET actors/{id}/profile、equipment、skills、explorations | 冒险面板、穿戴、技能与历史 |
| POST actors/{id}/equip、lock-equipment、sell | 原子换装、收藏与真实出售，校验实例及归属 |
| POST actors/{id}/buy-potions | 常驻补给交易，复用市场预算与账本 |
| POST actors/{id}/explore | 校验计划、预留资源与创建探索，必须提供幂等键 |
| GET explorations/{id} | 一致版本的观察快照、当前阶段和累计成果 |
| GET explorations/{id}/rounds、encounters、rewards、report | 游标战报、击败记录、掉落明细与固定结果；分页不超过快照确认游标 |
| POST explorations/{id}/recall | 主动召回，幂等终态，不重算奖励 |
| POST actors/{id}（operation=retry_promotion） | 请求后台 Agent 重试待转职决策；不接受客户端指定职业分支 |

不提供客户端直接写经验、伤害、等级或掉落接口。请求序号/取消处理用于居民切换，探索可见时短间隔轮询，隐藏时暂停前端轮询；后端推进不依赖页面打开。API 返回中区分已提交事实与派生展示。

前端按领域拆为冒险详情、装备、技能、探索、报告与图鉴组件，Hook 管理请求与轮询，API 与类型独立；纯属性预览与格式化不写在页面 JSX。后端目录读取、纯战斗规则、回合事务、调度、同步校验与 HTTP 分模块，不能一个 views.py 包办。

## 18. 验收与本轮复核

实施顺序为配置校验与纯规则 → 成长及装备库存 → 探索事务与调度 → 日程与市场 → 前端面板 → 事件与同步恢复。每阶段保留可复现结果，不能先开自动任务再补结算约束。

必须覆盖：正常/倒地/召回/体力不足/中断结果；重复出发、重复回合、重复返还和出售；同时召回与提交回合；升级到转职门槛与 99 级；技能冷却、持续效果和护盾；掉落额度跨探索跨日；无药剂/无技能/不可穿戴；配置损坏与升级；同步缺事实、同版本不同哈希和跨账号引用。

观察窗口验收覆盖：战斗/遭遇等待/暂停/结算/终态切换；已提交时长与本地倒计时区别；Boss 遭遇与击杀区别；动态去重与一致版本统计；阅读历史不抢滚动位置；关闭再打开、页面隐藏、断线重连与游标失效；切换居民/账号不串记录；召回与回合同时成立；移动端固定操作区与局部隐藏滚动条。验收时打开与关闭观察窗口不能改变同一固定种子探索的执行结果。

长期运行验收还需覆盖：跨午夜与设备时区不同、修改显示时区、调度严重延迟不补跑、自动生活停用与全局暂停区别、探索中删除拒绝及终态后删除、战报归档失败/重复/恢复、长时间多居民数据的同步体积与分页响应。

数值模拟使用设计 CSV、固定随机种子、独立状态，不连接真实数据库或网络。模拟报告必须说明覆盖机制与未覆盖项，不能冒充生产战斗、真实模型或多设备验收。

本轮已将原来的未展开事项补为默认方案，并检查：转职与战斗调用分离；较快回合不直接放大物品供给；Boss 奖励不绕过额度；失败不退已经消费体力；掉落价值不计现金；双设备不以同步文件冒充实时互斥。数值子模型结果见 [评估报告](./Agent战斗系统数值模拟评估.md)，可复现配置见 [目录说明](../data/combat/README.md)。独立读者复核进一步补齐了遭遇生成后首轮延迟、等待期状态推进、额度与终态同刻顺序、复合技能命中及待转职规则版本。

炼金、组队、强化、耐久、立绘换装、洗职业、跨离线后端并行执行不属于一期。没有核心玩法等待用户逐项填空，后续工作是实现、数值校准与验收；用户仍可修改任何设计默认值。

2026-10-15 目录修订发布为 `combat-1.0.5`：法师路线的法杖改为双手杖并占用副手，移除重复双手杖模板；圣杖保留单手属性。装备行囊卡片根据装备快照展示类型。

2026-10-15 目录修订发布为 `combat-1.0.6`：训练木剑成为正式图鉴模板，等级范围 1～10、通用单手武器、所有职业可穿戴，并进入区域普通装备池。初始绑定版本与随机掉落版本使用同一模板，但保留各自生成规则。

2026-10-15 目录修订发布为 `combat-1.0.7`：双手杖等级范围改为 30～99，只有学会双手杖精通的元素师路线职业可以穿戴，避免 30 级前生成不可穿戴的双手杖。

2026-10-15 目录修订发布为 `combat-1.0.8`：全部 17 种词条对全部装备模板开放，移除槽位、武器攻击类型和盾牌类型的词条白名单；每件装备仍按品质生成 1/2/3 条不重复词条，原词条数值范围与等权抽取规则不变。

2026-10-15 目录修订发布为 `combat-1.0.9`：新增 10～99 级的法师路线单手法杖；一转法师时以绑定白装替换训练木剑，元素师路线 30 级后仍可改用双手杖。
2026-10-15 目录修订发布为 `combat-1.0.10`：三转门槛从 70 级调整为 50 级；大盾精通在 50 级学习，精通等级为 50/60/70，大盾装备范围调整为 50～70 级。

2026-10-15 目录修订发布为 `combat-1.0.11`：新增 1～30 级通用戒指与双戒指位，吊坠范围调整为 10～30 级，Boss 专属饰品改称吊坠；新增 50～70 级双手剑，双手剑职业权限表当时只列剑圣和狂战士，遗漏了已学精通的剑士路线。精通装备的职业权限表与精通条件存在重复门槛，见 `combat-1.0.12` 修正。普通武器首段为 10～30 级；头饰和精通防具按精通门槛起步，按 20 级分段到 99 级，魔法盾/小盾/双手杖/圣杖分别为 10～30/30～50/30～50 级。词条池按槽位限制攻击、防御、暴击、命中和闪避适用范围。戒指位复用既有 loadout JSON 字段，装备快照复用既有 accessory 槽及 equipment_type；无新增数据库列或迁移。WebDAV 战斗快照版本升至 5，旧客户端拒绝写入新版本快照。

2026-10-15 目录修订发布为 `combat-1.0.12`：修正精通装备权限口径。凡模板配置了精通，穿戴只要求角色已学会任一对应精通且装备等级符合要求；不再叠加职业白名单。双手剑职业权限表按精通继承展开，包含 30 级学会精通的剑士路线及其后续职业，也包含狂战士路线。没有精通条件的普通武器仍按原职业权限限制。目录校验覆盖所有精通装备的权限继承；本次没有新增数据库字段、迁移或 WebDAV 同步实体。

2026-10-16 目录修订发布为 `combat-1.0.13` / `engine_schema=5`：法师冥想改为战斗中每 15 秒恢复最大法力的 2% / 3% / 5%；牧师新增「圣愈」被动，每 15 秒恢复最大生命与最大法力各 1% / 2% / 3%。恢复封顶于对应最大值，不在探索等待回合触发；恢复事件进入既有战斗事件流。没有新增数据库字段、迁移或 WebDAV 同步实体。

2026-10-16 目录修订发布为 `combat-1.0.14` / `engine_schema=5`：为头饰及各等级段布甲、重甲、皮甲、轻甲、板甲配置不同物品基础名称；盾牌名称改为符文法盾、橡木圆盾、壁垒塔盾，单手法杖与双手杖分别命名为秘法杖、法杖。装备模板 ID、等级范围、属性、精通、掉落池与同步结构均保持不变；已有装备快照不回写。

2026-10-16 目录修订发布为 `combat-1.0.15` / `engine_schema=5`：调整法师法杖命名，10～30 级单手法杖称为法杖，30～50 级双手杖称为秘法杖。装备模板 ID、类型、等级范围、属性、精通、掉落池与同步结构均保持不变；已有装备快照不回写。

2026-10-16 目录修订发布为 `combat-1.0.16` / `engine_schema=5`：牧师路线 30～50 级单手圣杖物品名改为晨祷权杖，圣杖仍作为装备类型与精通名称。装备模板 ID、类型、等级范围、属性、精通、掉落池与同步结构均保持不变；已有装备快照不回写。

2026-10-15 恢复职业装备间隔缩短：装备基础间隔为 5 分钟，按出发时职业配置独立缩短；普通物品机会仍按 5 分钟累计。装备判定最短间隔 1 秒、最多暂存 1 次，下一次击杀时处理。
