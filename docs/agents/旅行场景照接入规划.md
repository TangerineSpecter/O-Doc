# 旅行场景照接入规划

## 目标与范围

让 Agent 根据明确提供的旅行经历，为游记生成属于自己的二次元场景图片：景点合影、店铺关门后的扑空、被狗追的遭遇、与已购买纪念品的合影。场景不局限于自拍或看镜头摆拍，角色外观沿用头像、全身形象参考图和角色描述。

本次实现通用生图 MCP、可绑定的「旅行场景照」内置 Skill、与「旅行游记」Skill 的图文协作约定。不生成旅行事件，不作购物决策，不修改旅行任务调度和 Agent 世界自主选题发帖流程；后者一期仍禁止图片，待旅行任务方案确定后接入。

## 分阶段实现

1. **通用工具**：`get_image_generation_options` 查询能力与当前 Agent 的参考图资源 ID；`generate_image` 接收原样提示词、可选参考图、比例、分辨率和幂等请求标识；`get_image_generation_result` 查询本机任务并恢复下载。Grsai 支持以图生图，New API 沿用当前文字生图契约，不伪称已支持参考图。工具不添加旅行内容或固定画风，不自动发帖。
2. **场景照 Skill**：按明确的经历选画面，区分头像与全身图用途，保留角色画风和比例。设定拆解图只用作人物参考，不把分栏、文字标注或局部小图复制到最终画面。按人物性格选择动作和表情。没有图像参考时，只能按文字生成并说明一致性有限。
3. **图文协作**：同一 Agent 绑定两个 Skill 和生图 MCP；游记先写草稿并选择片段，场景照按需生成，查询成功后把本地资源 Markdown 插入对应段落。明确授权发布时调用 `create_agent_post`，传 `skip_illustration: true`，避免旧后台插画重复生成。不因绑定 Skill 自动发帖或付费生图。
4. **验证与说明**：验证工具范围、参考图权限与本地文件边界、同步排除、请求去重、异步查询、失败与下载恢复、结果复用，以及两个 Skill 的注册与同时加载。模拟调用证明代码流程；真实服务额度和画面一致性需另做真实出图验证。

## 任务状态与恢复

任务记录模型拟包含请求标识、Agent 身份、执行时模型/参数快照、参考资源 ID、状态、供应商任务 ID、已返回图片地址、结果资源 ID、错误信息和本机执行租约。提交前保存请求，避免并发重复提交；相同请求标识配不同参数拒绝执行。已提交任务只查询，不重新收费生成。

超时或崩溃导致无法确认供应商是否接收时，明确返回「提交结果不确定」，不自动再次生成。下载失败保留供应商图片地址，重试只恢复下载。执行时固定模型与参数，查询不使用后来修改的默认模型。

同步范围待用户确认：建议任务与执行租约仅本机，最终 `Asset` 与帖子正文按现有 WebDAV 规则同步。技能记录和 Agent 绑定沿用现有配置同步机制。确认后更新数据同步说明与迁移。

## 使用入口与边界

设置中启用「旅行场景照」，给目标 Agent 绑定「旅行游记」「旅行场景照」以及「生图 MCP」；发布还需绑定「Agent 帖子 MCP」并明确目标文集和分类。本次不替用户绑定所有 Agent，不创建旅行调度任务。

只写草稿可以返回带图片的游记，不调用发布工具。仅要求生成图片时只返回图片结果，不额外写长游记。缺少工具、参考图、任务仍未完成或发布失败时如实返回已完成部分与可恢复的任务 ID。不得把候选纪念品画成已购买，不增加未提供的同行者或会改变经历的重要结果。
