# Agent 结构化决策接入

本文说明当前决策连接、跨场景策略、文本模型路由和同步边界；2026-10-16 静态对照 `system_settings/decision/` 与前端 API。市场内的多步选择和工具执行从[市场决策说明](./Agent市场决策执行说明.md)继续阅读。

## 场景和模型分工

世界设置统一管理启用状态、排除场景和连接选择。当前使用的有限选择场景为：市场选择、生活预算选择、农场种植队列规划、美食菜谱/份数/继续/用料策略、社交行为选择、旅行目的地、游览与遭遇、迷宫探索准备、探索装备挂牌定价，实际枚举见 `routing.SCENES`；其中生活活动选择仅保留历史兼容，新日程始终走整日文本规划。启用字段仍使用兼容名称 `jev_enabled` / `jev_excluded_scenes`，连接不限于 JEV。

有限选择只接收服务端合法候选；普通文字生成、复杂计划和工具业务由相应文本流程承担。无候选不调用选择服务；单一候选直接选定；单个问题最多设置 255 个候选选项，超过时共享选择入口转普通模型。市场的分页和有限轮次另见市场说明。

普通文本请求按有效配置顺序尝试：任务指定模型；未指定且属于决策请求时使用世界文本决策模型；随后为居民模型、系统默认对话模型，并去重。具体使用范围由调用方的 `decision` 参数和场景决定。

模型错误、空内容或输出校验失败后尝试下一层；停止、授权失效和业务工具失败由原执行流程处理。回退不能重放已经提交的交易、奖励或其他写入。

结构化决策连接单次 HTTP 为 60 秒，给本地模型冷启动；这段时间只属于该连接。世界设置里勾选哪些决策连接加入故障转移顺序，并拖动或上下移动排列执行顺序，可以是一个、两个、三个或更多，最多 8 个。平时从顺序第一位开始。第一位挂起、超时或无效响应后，按顺序尝试后面的连接，每个连接重新获得自己的 60 秒。觉得第一位不稳定时，把已经稳定的模型拖到第一位并保存，下一次就从新的第一位开始。调用方截止时间只决定这条决策链是否开始；开始之后，前面的连接挂起不会因「当前阶段总时限已耗尽」跳过后面的连接。全部决策连接失败后，才进入普通文本回退。回退链上每个普通模型另有自己的 60 秒，包含该模型自己的一次格式修复，同样不会被前面的决策连接扣减。下一层仍使用原始提示，不携带上一层输出。调用方截止时间在决策调用开始前已经过去时，共享选择入口不再发起请求，并返回空以便转入普通文本回退，不把「当前阶段总时限已耗尽」抛出整段日程。市场循环直接调用决策连接，市场任务自己的执行时限仍然结束该次市场。逐段活动选择时，每一段使用自己的 60 秒。取消、权限或租约失效、业务条件变化仍然停止整条链。

顺序中靠后的连接成功后，本机把该连接记为暂时沿用，默认 2 小时，世界设置也可选 1 小时或 4 小时。沿用期间后续决策（包括同一次市场里的下一问）先调用这个已成功的连接，不再先等待排在它前面、刚刚失败的连接。窗口到期后的下一次调用重新从当前顺序的第一位开始；第一位成功则清除沿用。沿用中的连接如果也失败，立刻取消沿用，下一次仍从第一位开始。成功不会把到期时间往后推。保存时如果调整了顺序，本机沿用状态会清掉，下一轮按新顺序从第一位开始。同一时刻已经发出的请求仍会各自试到自己的顺序；成功写入后，尚未开始的决策才改为沿用。

## 连接与协议

连接在“AI 模型接入 → 决策模型连接”管理，保存稳定连接 ID、名称、协议、服务地址和模型 ID。没有预置连接。JEV（协议 `systemone`，TypeSafe System One；历史连接 ID 为 `jev`）和本地决策模型都从「新增决策模型连接」添加，并选择对应协议：

| 协议 | 请求和响应 |
| --- | --- |
| `systemone` | 发送 `{state, questions}`，读取并校验 `answers` |
| `openai_chat_json` | 用 Chat Completions 外层把相同结构写入 `messages[0].content`，从返回正文解析问题 ID 对应的选择结果 |

适配器统一校验候选、概率分布与置信度。协议不匹配的服务应实现独立适配器；置信度不作为未经验证的回退阈值。

2026-10-16 用户实测 `openai_chat_json` 连接 `startlux-decision`：单个药剂数量选择问题提供 20 个候选，响应同时返回选择项、置信度和各候选概率；本次 `choice` 为“2瓶”，置信度约 `0.297556`。该次响应的 usage 报告为 prompt 384、completion 0、total 384 tokens。测试只覆盖 20 个候选；255 项上限按共享选择入口配置记录。

关闭或排除场景时，调用方按场景进入普通文本路径；迷宫探索准备使用原整套文本规划，挂牌价格由文本模型决定。探索结构化决策连接临时不可用时，探索仍可按代码回退方案出发；装备问题跳过且不标记，挂牌价格问题暂缓该件。市场会保留同一机会、会话和已提交事实。连接检测不提交市场交易，也不证明真实业务质量或节省比例。

## 账号、持久化与同步

- 连接元数据在 `SystemSetting.system_decision_connections`，API Key 按账号与连接 ID 保存在 `system_decision_credentials`；世界选择在 `LifeConfig.settings.decision_connection_id`。故障转移顺序 `decision_connection_ids`（第一位即平时使用的连接，并写回 `decision_connection_id`；若两者不一致，保存时把 `decision_connection_id` 放到第一位，其余成员保持原有先后）和暂时沿用时长 `decision_sticky_ttl_seconds` 同在 `LifeConfig.settings` 中，随既有世界配置同步。顺序可以为空；空顺序不调用结构化决策。
- 迁移 `0076_custom_decision_connections` 不新增列。已经保存 JEV 密钥的账号会得到一条普通连接，ID 仍是 `jev`，协议、地址和模型与原先内置值相同，之后可以改名、编辑或删除。没有密钥、只是默认指向 `jev` 的世界会从顺序里去掉这个占位。同步恢复后若快照里仍有 JEV 密钥但还没有这条档案，读取连接时会按同样规则补上，不覆盖用户已经改过的档案。
- 本机正在沿用哪个连接存在 `SystemSetting.system_decision_sticky`，不进入快照、不记修订。本地决策服务是否宕机因设备而异，不能让另一台设备跳过自己仍然可用的第一位。调整顺序会清除本机沿用。
- 上述连接元数据、世界选择及密钥均按现有 WebDAV 业务范围同步。配置读取仅返回密钥是否已设置，不回传密钥；远端快照包含凭证字段。
- 旧 `AgentTask.market_config.decision_enabled/decision_provider` 保留历史兼容，当前策略读取世界设置。
- 新协议及连接沿用既有存储，是否新增同步字段须按[同步说明](../数据同步逻辑说明.md)逐项确认。

## 接口与代码入口

接口前缀为 `/api/settings/decision-models/`：`connections/` 新建连接，`connections/<id>/` 编辑/删除，`connections/<id>/test/` 检测。历史 `PATCH` 与 `test/` 仍只写或检测 ID 为 `jev` 的密钥，供已有客户端使用；新的 JEV 连接走同一套连接接口。准确字段见前端 [api/decision.ts](../../frontend_react/src/api/decision.ts)和[类型](../../frontend_react/src/types/api/decision.ts)。

- 后端：`system_settings/decision/config.py`、`views.py`、`routing.py`、`failover.py`、`jev.py`、`adapters/`、`restore.py`、`diagnostics.py`。`choose_connections` 供世界场景和市场循环共用。
- 前端：`hooks/useDecisionConfig.ts`、`components/Settings/DecisionSettings.tsx`、`DecisionConnectionModal.tsx`；世界策略、决策顺序和沿用时间在 `components/AgentWorld/WorldDecisionModelSettings.tsx` 与 `DecisionFailoverEditor.tsx`。连接卡片显示顺序位置和暂时沿用状态。
- 决策用量按 `decision:<connection_id>` 记录真实版本、状态和已知 Token；未知用量保持为空。详见[Token 用量说明](./AgentToken用量统计说明.md)。

阶段验收、市场上下文迭代和旧测试命令见[历史记录](../archive/agents/Agent结构化决策阶段记录.md)。真实费用、耗时、行为质量与多设备接续需要对应证据，不能由字符缩减或连接成功推导。

生活日程始终由普通文本模型一次安排居民当天全部待规划时段，不调用 `life_activity`；该场景枚举及旧排除配置只保留兼容。模型按世界文本模型、居民、系统默认顺序路由。旅行预算仍复用 `life_budget`，连接不可用时直接抽取最多三个地点交给日程模型，不额外调用文本预算模型；成功时先选择“不去”或固定金额档，再生成地点报价。农场与料理等领域准备继续有限候选选择。美食最多三轮菜谱选择，每轮另有份数和必要的用料选择；空候选由代码处理，唯一候选不调用供应商。

## 农场整套队列选择（2026-10-17）

`farm_queue` 复用世界连接和排除场景；生活日程选定农场后，程序提供单作物、短周期优先、单位地块时间收益优先和均衡混合方案，含一轮/当天剩余容量及不施肥、可选/必需两类肥料、按增量净收益配置的策略。先按实际内容去重，再按作物、数量和施肥覆盖保留最多80套；每套附不采购、补一轮、按当天容量补给三档上限，合并重复后最多240个候选。决策连接链上请求到第一次成功即停止；排在前面的连接失败时，按同一顺序尝试后面的连接。关闭、排除，或全部连接失败、非法响应时，普通模型也从同一候选集合选择ID。唯一候选不请求供应商。

决策连接收到的仍是完整候选状态。普通模型回退不重复粘贴估算明细和 24 位候选哈希：计划压成作物、可播数和收益摘要，候选改用短编号，校验时再映射回原候选。这样决策连接网络失败后，后续云端模型不会因为同一份超大 JSON 被立刻拒绝或返回空内容。

同一队列内容和估算在输入的 `plans` 中只出现一次，选项引用计划ID与采购额度；不加载完整生活经历、无库存作物清单或概率数组。无种子时保留空队列与补给额度，窗口或地块容量不足时仅保留空队列、零额度。预估收益按已持有肥料和先进先出成本计算，尚未购买的肥料不计入已具备的收益，必需肥料不足会显示等待风险。

当前报价缺失的种子使用目录基准价；空队列以可见种子报价中位数估算补给，缺少报价时使用目录价格中位数，周期也使用目录中位数。额度最多为扣除其他日程资金预留后的余额，不扣款、不新增预留；是否采购、采购预算及成交仍由每日市场决定。市场采购后的队列修改继续沿用现有工具与版本依据。

提交前重新裁剪最新种子库存和可支配余额，保存既有 `farm_plan` 与原始来源；普通日程修订不重建已经固化的队列。跨日顺延后按目标日期重新准备，成熟可跨日。后续队列执行不请求决策或文本模型。

只读文本模型对比命令继续使用原 `life_plan_proposal.propose` 生成比较草稿，不建立队列；正式生活日程使用本节的整套候选路径。

入口：`farm_queue_candidates`（纯候选及估算）、`farm_queue_decision`（事实加载、选择和提交前复核）、`life_daily_planner`（整日活动及领域准备）、`life_sequential_planner`（已选活动执行前兼容复核）、`farm_queue_plan.install`。临时候选和候选ID不新增同步字段，最终方案及原始来源沿用已有快照。
