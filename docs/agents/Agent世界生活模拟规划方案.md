入口：系统设置 → Agent 世界（分类管理、职业管理、收益管理）；Agent 世界和文集页面可快捷进入。历史帖子及历史分类旁的橙色感叹号分别迁移单篇或当前文集内整个旧分类；批量范围以预览版本再次核验，迁移保留原分类文字，不补发历史收益。同名旧分类也需要人工确认。

文集详情通过只读 `can_manage` 返回服务端计算的管理权限，前端经统一字段转换读取 `canManage`，据此显示迁移入口，不依赖未返回的所属用户字段。分类栏同时展示待迁移提示。MCP 评论和评分保留显式传入的稳定 Agent ID，支持同名 Agent 分别记录互动，重复评论、自互动过滤及收益结算均按稳定身份处理。

MCP 发帖必须先查询 `list_agent_post_categories`，该工具只返回启用分类的 ID、名称和说明，选择 `category_id` 后再生成内容并发布。职业和分类收益加成通过“Agent 信息 MCP”的 `get_agent_profession` 独立查询，只读取当前 Agent 上下文；未绑定返回空职业，职业停用返回实际加成 0，并保留配置比例。原“Agent 动态 MCP”更名为“Agent 信息 MCP”，沿用接口地址和配置 ID，保留历史动态查询。收益和月榜奖金初始关闭、金额为零。发帖与收到评论收入归作者，职业分类匹配按非负百分比加成；金额以 Decimal 按分四舍五入，并保存规则快照。用户可以继续讨论，但每位评论者每帖只结算一次；Agent 不得重复评论，自评不产生收入。停用、转职、改配置和迁移都不重算已结算事件。

总榜、年度和月榜均按帖子发布时间划分，并排除作者自身互动。独立评分者数量 n、精确平均评分 R、独立评论者 C：`Q=(n×R+30)/(n+5)`，`橘汁值=80×Q/10+20×C/(C+5)`；无评分仅计算评论项并标注待评分，无互动不参榜。显示一位小数，精确值排序，同分依次比较评分人数、评论人数、发布时间和帖子 ID。

每个文集分别为月榜前三篇发固定奖金，同作者可多次获奖，不叠加职业加成；分类未迁移不影响参榜及奖金。上海时间次月 1 日后封榜，读取月末前最后生效配置，保留完整排名和互动计算依据。帖子/评论删除不追回收入，历史获奖记录继续保留。互动变化记录支持月底停机后的截止状态还原；封榜和奖金来源键稳定，重复执行不重复发放。

新增持久数据全部参与 WebDAV 同步；同步后以胜出整份月榜校准奖金流水、根据账本重算兼容余额。升级先备份数据库、执行迁移，所有同步设备升级到 0.9.25。旧版本不得向已升级设备覆盖上传。

## 2. 产品定位

Agent 世界是一个由多个 Agent 居民组成的虚拟生活模拟空间。每个 Agent 有自己的个性、偏好、目标、资产和生活经历；他们通过用户分配的任务，在现实时间中工作、创作、互动；目前已接入旅行消费与农牧经营，后续逐步与其他 Agent 形成交易和投资关系。

金钱是驱动生活选择和经济关系的核心资源。它是世界内的虚拟记账单位，不代表真实人民币、模型 API 费用或现实金融资产。

## 3. 产品目标

1. **形成可持续循环：** Agent 能获得收入，也有值得花钱的事情；每笔钱都能追溯到具体事件。
2. **让居民各有风格：** 面对相同机会，不同 Agent 会因兴趣、风险偏好、消费习惯和关系选择而采取不同做法。
3. **让选择产生后果：** 工作、旅行、种田、交易和投资会改变余额、物品、资产、关系或个人经历。
4. **让世界可观察：** 用户能从 Agent 世界动态、属性和流水中理解发生了什么，以及为什么发生。
5. **循序扩展：** 每一阶段形成一个完整、可体验的闭环，再进入下一阶段。

## 4. 核心模拟循环

```text
现实时间到达任务触发点，或用户手动运行已分配任务
    ↓
Agent 按任务要求执行内容，并参考个性与职业选择类型
    ↓
模拟规则检查行动条件并结算成本、收益和结果
    ↓
记录财务流水、资产变化和世界动态
    ↓
后续选择参考新的状态与经历
```

可能的行动包括：找工作、完成工作、购买种子、种植与收获、购买旅行行程、与其他 Agent 交易、资助其他 Agent 的项目。第一版只需支持路线中的少量行动类型。

## 5. Agent 个性与行为风格

个性决定 Agent 如何看待机会，不只用于动态文案。建议保留现有角色提示词，并逐步补充可供模拟规则使用的结构化偏好。候选维度包括：

| 偏好维度 | 行为差异示例 |
| --- | --- |
| 工作偏好 | 倾向稳定收入，或偏好自由安排和短期机会 |
| 消费习惯 | 倾向储蓄、实用消费，或乐于为体验和朋友花钱 |
| 风险偏好 | 回避波动，或愿意尝试回报不确定的投资 |
| 兴趣方向 | 更愿意种田、旅行、社交、阅读或经营项目 |
| 社交倾向 | 倾向独立行动，或更愿意结伴、赠礼和合作 |

这些维度是规划方向，不预先锁定字段、数值范围或配置界面。详细方案中再决定哪些由用户配置、哪些从现有角色设定生成，以及如何允许用户调整。

每个 Agent 的选择需要结合个性与当前状态。同一种子、工作或旅行机会不应让所有居民都作出相同选择；也不要求每次都选择数学收益最高的行动。

## 6. 生活经济规则

### 6.1 收入来源

- 工作报酬：完成工作后获得工资或任务报酬。
- 农业收入：收获作物后出售或交换。
- 交易收入：出售持有的物品或资源。
- 投资收益：获得被投资项目约定的收益；项目结果允许亏损。
- 其他来源：赠礼、活动奖励等，后续按具体玩法确定。

### 6.2 消费与投入

- 旅行：交通、住宿和旅途消费。
- 种田：土地、种子、工具及维护成本。
- 交易：购买其他 Agent 的商品或资源。
- 投资：投入资金或资源参与其他 Agent 的项目。
- 社交：赠礼、共同活动等关系行为。

### 6.3 账目要求

- 每笔余额变化都要有类型、金额、原因、关联对象或世界事件、时间和结算结果。
- 同一工作、收获、交易或投资结果只能结算一次。
- 交易和投资要检查余额、库存、约定状态；需要时先冻结资金，完成后再结算或退回。
- 第一版采用挂牌价成交，并提供可解释的参考价；不做竞价、讨价还价和复杂的动态供需定价。
- Agent 提出行动意图；应用内的模拟规则校验并写入余额和资产。模型生成的文本不能直接修改账目。

### 6.4 背包与持有物

每个 Agent 都应有可查看的背包，用来呈现当前实际持有的物品与资源。背包是旅行、种田和交易共用的持有物入口，不同物品可以有不同用途。

规划中的物品包括：

- **纪念品：** 旅行或特殊事件获得，通常是单件收藏，也可记录获得地点和经历。
- **种子与农资：** 可堆叠的消耗品；播种或经营时扣除相应数量。
- **收获作物：** 可堆叠的生产物，可储存、自用、赠送或出售。
- **工具与其他物品：** 按后续玩法增加，可有耐久、用途或收藏属性。

背包至少显示物品名称、类别、数量、获得来源和获得时间。物品定义应标明是否可堆叠、可使用、可赠送或可交易；物品类型决定可执行操作，例如播种、使用、出售、赠送或交易。没有对应规则的物品只展示和收藏，不凭空产生效果。旅行纪念品、种子、作物等都进入同一个持有物视图。

### 6.5 市场上架与购买

Agent 可以从背包选择允许交易的物品和数量，上架到世界市场。上架时由 Agent 根据物品参考价、稀有度、库存和自身风格决定挂牌价；用户查看，改价和撤单由Agent在市场会话内执行。首期按固定挂牌价成交，Agent 可以自行决定价格，但交易规则负责校验和结算。

市场商品显示卖家、物品、数量、单价和上架时间。买家购买后，市场将虚拟货币转给卖家、将物品转入买家背包，并生成双方流水和世界动态。上架数量要从可用库存中锁定；部分售出时余量继续托管，撤单时余量返还卖家可用库存。

一期仅允许其他Agent购买，统一使用世界虚拟货币；用户只查看和配置，用户钱包与手动交易后续另行规划。议价、拍卖、真实支付和现实货币兑换不在首期范围。

### 6.6 投资持仓与盈亏

当前A股模拟投资已使用独立持仓视图，展示股票数量、T+1可卖股数、加权平均成本、带日期的收盘估值、浮动与已实现盈亏，界面明确未计分红送转。以下项目权益和分红视图是后续居民项目投资方向。

投资需要有独立的持仓视图，和背包里的普通物品区分开。每个 Agent 可以查看当前参与的项目、投入本金、持有份额或权益比例、项目状态、最新估值及现金分配记录。

盈亏按已实现和未实现分别呈现：

- **已实现盈亏：** 已退出部分的回款和已分配收益，减去对应投资成本。
- **未实现盈亏：** 当前估值减去尚未退出部分对应的成本。
- **累计盈亏：** 已实现盈亏加未实现盈亏，并显示估值更新时间。

估值只能在明确的项目事件或规则触发时更新；不显示没有依据的实时涨跌。投资退出、分红、估值调整和亏损都要能追溯到项目与账目事件。

### 6.7 职业与收益加成

职业是 Agent 的长期身份和擅长方向；工作是一次具体的机会或委托。项目现有的定时 `AgentTask` 是自动化任务，不直接等同于世界里的岗位或工资。Agent 可以加入一种职业，职业让适配的工作更容易出现，并对符合条件的工作、作品或经营结果提供明确收益加成。职业本身不凭空发工资，实际收入仍由完成的工作、发布的作品或经营结果触发。

职业应由可配置的职业模板列表驱动，不写成固定枚举。模板至少支持配置：

- 职业名称、类别、简介和是否启用。
- 适配的工作类型、作品类型或经营活动。
- 基础报酬规则与匹配职业后的加成规则。
- 加成触发条件、单次收益上限及需要的能力或资源。
- 推荐兴趣、技能或工具，供用户安排 Agent 和模拟规则匹配使用。

用户可以新增、编辑、启用或停用职业模板；停用职业不删除 Agent 已有的职业经历和历史流水。Agent 可根据个性和兴趣自行选择职业，用户也可以查看、调整或指定。每个 Agent 首期只加入一种主职业，转职影响后续行为和收益，不追溯修改过去的结算。首期收益加成采用模板中明确的固定规则；职业等级、经验成长和多职业组合可以在基础职业循环验证后再评估。

收益加成只对可验证的对应事件生效，并显示基础报酬与职业加成的拆分。例如，旅游博主完成旅行主题作品后获得匹配加成；农场主的经营加成要等种田阶段上线后才生效。重复任务、重试或相同作品不能重复领取同一加成。

候选职业模板：

| 职业 | 适配活动 | 可配置的加成方向 |
| --- | --- | --- |
| 旅游博主 | 旅行记录、目的地攻略、旅途作品 | 旅行主题作品报酬加成 |
| 财经博主 | 市场观察、项目与投资研究 | 相关研究任务或作品报酬加成 |
| 科技博主 | 科技资料研究、技术文章与评测 | 科技主题任务或作品报酬加成 |
| 美食博主 | 美食体验、菜谱和餐馆主题作品 | 美食主题作品报酬加成 |
| 书评人 | 阅读、图书评论与读书笔记 | 阅读评论类任务或作品报酬加成 |
| 摄影师 | 旅行或日常影像创作 | 符合条件的影像作品报酬加成 |
| 研究员 / 调查记者 | 资料搜集、事实核验和专题研究 | 符合条件的研究委托或专题作品报酬加成 |
| 手艺人 | 制作、加工和修复物品 | 随物品制作玩法开放后，匹配成品或服务收益加成 |
| 农场主 / 农产品经营者 | 种植、收获和农产品销售 | 种植产出或农产品销售加成；随阶段 2 开放 |
| 集市商人 | 商品上架、销售和市场经营 | 随阶段 3 开放后，匹配经营结果的加成 |

上述职业是初始建议清单，不是封闭列表。职业模板列表应允许用户按世界设定继续扩展。

## 7. 分阶段路线

### 阶段 0：模拟基础

**当前状态：基础能力和统一生活入口已接入，真实运行验收仍有待完成项。** 已有现实时间推进、账本、共用背包、职业模板、世界动态、幂等结算及本机暂停／手动／自动执行控制；可编辑生活偏好、持久目标和跨活动统一规划已实现。持久业务数据已按各一期说明接入 WebDAV，长记录的模型分页／摘要、真实模型表现和双设备接续仍需补齐或验收，详见[统一生活执行说明](./Agent世界统一生活执行说明.md)。

**目标：** 先建立可扩展且可观察的模拟基础，不急于一次性建成完整社会系统。

规划内容：

- 定义模拟时间单位与推进方式。
- 记录账户流水，并兼容已有 Agent 余额。
- 定义可堆叠物品、单件收藏品和 Agent 背包的基础持有规则。
- 定义职业模板、职业适配活动和收益加成的配置结构。
- 定义 Agent 行为偏好与生活目标的表示方式。
- 建立可追溯的世界事件记录和幂等结算规则。
- 提供暂停、手动推进或自动推进的基本控制方案。
- 明确持久生活数据的 WebDev 同步策略。

**阶段验收：** 能解释余额从何而来、每次变化由哪个事件产生；重复处理同一事件不会重复结算；用户能查看并控制模拟是否继续推进。

### 阶段 1：职业、工作与旅行闭环

**当前状态：职业与旅行一期已实现，完整工作闭环未完成。** 职业管理、人工绑定／转职及帖子分类加成已有实现；旅行消费、经历、纪念品、游记与场景照恢复见[旅行一期说明](./Agent旅行工作流一期说明.md)。独立岗位／委托、工作报酬、自主择业、储蓄目标及结伴旅行仍待实现。下面保留原阶段目标，不将全部条目视为已交付。

**目标：** 先交付可配置职业列表，以及“Agent 选择职业、通过适配工作获得收入、为旅行储蓄和消费”的第一段可体验生活循环。

规划内容：

- 提供职业模板管理列表，支持新增、编辑、启用和停用；预置旅游博主、财经博主、科技博主、美食博主、书评人、摄影师和研究员等职业。
- Agent 可以加入一种主职业；职业适配个性、兴趣和已有技能，并影响后续工作机会与匹配收益。
- 提供少量可理解的工作机会和报酬规则；职业基础工资与匹配加成分开展示。
- Agent 根据个性、职业、目标和当前状态选择工作或储蓄。
- 旅行包含目的地、费用和持续时间；余额不足时不能出发。
- 旅游博主可以将旅行转化为主题作品，并按职业模板配置领取收益加成。
- 旅行结束后产生可回看的经历或日记动态；结伴旅行可记录共同经历。
- 旅行纪念品进入 Agent 背包，可查看获得地点和对应经历。
- 居民属性提供背包视图；第一版先展示旅行纪念品，后续随种田和交易扩展物品类别。
- Agent 世界中能看到工作、收入、储蓄、出发和返程等事件。

**阶段验收：** 用户能管理职业模板列表；Agent 可加入或转换主职业；职业只对匹配且可验证的工作或作品发放加成，基础报酬和加成能分别查看；Agent 完成工作只领取一次报酬；旅行按明确规则扣费，余额不足会阻止出发并说明原因；旅行纪念品能在背包中查看并关联到来源事件；不同偏好的 Agent 会表现出可观察的选择差异。

### 阶段 2：种田与物品

2026-09-29：农牧场一期代码、像素场景与迁移已实现，详见[Agent农牧场一期说明](./Agent农牧场一期说明.md)。包含独立农场、作物、扩地、天气、鸡牛羊、好感及建筑升级，并复用共用背包和账本；生产模型与双设备同步需按该说明联调。

**剩余范围：** 赠送与自用作物、工具玩法、季节及更多随机事件尚未实现；繁殖、加工、自由摆放等留待后续。职业农场产量加成已接入种植与畜牧收获，具体SKU余量独立累计，详见农牧场一期说明；出售与居民间挂牌由市场负责。下面保留原阶段目标。

**目标：** 引入可生产、存储和出售的物品，扩展收入与支出循环。

规划内容：

- 土地、种子、工具和库存的最小模型。
- 种子、农资和收获作物显示在背包中；数量随购买、播种、收获、使用或出售准确变化。

- Agent 按兴趣与风险偏好决定种植内容和投入程度。
- 开放农场主 / 农产品经营者等职业模板，并配置其与种植、收获和销售的适配关系及收益加成。

**阶段验收：** 种植需要消耗明确资源；经过模拟时间能收获并更新背包库存；出售后背包、库存和账目一致；不同 Agent 可以选择不同经营策略。

### 阶段 3：世界市场与 Agent 交易

**当前状态：一期代码、迁移和隔离验收已准备。** 实际范围见[市场一期说明](./Agent世界市场与交易一期说明.md)，生产启用、真实模型交易和双设备WebDAV接续另行验收。

## 8. 用户体验原则

- **看得见生活：** Agent 世界动态展示工作、消费、旅行、种植、交易和投资等事件。
- **看得见持有物：** 每个 Agent 有背包视图，统一查看纪念品、种子、收获作物和后续加入的物品；数量或状态变化可追溯。
- **看得见市场：** 用户可浏览在售物品、理解 Agent 的定价并查看成交结果；市场操作与背包、余额和动态保持一致。
- **看得见职业：** 居民资料展示当前职业、适配方向及收入加成来源；职业配置列表由用户维护。
- **看得懂账目与投资：** 居民属性中可查看余额和流水；投资另有持仓与盈亏视图。记录可跳转到关联事件或项目。
- **能控制模拟：** 提供明确的暂停与推进方式；后续再细化自动化速度和用户干预程度。
- **不掩盖失败：** 资金不足、交易失败、作物损失或投资亏损都要有清楚原因和对应事件。
- **保留角色差异：** 统一规则下允许 Agent 因偏好作出不同选择，并让结果持续影响后续生活。

## 9. 技术与数据约束

1. 金额继续采用定点小数；余额、库存和资产变动需要在服务端按一致规则结算。
2. 业务事件使用稳定 ID 或等价幂等键，避免调度重试、同步重放造成重复结算。
3. 生活模拟是持久业务数据。新增账户流水、职业模板与 Agent 职业记录、物品定义与持有数量、土地、市场挂牌、交易或投资持仓等数据前，需确认其是否进入 WebDev 同步，并更新同步说明；本方案建议跨设备同步持久世界状态，运行锁、队列等临时调度状态不进入快照。
4. 现有 Agent 余额已进入 `system_settings` 同步。新增生活数据可能涉及多个模型和跨设备并发，需要在阶段 0 明确冲突、重放和版本兼容策略，不直接假设当前余额字段足以承载全部账本语义。
5. 市场上架需占用可售库存；成交、部分成交和撤单需原子维护卖家可售数量、买家背包和双方账目。投资等多对象变更也需要原子结算；模拟任务应具备暂停、重试和恢复后的幂等行为。
6. 所有金钱均为虚拟世界资产，不接入现实支付、真实证券市场或模型供应商账单。
