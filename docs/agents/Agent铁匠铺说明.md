# Agent 铁匠铺

核对日期：2026-10-23。本文说明本地实现；正式数据库迁移、真实决策连接及双设备 WebDAV 分别验收。

## 范围与入口

Agent 管理 → 任务分配 → 空档活动中的「铁匠铺打造」能力默认关闭，参与居民继承统一生活配置。自动打造属于[空档穿插](./Agent空档穿插与资源保护说明.md)，不占主日程次数；手动执行同样由决策连接选择。居民须已有本账号的冒险档案。配置弹窗展示统一决策连接的配置位置，不提供普通任务模型选择；原有任务模型字段不影响打造决策。

世界图鉴 → 铁匠铺查看配方、编辑材料及查看打造记录。图鉴保留不可制作配方并解释原因，模型只收到合法候选。成品进入现有装备行囊，穿戴、回收、挂牌沿用原机制，不直接更换穿戴。本期不增加装备模板、锻造熟练度、强化、重铸或 Boss 专属打造。

图鉴沿用白底卡片与橘色选中态。配方列表显示对应部位的像素装备、所需材料图标与数量；详情先展示职业路线可打造的装备类型、随机等级和穿戴等级，再显示材料可用/所需量、预留量及怪物与迷宫来源。装备复用冒险图鉴像素素材，材料复用 `MaterialPortrait`，编辑配方也显示当前材料图标。桌面列表与详情独立滚动，窄屏点击配方进入详情并可返回列表。图标为随前端发布的静态展示，不新增持久字段或 WebDAV 同步内容。

## 等级、品质与配方

- 等级档为 1～10、10～20、20～30……80～90、90～99，包含两端，允许相邻档产出相同边界等级。
- 配方以「等级档＋部位」为身份，共 70 条。部位为武器、副手、头、身、手、脚、饰品；戒指和普通吊坠共用饰品配方，两枚戒指穿戴位不另建配方。
- 同档同部位所有类型用料相同。实际等级在档位与模板交集中均匀抽取，无模板时不提供候选、不越界生成。
- 品质独立抽取白 70%、蓝 25%、金 5%；每件成功提交必定产出一件。词条、数值、名称及回收价复用现有装备生成规则，穿戴规则随实例固化。
- 每件 2 体力，不收加工费；一次最多 3 件。待打造目标按实时配方保护需求量，真正提交时才冻结单件材料批次。

初始材料分档、部位组合及最终数量固化于 `blacksmith_catalog.py`。材料须由与该档相交的实际怪物、迷宫产出，不用材料表等级代替采集门槛。普通材料承担主要用量，精英材料每件合计最多 2 个，不使用 Boss 印记；图鉴显示来源怪物、等级和迷宫。

数量按基础组合合并相同 SKU 后，从整数倍 k=1 起增加；普通材料为基础数量×k，精英材料为 min(基础数量×k, 2)，不先约分。档位上限为 H，按目录基础回收价达到 `2 × 1.1 × (10＋0.5H)` 的首个整数倍固化发布，运行时不随市价重算。编辑仅修改同档合法材料和数量，并检查重复 SKU、精英上限及成本下限。修改递增配方版本，只影响后续选择，历史沿用冻结材料名称、价格及规则。

## 模型选择与职业路线

新活动流程：先检查已登记目标并逐件打造，再由模型决定是否登记新目标；登记时每个目标独立选择等级档、部位和装备类型。每位居民最多同时保留 3 个目标，可以少于 3 个。每个目标代表一件装备；成功打造即完成并空出目标位，与品质和属性无关。本次活动实际打造仍最多 3 件。旧版活动检查点保留原逐件选择流程。

登记候选由职业路线合法类型向上汇总，不以当前材料是否齐备为门槛。实际打造仍须材料、体力、模板和空档均满足；唯一选项由系统直接确定。模型不能修改用料数量、品质、随机等级、属性或回收价。

职业路线包括当前职业及其可达后续分支，排除已放弃的兄弟分支；未一转新手只提供通用装备。依据现有精通和穿戴规则判断未来适用性，不因当前等级或尚未学到未来精通而误删，也不借重选职业残留技能开放旧路线。超出当前等级的成品可先入库，穿戴仍检查实际条件。

新活动场景为 `blacksmith_goal_count`、`blacksmith_level_band`、`blacksmith_slot`、`blacksmith_type`；多个目标各自可做但材料不够一起做时才问 `blacksmith_goal_priority`。旧活动仍识别 `blacksmith_continue`。仅加载本人职业等级、当前穿戴、合法候选、材料余量、目标进度、可用体力和偏好，不附全生活快照。连接只返回候选时，理由明确标为系统选择说明。空档顶层只接收可登记数、已就绪数和缺口摘要。

## 资源、事务与恢复

目标只存配方 ID 与装备类型，材料需求及缺口按当前配方和库存实时计算。已有炼金计划与正在提交的单件打造先占用材料；新炼金计划和自动市场处置只能使用目标需求之外的余量。多个目标共享材料时，各自显示单独可打造状态；实际提交前重新计算，必要时由模型选先做哪一个。目标完成后余量立即释放。配方或职业路线不再合法的目标在图鉴查询中显示失效并立即释放目标位和材料保护，查询不写入状态；铁匠铺下一次登记或执行时固化失效状态。手动交易仍可显式改变库存，进度随之变化。具体单件提交继续冻结实际库存 ID、数量、单价及规则。

模型调用在事务外。保存选择及提交时复核最新资源，防止等待模型期间的变化使旧响应无条件提交。每件短事务统一提交授权/租约/路线校验、扣材料、2 体力消费、装备实例、制作与装备来源事实、进度推进。

单件提交中的操作、体力事实和活动更新合并为一次完整性指纹重算，在同一事务提交前完成；指纹失败时连同本件业务写入一起回滚。此合批只作用于铁匠铺指纹，不暂停同步修订跟踪；嵌套批次回滚会清理本批次状态，其他单次保存入口仍即时刷新指纹。

操作键为「活动 ID＋件序号」，序号仅 0～2。重复提交返回原成品，不重扣或重抽。进度保存于版本化 `WorldAction.snapshot`；恢复只接续未完成阶段。模型暂不可用按题目退避，超过次数上限结束并释放未提交预留。主动停止、无材料、体力保护、暂停或空档过期保留已完成装备与消耗；异常展示中断原因和已完成件数。

目标登记中途终止时，保留已经保存的数量、等级档和部位选择作为历史；未选完类型的部分不生成目标。同步允许已终止活动保留这类未完成登记，但仍核对计数、实际目标和成品事实；执行中的活动不能跳过未完成登记直接进入打造或结束阶段。

## 接口

前缀 `/api/settings/agent-world/blacksmith/`，需认证并校验账号、居民归属。

| 接口 | 行为 |
| --- | --- |
| `GET recipes/?agentId=…` | 配方、来源、合法类型及实际等级范围、库存/预留/可用量、最多 3 个待打造目标与逐项材料缺口、失效目标和空余位数；不建立目录或档案 |
| `PATCH recipes/{id}/` | 仅编辑 ingredients 的 sku、quantity，校验来源、成本及精英上限 |
| `GET agents/{id}/history/?page=…` | 每页 20 个活动，含最多 3 件成品、选择过程、消耗及执行记录 |

执行复用内置任务和生活手动执行接口，不提供前端直接设置品质或结算装备的接口。

## 持久化与 WebDAV

用户确认全部业务数据同步。迁移 `0091_blacksmith_goals` 新增 `BlacksmithGoal`，同步活跃、完成或失效状态；材料缺口不另存快照。原 `0090_blacksmith` 的目录、单件事实、完整性记录及任务配置继续保留。进度复用 `WorldAction`，不保存第二份体力余额。

新快照使用 `blacksmith_schema_version=2`，包含账号、活动、操作和目标清单；旧版本 1 活动按原规则验证。每件写 `CombatFact.kind=forge`，保存唯一来源及冻结装备规则；材料余额只从该事实扣算一次。战斗协议保持 12。

来源、合并、导入和恢复核对配方完整性、账号、序号和决策顺序、材料批次、体力事实及装备来源。历史只校验冻结快照，不重抽或依赖已裁剪目录生成装备。同一操作跨设备产生不同结果时拒绝拼接；重复恢复不消费或发奖。

旧快照无铁匠铺时按未启用兼容；旧设备拒绝新版战斗快照。线程、租约及本机执行授权只用于当前设备协调，不同步；恢复会清除铁匠铺的本机授权。世界暂停时，再次手动执行同一居民、同一铁匠铺能力，会复用该账号仍在执行的手动日程及原打造检查点，并重新授权本机接续；已提交件不重扣、不重抽。只有账号、居民、能力和日程执行身份全部对应时才允许复用，不接续其他居民、其他能力或自动打造。后台调度不能自行授权手动进度。所有设备先升级、迁移后交换新快照。
