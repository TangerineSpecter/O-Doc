# Agent 居民归档（1.2.2）

Agent 管理的删除改为可恢复归档。归档保留同一 Agent ID、角色配置、任务绑定、记忆、公开历史、关系、余额和资产，不触发物理删除或级联清理。此前已经删除的居民只能展示明确的历史身份，不能恢复完整档案。

## 管理与名称

管理顶部的「归档居民」可查看资料和恢复。归档期间资料只读，新任务不能选择归档居民；已有任务保留原绑定并标记「已归档」。创建和编辑对整个共享居民列表（包括归档）校验名称唯一，去除首尾空白后精确比较，区分大小写；当前架构没有 Agent 账号归属字段，本功能不新增账号隔离。

归档名称冲突返回 HTTP 409、原居民 ID 和归档标记，提示打开归档列表恢复。数据库唯一约束处理并发重名；迁移发现空名或重复时报告名称和 ID，不自动合并、改名或删除。

`GET /settings/agents/?status=active|archived|all` 默认只返回当前居民；详情允许读取归档居民。`POST /settings/agents/<id>/archive/`、`restore/` 均幂等；旧 `DELETE` 兼容为归档，不再物理删除。响应提供只读 `archived` 和 `archivedAt`。

## 执行与恢复

归档与执行认领共用业务锁，并重新读取数据库状态。有效租约、执行中的任务、飞书处理或记忆整理，以及未结束的旅行、探索、市场会话和生图请求会阻止归档，接口返回具体原因。请先结束，或使用对应活动已有的取消、召回和查询功能。

归档后所有以居民身份执行的定时、手动、后续任务、生活规划、农场队列、社交、旅行、探索、市场、投资、随手记、记忆及飞书入口停止。原任务开关和参与名单不改动，混合任务的其他居民继续执行。历史查询和资产完整性校验仍读取归档居民。

恢复沿用原配置和已有暂停状态，不额外打开本机自动执行。`execution_resumed_at` 记录最近恢复时间，阻止固定任务补跑此前的时间点；间隔任务从恢复后的下一个完整间隔起执行。已错过的生活安排取消，随机机会在原执行记录的 `random_context.skipped_agent_ids` 中按机会记录跳过，不计成功、不重分配、不把居民永久标记为不可用。未来机会仍可执行。

恢复时也会将已到期的待执行社交机会标记过期，不补做旧机会。归档只停止居民主动操作，不冻结世界时间；农场自然生长、体力恢复和持仓估值沿用现有规则。

## 商品下架

归档在同一事务内下架全部在售挂牌。只将未成交的剩余托管物品返回原居民背包，保留品质、价格批次、来源和图片；更新挂牌版本并保存 `withdraw` 交易及 `mode=archive` 的已关闭管理会话。管理下架不使用模型、不收费用、不扣体力，恢复或同步也不生成市场进入体力事件。

任一返还或校验失败，归档、所有挂牌与返还一起回滚。恢复后挂牌保持 `withdrawn`，由居民之后自行重新上架。

## 关系与同步

关系图开关仍叫「显示已离开居民」，默认关闭。打开后同时显示「已归档」和以前删除留下的「历史居民」，只有前者可恢复。始终按原 ID 保留关系，不通过姓名重连。

`Agent.archived_at`、`execution_resumed_at` 随既有 Agent 实体参与 WebDAV、同步修订和备份。归档不是删除墓碑。挂牌返还、管理下架交易、会话与市场完整性记录同时参与同步；本机租约、线程和连接不参与同步。

旧快照新增居民缺失字段时默认未归档；普通合并对缺失字段保留本机已有状态，明确全量恢复旧备份则采用旧快照当时的未归档状态。写回前检查最终名称集合；名称交换只在恢复事务内暂时释放名称，保留原 ID。名称冲突或归档居民缺少完整下架事实时拒绝并回滚。导入归档状态收回本机执行资格并关闭飞书连接，后续调用及业务提交再次检查状态。继续限定同一世界单设备执行。

上线前备份数据库与媒体，所有同步设备升级至 1.2.2 并执行迁移至 `system_settings.0068_agent_execution_resumed_at`；旧客户端按现有应用版本检查拒绝新快照。真实双设备 WebDAV 接续需单独实测。

`0067` 已被部分开发数据库执行，恢复时间字段以独立的 `0068` 增量迁移补齐。`0068` 同时兼容已提前存在该列的开发数据库。修改已执行过的迁移文件不会使 Django 重跑，不能仅靠重启热加载补齐数据库字段。`dev.sh` 和 `start.sh` 均会在启动服务前执行 `migrate`。
