# Agent 美食星级与厨艺成长二期

本期保留 20 个食谱及默认解锁等级，厨艺上限扩展为 99，美食增加 1～5 星。用户已确认全部新增持久数据纳入 WebDAV。食谱仍由居民在制作日程中自主选择，一次最多六份、每份一个成品；没有直接制作 HTTP 接口，不新增失败、增产、厨房建筑或畜产品星级。

## 品质、价格和经验

材料按实际消耗的库存记录与 FIFO 价格批次分配。材料权重为 `数量 × 该 SKU 一星基础价值`，平均星级 `A=Σ(权重×星级)/Σ权重`；`q=(A−1)/4`。基础价值取确认计划时农牧目录并保存快照，与高星回收价值和市场购买价格无关。普通鸡蛋、牛奶按一星，金色产品不可替代。内部计算不提前舍入平均星级。

设 `t=(每份提交时厨艺等级−1)/98`，`p=0.04+0.46×t^0.8+0.25×q`，成品 `s` 星概率为 `C(4,s−1)×p^(s−1)×(1−p)^(5−s)`。每份用自己的稳定操作 ID 和品质版本生成独立随机值，保存依据与结果；预览不抽奖，重试与恢复不重抽。前一份升级后，后一份使用新等级。

| 星级 | 回收倍率 | 经验倍率 |
|---|---:|---:|
| 1 | 1 | 1 |
| 2 | 1.2 | 1.1 |
| 3 | 1.5 | 1.2 |
| 4 | 1.8 | 1.3 |
| 5 | 2.2 | 1.4 |

一星保留食谱基础价格精度；二至五星 `ceil(基础售价×倍率)`，先确定单价再乘数量。经验 `floor(基础经验×倍率)`，按份只发放一次，不叠加材料经验奖励。成品入库保存价格批次，后续规则修改不重估旧货。

厨艺升级所需经验：L=1～9 为 `200L−100`；L=10～98，令 `x=L−10`，为 `ceil(1900+10x+0.5x²)`。旧 Lv.1～10 门槛不变，Lv.10 为 8,100 总经验，Lv.99 为 331,904。历史经验及旧满级后累计经验保留，满级继续累计，不设每日上限。食谱要求等级可配置 1～99；基础经验和体力独立配置，不随要求等级编辑自动改变。品质规则版本 1 固定，无全局算法编辑面板。

## 材料策略与原子执行

模型选择兼容 `recipe_id/quantity`，新增 `ingredient_strategy`：`low_stars_first`（日常制作）、`high_stars_first`（精品制作），缺省低星优先，同星 FIFO。同一食谱每计划只选一条，合计最多六份。

查询提供两种策略最多六份连续材料分配、平均星级、五档概率／价格／经验、材料机会成本及预期收益。连续预览逐份消耗模拟库存，概率按查询时等级估算。预期收益枚举所有星级，挂牌溢价不计入保证收入；使用库存也有机会成本。原有 `sale_price/experience/ingredient_value/processing_gain` 是一星基准估算；新品质字段在 `quality_previews`。

确认计划按模型选择顺序统一校验材料和总体力，跨食谱不得重复使用资源，无效计划最多纠正一次。持久计划冻结食谱、品质规则、材料基础价值及每份材料分配。每份短事务复核授权、锁、旅行、等级、体力、精确库存记录和 FIFO 批次，原子提交原料、成品、经验、体力与事实。材料变化停止剩余份数，不自动替换；中断保留已提交结果，剩余停止。

`ingredient_value` 指被消费原料价格批次的回收机会价值，不是市场溢价采购成本。`processing_gain=成品实际回收价值−ingredient_value`，预期收益使用同一口径。

## 库存、接口和界面

保留 `dish.<recipeId>` 和图片关联，`source.stars` 为 1～5，与 normal/gold 品质独立。不同星级分格，同星保留来源隔离和 FIFO 价格批次。托管、部分成交、购买、撤单及回收保留星级与批次价格。图鉴仍是基础食谱条目，提供各星级数量和参考价值；已有库存回收值仍取自身批次。

食谱规则编辑对无效参数返回 HTTP 400 及原 code/msg/data 错误契约。现有食谱查询接口增加两种材料策略的逐份预览；历史接口增加实际星级、单价、材料均星、用料策略、材料价值与加工差额。现有 API、Hook 自动传递扩展类型，不新增制作入口。食谱详情只切换预览，由居民实际决定用料；居民属性和图鉴显示厨艺 /99，规则编辑区分基础经验与一星价格。背包、图鉴、每日活动、市场与制作历史展示星级，挂牌价和回收价分开展示。

## 迁移和 WebDAV

执行 `system_settings.0056_dish_stars` 为旧美食库存及有效托管库存补一星，不改变 ID、数量、来源、原价格或历史事实。历史事实缺省一星，旧确认计划继续一星产出与原经验；新计划启用品质规则。

同步元数据升级 `cooking_schema_version=2`，保存烹饪域、品质制作与品质计划清单；完整性指纹覆盖库存、托管、交易、成长、制作、体力及新品质计划。新版缺少关键字段、整个品质记录或计划时拒绝恢复。恢复校验实际随机结果、星级、单价、原料价值、加工差额与经验链，不重放制作。

旧快照先按原完整性验证，再补一星，最后刷新烹饪和市场指纹。烹饪时间字段兼容序列化后的零毫秒表示（`.000` 与无小数部分等价），原始来源与恢复后的资产均需通过指纹检查，不放宽缺失或篡改校验。WebDAV 三方合并分别验证两个来源及合并结果，内部恢复携带从合并数据生成的二期清单，不为混合冲突资产重造烹饪指纹。现有农场状态／周期指纹继续使用原验证链，不重抽农作物或肥料报价。锁、许可、凭证、线程和临时界面状态不同步，恢复继续关闭自动运行。

上线前备份，全部同步端升级并执行迁移后再使用版本 2。此次未迁移正式数据库，未部署；真实模型决策、双设备 WebDAV 需单独验收。

## 平衡报告

运行 `.venv/bin/python scripts/analyze_cooking_quality.py` 可复现全部 20 食谱在 Lv.1/10/25/50/75/99 的枚举结果。低星方案为全一星材料，精品方案为五星农作物加普通一星畜产品；原料价值按默认回收单价逐个取整。不计挂牌溢价，低于解锁等级的行只作为算法对照，不表示当时可制作。

例如烤土豆：

| 厨艺 | 一星土豆原料成本 | 一星材料预期差额 | 五星土豆原料成本 | 五星材料预期差额 |
|---|---:|---:|---:|---:|
| Lv.1 | 36 | +11.63 | 80 | −21.04 |
| Lv.50 | 36 | +23.66 | 80 | −7.10 |
| Lv.99 | 36 | +33.88 | 80 | +4.65 |

五星材料提高品质和经验概率，但机会成本更高，不能保证制作比直接回收更划算。烤土豆在厨艺提升后可出现精品加工净值由负转正；其他食谱含一星畜产品，精品材料均星也未必达到五。

成长采用逐级期望经验近似：始终制作已解锁的最高期望经验食谱，原料和体力无限、每份一个结果，不计备料、货币、日程阻塞或随机偏差。

| 用料 | 估计总份数 | 每日1份 | 每日3份 | 每日6份 |
|---|---:|---:|---:|---:|
| 全一星 | 2984.2 | 2984.2天 | 994.7天 | 497.4天 |
| 五星作物＋普通畜产品 | 2744.9 | 2744.9天 | 915.0天 | 457.5天 |

该表不承诺完成日期；真实成长还受原料供应、体力和居民选择影响。本期不因统计结果自动修改公式。
