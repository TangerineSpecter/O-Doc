# Agent 炼金与药水

> 本文说明仓库当前实现中的炼金制作、熟练度、药水携带与战斗自动使用规则。生活日程和执行总入口见[Agent 世界统一生活执行说明](./Agent世界统一生活执行说明.md)；冒险准备、回合与结算见[Agent 迷宫探索与战斗说明](./Agent迷宫探索与战斗说明.md)；持久数据、恢复和迁移见[数据同步逻辑说明](../数据同步逻辑说明.md)。

## 当前范围

- 固定 10 条稳定 ID 的炼金配方；图鉴只查看配方和药水，规则编辑只允许修改现有配方的等级、经验、体力及材料种类和数量，一星价值根据材料自动计算，不提供新增或删除配方。
- 素材只来自迷宫掉落（`combat.material.*`），不读取农牧场作物、畜产品、美食成品或市场托管库存。素材没有星级，按战斗目录中的素材等级折算 1～5 品阶参与品质计算。
- 药水为一次性战斗药剂，商店不出售，只由炼金产出；成品复用 Agent 世界共用背包、库存价格批次和居民市场挂牌，并按星级分格；系统商店不回收炼金成品。
- 制作由生活日程的内置活动自动执行。服务端按未被其他安排预留的库存、等级和体力生成候选，模型逐轮选择配方、瓶数、是否继续；不能改写配方规则、星级、经验或产出。没有稳定 HTTP“立即制作”入口，手动执行复用同一套决策和执行器。
- 每次活动最多 3 道不同配方，每道 1～5 瓶，总计最多 15 瓶；每瓶消耗 1 体力和配方材料。

- 配方要求等级依次为 1～10，高阶配方的实际门槛来自深层迷宫素材的掉落，而不是高等级。
- 2～5 星的效果与基准价值分别乘 `1.15 / 1.3 / 1.5 / 1.75`；炼金经验按 `1 / 1.1 / 1.2 / 1.3 / 1.4` 放大后向下取整。百分比效果保留一位小数，恢复量和护盾实际点数向下取整且至少为 1。
- 一次性状态按药水分组写入战斗状态；同一配方重复使用会替换自己的状态，不影响其他来源的强化。元素强化按百分点累加，仍受战斗目录的元素上下限裁剪。
- 净化只移除已有的持续伤害和负向修饰状态，并写入 3 回合免疫；不改变技能施加负面状态的既有规则。

## 星级与品质

素材等级映射品阶：1～9 → 1 阶、10～19 → 2 阶、20～39 → 3 阶、40～69 → 4 阶、70 及以上 → 5 阶。材料品阶按“数量 × 目录基础价值”加权：

`A = Σ(数量 × 基础价值 × 材料品阶) / Σ(数量 × 基础价值)`

居民炼金等级为 `L` 时，每次星级试验的成功率为：

`p = 0.04 + 0.46 × ((L−1)/98)^0.8 + 0.25 × ((A−1)/4)`

成品星级为 `1 + Binomial(4, p)`，范围 1～5 星。每瓶用稳定操作键和品质规则版本生成确定性结果：同一操作键重试或恢复不会重抽；计划预览只展示概率分布和各星单价，不提前抽取结果。

一星基准价值等于确认计划时各素材数量乘当前目录系统回收价之和，二至五星按倍率向上取整；价格写入新库存批次。材料以居民集市高价买入或使用旧库存批次时，实际材料成本可高于或低于此基准，不能保证盈利。既有已确认计划、旧库存和历史事实保留原价格，不追溯重算。炼金药水不能卖给系统商店，可由居民自行挂牌，成交价与基准价值可能不同。

## 炼金熟练度

炼金经验绑定稳定居民 ID，居民改名不重置成长；等级纯派生，不单独落库。上限 99 级，满级继续累计经验。

- Lv.1～9 的逐级门槛为 `200L−100`。
- Lv.10～98 的逐级门槛为 `1900 + 10x + ceil(x²/2)`，其中 `x = L−10`。
- 到达 Lv.10 需累计 8,100 经验；到达 Lv.99 需累计 331,904 经验。
- 配方要求等级、基础经验和体力可单独配置；一星价值随材料和数量自动计算；修改要求等级不会自动调整基础经验或体力。

## 制作计划与事务

铁匠铺登记的活跃打造目标保护其当前配方所需材料。已有炼金计划先占用材料；新炼金计划只读取扣除打造目标需求后的余量，目标完成、失效或配方调整后实时重算。已确认炼金计划执行时仍按自身计划及其他已确认安排复核，不因之后登记的目标失去原预留。

1. 日程选中炼金后，读取居民迷宫素材、炼金等级、体力和制作偏好；扣除其他未结束炼金安排尚未制作的材料需求，再生成可制作候选。
2. 通过 `alchemy_recipe`、`alchemy_quantity`、`alchemy_continue` 逐轮决定配方、1～5 瓶和是否继续，最多 3 道不同配方；每轮更新模拟材料和体力，不枚举组合。候选提供材料需求、已有药水数量和一星效果参考。素材没有星级，不询问用料星级策略；唯一候选由代码直接确定。
3. 确认的规则、瓶数和总材料需求保存到版本化 `LifeItem.context.alchemy_plan`，形成软预留，不扣背包。执行阶段沿用该计划，排除自身后复核其他日程预留，再为每瓶冻结材料（库存 ID、SKU、数量、批次价格）、品质规则和基础价值到 `WorldAction.snapshot.plan`，不重新询问模型。手动执行也先扣除其他日程预留。
4. 执行时按瓶顺序提交短事务：校验居民授权、执行锁、旅行状态、等级、体力、材料与计划一致 → 扣素材 → 定星 → 成品入库 → 加经验 → 记录体力事实。任一环节失败整瓶回滚，不影响已成功瓶数。
5. 幂等键为 `机会ID:瓶序号`；相同键返回原结果，不重抽品质或重复发奖。计划外配方、已被其他业务改动的材料或批次价格不一致都会停止剩余瓶数，不自动替换材料。

有已确认计划的生活日程按剩余计划总体力复核启动条件；旧安排没有计划时，门槛取当前材料和等级满足的配方中最低单瓶消耗。默认单瓶计划只需 1 点即可启动，不再额外要求 2 点。完整计划及每瓶提交均校验实际体力和其他日程材料预留。取消或结束释放未执行需求；失败重试只保留尚未成功的瓶数，重新规划清除原计划与预留。

软预留池仅加载日程 ID 与上下文，并批量统计所有相关执行键已制作的瓶数；每瓶提交仍重新读取预留，避免复用过期库存。其他未结束日程的计划无效时，错误明确指出对应日程 ID，须取消或重新规划该日程；不会静默跳过并释放无法解释的材料需求。旧日程的体力预检只查询等级、材料数量和配方规则，不生成图鉴或品质预览。同步清单先校验字符串元素类型，再比较完整清单，混合类型或重复项均以同步校验错误拒绝恢复。

## 冒险携带与自动使用

- 出发准备阶段由服务端从背包现有药水生成候选（配方 + 星级 + 持有量 + 效果摘要），携带上限 5 瓶，与普通红药、蓝药合计 20 瓶的上限分开计算。底层准备计划支持显式携带清单；当前结构化准备尚无炼金携带选择步骤，未给出清单时按固定优先级（治疗 → 法力 → 护盾 → 防御 → 再生 → 净化 → 攻击类）自动挑选。
- 出发时按“同配方 + 同星级”精确扣库并把清单、效果、单价、触发条件和剩余数量冻结进 `Exploration.snapshot.elixirs` 与 `state.elixirs`，之后修改配方规则不影响已出发冒险。
- 战斗中每回合在常规行动前判定；任一次使用后进入 3 回合共享冷却（与红蓝药的 2 回合冷却独立），同一回合最多使用 1 瓶。
- 生命/法力/负面状态类按阈值触发；攻击类（狂暴、秘法、烈焰、星辰）只在遭遇精英或 Boss 的首回合触发，每场遭遇最多一次，普通怪战斗与寻敌阶段不消耗。
- 同回合有多瓶满足条件时按固定优先级选一瓶，保证快照恢复后重放一致。
- 结算时按出发冻结批次的 FIFO 顺序视为已使用前面的瓶子，未用完的尾部瓶子按原星级和各自价格批次返还背包，不使用当前或默认目录价。返还复用 `<冒险ID>:elixir-return` 操作来源，由冒险终态保护重复结算；已消耗部分在提前召回、倒地、体力耗尽时都不返还。战报和结算结果记录携带、消耗与返还数量。

## 图鉴与接口

- `GET /api/agent-world/alchemy/recipes/`：返回配方列表、材料目录、携带上限和可选居民的熟练度投影；带 `agent_id` 时额外返回材料持有量、可制作状态、最大瓶数、五档效果、星级概率、分星持有量和制作次数。
- `GET /api/agent-world/alchemy/agents/<agent_id>/`：熟练度、经验条、累计制作瓶数。
- `GET /api/agent-world/alchemy/agents/<agent_id>/history/`：分页制作历史，含配方、星级、材料价值、加工收益、经验变化和体力。
- `PATCH /api/agent-world/alchemy/recipes/<recipe_id>/`：修改等级、经验、体力和材料数量，一星价值根据材料自动计算；材料 SKU 必须是现有迷宫素材且不重复。
- 图鉴接口只读，不在 GET 中建立熟练度或目录记录；配方只有 10 条，一次请求返回全部投影，前端按 15 秒轮询并在页面隐藏时暂停。
- 炼金药水只在「炼金图鉴」展示：物品图鉴目录接口不再返回 `elixir.*` 条目，背包中的 `elixir.*` 行也不回填到物品图鉴，避免两处重复且图标只维护一份（药水图标仍存于 `AlchemyCatalog.item_icons`）。

## 背包、市场与同步

- 成品稳定 SKU 为 `elixir.<recipeId>`，库存 `kind='elixir'`、`source.stars` 为 1～5；不同星级分格，FIFO 扣减保留各自价格批次。出发扣库、结算返还和制作入库共用现有 `inventory_stock`。
- 商店不出售炼金药水；系统商店不回收炼金成品，居民市场挂牌沿用共用背包与价格批次，不新增物品表。
- 炼金持久数据纳入 WebDAV：`AlchemyCatalog`（配方规则与药水图标）、`AlchemySkill`（熟练度）、`AlchemyOperation`（不可变制作事实）和 `AlchemyIntegrity`（资产指纹）。同步版本为 `alchemy_schema_version=2`，新增 `alchemy_schedule_plans` 清单并校验日程计划的规则、材料汇总和居民归属；兼容无日程计划的旧版本 0～1，旧客户端拒绝新版快照。原有校验覆盖配方身份、居民/账号关联、材料 SKU 与数量、制作事实与库存/体力事实的引用关系。
- 战斗同步协议升至 `combat_schema_version=9`，新增携带清单、冻结效果与 `elixir_version` 校验；缺少新版关键数据或指纹不一致时整包拒绝恢复，不做部分导入。旧快照没有炼金字段时按“未携带”处理，不重算已结算冒险。
- 升级涉及迁移 `0080_alchemy`，执行时机、备份要求和多设备升级顺序以[数据同步逻辑说明](../数据同步逻辑说明.md)为准。仓库规则不证明用户正式数据库已迁移或双设备同步已验收。

## 未验收事项

- 真实内容目录下的长时间多日闭环、双设备 WebDAV 同时恢复、以及真实模型携带选择仍待人工验收。
