# 日程规划中的组队探索预约

2026-10-25 本地实现。迁移0094新增每日协调与预约；战斗同步升级15，真实模型、生产迁移部署及双设备WebDAV另行验收。

## 规划与配对

逐个居民的整日日程请求附加独立探索意向：是否参加、合法地点、30／60／120分钟及理由。不把探索放入主日程六类次数，也不由模型选择出发时间。意向写入按账号／上海日期唯一的 `AdventurePlanningDay`；同日普通重试复用答案，旧检查点缺少意向时只补问探索，不重排已确认主日程。补问失败每5分钟重试，三次失败则本日不预约；居民忙碌不计失败。

同批居民日程都完成或已达到现有失败终态后，代码按地点统一配队；协调结束前不发起该账号当日新的自由活动选择，主日程继续。每队2～4人，优先覆盖更多居民、减少队伍数量、均衡人数、分散相同职业，再选较早时间，以居民稳定ID打破同分。6人分3＋3；同职业不禁止组队。

每队选择唯一最高票时长，平票则30分钟。先找能容纳“10分钟准备＋投票时长”的最早共同空档；时长、额度或体力不可行时再试30分钟，并尝试其他人员组合。仍不成队或落单不创建单人预约，也不跨日顺延。已出发／已完成的本日预约不重复配队。

共同空档排除现有主日程、长活动、执行租约和预约。未知结束时间的主日程保守占用到下一时段或当日活动窗口终点，不凭空当作瞬间完成；未知结束时间的在途长活动保留整个剩余窗口。体力预测沿用既有恢复与承诺模型，并保留所有主日程资源。

## 预留、准备与出发

`AdventureReservation` 和各成员独立的 `LifeItem` 在同一事务保存。安排来源为 `reservation`，列表与详情显示地点、成员、各自投票、准备／出发／返回时间及状态，不占主日程或自由活动次数。

自由探索剩余额度＝每日上限－当日实际探索用量－尚未实际消耗的预约预留。200分钟上限、预约120分钟后自由可用80分钟；两次30分钟后剩20分钟，不提供最低30分钟的自己出发，途中加入仍须至少10分钟且不能超额。默认每日上限仍为120分钟。

预约保护准备至返回的完整时间段；体力按既有规则预留，不提前扣款或体力。出发、加入、推进、恢复、自由候选和自动消费共用预留查询；本人预约执行排除自身预留，其余预留必须继续保护。开始后只保留尚未实际发生的时长／体力，避免实际用量和预留重复计入；取消或终止释放未用部分。

出发前10分钟创建真实准备请求，固定地点与时长，跳过冒险方式和地点／时长的模型选择；美食、战术、药剂和装备继续逐项准备。准备完进入 `waiting_reservation`，释放执行租约，不立即出发；准备物资禁止被其他库存消费、出售或托管用尽。已成交采购即使取消也保留在本人背包。

到点复核任务、活动授权、区域、转职、休整、体力、额度及主日程占用。未就绪或失效成员退出；至少两名就绪成员才能在同一事务扣资源、全部入队后生成第一波，不形成单人首波。不足两人取消整队，不改成单人或自动推迟主日程。调度延迟保留原返回时刻，剩余不足10分钟取消，不补打离线回合。

主日程人工改期、活动变更或取消会撤销受影响的未出发预约，并重新协调；明确重新规划才重问该居民意向。已出发队伍不重新配对，沿用原探索召回入口。预约卡片可取消整队；恢复后的未出发预约可通过详情“恢复本机预约授权”重新授权，仍不延长原时间。

## 同步与接口

两张新表、各成员安排、逐题准备快照、投票、执行关联均同步；`LifeIntegrity` 覆盖新表，成员安排保存预约修订号。来源、合并及恢复均校验完整队伍、归属、日期、时间、成员唯一性、地点意向、修订和实际探索关联；分叉拒绝拼接，需选择完整设备快照。

沿用生活日程接口，增加 `source=reservation`、`counts.reservation`、成员条目的 `reservation` 摘要和 `explorationPlanning` 每日意向结果；取消和恢复授权复用条目 `cancel`／`retry`，预约不能单独调用 `replan`。每日活动时间线展示已确认预约或取消这类真实安排事实，不把计划写成已获得经验或奖励。

新表由通用快照模型发现进入导出／导入；旧快照仅在两张新表确实为空时补空表摘要。战斗同步15让旧代码拒绝新格式；本机 `CombatRuntime` 授权不随同步复制。重复恢复不问模型、不采购、不扣款、不自动出发。已开始探索和历史收益不重算。
