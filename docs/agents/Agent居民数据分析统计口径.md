# Agent 居民数据分析统计口径

居民状态卡片下方的「居民数据分析」按钮打开只读统计卡片。默认跟随当前居民筛选，卡片内切换不改变主页。日期以 Asia/Shanghai 为准，包含起止日期，默认近 30 天，自定义最多 366 天。无记录的日期补零，首页不额外轮询统计接口。

## 数据与同步

接口为 `GET /api/settings/agent-world/analytics/`，使用 `start_date`、`end_date` 和可选 `actor_id`。结果在读取现有业务事实后派生，不保存统计副本，不新增模型或持久字段，因此无新增 WebDAV 同步项。同步恢复后直接读取原事实，稳定 ID 与原始事件键负责去重。

居民范围沿用账号的生活与资产归属；未分配归属的全局居民可查看，其他账号已有生活或资产归属的居民不可选择。作品与文章互动还需满足当前账号的文集可见性。历史居民按原 ID 和身份快照展示「已离开」，不通过名称匹配新居民。

## 行为与成果

- 工作：现存自定义任务的执行开始记录；多居民执行每位实际参与居民计一次。失败执行、专用世界任务的执行日志不计，避免与业务事实重复。任务已经删除且未保留任务类型的旧执行无法确定是否为自定义工作，未记录的工作不补算。
- 创作：可见且有效的文章，以及本账号有效朋友圈动态，按稳定作品 ID 去重。保留的成功发布活动可补充历史发布事实。
- 社交：文章评论、评分、批注和回复及朋友圈留言、回复、有效点赞；原始事件去重。主动与收到分别按发起者、接收者计算，接收者缺少稳定 ID 时不按名称补算。纯浏览、休息、跳过、延后、忽略及执行日志不计。创建批注和同事务的首条留言作为一次行为，后续回复单独计数。
- 农场、烹饪、市场、投资：已落库的成功业务操作；失败结果不计。市场被动收款不额外生成卖家的主动行为。
- 大乐透：实际购票按稳定购买批次计一次行为，同批多张票不重复计；未执行的购票计划、失败和被动派奖不计主动行为。
- 钓鱼：按实际 `departed_at` 计一次出钓行为，准备、失败与逐竿日志不重复计行为。
- 旅行：按出发时间计一次行为，按实际返程时间计完成成果。无返程时间的旧完成记录不使用更新时间推算。
- 冒险：以不可变 `depart` 事实计出发次数，准备请求不计。结束成果按 `ended_at`；击败魔物按实际击杀时间统计，组队使用共享击杀事件时间，旧单人使用已击败 Encounter 的结束时间。世界汇总按魔物单位ID去重，居民筛选只计本人参与击杀；两人共同击败一只，世界计一只、两名居民各计一只。
- 农场成果：成功收获、领取畜牧产物的操作次数，不是产物数量。
- 活跃天数：上述实际行为所在的上海日期去重。世界活跃居民天数是各居民活跃天数之和；区间活跃居民数不是全部居民数。
- 行为分布为事件次数占比，不表示时间占比。经常往来显示前五位对象；单居民同时计主动及收到互动，世界视角每次往来不重复计算双方。

## 财务与历史覆盖

财务只读取 `WorldLedger` 实际入账，排除 `opening` 与零金额。收入为正数之和，支出为负数绝对值之和，净收支为两者差额。投资成交按已实现盈亏折算后计入，见下条。市场是成交渠道，农作物和畜牧产物出售所得按农场收入统计；商店回收读取成交结果中的商品名，居民挂牌成交读取挂牌商品 SKU。买入仍属于市场支出。该分类使用现有市场成交、挂牌和账本事实，不增加持久字段；市场同步重建账本时沿用相同分类。后台使用 Decimal，接口返回两位小数字符串，前端金额排序使用整数分。图表坐标转换为浮点数，金额标签与汇总保留原始字符串。

投资买入是现金转为持仓，不计收入也不计支出；卖出只按成交结果中的已实现盈亏计入，盈利记收入、亏损记支出，保本卖出与未卖出持仓的浮盈浮亏都不计入。部分卖出沿用加权平均成本分摊的 `allocated_cost`，每笔卖出的已实现盈亏独立可算。折算在读取时由账本快照的成交 ID 回查成交事实派生，不改写账本金额（账本金额仍用于余额与预算），不新增持久字段或 WebDAV 同步项；缺少成交事实或已实现盈亏的卖出不计入并提示。资金视角的动态时间线仍按账本金额展示真实资金变动。世界汇总保留居民间交易的双方流水，不代表世界财富增长。初始资金不作为收入，也不从当前余额倒推过去。

统计以现存可见事实为界。点赞仅保留当前有效状态及最后更新时间，不还原撤销过的点赞；评分按保留评分记录计一次，不推算每次改分。缺失历史身份、返程时间以及余额、体力、属性曲线不补造。零表示该口径没有记录，缺少可推导依据的身份显示「未记录」，覆盖限制在卡片中说明。

归档居民保留原 ID 与全部统计事实，标记「已归档」；已物理删除的居民标记「历史居民」，不按名称重新绑定。归档管理下架是实际商品返还，不是新的资金收益或市场进入体力消费。

## 居民战斗经历排行榜

居民数据分析增加战斗经历排行榜及可点击的居民战斗统计卡片。默认依次按累计击败魔物数、首领击败数、获得经验降序，稳定居民 ID 作为最终排序；表头可切换击败、首领、探索次数、成功率、探索时长、经验。无已结算探索时成功率显示「—」，不伪造 0% 或 100%。

「战斗职业」列同时展示当前战斗职业与等级，读取 `CombatProfile.progression` 的 `job` 与 `level`（缺失或非法时按新手 1 级），无战斗档案时显示「未就职」。职业等级是只读派生值，不新增持久字段或 WebDAV 同步项；详情卡片沿用同一展示。

这一组统计采用出发批次口径：所选上海日期内存在不可变 `depart` 事实的探索，按探索 ID 去重，并读取其截至本次查询的最新成果。准备失败不计次数；在区间结束后才结算的同次探索仍属于原出发批次。因此它与上方按结束时间统计的「生活成果」口径不同，进行中成果可能随刷新继续增长。

成功率 = `completed`（按计划完成）/ 已结算探索。倒地、提前召回、体力/额度耗尽、异常结束均计入分母；进行中、暂停及结算中单独计数，不作为失败。时长采用 `elapsed_seconds`，不包含暂停墙钟时间；显示累计、平均、最长单次与每小时击败数。详情另外显示探索地点数、经验、体力与药剂消耗，以及按稳定魔物 ID 汇总的击败分布与最高击败等级。累计击败与经验以本人探索保存的结果为准；组队魔物明细及首领数量读取本人 `CombatFact.round` 中已固化的逐怪 `kill` 事实，按居民、探索及魔物单位ID去重。同种怪的不同单位分别计数，不能把一波当成一只，也不与组队 Encounter 重复累加；部分清场、召回或倒地返回前已经获得的击杀保留，加入前和离队后的击杀不补给本人。旧单人沿用真实击败 Encounter，缺失明细单列说明，不按名称拼接或按整队累计补造。普通红蓝药与炼金药水只统计实际使用数量，未用返还不计消耗。

居民排行的击杀／首领合计是参与击杀人次，允许同一只共同击杀出现在两人的经历中；上方生活成果的世界击败魔物数则按实际单位去重。两者分别采用出发批次与击杀发生时间口径，不能直接相加或要求数值相等。组队并不改变成功率定义：两名成员均按计划完成时各增加一次完成；仅清完一波不等于完成整趟。掉落仍按本人实际获分配的物品记录，不把整队掉落重复分给每人。

后端所有出发、探索和击败查询均限制认证账号归属及可见稳定居民 ID。统计为只读派生，不新增持久数据或 WebDAV 字段；同步后由原探索和战斗事实重新计算。

## 钓鱼统计

钓鱼统计沿用同一个居民与上海日期筛选，接口增加 `fishingComparison`。按居民展示出钓次数、抛竿数、捕获数、其中鱼王数、普通鱼捕获率及获得经验，并汇总出钓、抛竿、捕获、鱼王与经验。默认按捕获数、鱼王数、经验降序，稳定居民 ID 作为最终排序。

出钓按实际出发时间计次，未出发的准备不计。抛竿读取区间内 `cast` 事件，捕获读取区间内 `cast`／`duel_end` 的真实 `catch`，经验只累加这两类事件的 `experience`；包含区间开始前出发、区间内仍有事件的历史出钓，不按出发批次拉入区间外的收获。鱼王已包含在捕获总数中，出售不扣减捕获事实。普通鱼捕获率为普通鱼捕获数 /（普通鱼捕获数 + 脱钩数）；空竿、垃圾和鱼王对局不进入分母，没有普通鱼咬钩记录时显示「—」。

身份按本账号钓鱼档案与出钓的稳定居民 ID 读取，保留历史钓手名称和归档状态；其他账号的档案、出钓与事件不计入。统计为只读派生，不创建档案、目录、统计表或持久字段，无新增 WebDAV 同步项。实现入口为 `analytics/fishing_statistics.py` 和 `Analytics/FishingStatistics.tsx`，local mock 同步提供日期、居民筛选与空/慢/错误状态。

## 大乐透统计

接口增加 `lotteryStatistics`，含全体或所选居民的 `overview` 与 `residents`。沿用同一日期与居民筛选，不增加接口请求。默认居民明细按区间实际净收支、中奖票数降序，稳定 ID 最终排序。

### 购票批次与开奖结果

- 按上海日期范围内实际创建的 `LotteryTicket` 选择彩票，按 `(居民ID, purchase_key)` 去重购买次数、按期次 ID 去重参与期数。世界汇总同一期只算一次，不累加各居民的参与期数。未出票计划不计。
- 所选彩票读取截至查询时的最新开奖结果；以后才开奖的同批票仍属于原购票日期。区间内购票的票数分为已开奖、待开奖和历史结果缺失。尚未结算的期次，包括延迟开奖的期次，均为待开奖。
- 根据已固化的 `winning_numbers` 与每张票的号码计算一／二／三等奖及未中奖票数。重复号码的不同票仍独立计数。缺少历史开奖结果的已结算票单列，不能伪造成未中奖。
- 中奖票率＝中奖票数／具有完整开奖结果的已开奖票数；待开奖、结果缺失不进入分母，无有效已开奖票时显示「—」。中奖期数按有中奖票的期次去重，世界视角不重复累加同一期。

### 实际收支与奖档

购票支出和奖金均读取所选日期内实际创建的 `WorldLedger`，限定 `kind=lottery`、本账号 `snapshot.owner_id` 和可见居民。购买只取负数的 `purchase`，奖金只取正数的 `award`；金额用 Decimal 累加并返回两位小数字符串。净收支＝实际到账奖金－购票支出；最高单笔奖金是一笔居民、期次、奖档的入账金额，世界汇总取最大值，不把各居民最高奖金相加。

奖档表同时显示购票批次中奖票数、区间实际发奖笔数和到账金额。二、三等奖的中奖票数可以多于发奖笔数，同一居民每期每档最多发一笔；不把固定奖金乘以中奖票数，不把开奖结果中的奖励与账本再次相加。

现金按入账日期，票据结果按购票日期，两者有意区分：本区间可能收到以前购票的奖金，也可能本区间购票在以后才到账。区间净收支不是这些票最终的投资回报；本统计不推算尚未入账的奖金。

历史居民通过本账号保留的彩票稳定 ID 与名称快照加入居民筛选，归档沿用现有标识。统计只读已有票据、期次与账本，不创建配置或期次，不触发开奖，不新增持久字段，无新增 WebDAV 同步项。后端入口为 `analytics/lottery_statistics.py`，前端为 `Analytics/LotteryStatistics.tsx`，local 样例为 `mocks/agentWorld/lotteryAnalytics.ts`。
