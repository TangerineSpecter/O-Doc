# 居民主日程与空档穿插

核对日期：2026-10-22。本文描述本地实现；真实决策连接质量、正式库迁移、双设备接续另行验收。

## 活动边界

| 路径 | 活动 | 执行规则 |
| --- | --- | --- |
| 主日程 | 旅行、农场、模拟投资、发帖、阅读评论、大乐透 | 一次安排居民当天待规划时段；次数为上限，允许留空 |
| 空档穿插 | 美食、炼金、铁匠铺、钓鱼、迷宫 | 先代码预检，再由决策连接选择活动或暂不活动 |
| 独立业务 | 市场、社交、悬赏、小剧场、武道大会、农场队列 | 保留触发方式；有体力消费的自动入口共享保护 |

铁匠铺通过活动注册表接入空档候选，沿用等级范围、部位、类型及逐件继续判断的有限决策流程；与其他四类活动共用空档准入和资源保护。

旧日程及已确认的领域计划保留执行身份。新规划不再生成上述穿插活动的主日程。已选活动对应 `LifeItem`，不占周期分配、不进入遗留机会补跑；实际执行仍参与居民忙碌判断。暂不活动只保留决策检查点，不生成日程卡。

## 触发与检查点

Agent 管理 → 任务分配 → 空档活动 → 空档总开关与节奏，默认关闭。代码预检默认5分钟，活动选择至少间隔30分钟，暂不活动后等待60分钟，均可配置。有效库存、日程、体力消费或恢复规则变化会唤醒预检；不会绕过决策冷却。恢复体力跨过候选门槛由周期预检发现。

主日程优先：世界开启、居民可用且无其他占用、当天必要规划已完成、没有到期主日程才进入穿插。每轮按最早可检查时间处理一位居民。选择与各领域有限决策复用本机租约，避免同时发出无限量请求。没有候选不调用模型；单活动仍与暂不活动一起交给决策连接。

`LifeInterleavingState` 每居民一条，保存阶段、下次预检、下次可决策时间和关联日程。`LifeItem.context.interleaving` 保存版本、稳定机会ID、截止时间、有限选择检查点、资源预测依据及选择用量记录。模型响应保存后才进入领域操作。已保存步骤复用原选项；条件变化使原选项失效时结束当前准备，不重抽另一个活动。

活动选择返回后，若运行许可、居民状态或空档已经变化，尚未创建日程的机会会结束其决策记录，并同时清除阶段与选择检查点，保留原决策冷却。没有关联日程的过期机会独立收尾，不受世界或穿插开关、暂停、退出参与和归档影响；已关联日程的机会继续由原领域执行器负责，已结束的决策记录不会复用为新活动。

连接按现有故障转移顺序切换，全部失败后退避，不使用普通文本模型替代。探索和钓鱼准备保持原业务记录；过期且未出发的准备结束。已开始后延长沿用领域接续与主日程顺延。准备耗时压缩空档时只提供剩余合法时长，探索仅允许缩短，避免反复扩大时长。

## 资源保护

`life_energy` 是纯预测模块，不保存第二份体力余额。它以真实成功消费计算的当前体力为起点，沿恢复设置历史、100点上限和承诺时间线逐项计算。保护当天主日程、已确认的次日日程、农场队列及已接悬赏；未知消耗不视作零。材料、采购和收入只使用真实已有事实。

`life_commitments` 提供承诺查询、当前可用额度和消费复核。制作按数量，钓鱼按逐竿，探索保留原全程体力门槛；药剂采购复用未预留资金限制及市场入场实际体力；若入场会破坏全程体力门槛，则取消可选采购并只携带现有补给。实际消耗汇总包含这次补给入场。农场按已有种子、种植时点和收获时点预测，施肥采用保守预留。现有作物按各成熟时点分组，每批最多四块地预留两点体力；已成熟作物可合批，待领取动物产物同样每批最多四只。当前收获或领取仅替换本批实际目标的预留，播种仅抵扣已经到点的播种预留，不能抵扣其他阶段或未来批次；实际执行仍按原批次计费。

美食、炼金逐份提交，铁匠铺逐件决策和提交，钓鱼逐竿、探索持续消费，以及自动市场、社交、悬赏、农场操作在原事务内复核。已安排主日程优先消费；手动入口保留现有即时校验，之后自动预测重新计算。资源保护不预扣体力。部分制作成功保留真实材料、产物、经验；进程中断接续使用原操作ID和规则，不重复结算。

## 模型输入与统计

主日程采用 `life_main_context` 白名单：上海日期、时段、已确认占用、角色相关偏好、明确用户要求、六类准入摘要、资金预留、恢复规则和代码计算的体力承诺。任务自定义要求单独保留，不机械裁掉影响安排的要求；领域系统执行提示词、完整背包、菜谱、装备、战报及原始长历史不进入活动选择。近期成果按完成次数、发帖标题和对应目标表示。发帖摘要包含冷却和剩余额度，阅读只含候选内容数量。

整日校验按时序保留有效项，仅将冲突项改为不安排。旅行总预算、累计体力、重复农场、发帖冷却及额度分别检查；领域准备、出发和提交仍再次执行权威业务校验。

穿插顶层只传空档、体力额度、偏好、近七日五类活动次数和至多五份领域摘要，不注册业务操作工具。选中领域后才读取具体方案。选择用量建立真实执行记录，关联准备和重试；日程详情汇总该记录和领域执行记录的实际请求数、usage。未知用量保持空值，字符数不换算成Token节省。

目标不再在每次排完日程后额外请求模型。客观目标按真实业务事实核实；主观目标由新成功执行记录触发，并保存记录ID防止重复评估。

## 接口、展示与同步

沿用生活配置及日程接口，无额外立即启动接口。设置增加 `interleaving_enabled`、`interleaving_check_minutes`、`interleaving_decision_minutes`、`interleaving_wait_minutes`。日程增加 `source`、`actual_started_at`、`actual_ended_at`、`actual_energy_cost`、`domain_detail`；详情增加 `activity_usage`。列表批量查询业务事实，缺失值为null。今日日程、周日程和列表显示空档穿插标签，主日程与穿插统计分开。

新增迁移 `0089_life_interleaving`。配置、调度状态、业务记录及检查点都进入WebDAV；线程、执行租约和本机授权不复制。旧快照缺少新表摘要时，只允许补入空表摘要，配置缺省为关闭。来源、合并及恢复核对居民归属、活动、检查点和关联日程；重复恢复不会启动行动。恢复后仍需本机授权。
