# 居民大乐透

核对日期：2026-10-24。当前代码已接入规则、生活日程、决策连接、金币账本及 WebDAV；真实决策服务、正式数据库迁移和跨设备同步需部署后验收。2026-10-24 起新期次使用规则版本2：单张50金币，一等奖起步补贴1000金币，二、三等奖500和200金币。

## 当前规则

Agent 世界「大乐透」查看期次及彩票，Agent 管理 → 任务分配 → 日程任务 → 大乐透启用购票能力，默认关闭。每个账号独立配置、期次和奖池；参与者沿用统一生活运行的居民。购票能力任务仅所属账号可查询，通用任务接口禁止删除该内置任务，能力开关在任务分配中修改。首次启用日期加三天20:00首开，此后每三天20:00开奖，19:55停售，全部使用北京时间。停用再启用不改变起始日期；停用新购买不会撤销已售彩票的兑奖权。

每张50金币，每人每期最多10张。从1～10选三个不同数字，顺序不计，共120种组合。同一居民的不同票可以完全相同，每张均收费、占额度、独立计算一等奖份额。

期次创建时冻结当期规则（票价、补贴及各档奖金）。后续调整只作用于新期次；已开售或已结算期次继续按其冻结值售票、派奖和同步校验，不追溯改票款或历史奖金。

| 命中数 | 奖项 | 发放方式 |
| --- | --- | --- |
| 3 | 一等奖 | 所有一等奖票按张数分配整个奖池，居民金额按其中奖票占比计算 |
| 2 | 二等奖 | 系统额外发500金币，每人每期至多一次 |
| 1 | 三等奖 | 系统额外发200金币，每人每期至多一次 |
| 0 | 无奖 | 不发放 |

每张只计本身对应奖档；居民可凭不同票跨档领取。二、三等奖不扣一等奖奖池，也不参与平分。固定奖励额外发行货币，系统不保证购票收益小于票价。

一等奖奖池＝上期结转＋本期实际售票款＋1000金币补贴。本期有实际售票才兑现补贴，空期不增加。无人中一等奖则全额结转；有一等奖时按居民中奖票数比例计算并向下取整到分，零头结转。页面待开奖奖池按该期冻结规则计算，包含1000金币条件补贴预估，并显式说明这一口径。

## 居民数据分析

居民状态下方「居民数据分析」增加大乐透统计，支持居民及上海日期筛选。展示购票次数、票数、参与期数、已开／待开奖、各奖档中奖票、中奖率，以及实际购票支出、到账奖金、净收支、最高单笔奖金和居民明细。票据按购票日期选取并读取查询时最新结果；资金按真实入账日期统计，二、三等奖不按中奖票数重复发奖。详见[居民数据分析统计口径](./Agent居民数据分析统计口径.md#大乐透统计)。只读派生，无新增持久字段或 WebDAV 项。

## 生活日程与决策

大乐透是普通日程活动，占一次行动机会，不额外扣体力。整日文本规划只增加一份短状态：当前奖池、本人实际持票数、有效待购张数、每期上限、单价及开奖时间；另附本账号最近最多三期已结算开奖中的本人参与摘要（由近到远）：期号、开奖时间、购票张数、中奖张数、最高奖档及实际到账奖金。未参与保留零张，与参与未中奖区分；无历史省略，少于三期按实际提供，历史开奖号码缺失时中奖张数为未知。奖金按本人对应期次实际派奖账本累加，不按中奖票数推算二、三等奖。结合性格自主判断是否安排购票，不强制中奖后增加购买。不附具体号码或他人中奖记录。该摘要只从已有期次、票据和账本派生，无新增持久字段或 WebDAV 同步项。只有当前已开售期次、且目标时段早于停售的安排可选择购票。停售、满额、余额或后续生活预留不足、购票能力关闭、数量或选号决策场景关闭时，代码先排除。

选定购票后，日程保存目标期次。数量模型从代码生成的1～最大可购张数中选择，没有“不买”。上限同时受本人本期已购票、其他有效计划张数及未预留现金约束。确认数量后预留张数与当期票价乘数量的金币；计划本身不扣款，也不是已购彩票。通用预算调整工具及其他日程规划均不能单独改变这笔已确认的购票预算，可保留原金额并调整其他活动；要改变购票意向须取消或重新规划该安排，释放原预留。

到点执行才选号。每张票逐位选择，候选数为10、9、8：后续数字排除本票已有数字，下一张重新从1～10开始。模型收到性格、补充要求、本人本期已有号码、本次选号进度、开奖时间、当前奖池、票价和预算；每次逐位选号还即时读取本账号本期全体居民（含自己）的已出票总张数 `sold_ticket_count`、数字1～10各自在已出票中出现的次数 `number_bet_counts`（含零次），以及最近最多三期已结算期次的期号和开奖号码 `recent_draws`（由近到远，不足三期按实际提供，无历史时不传该字段）。统计只计成功出票，不计待购预留或本次尚未出票的选择；本次选择仍单独放在进度中，不重复计数。不传其他账号数据或所有居民的逐票明细，不加载身份外貌、完整生活状态、记忆或工具。下注分布和历史开奖仅提供选择背景，不预测中奖或强制避免重复组合；模型仍可能选择相同号码。数量决策不额外加载这些选号统计。问题沿用世界决策连接故障转移，新增场景 `lottery_quantity` / `lottery_number`；唯一候选直接选定。

本功能禁止普通文本模型回退。连接失败或无效选择时保留已确认进度，最多三次尝试，间隔5、15分钟；超过停售时间则结束并释放预留。整日活动意向保留，不为购票失败额外请求整日日程模型。决策连接自身的实际Token及费用仍取决于服务，不能将“不调用普通文本模型”理解为供应商免费。

所有数字准备好后，在短事务中复核居民授权、期次、额度、余额和生活预算，一次扣款并创建全部彩票；不静默减少张数或改买下一期。取消/失败释放未使用预算及额度，已完成购票不能撤销。日程详情显示张数、预算、选号进度与失败原因。

## 调度、账本与恢复

世界运行轮询处理到期彩票，独立于居民体力和当时是否空闲；世界自动运行关闭时暂停新的开奖，恢复后按原时间顺序逐期补结算，每轮有处理上限。已停售的计划结束，不补买往期票。代码均匀随机生成开奖号码，开奖、奖金计算、账本、结转及下一期创建在同一事务中完成。

开奖故障按期次隔离，失败期次的结算事务整体回滚，后续轮询重试；其他账号的开奖和停售计划预留清理继续。彩票维护异常会记录账号、期次或阶段信息，不阻断本轮其他居民的生活执行与规划，也不放宽票款和奖金完整性校验。

购票按日程ID形成稳定购买身份，奖票再按该次购买中的序号区分；派奖按期次、居民和奖档形成稳定账本键。重复调用不重复出票、扣款或派奖。居民改名和删除后保留票上的身份快照和历史账本，归档不取消兑奖权。

每日活动时间线从现有金币账本投影购票及中奖事实，流水显示期次、购票或具体奖档，不新增一份活动事实源。

## WebDAV与版本

用户已确认全部业务数据同步：`LotteryConfig`、`LotteryRound`、`LotteryTicket`、`LotteryIntegrity`，以及已有 `AgentTask.lottery_config`、日程中的目标期次/数量/选号检查点、执行记录和金币账本。每期冻结规则与开奖、派奖结果；奖池由实际事实推导。

快照增加 `lottery_schema_version`（当前为2）和 `lottery_owners`。导出、合并来源、合并结果、备份导入及数据库恢复均检查账号、期次链、冻结规则版本、号码、购买时点、每人十张限制、预留额度、扣款、中奖金额和奖池守恒；哈希覆盖配置、期次、彩票与相关账本。版本1快照仍可读取，其期次按冻结的版本1规则校验；版本2快照会被旧设备版本校验阻止。两端同一期有不同开奖结果、同张票内容不同、开户时间不同，或合并后超额/残缺时拒绝提交；即使放宽其他领域完整性，也不放宽彩票资产校验。

选号统计与近三期开奖号码输入从已有彩票和开奖事实只读派生，不新增持久字段或 WebDAV 项；每次新号码请求重新读取。

执行租约和线程沿用现有本机模型，不同步。业务检查点和累计尝试次数是同步事实，不携带跨设备执行权；恢复后世界运行保持关闭，不重新抽号、扣款或发奖。旧快照完全缺少彩票域时按未启用兼容。所有同步设备应先升级到包含规则版本2的应用版本（既有1.4.13与迁移 `0086_lottery` 仍为最低要求）；规则随期次冻结，本次调整不需要新增数据库迁移，旧设备由应用版本校验阻止读取新版快照；继续遵循只在一台设备自动运行。
