# 装备词条前缀命名

普通掉落的白装、蓝装、金装分别根据实际生成的 1、2、3 条词条，组合成一个意象前缀，再拼接基础装备名。基础图鉴仍展示装备模板名称。

例子：力量 → 强壮的长剑；力量＋物理攻击 → 凶猛的长剑；智力＋魔法攻击＋魔力 → 辉耀的法杖；生命＋物防＋魔防 → 不破的护甲。

## 匹配与扩展

纯规则在 `system_settings/agent_world/combat/equipment_names.py`，掉落入口在 `equipment.generate`。用稳定 `affix.*` ID 去重、排序；词条顺序、数值高低、装备等级均不影响相同组合的前缀。不调用随机数，不改变词条、数值、品质、掉落概率或回收价。

匹配顺序：特色组合表 → 单词条名称 → 多词条意象规则。多词条按照攻击、魔法、生存防御、灵巧和幸运五个方向组合，并区分两条与三条词条；多个组合允许共用名称。已有目录全部普通装备词条池的 1～3 词条组合均有命名覆盖。未来未知词条使用“奇异的”兜底，不宣称不存在的元素伤害、抗性或技能。

首领专属装备保留苔冠护符等专名；初始与转职绑定训练装备保留既有名称。后续增加特色组合，只需扩展组合表，避免按本地化显示名匹配。

## 保存与同步边界

生成时只更新已有装备快照的 `name`，同一快照用于 EquipmentInstance、掉落结果、遭遇结果和战斗事实。沿用用户已确认的战斗业务 WebDAV 同步范围，不新增模型、数据库字段、迁移或独立同步数据。命名词库是随后端发布的内置规则，不单独同步。

已有装备和历史掉落保持原快照，不自动重新命名。同步完整性会比较装备快照与掉落来源，单独修改历史装备名字会导致不一致；新名字只用于此次代码更新后生成的普通掉落。刷新、重启与跨设备恢复沿用保存的名称，后续调整词库也不重命名既有实例。

## 验证

`test_equipment_names.py` 穷举普通装备词条池的有效组合，检查命名覆盖、顺序和数值无关性、输入不变性，以及白蓝金生成、首领和训练装备例外、真实掉落规则入口。测试不访问数据库或外部服务。
