# Agent 场景输入与工具治理方案

更新时间：2026-10-23。状态：治理方案已形成；本轮已按阶段落实多类模型输入投影、部分工具边界与入口收窄。整日日程及农场专项已通过隔离数据库、临时媒体和 mock 模型验证；治理整体及真实供应商usage/质量对照仍需分别验收，不能视为生产验收完成。2026-10-17新增已获用户确认的美食日程JSON计划，随LifeItem同步。

覆盖现有 Agent 任务类型：自定义、帖子评论、自主发帖、旅行、农场、市场、投资、料理、探索、随手记，以及其生活规划、记忆、角色与配图辅助阶段；飞书 Agent 对话作为开放能力入口一并列入后续治理。学习、小说等其他应用领域沿用通用规范，另行盘点其请求链路。

代码位置约定：未写目录的领域模块位于 `system_settings/agent_world/`；`agent_role.py`、`agent_task_scheduler.py`、`feishu_im.py` 和角色生成/整理模块位于 `system_settings/`。本文引用的当前代码行为以本次工作区盘点为准。

## 1. 已有规范与本次缺口

已有[模型输入上下文优化规范](../模型输入上下文优化规范.md)要求按阶段投影、删除重复内容、按开放能力加载资源，并把工具 Schema、结果、记忆和重试纳入用量分析。因此此前并非只约束提示词措辞；但缺少覆盖所有 Agent 任务的阶段清单、字段用途、工具开放条件及统一验收记录。

[角色设定与决策路由说明](./Agent角色设定与决策路由说明.md)已定义角色字段拆分与模型兜底。角色投影解决“人物设定传哪部分”，不能自动解决“本次任务传什么业务状态、注册什么工具”。当前 `agent_role.SCENES`、`decision.routing.SCENES` 分别管理角色模块与有限选择路由，也不是全部业务阶段的输入、工具契约。

后续将三项要求分别落实到每个实际请求边界：

| 层次 | 要回答的问题 | 权威位置 |
| --- | --- | --- |
| 角色投影 | 当前阶段需要哪些性格、偏好或表达设定？ | `system_settings/agent_role.py`，沿用已有角色来源 |
| 信息投影 | 哪些动态事实影响本阶段输出，来源、单位、时效是什么？ | 各领域的上下文构造函数及本文阶段矩阵 |
| 工具策略 | 本阶段允许查询或修改什么，什么时候才能开放？ | 场景调用方的工具白名单与执行器复核 |

优化对象是完成一个业务任务的总消耗。不得为了追求更短的单次输入，无必要地增加分类、摘要或工具发现模型调用。

### 2.2 本轮修正与核实

- **发帖规则分阶段**：原选题允许把最多100类完整规则一起传入，仅三项各2000字符的配置字段就可能达到60万字符。现先分类、后单类选题；已选分类完整要求保留，不机械截断；图片配置留在原配置中供真实配图，恢复沿用检查点。
- **旅行预算有上限，不按全部余额盲目列档**：原本就查询已启用且可负担的最高目的地报价；默认种子目录最高价5750时只有约7个金额档。原平铺实现仅在报价配置放大时超过连接255项边界。现在区间每轮最多4选＋不去，细档最多12选＋不去，不先构造巨大列表；区间内连接失败也不会退回更大的全余额范围。
- **装备处置标记原本存在**：结构化准备已按当前持有期跳过`sell/list`。本次修正旧文本准备输入漏过滤；正在穿戴的装备仍可作为比较依据。未新增装备截断、排序或数量策略。
- **商品求购星级与报价**：按用户确认先选真实可负担星级，再以满足星级的最新报价生成上限，不把不同挂牌的最低价格与最高星级拼接。种子、肥料、鱼饵、星级、价格及空装备部位完整序列最多8题，缓存和唯一选项不计调用数。
- **已确认装备意向接入批量市场**：复用既有出售/上架处理器，与其他买卖共享一次入场。挂牌只用有限价格连接，失败保存待处理意向；选择价格保存到同步的市场计划上下文，故障重试不重选。
- **空档炼金调用错误**：修正共用准备函数给炼金传入其签名不接受的`key`。回归调用真实计划函数，验证三题检查点、失败不回退文本模型和重试不重选。
- **钓鱼缩时分支**：已确认的鱼饵与结束选择在缩时后继续沿用，不重新进入第4种鱼饵；时长重选必须严格缩短，并有可重放的原时长与合法候选依据。准备与出发的真实业务记录纳入同步校验。

### 历史投资样本基线

用户提供的同一次投资执行：首轮输入24,292、输出77；工具返回后第二轮输入24,770、输出525，其中缓存读24,320。两轮总输入49,062、总输出602。缓存是输入的子集，不重复累加；第二轮输入比首轮增加478，与该轮工具往返的结构相符。

所提供第二轮请求包含两个初始消息、一次 assistant 工具请求和两条工具结果：`positions(page=1)`、`analyze_stock`。初始用户消息51,340字符；按紧凑JSON单独统计，`life` 为47,205字符，其中种植19,032、料理12,404、最近社交4,321、最近经历4,331。20条经历中7条投资、13条其他任务。顶层账户与 `life.investment` 完全相同，各633字符；当前意图在 `current/upcoming` 也重复。

字符数用于定位字段负担，不可按比例宣称Token节省。请求中已有第一页持仓；提示词仍要求“先检查分页持仓”，容易导致再次查询同一页，应明确快照覆盖范围和刷新条件。

## 3. 每个请求的统一契约

### 3.1 先登记阶段，再构造请求

每个调用方应能明确列出下表内容，可用领域常量、纯函数与文档维护；第一批不建立新的数据库配置平台，也不要求所有流程重写成同一个框架。

| 项目 | 规则 |
| --- | --- |
| 场景与阶段 | 例如投资/持仓研究、旅行/购物；与角色投影名、JEV支持场景和现有统计标签建立对应，不能混为一个枚举 |
| 本阶段输出 | 选择、预算、正文、查询参数或写操作；引用哪些稳定ID，输出由谁验证 |
| 角色与补充 | 采用哪个已有角色投影；用户补充提示词沿用原契约，不能自动丢弃或按字符截断 |
| 动态信息 | 字段白名单、来源、单位、时点、相关历史范围、缺失/未知含义；每项有决策用途 |
| 记忆与技能 | 是否需要、查询主题、数量/体积边界；只装载本阶段使用的技能合同 |
| 工具 | 注册白名单、开放条件、对应执行器与结果投影；无模型工具时明确为空 |
| 限制与恢复 | 总时限、剩余调用、格式修复预算、已确认选择及已完成操作，沿用业务恢复约束 |
| 验收 | 必保留字段、禁止出现的领域、代表场景及实际usage基线 |

模型投影从权威状态派生且不修改源对象；提交仍使用完整服务端状态复核。模型用不到的租约、审计链、图片资源路径、原始网络响应与内部执行元数据不进入请求。模型需要引用的业务ID、来源、数据版本与未知状态必须保留。

查询也应按阶段拆分：活动选择只加载活动摘要；已选择料理才查询可制作候选；已进入投资才查账户与投资经历。先生成所有领域资料再丢弃字段，可作为迁移步骤，不能作为最终的数据加载方案。

### 3.2 工具注册与调用

“Agent绑定了某个MCP”表示可能可用，不表示每次请求都要发送其全部Schema。领域内置函数也适用相同规则。

```text
本轮可注册工具 = 已启用能力 ∩ 居民/任务授权 ∩ 当前阶段允许能力 ∩ 当前业务前置条件
```

前置条件包括完成操作所需的查询和预算调整能力：不能仅因余额暂不足就删掉全部采购能力，也不能因当前有持仓就禁止寻找新投资方向。工具集合应服务于用户意图与业务允许的选择，而非人为压缩合法选择范围。

- 注册和执行使用同一策略。执行器必须拒绝本阶段未开放的工具、详情主题或参数分支；仅从Schema移除、仅写一句“不要调用”均不够。
- 工具定义复用权威Schema，只发送本阶段相关函数、参数与说明。保留类型、必填、枚举、数量边界和幂等参数，不为缩短输入破坏契约。
- 没有工具需求的结构化决策/正文请求，不发现、不注册Agent全部MCP。只检查本阶段依赖的服务；无关服务离线不能使当前任务失败。
- 明确区分模型工具与宿主调用：程序调用搜索、成交、发布、生成图片，不等于这些工具Schema需要进入模型。本文的“无”仅指不向该模型请求注册工具。
- 细节优先由相关分页查询提供；不得把“详情工具”变成绕过阶段边界的全量生活查询。主题、分页、结果字段与对象归属同时受限。
- 已提供完整且适用于当前数据时点的第一页快照时，模型无需为完成形式要求再查同一页；数据不足、发生写入、版本变化或需要其他页时允许刷新。
- 若阶段或状态变更需要新能力，在下一请求边界重算工具集合；现有静态工具循环可先按调用阶段缩小集合，再逐步增加逐轮刷新，不能只更新工具说明而保留过时执行权限。

### 3.3 历史、工具结果和模型兜底

工具结果只提供下一步判断需要的字段。保留写入回执、业务键、实际金额/数量、剩余资源、数据日期和失败原因；原始大响应、已被新版状态取代的只读查询不反复累积。

压缩历史必须成对处理 assistant 的工具调用与对应结果，保持调用ID完整。旧结果被替代时保留简短来源与版本指向；成交、扣款、发布等写入事实不能因压缩丢失。兜底只重建当前阶段，带入已完成操作与最新状态，不能重做整条业务链。

`utils/ai_service.py` 当前会在工具往返中回传供应商返回的 `reasoning_content`。不同供应商协议要求需在适配层分别验证：协议要求保留的当前工具轮次内容应正确保留，不要求的旧轮次内容可按适配规则省去；不能统一删除导致协议错误，也不能把思考文本复制到普通业务上下文或长期记忆。思考开关、强度与输出费用另行优化，本方案不以统一关闭思考作为输入治理措施。

稳定的system、Schema及阶段规则可放在可缓存前缀，变化状态放后；缓存只减少相应处理成本，不能替代删除无关输入。缓存读、思考等细分口径以供应商usage为准，避免重复累计。

## 5. 角色、记忆和跨领域信息的取舍

有限决策沿用 `decision` 或领域既有角色投影；整日日程、预算/复杂计划用 `planning`（姓名、性格、兴趣和补充提示词，日程职业另传一次）；评论、回复、游记与正文用 `expression`；核实/修复用 `repair`；记忆提炼用 `memory`；生图按 `image` 与画面主体规则。现有补充提示词仍只注入一次。不得每轮调用模型重写角色，也不自动从MBTI扩写消费/风险习惯。

居民信息不能按“属于这个人”全装，也不能按“不是账户字段”全删。例如投资纪律、风险偏好、当前意图与已作出的资金承诺相关；农场肥料概率和菜谱无关。社交表达可能需要最近一次旅行或投资结果，但通常只需“时间、实际结果、可引用来源”的摘要。

相关性不能只用任务名过滤：跨任务记录中的明确承诺或尚未履行约定可能影响本阶段。先选有关主题/对象/资金/承诺，再去重、按新鲜度和重要性取代表事实；计划、模型判断与已发生结果分开标记。来源不足保持未知，不能把人物设定补成真实经历。

沿用记忆召回现有上限，不为每个简单核实/购物节点机械召回同一批记忆。近期经历与长期记忆承载同一事实时只保留一处必要证据。调整数量之前先确认用途；一次选择后进入无独立偏好判断的纯执行阶段，不再重复装载全部人物背景。

### 7.2 真实用量与质量对照

使用既有请求用量与受控本机诊断机制，按相同任务、阶段、模型/供应商记录输入、输出、缓存命中、思考、请求/工具次数、失败/修复/降级及业务结果。工具调用数与模型请求数分列；只有供应商usage是实际Token证据。固定前缀、业务数据、工具Schema与历史结果的字符/估算量可作定位指标，不冒充供应商分项计费。

比较完整一次业务任务，同时覆盖JEV成功、JEV失败后普通模型继续、普通模型独立执行和已有写入后失败恢复；不要求为采样制造真实付费交易。优先利用正常运行中的代表请求观察，任何刻意付费对照按实际授权执行。

合格标准：无关输入和重复查询下降，关键候选/来源/时间/预算依据完整，总请求与重试没有因裁剪无故增加，业务边界和表达质量无不可接受退化。未取得真实usage时，只报告投影覆盖、字符变化和隔离验证，不承诺固定节省比例。

### 7.3 同步与留存

本方案的阶段清单、投影和临时摘要为代码/请求派生数据。自定义任务 MCP 白名单是唯一新增持久化配置，已通过 `system_settings.0074` 进入 `AgentTask` 并随 WebDAV 任务快照同步。权威账户、库存、日程、成交、文章、记忆与恢复检查点仍沿用既有数据路径。

后续若新增持久化请求指标或新的恢复字段，按[数据同步逻辑说明](../数据同步逻辑说明.md)确认是否纳入WebDAV管理，并补充默认值、迁移、导入导出及旧设备兼容。完整提示词、思考、原始工具响应不作为常规同步内容；诊断仍遵守本机留存和隐私边界。
