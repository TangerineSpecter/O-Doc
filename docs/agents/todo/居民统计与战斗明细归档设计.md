# 居民统计与战斗明细归档设计

状态：2026-11-02 阶段实施中。本地新增可显式启用的回填保护、来源盘点、已结束组队会话及出钓的每日贡献和同步版本校验，并允许在保护下分批回填；统计接口可合并这些贡献和未覆盖的原事实。WebDAV 强 ETag 条件写入和显式能力探测只是独立基础能力，尚未接入发布或恢复。该阶段不删除回合，仍需其他领域与旧单人统计、各设备完整回填、资产及远端恢复核验和新的七天清理。尚未部署或清理线上数据。现行规则见[居民数据分析统计口径](../Agent居民数据分析统计口径.md)、[冒险历史固化与同步](../Agent冒险历史固化与同步说明.md)和[数据同步逻辑](../../数据同步逻辑说明.md)。下文的完整方案仍是待实施目标。

## 已确认的目标

- 居民数据分析的各领域历史统计采用增量汇总；战斗、钓鱼、农场、制作、市场、旅行、投资、收支、创作和社交等每日汇总都纳入 WebDAV 同步。
- 已结束且完成结算的单场探索，其逐回合明细至少保留至实际结束后满七天；满足覆盖和校验条件后删除，不做可恢复的长期逐回合冷归档。七天是最早可清理时间；同步或来源阻塞可推迟清理，进行中或尚未完成结算的战斗不因年龄清理。
- 单场摘要、胜负、掉落和统计长期保留。资产归属、库存和奖励来源必须能够继续校验；摘要不能替代尚未解决的来源依赖。
- 其他业务的账本、交易、作品、对话和用户可查看的历史，不因战斗的七天策略自动删除。其他明细如需压缩或清理，需先单独核对其业务和同步依赖。

## 当前问题与证据

排查时的旧版 `GET /api/settings/agent-world/analytics/` 每次从原始业务事实计算结果，没有每日汇总；`load_facts` 先读取全体可见居民事实，再应用单居民筛选，部分历史居民身份发现不受日期窗口限制。战斗的发生时点统计和出发批次统计分别读取战斗事实。实际 SQL 可能采用索引或扫描，不能仅凭表行数断言每次扫描了全部历史。本地新代码的部分汇总与回退范围见[现行统计口径](../Agent居民数据分析统计口径.md)。

2026-11-02 排查时，浏览器请求在通用 10 秒时限内未完成；采样捕获了同一数据库连接依次执行农场操作、个人战斗事实和战斗遭遇查询，但采样没有请求 ID，不能单凭连接证明它们属于同一次 HTTP 请求。用户提供的 PostgreSQL 估算显示 `CombatFact` 约 13.6 万行、159 MB，`AdventureEvent` 约 11.4 万行、155 MB；体积包含索引等，时间跨度未知，不能直接推算日增长率。

当前共享战斗每次回合生成共同事件，并为参与居民生成个人事实。个人事实追加时仍会读取该居民的全部探索和遭遇计算聚合指纹，历史增大会影响战斗写入；本地新代码改为逐行生成与旧格式相同的指纹，降低峰值内存，但尚未减少遍历量。共同事件同步校验也会遍历事实。相关入口：`combat/party_tick.py`、`combat/facts.py`、`combat/party_sync.py`。

旧版 `ODOC_COMBAT_ARCHIVE_DAYS` 默认七天，但它不是完整的七天回放保留：存在进行中探索时跳过居民归档；待删除范围包含 `shared_event_id`、打造或大会奖励来源时跳过；旧归档只清理个人 `CombatFact`，不清理共同 `AdventureEvent`，还会删除出发等非回合事实。本地新代码已停用旧自动和手动实际删除，遗留正数配置也不会启用；尚未部署的旧实例仍须核对配置并停止或隔离。

## 统计的写入与读取

### 分层

1. **权威业务事实**：结算、到账、物品归属、作品及可变业务状态沿用各领域权威来源。战斗逐回合是有保留期的细节，不以统计表替代资产事实。
2. **来源贡献和单场摘要**：为已结束探索及其必要的个人、队伍和日期范围生成版本化摘要。保存稳定来源 ID、覆盖边界、统计贡献与校验信息；不为每个无统计意义的回合新增一条长期摘要。
3. **每日统计**：按账号、上海自然日、居民或世界、领域以及必要的怪物、往来对象、可见文集等维度保存聚合值。按日期和居民建立查询索引，金额保持 Decimal 精度。
4. **当前增量**：业务事实或结算完成后以幂等的后台增量更新汇总；每日维护对已覆盖的日期核对和固化。当天及仍在进行的探索也通过已处理的增量和有界未处理部分展示，不在每次打开页面时重扫当天全部回合。

每日汇总、长期来源贡献、单场摘要、覆盖与修订信息均按用户确认纳入 WebDAV。线程、租约和临时处理状态不属于业务统计，沿用本机运行状态。具体模型名、索引和协议版本由实施时确定。

### 增量、修正与范围查询

- 每个输入使用稳定来源标识及版本，增量应用和水位推进在可恢复的事务边界内完成；重复消费、重启和同步恢复不得重复累计。批次限制行数与执行时间，失败保留待处理范围并重试。
- 业务写入与变更捕获必须原子衔接：在业务事务中写入可重试的变更登记，或使用具有等价保证、可重扫的修订序列。按修订顺序及稳定 ID 处理，不能只按事件发生时间推进水位，否则迟到事实可能被遗漏。撤销、硬删除和权限变更须在同一业务事务中产生可同步的持久修订或墓碑，包含定位旧贡献所需的来源键；也可使用能证明等价效果的完整来源清单差异。不能只依赖本机队列或同步仍然存在的记录。跨设备恢复后根据来源清单和修订重新标记待处理范围；运行队列可为本机状态，但业务事实、来源贡献、覆盖信息和必要的删除修订进入同步。
- 业务事实晚到、撤销、修订或可见范围变化时，按来源的旧、新贡献修正受影响日期；不能认为过了午夜就永远不会变。已完成且来源覆盖稳定的日期可以固化，但仍支持有依据的更正。
- 战斗原始回合删除后的更正必须具备可验证的旧、新贡献及其日期、居民和怪物归属，例如仍保留的来源片段，或能与归档检查点核对的完整原始依据。仅有分组总数或哈希不足以还原某次击杀的贡献；证据不足时标记受影响范围待核对并暂停自动更正/清理，不能猜测扣减或宣称支持任意逐怪修正。
- 查询 7、30 或自定义范围时，读取带覆盖水位的每日聚合；若需叠加当前增量，只读取该水位之后、尚未计入且范围不重叠的来源，并在一致性快照下合并。回填、并发查询和重试使用同一边界。缺失、回填中或部分覆盖要显式标记，不能把缺失当成零，也不能为一个尚未回填日期同步重扫全部历史阻塞整个页面。
- 稳定居民 ID、账号归属及文集可见性继续生效。作品与社交统计保留按文集等权限范围分组的信息，读取时按当前可见性过滤；撤销点赞、删除内容和权限变更能修正历史，不泄露不可见数据。
- 相加指标保存计数和金额；成功率保存分子、分母；最长时长取最大值。活跃居民、旅行地点、大乐透期数等跨日去重保留可合并的稳定身份；往来对象保留足够的对象维度，不能只保存每天前五名后再相加。撤销或修订影响最大值、去重集合时，使用来源贡献重算受影响分组或使用可靠的来源引用计数，不能简单减去最大值或移除仍被其他来源引用的身份。
- 战斗按实际击杀日期统计世界去重数量，并按居民本人参与计个人击杀；共同击杀在世界计一次、参与者各计一次。战斗排行继续按出发批次归属，即探索跨日或晚结算时更新出发日的最新成果。彩票按购买批次统计开奖结果，奖励按实际入账日统计。钓鱼事件按发生日期统计。

其他领域逐项沿用[现行统计口径](../Agent居民数据分析统计口径.md#行为与成果)：自定义工作按有效执行开始记录；创作、社交按当前可见和有效事实；农场、烹饪、市场、投资按成功操作；旅行出发与完成分别按实际出发和返程；财务读取有效账本，投资买入不计收支、卖出只计已实现盈亏。各领域的稳定来源键、去重、可变状态及数据缺口须在实施时逐项列出并以现有结果校验。

### 同步合并

按稳定来源实体和确定的覆盖区间标识贡献片段，例如单次探索、共同会话及其日期/序列片段；世界与个人贡献分开。片段保存覆盖范围、规则版本、来源指纹及必要的统计维度。已验证的同一片段在多设备重复同步只计一次，不同片段仅在确认覆盖不重叠时合并。

组队世界击杀以账号及共同魔物单位 ID 为去重依据；个人击杀沿用账号、居民、探索和魔物单位 ID 的既有口径。发生日期取共同击杀事件时间，出发批次取个人探索出发日。归档时在原始来源仍完整的条件下完成逐怪去重，再按会话、日期及可证明不重叠的序列范围固化数量和怪物维度；同一怪的不同居民贡献合法，世界贡献只能计一次。同一居民退出后重入时，以击杀时真实参与的个人事实归属探索；若同一居民/共同单位跨探索出现互相冲突的个人贡献，不能仅因探索 ID 不同就重复累计，应保留来源并阻塞核验。旧单人只有可证明一条遭遇对应一个击败魔物时才以稳定遭遇 ID 计数；来源不完整或不是单怪的情况保留未知，不能假定一行必然等于一只。来源顺序或日期异常导致片段不能证明不重叠时，保留明细并阻塞该范围。

长期贡献以场次、日期和必要的来源范围聚合，不能为每个普通回合永久保留一个贡献或去重标记，否则明细被删除后仍会按回合数增长。奖励、装备等确需保留的独立来源按资产事实保留，不把一般回合全部保留为奖励凭证。

增量队列、来源修订、同步清单和准备快照也必须有可证明安全的压缩或回收边界：待处理记录在贡献已持久化、覆盖水位可恢复后才回收；跨设备必要的删除修订只能在归档标记、旧设备兼容和恢复路径都能承接时合并或清理。不能把每个普通回合的队列、修订、墓碑或快照永久留下，造成明细换表增长。

同一来源出现不同内容时，先验证来源链、覆盖关系和摘要版本；可证明为同一链后续扩展时更新受影响日期，出现分叉或无法证明覆盖时拒绝自动合并并提示修复。不能对两端当日总数直接相加，也不能简单用最后写入覆盖。同步合并后，以已验证的来源贡献重新计算受影响的每日汇总；读取前校验汇总版本与覆盖状态。

删除回合后，摘要和检查点将是相应历史的长期依据。哈希只能保证对已固化内容的完整性承诺，不能在原文删除后独立重现逐回合动作、随机数或 roll 过程；归档前须完成原事实与资产来源核验，并明确这个回放边界。归档标记必须随摘要同步，旧快照不能通过普通合并重新引入已确认归档的事实或覆盖较新的边界。

同步协议需要版本化。正式清理前，所有仍可写入该远端目录的旧设备须升级或停止写入；尚未同步的数据先按[回填前保护](#回填前冻结旧归档与同步裁剪)分别保存、提取，再通过新协议核对合并，不能先使用旧版裁剪路径。不能只依赖新客户端校验来阻止未升级客户端直接覆盖 WebDAV。新客户端持现有远端同步锁后重新读取当前指针与协议版本，在发布时验证预期快照仍是最新，并处理锁失效、续期和旧持锁者迟到发布，确保过期持锁者不能覆盖新结果。若远端不支持可验证的互斥/条件写入、设备未隔离或源头分叉，暂停清理和发布并报告原因。强制覆盖、旧备份恢复和远端回退也须检查版本、归档标记和覆盖关系；无法证明安全时保留原事实，不能静默覆盖。

## 回填前冻结旧归档与同步裁剪

旧版每日维护默认按七天执行，启动后当天也会补做；如果回填期间仍运行，可能先删除尚未固化的 `CombatFact.depart` 等事实。本地新版本默认关闭旧自动维护，但显式正数配置仍会启用。旧版普通同步会按各端最大的 `archive_sequence` 裁剪来源，发布快照也会按本端边界裁剪；本版在发现本机、远端或基准快照的边界内仍有事实时拒绝裁剪和发布。旧版本不受此保护，仍须停止或隔离，仅关闭每日维护也不能阻止旧版同步裁剪。

1. 在任何迁移、回填或可能裁剪历史的同步之前，先识别所有共享该数据的设备、运行实例和远端目录，暂停旧版自动同步、手动同步/强制覆盖及可能执行归档的旧进程或作业；等待正在进行的归档和同步完成或确认回滚。未知设备、无法停止的旧写入或不确定的运行中操作均视为未满足保护条件。
2. 对每个仍需运行旧代码的应用实例，**在其进程启动前**配置 `ODOC_COMBAT_ARCHIVE_DAYS=0`，并核验实际运行进程的配置；重启或容器重建后重新核验。该开关只关闭旧版 `maintain_combat_history`，不阻止旧版手动归档或同步裁剪。保护期间禁止这些旧版写入入口。本地新代码无条件停用旧实际归档，另提供 `ODOC_COMBAT_BACKFILL_PROTECT=1` 拦截本版同步写入；该同步保护默认未开启，必须在每个实例启动前显式设置并核验。旧版本不认识新门禁，必须停止或隔离，不能只依赖新代码的检查。
3. 分别保存并验证各设备数据库的一致性备份及远端当前快照，记录每端的战斗归档边界、来源覆盖和版本。本版 `inventory_combat_backfill` 只读统计本机事实数量和旧边界，但不能核验备份、完整性或其他设备。备份/盘点不得先经过会裁剪战斗事实的旧同步发布路径；在本地、远端和基准版本的差异尚未固定前，不运行旧版 `combat_archive.compact` 相关的合并、发布或覆盖恢复。无法确认备份完整、锁状态或来源边界时，不开始回填。
4. 在保护期间，先从各设备仍保留且可验证的原事实分别提取来源贡献，并按稳定来源、链和覆盖边界合并；不要先执行旧协议的最大归档边界裁剪。若不同端存在未同步事实、分叉或共享来源无法闭合，保留各端原副本并暂停受影响范围。此前已经删除且没有可验证副本的事实标记为历史缺口，不以探索创建时间冒充出发时间。
5. 保护贯穿回填、覆盖校验和新协议切换。新版本恢复同步前须确认各端均已升级或隔离、差异已处理，且不会执行旧裁剪；未完成的范围继续保留来源。只有新归档所需摘要、资产来源、跨设备恢复及清理验收均通过后，才允许新的七天清理接管；不能简单恢复 `ODOC_COMBAT_ARCHIVE_DAYS` 而重新启用旧归档路径。

## 战斗七天保留与清理

### 按场次和来源判断

- 七天从单场探索实际结束时间起计算；暂停、准备、进行中、结算中或没有可信结束时间的场次不得按已结束处理。
- 共享事件只有在相关会话和所有依赖它的个人探索均已结束、各自满足七天保留且来源已固化时才能清理，确保最后离队的居民也有完整回顾窗口。
- 归档前冻结单场身份、职业/地点、参与人数范围、开始和结束、状态、时长、个人及世界击杀、魔物分布、经验、消耗和掉落等当前产品需要展示的结果。图鉴的遭遇/击败集合、时间线人数、个人与世界去重口径也要有等价来源。
- 将必要的装备/材料来源、库存净变化、奖励唯一归属、检查点和来源校验迁移到可长期保留的事实或基线，分别覆盖个人链和共同事件链。不能因为 `CombatFact`、`AdventureEvent`、`AdventureWave` 或 `CombatEncounter` 名称相似而整表、整类盲删；逐波/遭遇记录先检查回顾、图鉴、参与和同步依赖，只有其必要信息已被等价承接时才能纳入清理范围。
- 已归档历史不提供逐回合回放；详情要明确提示回放已过保留期，仍可查看单场摘要。当前窗口内和在途场次的回放接口行为不变。

### 执行顺序和失败处理

1. 先完成[回填前保护](#回填前冻结旧归档与同步裁剪)，再以各端真实保留事实回填摘要和每日汇总，记录每个账号/领域/日期的来源覆盖及未知缺口。已被旧归档删除的内容只能使用仍可证明的来源回补，不能伪造逐怪或逐日结果。
2. 对照旧统计与摘要验证场次、本人/世界击杀、奖励、库存、金额、时间及权限；本场所需来源未覆盖或校验不一致时保留其原明细。历史上不可恢复的其他场次可使整日统计标记为部分覆盖，但不自动阻塞来源完整、互不依赖且已核验的场次；若共享去重或来源边界无法分离，则整个受影响范围暂停清理。
3. 先对可清理场次生成预览，列出来源边界、条数、预计释放空间、缺口和阻塞原因。清理前将包含批次 ID、基准快照、待清理原文、摘要、来源覆盖和准备状态的可恢复快照可靠发布并回读校验；源事实和远端未能保护时暂停。该准备快照是处理中断保护，不是长期逐回合冷归档。从确认准备快照到本机删除及远端提交发布，持续持有有效的远端互斥锁及可防迟到写入的门禁；本机删除提交时重新确认准备快照仍是远端最新指针。锁失效或远端已变化时暂停本批，先恢复锁并合并/重验远端，不能只看本机水位。随后以小批事务持久提交检查点、归档标记和本机删除，再发布并验证新的远端边界；这些跨本机与远端的步骤不能声称是一个事务。校验时记录来源修订和水位，删除提交前在同一锁或条件校验边界内重新确认；业务写入、迟到事实或同步导入改变来源时回滚本批并重算。
4. 任何设备读到准备态时暂停该范围的普通合并和发布，先在有效远端锁内进入恢复流程。若准备快照、原文、摘要和覆盖边界均核验通过，且远端基准未变化，则从这份共同依据幂等完成归档并发布提交标记；不需要猜测原设备是否已做本机删除。若来源、锁或基准发生变化，则保留准备快照并停止自动清理，明确报出冲突，按已验证的数据恢复或重新生成批次，不能无条件把普通旧快照当作回滚依据。提交标记发布前机器丢失时也遵循同一流程；同步导出、导入和清理的并发必须遵守同一覆盖边界。
5. 参与同步设备支持新协议、旧设备已隔离且通过真实跨设备同步和恢复验收后，按已确认的七天策略清理。删除旧回合不重放奖励、不修改余额。记录已归档场次、进度、覆盖缺口、失败和被阻塞原因；异常链或缺失来源只阻塞其关联范围。

准备快照属于有界临时恢复材料：提交标记及远端结果验证成功后，按引用关系清除该批次独占的准备记录和临时原文；失败时保留至安全恢复完成并报告占用，清理失败可重试。不得删除其他快照或备份引用的共享数据。既有独立备份仍按原保留策略管理，但不将准备快照提升为永久逐回合冷归档。

PostgreSQL 删除记录后通常先释放为表内可复用空间，不保证文件立即缩小；实际磁盘回收需结合表膨胀、维护锁、可用空间和备份另行评估。主库删除、阻止旧数据自动回流、旧备份介质删除是三件事：WebDAV 的旧快照及备份保留策略独立于主库，仍可能包含旧回合，不自动删除，也不承诺七天后全介质抹除。

## 实施与验收顺序

1. 先按[回填前保护](#回填前冻结旧归档与同步裁剪)冻结各端旧归档和同步裁剪，核验备份及保护门禁；再建立来源范围、汇总与状态模型，迁移和 WebDAV 协议，按领域增量回填。优化身份读取和农场关联字段投影，统计接口按居民和日期读取汇总。
2. 用同一批真实口径样本对照旧/新结果：7、30、366 天，全体和单居民，跨午夜、在途及迟到结算、历史居民、权限变更、点赞撤销、投资收益和彩票迟开奖。对无法恢复的历史标注缺口。
3. 建立个人与共享战斗归档基线及版本化同步校验，调整逐回合写入时的历史指纹计算，避免每回合读取全部历史；不能因此降低资产和链校验强度。
4. 用单人、组队、成员中途加入/离开、跨天、暂停/召回、部分击杀、奖励、打造与大会来源测试七天边界、幂等重试、中断恢复及冲突拒绝；检查图鉴、活动时间线、战斗回顾和资产。
5. 用接近真实增长量的数据测量统计接口、后台回填、战斗每回合写入、同步时间、数据库空间和每日增量；持续模拟至少 30 天的高频回合，分别检查明细、汇总、来源贡献、变更队列、同步修订和临时快照在七天清理后的数量与空间走势。在真实 PostgreSQL 和目标部署复核后再启用清理。数据库、WebDAV 双设备和部署验收分别记录，不能用 local mock 代替。

专项故障验证至少覆盖：保护期间进程重启和多进程启动，新版保护门禁拦截自动归档、手动 `--apply` 及直接归档调用，旧版实例则保持停止或隔离；两设备具有不同旧归档边界且较旧端仍有独有 `depart` 事实时，回填前不会被同步裁剪，跨午夜出发日期可正确保留；准备快照发布后、本机删除前中断；本机删除后、远端提交边界发布前中断及本机丢失；准备后另一设备提交新修订或远端锁失效；硬删除/撤销后本机增量队列丢失；重复恢复和旧设备尝试发布。均须验证来源、资产、统计和远端边界不丢失、不重复，并能明确暂停或恢复。体积验证还须固定场次数、显著增加每场回合数，对照全部长期摘要、修订、清单与临时快照，检查是否仍按普通回合数无限增长。

战斗明细窗口受七天约束，长期摘要、业务事实和备份仍会随场次或业务数量增长；目标是降低增长速率并避免按回合数无限保留，不承诺数据库总体大小固定。
