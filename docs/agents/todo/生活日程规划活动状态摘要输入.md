# 生活日程规划的活动状态摘要输入

状态：部分实施，待验收。2026-10-17已增加独立活动过滤、比例预算和美食计划材料预留；农场等领域的完整状态摘要仍待讨论。本文保留，验收后需用户明确同意才删除。

## 问题

生活日程选择会读取近期 Agent 运行记录。农场记录可能只表示“当天种植队列已启动；后续由程序按实际条件执行”，而队列后续的实际结果没有反馈到这条记录。日程规划因此可能把“队列已启动”误当成“农场已完成播种”，无法判断当前土地是否空闲、是否有作物生长或是否有种子。

## 待办方向

- 讨论是否为日程选择提供按可选活动整理的简短状态摘要，而不是直接传入各领域的大量原始 JSON 或混杂的近期记录。
- 至少为农场摘要当前权威状态，例如空地、作物生长或成熟情况、种子库存，以及当天农场队列的实际状态；区分已创建计划、执行中状态和最终结果。
- 评估美食制作、迷宫探索、旅行、投资、发帖和帖子互动等可选活动是否各自需要摘要。只提供影响日程选择的事实；领域执行细节仍在活动选定后按需加载。
- 梳理时段、活动候选、今日安排、近期经历和领域摘要之间的重复字段，明确模型决策所需信息与仅供服务端关联的标识。

## 完成条件

- 与用户确认日程选择阶段所需的活动类别、状态语义和摘要粒度。
- 核对摘要来自权威的当前状态，并清楚区分计划、过程和实际结果。
- 明确无数据、无活动、未知状态和历史记录的表达方式，避免让模型从“已启动”推断“已完成”。
- 实现与验证完成后，待用户验收；验收后询问用户是否可以删除本 TODO 计划，收到明确同意前保留。
