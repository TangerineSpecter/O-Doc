# Agent 农场物品与素材规范

更新日期：2026-10-09。

本文是后续新增或修改农场种子、作物、饲料等内置物品素材的设计入口。种子规范已经实现，必须沿用；末尾的饲料与牧草方案仅是待确认提案，不代表当前喂养规则。经营与同步细节见 [农牧场一期说明](./Agent农牧场一期说明.md)。

## 1. 素材来源与共同风格

- 绘制源为 `scripts/generate_farm_sprites.py`，执行 `.venv/bin/python scripts/generate_farm_sprites.py` 重建素材。新增画法应在脚本内维护，不能只改生成PNG而使下次重建丢失设计。
- 物品及作物生长帧统一32×32透明画布，使用整数坐标、硬边像素及现有柔和田园配色。禁止抗锯齿、模糊、渐变和写实阴影；缩放使用最近邻，前端保留像素显示。
- 保留原有素材的视觉尺度与脚本配色。新物品应通过轮廓、图案和适量配色区分，不能只依赖颜色或文字。
- 图集与清单位于 `frontend_react/public/farm/sprites.png`、`sprites.json`；独立物品图标位于 `frontend_react/public/farm/items/`。三处应由同一脚本生成，不能维护互不一致的手工副本。
- 市场、物品图鉴和背包复用稳定SKU对应的内置图片；用户设置的图鉴图片沿用现有覆盖机制，不替换农场生长帧。内置图标必须在没有用户图片时完整可用。

## 2. 种子袋规范（已实现）

每种种子必须使用 **统一纸袋轮廓＋浅色标签＋对应成熟作物的微缩像素图＋袋口辅色**。纸袋表示“种子”，标签图案表示“哪一种作物”；不能恢复为所有种子共用一张旧棕色袋子。

`seed_packet(kind)` 是统一绘制入口：

| 元素 | 约定 |
| --- | --- |
| 袋体 | 棕色边框、浅棕袋体及袋口，沿用原农场风格 |
| 标签 | 浅色底，给作物图案提供清晰对比 |
| 作物图案 | 从 `crop(..., kind, 2)` 的成熟作物画法生成，使用最近邻缩小；与该作物产物图对应 |
| 袋口辅色 | 使用对应作物主色，仅作辅助；相近作物允许同色，但图案必须不同 |
| 名称 | UI继续显示完整中文名称，例如“花生种子”；不在32×32图内绘制文字 |

禁止直接用 `item_icon(d, 'seed')` 的通用旧袋子为新增种子生成图片。饲料也不能复用新的带作物标签种子袋，让玩家将其误认成种子。

验收时必须在实际物品卡片的显示尺寸下，检查种子之间以及种子与产物、饲料的辨识度。16张图片像素内容不同只是基础检查，不替代视觉判断；小麦／水稻、番茄／辣椒、黄瓜／大豆等相近图案要放在一起比较。

## 3. 新增作物时的更新路径

1. 在后端 `farm_catalog.DEFAULT_RULES.crops` 定义稳定作物ID、中文名、生长时间、种子价、产量及回收价。沿用 `seed.<kind>` 与 `crop.<kind>`，已有ID不能为了改名而更换。
2. 在前端 `types/api/farm.ts` 的 `cropKinds` 加入同一ID。`components/Farm/assets.ts` 从此列表生成图片白名单，物品图鉴的 `cropKindFor()` 也使用同一列表识别规则编辑入口；不得另建只包含部分作物的硬编码名单。
3. 在素材脚本的 `CROP_KINDS` 添加同一ID，扩展 `crop()` 的三个生长阶段，并给 `seed_packet()` 配置袋口辅色。成熟作物必须有独立、可辨认的形态。
4. 重建图集、清单及种子／产物PNG；确认每种作物有 `<kind>-0/1/2`、`item-seed.<kind>`、`item-crop.<kind>`，以及独立 `seed.<kind>.png`、`crop.<kind>.png`。
5. 更新市场说明及农牧场文档。旧目录补齐缺失内置项时，不覆盖用户规则、图标关联、天气种子和进行中的生产快照；不重建已生成的市场小时批次。
6. 验证市场商品池、共用背包播种／收获、规则快照、幂等及旧目录兼容。涉及新持久字段时，按根目录 `AGENTS.md` 先确认WebDAV同步需求；仅增加现有目录项也要检查同步恢复兼容。
7. 查看种子和产物并排预览，检查实际页面图片加载；对比无关帧是否意外改变。报告素材检查、自动测试、浏览器和真实跨设备同步各自的验收结果。

美食原料保持作物身份；小麦磨粉、水稻碾米、榨油、豆制品与成品菜使用未来加工系统的独立身份，不把基础作物直接改成菜名。

## 4. 当前饲料规则（已实现）

当前只有稳定SKU `feed`，名称“饲料”，鸡、牛、羊都消耗它。每只动物每次消耗1份，补足最多24小时喂养覆盖；缺少饲料暂停生产。市场按当前小时批次的饲料价格常驻供应。

候选生成在 `farm_runner.py` 按共用 `feed` 库存筛选动物，经营事务在 `farm_service.py` 消耗同一SKU。因此只改名称或图标不能实现“鸡用鸡饲料，牛羊用牧草”。当前饲料仍使用原袋子图标，与种子袋标签设计已经区分。

## 5. 饲料与牧草方案（待用户确认，未实现）

为使游戏中的物品用途更直观，建议新增两类专用供给：

| 动物 | 建议供给 | 建议图标 | 获取方式 |
| --- | --- | --- | --- |
| 鸡 | 鸡饲料 | 带谷粒标识的饲料袋，与种子袋不同 | 第一阶段商店常驻购买；后续可由玉米／小麦加工 |
| 牛、羊 | 牧草 | 有束带的绿色草束，不使用种子袋 | 商店常驻购买；新增牧草作物后也可种植、收割入背包 |

牧草建议沿用现有地块、保湿、一次性收割及整数库存机制；不立即增加自动放牧、割草再生或新的地块类型。鸡饲料加工与美食加工可后续共用原料消费能力，当前不开放玉米／小麦直接替代饲料。

专用供给第一阶段仍建议每只每次1份、补足24小时，保持既有好感和生产周期规则；这样先增加物品用途差异，避免同时引入营养值或复杂配方。价格、牧草生长参数及最终SKU尚未确定。

### 兼容与实施边界

- 不把已有 `feed` 库存静默变成只能给鸡吃的物品；建议保留为“通用饲料”，继续兼容旧库存及历史经营，新常驻采购转向两种专用供给。旧市场批次及历史成交保留原商品快照，不能回写为新SKU。
- 消费优先级建议为“先使用对应专用供给，不足时用旧通用 `feed` 补足”，允许一次批量喂养混用；全部需求在提交前合并校验，审计记录每种实际用量。此优先级同属待确认方案。
- 农场候选按动物类型与可用供给生成；批量喂养必须逐种汇总需求，检查全部库存后在同一事务扣除，缺少任一种时整体失败，不发生半次喂养。
- 喂养结果记录实际消费的SKU与数量；重复操作键不重复扣料。旧喂养事实保持可恢复，不按新映射重算历史消耗。
- 同时更新市场常驻供给接口与购买校验、图鉴、背包、配置、前端类型、经营候选、生活采购决策、MCP上下文和同步恢复测试；不能仅改一个图标或喂养按钮。
- 现有 `feed_price` 和商店响应 `feed` 是单一饲料契约。实施前确定两类供给的价格配置、旧接口兼容及字段迁移；新增持久字段必须先向用户确认是否参与WebDAV，并记录决定。

本节仅保存讨论方案，没有更改现有 `feed` 的用途、价格、库存或喂养行为。

## 6. 肥料素材（2026-10-09）

品质肥和增产肥使用独立32×32透明像素容器，品质肥为紫色容器配花朵标识，增产肥为绿色容器配多穗谷物标识。保留纸袋种子和原饲料图案，肥料不能复用种子袋。两帧追加到图集，原有642帧像素及坐标不变，市场、图鉴、背包复用fertilizer.quality/fertilizer.yield图片。
