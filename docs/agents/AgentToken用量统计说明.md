# Agent Token 用量统计

入口为 **Agent 世界顶部「用量统计」**；任务执行详情增加 **本次 Token 用量**。

## 统计范围

统计自定义和内置任务、后续执行、日程规划、Agent 世界社交决策、飞书及站内 Agent 对话、记忆整理，以及发帖预览。发帖预览单列为其他调用。旅行、自主发帖的格式修复、工具循环和显式重试按每次真实模型请求记录。任务步骤中的嵌套调用继承执行归属。非 Agent 普通 AI 对话、创建角色配置、独立学习文集老师（没有 Agent 身份）及生图不纳入。

统计按北京时间的请求开始时间归属，跨午夜任务逐请求分到不同日期。输入／输出／总 token 以提供商返回的 `usage` 为依据；总量缺失而输入输出完整时相加。缓存、思考 token 仅作细分，不重复计入总量。接口无用量、超时、断流、中断均保留请求事实并提示不完整；失败任务中已经确认的消耗仍计入。SDK 隐式重试改为相同条件和次数的显式请求记录。流式用量只在同一请求内更新，重复事件不重复计数。

## 查看方式

- 今天、近 7 天、近 30 天、自定义日期或全部历史；按 Agent 和任务筛选。
- 总量卡片显示已知输入、输出、总 token、模型请求次数和不完整请求次数。
- 每日趋势；按 Agent、按任务及其他调用排名。任务显示有采集请求的执行次数和平均已知消耗；未知用量不能理解为零。
- 点击排名查看执行记录，展开查看整次执行的各 Agent 用量；进一步查看每次模型请求及可用细分。筛选后的执行行显示筛选范围消耗，展开的「本次 Token 用量」展示该执行全部已采集请求。
- 执行详情展示自身用量及各 Agent 汇总；存在后续执行时另显示整条执行链合计。每日总量只累计请求事实一次。
- 旧执行没有采集数据显示「未采集」；删除任务或居民后历史身份和用量仍保留。
- 「刷新明细」从第一页重新获取最新请求及状态；分页加载失败后「重试」保留当前位置。

## 接口与实现边界

认证只读接口位于 `/api/settings/agent-world/token-usage/`：`summary/` 返回总量、每日趋势和筛选选项；`breakdown/` 支持 Agent、任务、用途和执行维度分页；`requests/` 按时间与 ID 游标分页，每页 50 条。日期参数为 `start_date`／`end_date`，`all=1` 查询全部历史；支持 `agent_id`、`task_id`、`record_id`、`purpose` 以及 `other=1`。日期和分页错误返回 HTTP 400。响应沿用现有 `code/msg/data` 与驼峰转换。

持久化、用量归一化、归属上下文、查询和 HTTP 各自拆分；通用模型方法保持原返回内容契约。请求时间、Agent、任务、执行记录均建立索引。执行记录列表用两次聚合批量计算自身及各 Agent 用量，避免逐条查询。拥有独立账号归属的世界调用沿用账号范围；共享 Agent 配置的调用继续共享，IM 统计不返回内容或发送者。

WebDAV 同步与升级说明见[数据同步逻辑说明](../数据同步逻辑说明.md)。第一版只统计 token，不折算费用、不限制模型消耗。

## 用量报告导出

记录日期：2026-10-10。导出按钮与接口已实现，目的是先分析真实任务消耗，再决定 [Jev 决策模型接入范围](./Agent决策模型迁移评估与演示记录.md)。正式 Jev 接入仍未实施。

### 入口与筛选

- 在用量统计弹窗首行筛选条右侧增加“导出用量报告”，与刷新按钮相邻，窄屏允许整齐换行。
- 按点击时当前生效的日期、Agent、任务条件导出；默认今天、全部历史、自定义日期和系统规划等特殊筛选语义必须与统计一致。后台复用 `filtered_usage` 与账号可见性，不能扩大权限。
- 导出当前筛选下的全部请求，而非当前排名页、当前展开项或每页 50 条明细。分组切换只影响页面展示，不改变首行筛选范围。
- 点击后冻结本次筛选条件，显示导出中并防止重复触发；失败显示可重试提示。筛选为空时也应产生明确的零记录报告。

### 建议格式与内容

第一版导出单份 UTF-8 JSON 报告，保留 `null`、布尔值、字符串 ID 和结构化汇总，便于程序直接分析。CSV/Excel 可后续按人工查看需要扩展，不作为首版必需品。

| 部分 | 内容 |
| --- | --- |
| 元信息 | 报告格式版本、生成时间、Asia/Shanghai 时区、已生效筛选条件、记录条数及采集边界说明 |
| 汇总 | 已知输入/输出/总 Token、请求数、不完整请求数；按任务、用途、阶段、模型/服务统计，区分无执行 ID 的请求 |
| 逐请求明细 | 请求 ID、请求开始/结束时间、居民与任务 ID/名称快照、执行记录 ID、用途、阶段、模型与服务 ID/名称、重试序号、状态、usage_complete、输入/输出/总量、缓存和思考 Token |
| 派生信息 | 有有效开始/结束时间时计算 elapsed_seconds；未导出当前任务类型，不根据名称猜历史类型 |

当前持久模型已具备上述逐请求字段，现有明细 API 未返回模型/服务 ID；导出可读取现有持久字段，无需为导出增加业务数据字段。汇总和明细需使用同一导出数据边界，注明生成过程中仍可能发生的运行状态更新，避免误称为冻结的历史账单。

认证只读文件接口：`GET /api/settings/agent-world/token-usage/export/`，筛选参数与现有统计一致，非法日期/用途返回 HTTP 400，成功返回 JSON 附件。文件协议使用固定 snake_case，不经过普通 API 的驼峰转换：`metadata`、`requests`、`summary`、`by_task`、`by_purpose`、`by_phase`、`by_model_provider`。`metadata.format_version=1`，实际记录条数为 `summary.request_count`；汇总包含失败、运行中、不完整请求次数。阶段按用途与阶段一起分组，模型按历史模型/服务身份一起分组；名称为采集时快照。

服务器单次查询分批读取请求，并从同一遍历计算汇总；报告先写内存临时文件，超过 8 MiB 后转系统临时文件，通过附件响应关闭清理，不在媒体或备份目录留文件。大量历史下载可能耗时，前端设置 120 秒请求超时，失败后可缩小范围重试。

实现入口：[`report.py`](../../system_settings/token_usage/report.py)、[`views.py`](../../system_settings/token_usage/views.py)、[`useTokenUsageExport.ts`](../../frontend_react/src/hooks/useTokenUsageExport.ts)、[`TokenUsageDialog.tsx`](../../frontend_react/src/components/TokenUsage/TokenUsageDialog.tsx)。

### 数据语义与分析边界

- 请求 ID 是去重依据，居民/任务/执行 ID 全程为字符串；缺失用量保留 `null`，真实零消耗保留 0。
- 汇总仅累计已知值，同时报告不完整条数。缓存和思考 Token 是细分，不与总量再次相加；失败请求已经确认的消耗仍计入。
- 不导出 API Key、认证信息、服务凭据、提示词、对话正文、发帖正文或模型完整响应；不新增这些内容的持久采集。
- 耗时包括调用链可能的网络/工具因素，不能直接代表纯模型推理时间；当前未记录独立 decision/generation 角色标签，不能把所有同阶段调用推定为纯决策。
- 单靠现有统计可定位大模型消耗热点，不能证明性格判断效果或 Jev 能替换整段工作流；仍需结合阶段代码和同状态对照实验。
- 本报告不是服务商账单，不自动估算价格或补齐历史未采集用量。当前独立 Jev 测试没有走正式采集链，不在此报告范围内。

### 实施与验收要求

实现按后端查询/报告构建/HTTP、前端 API/导出 Hook/UI 职责拆分。大量历史数据不在浏览器反复拉分页拼接，需考虑服务器分批读取及文件生成，避免静默截断；文件不保存到真实媒体或备份目录。

验收覆盖：日期与北京时间边界、全部历史、居民/任务/系统规划筛选、其他账号不可见、未登录拒绝、超过 50 条全部导出、空结果、重复 ID、防止未知用量转零、失败/运行中请求保留，以及导出汇总与明细一致。前端验证按钮加载/失败/重试及窄屏布局。

导出不新增持久化字段、不产生同步数据；Jev 配置或采集字段的新增属于后续独立实施，需要另行确认 WebDAV 同步边界。
