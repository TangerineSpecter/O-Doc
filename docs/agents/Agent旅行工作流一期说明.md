# Agent 旅行工作流一期

> 2026-09-29 统一生活接管：内置活动不再独立配置频率和参与居民，自动机会由统一生活日程分配，手动执行明确选择居民。本文保留具体活动规则；涉及旧独立调度的描述以 [统一生活执行说明](./Agent世界统一生活执行说明.md) 为准。资金支出受共享生活预留约束；市场准备不占行动次数，旅行整个工作流占一次机会。


## 使用入口

在设置 → Agent 管理 → 任务中配置内置「旅行」任务：选择参与 Agent、输出文集、旅行工作流分类、Tavily 搜索服务、固定或随机机会频率。默认关闭，每周一次随机机会，每分钟推进一个节点。目标 Agent 需有写作模型并绑定启用的旅行游记 Skill；场景照另需旅行场景照 Skill 和具备通用生图工具的 MCP。默认配一张图，缺少条件也会先发文字日记并发送通知。

先备份数据库并执行 `.venv/bin/python manage.py migrate`。城市种子会自动导入，无需 AI。启动服务后启用「本机自动执行」与旅行任务以自动产生机会；其他设备仅同步查看。手动执行授权本机推进整趟旅行，后续节点及图片补偿不受「本机自动执行」开关限制，但不会因此产生新的自动机会。自动启动的旅行仍受本机开关控制，同步导入的旅行没有本机授权，不自动接管。任务停用暂停后续旅行节点，不删除已出发事实。执行记录展示中文阶段、候选资料准备数量和已保存的节点结果及错误。

## 默认规则

每次固定最多五个不同城市报价，优先没有去过的城市，避开最近三个实际抵达城市；兼顾国家与价格档位，存在可负担路线时至少提供一条。候选不足时少于五个；如果只有最近去过的城市可负担，为保证存在可选路线可例外提供一个。目录含城市/聚落，不是旅游白名单；冷门地点查不到充分资料时等待恢复，不伪造景点，不出发扣费。

按「候选资料 → 选择或不去 → 行程准备 → 出发 → 2–3站游览与1–2个轻事件 → 一次美食选择 → 一次纪念品购物 → 返程 → 日记 → 发布」推进。内部节点不等于主阶段。拒绝正常结束；同一次机会的候选、报价、有效决策不重新 roll。

旅行总价包含游览和美食，出发只扣一次并消耗默认20点体力。旅途中暂停该 Agent 的其他自动世界任务，返程立即释放。纪念品3–5种，价格取旅行总价1%–10%范围内的10世界币整数，每种最多3件；允许不买。购物预算是上限，实际扣费与物品入库同一事务，禁止透支、重复商品、越界数量及重复结算。

城市默认模拟价格已调整为原价格的25%（例如8700→2175），正式初始化CSV直接保存折后价。迁移0042按稳定城市ID和旧默认价格匹配更新已有目录，保留人工定价及已固定机会、旅行、纪念品与账本。目录价格和修订时间沿既有WebDAV规则同步，不新增同步字段。纪念品主题由模型整理，单价由系统在上述区间随机抽取后保存；新旅行随折后总价计算，历史商品不重新定价。

旅行任务可在“场景照生图模型”选择独立模型；留空跟随系统默认。`travel_config.image_model_id`沿已确认的任务配置WebDAV同步范围保存，并进入旅行配置快照；已创建旅行不随任务改配置而变更。新生图请求保存解析后的模型ID，恢复查询使用原任务模型，不重新提交付费。通用MCP的`generate_image`与`get_image_generation_options`均支持可选`model_id`，无效指定模型报错，不擅自切回默认。

地方素材使用搜索来源、摘要与原文依据片段。模型整理名称、关联和叙事；引用校验不能保证现实事实百分之百准确，来源仍需核实。纪念品是按当地主题生成的虚拟商品，事件是模拟遭遇，首版不产生额外钱款、物品奖励或伤害。

## 恢复与人工处理

节点失败按1、5、15分钟最多自动重试三次，再进入人工处理并创建去重系统通知。有效模型决策先保存，恢复只执行后续效果；断网不是旅行取消。出发前人工结束不收费；出发后结束不自动退款，保留经历和纪念品，根据已发生事实写日记。

行程准备失败且尚无有效决策时，恢复会绕过30天缓存，为已选城市重新检索资料并保存来源；不改变目的地、候选报价或已有有效决策。执行锁内再次核对人工状态与执行时间，避免旧扫描覆盖暂停或结束。打开的旅行详情每15秒刷新，旧查询不能覆盖人工操作结果。

日记按旅行 ID 幂等发布，正文完成即可发布，不等待图片。场景照使用稳定请求 ID，按分钟查询同一任务，最多自动等待30分钟。失败、欠费、未配置或提交结果未知转人工处理，不自动换请求标识重新计费。

Agent 世界 → 旅行可查看记录、来源、选择、购物与背包；详情支持暂停、恢复和结束。补图可恢复查询、明确确认可能再次计费后重新生成、选择资源库图片或放弃。系统通知直接链接对应旅行详情。正文变更或帖子删除时保留图片并提示人工插入，不覆盖用户修改；补图不重复结算帖子收益。

## 接口与同步

执行详情每10秒刷新，展示最近推进、当前节点失败次数和下次尝试时间；`travelProgress` 是详情接口即时读取本机运行队列的派生信息，不写业务记录、不参与同步。通用重启清理不将有旅行记录的执行日志标为失败，旅行从已保存节点续跑；进程中断时执行锁仍有效需等待过期（最长约10分钟）。暂停、待人工处理及任务停用不会因重启自动撤销，跨设备同步不会自动授权接管。模型校验失败保存具体原因并反馈修正，不降低事实来源或金额校验要求。

居民属性卡片显示当前持有物总件数（按数量求和），可点击「打开背包」查看该 Agent 的物品、稀有度、参考价值与原始获得者。弹窗独立读取背包，支持刷新及空数据提示；数量仅为接口即时聚合结果，不新增持久化或同步字段，统计和物品读取均按当前账号权限过滤。

任务接口新增 `taskKind=travel`、`travelConfig`，包括输出文集、旅行分类、搜索服务、节点分钟数、历史避让数、出发体力与配图开关。以下均需登录，按旅行创建者限制可见与操作范围：

- `GET /api/settings/agent-world/travel/`：旅行记录，可按 `agentId` 筛选。
- `GET /api/settings/agent-world/travel/<id>/`：详情及节点结果。
- `POST /api/settings/agent-world/travel/<id>/`：`action` 为 `pause`、`resume`、`end`、`query_image`、`regenerate_image`、`use_image`、`abandon_image`。
- 重新生成需 `confirmCharge=true`；选择已有图片需 `assetId`，服务端校验拥有者与图片类型。
- `GET /api/settings/agent-world/inventory/`：背包，可按 `agentId` 筛选。

业务记录已确认同步，本机初始化标记、锁、授权、重试时间和素材缓存不同步。新设备不会自动接管同步旅行。现有世界账本仍是资金依据，端上不得直接修改余额或节点结果。旧设备需先升级和迁移再恢复新快照。

### 旅行记忆与历史数据修正

已出发并返程的旅行发布后，将实际节点摘要写入现有 `AgentLongTermMemory`，使用旅行 ID 去重，范围为角色自身（`scope=agent`）。以后旅行选择、Agent 网页聊天、自动任务和飞书对话会读取有效记忆。可在既有记忆管理中修改或归档；重复补记不覆盖用户编辑和归档。升级时可运行 `python manage.py backfill_travel_memories` 补记历史返程经历。不出发的机会和本地调试物品不成为旅行记忆。

2026-09-30 调整居民视角的旅行叙述：记忆正文、模型写作提示、预设旅途事件和旅行详情不再把已经发生的世界内旅行称为“模拟旅行”。`metadata.source=travel` 仍标识记忆来源；对话被问及现实世界经历时如实区分。迁移 0051 只修正已有旅行记忆中旧模板生成的第一行和遭遇标签，保留手工编辑的其他内容、归档状态、旅行 ID、账本、游记以及“具体城市未确认”标注。已存在的旅行记忆不会由补记命令覆盖。未新增同步字段，修正后的记忆内容沿现有 `AgentLongTermMemory` WebDAV 同步规则传播；所有同步端升级并运行迁移后再恢复新快照。

迁移 0040 修正 GeoNames 5884051 的错误中文别名，实际居民点为 Alliston（安大略省）。既有以省级资料生成的旅行保留原文及地点快照，标注具体城市未确认，不计为该城市的已访问历史；新候选使用修正后的城市名。

已成功插图的旅行也支持重新生成，必须明确确认可能再次计费。原请求记录保存在 `photo_history`，旧图片资源保留；新图成功且正文未冲突时替换旧图，否则保留新图供人工插入。原来的正文散列兼容升级前的补图记录。

人工点击重新生成时，仅将旅行快照中已有的 `image_model_id`、`image_aspect_ratio`、`image_size` 更新为任务当前保存的配置；经历、目的地、费用、正文等继续使用原快照。任务已删除时沿用旅行原配置。任务未指定模型时使用提交时系统默认模型。首次配图仍使用旅行创建时的配置，查询原请求继续使用原生图任务绑定的模型与服务商。刷新后的生图配置和原请求历史沿用既有旅行快照 WebDAV 同步范围，无新增业务字段或迁移。

### 城市目录清洗（0041）

目录保留 34,146 条 ID 和原模拟价格，其中 31,716 条启用、2,430 条停用；修正 34 条行政区别名。停用片区、历史/废弃/毁坏居民点、聚落集合与 6 条城市范围待确认记录，保留正常城市/城镇和合法同名地点。城市/省同名本身不是停用依据。导出规则按 GeoNames 分类和别名层级过滤，缺乏可靠中文居民点名时保留原名。旧旅行不改写，涉及纠错的记录标注范围歧义，不作为确定城市的到访历史。[完整报告](../data/travel_city_cleanup_report.md)

旅行场景照提供 1:1、16:9、9:16、4:3、3:4、3:2、2:3 常用比例，以及模型支持的 1K/2K/4K 档位，默认 16:9、1K。比例和分辨率保存在已有 travel_config JSON 中，沿用用户确认的 WebDAV 同步范围及旅行快照；无需迁移。首次配图和原任务查询保留旅行快照中保存的比例；人工重新生成使用当前任务配置；新配置及未设置比例时使用 16:9。GPT Image 2 普通版固定 1K，GPT Image 2.5 和 Nano Banana Pro 支持三档。GPT 按已核对的 Grsai 尺寸表转成像素参数，Nano Banana 分别发送比例和尺寸档位；已保存的生图请求不修改。
