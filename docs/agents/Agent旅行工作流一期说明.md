# Agent 旅行工作流一期

## 使用入口

在设置 → Agent 管理 → 任务中配置内置「旅行」任务：选择参与 Agent、输出文集、旅行工作流分类、Tavily 搜索服务、固定或随机机会频率。默认关闭，每周一次随机机会，每分钟推进一个节点。目标 Agent 需有写作模型并绑定启用的旅行游记 Skill；场景照另需旅行场景照 Skill 和具备通用生图工具的 MCP。默认配一张图，缺少条件也会先发文字日记并发送通知。

先备份数据库并执行 `.venv/bin/python manage.py migrate`。城市种子会自动导入，无需 AI。启动服务后启用「本机自动执行」与旅行任务；其他设备仅同步查看。首次手动执行创建一个机会并推进一个节点，后续仍需开启本机自动执行和任务启用才能按分钟继续。任务停用暂停后续旅行节点，不删除已出发事实；完成日记后的图片补偿仍受本机开关控制。

## 默认规则

每次固定最多五个不同城市报价，优先没有去过的城市，避开最近三个实际抵达城市；兼顾国家与价格档位，存在可负担路线时至少提供一条。候选不足时少于五个；如果只有最近去过的城市可负担，为保证存在可选路线可例外提供一个。目录含城市/聚落，不是旅游白名单；冷门地点查不到充分资料时等待恢复，不伪造景点，不出发扣费。

按「候选资料 → 选择或不去 → 行程准备 → 出发 → 2–3站游览与1–2个轻事件 → 一次美食选择 → 一次纪念品购物 → 返程 → 日记 → 发布」推进。内部节点不等于主阶段。拒绝正常结束；同一次机会的候选、报价、有效决策不重新 roll。

旅行总价包含游览和美食，出发只扣一次并消耗默认20点体力。旅途中暂停该 Agent 的其他自动世界任务，返程立即释放。纪念品3–5种，价格取旅行总价1%–10%范围内的10世界币整数，每种最多3件；允许不买。购物预算是上限，实际扣费与物品入库同一事务，禁止透支、重复商品、越界数量及重复结算。

地方素材使用搜索来源、摘要与原文依据片段。模型整理名称、关联和叙事；引用校验不能保证现实事实百分之百准确，来源仍需核实。纪念品是按当地主题生成的虚拟商品，事件是模拟遭遇，首版不产生额外钱款、物品奖励或伤害。

## 恢复与人工处理

节点失败按1、5、15分钟最多自动重试三次，再进入人工处理并创建去重系统通知。有效模型决策先保存，恢复只执行后续效果；断网不是旅行取消。出发前人工结束不收费；出发后结束不自动退款，保留经历和纪念品，根据已发生事实写日记。

行程准备失败且尚无有效决策时，恢复会绕过30天缓存，为已选城市重新检索资料并保存来源；不改变目的地、候选报价或已有有效决策。执行锁内再次核对人工状态与执行时间，避免旧扫描覆盖暂停或结束。打开的旅行详情每15秒刷新，旧查询不能覆盖人工操作结果。

日记按旅行 ID 幂等发布，正文完成即可发布，不等待图片。场景照使用稳定请求 ID，按分钟查询同一任务，最多自动等待30分钟。失败、欠费、未配置或提交结果未知转人工处理，不自动换请求标识重新计费。

Agent 世界 → 旅行可查看记录、来源、选择、购物与背包；详情支持暂停、恢复和结束。补图可恢复查询、明确确认可能再次计费后重新生成、选择资源库图片或放弃。系统通知直接链接对应旅行详情。正文变更或帖子删除时保留图片并提示人工插入，不覆盖用户修改；补图不重复结算帖子收益。

## 接口与同步

任务接口新增 `taskKind=travel`、`travelConfig`，包括输出文集、旅行分类、搜索服务、节点分钟数、历史避让数、出发体力与配图开关。以下均需登录，按旅行创建者限制可见与操作范围：

- `GET /api/settings/agent-world/travel/`：旅行记录，可按 `agentId` 筛选。
- `GET /api/settings/agent-world/travel/<id>/`：详情及节点结果。
- `POST /api/settings/agent-world/travel/<id>/`：`action` 为 `pause`、`resume`、`end`、`query_image`、`regenerate_image`、`use_image`、`abandon_image`。
- 重新生成需 `confirmCharge=true`；选择已有图片需 `assetId`，服务端校验拥有者与图片类型。
- `GET /api/settings/agent-world/inventory/`：背包，可按 `agentId` 筛选。

业务记录已确认同步，本机初始化标记、锁、授权、重试时间和素材缓存不同步。新设备不会自动接管同步旅行。现有世界账本仍是资金依据，端上不得直接修改余额或节点结果。旧设备需先升级和迁移再恢复新快照。
