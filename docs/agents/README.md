# Agent 世界文档导航

本目录混有当前行为说明、设计计划、评估与素材记录。按任务只打开对应条目；“规划 / 评估 / 验收 / 预览”文档用于追溯其标注的范围和时间，不单独作为当前实现依据。

涉及代码时先看下表中的当前说明，再用代码确认实际入口。涉及持久数据、迁移或恢复时，同时阅读[数据同步逻辑](../数据同步逻辑说明.md)。

## 当前规则与历史材料的边界

2026-10-23 完成目录根层 Markdown 分类及高风险冲突条目的定向核对；不表示所有数值、规则和外部验收已全量复核。

- **现行规则**：先读共享行为与当前业务说明；涉及活动分类，以 `life_activities.py` 及空档穿插说明为准。市场灰度两条路径须按开关区分，不能把旧每日机会与小时执行叠加理解。
- **设计与历史**：规划、模拟评估、分期验收和素材预览不作为当前功能状态。已归档材料见[历史索引](../archive/README.md)，旧文件只保留跳转。
- **待验收事项**：`todo/` 中已实现的计划保留验收状态；需用户验收并明确同意后才能删除。
- **代码已实现与环境验收分开**：旧报告里的“待生产迁移／真实模型／双设备验收”只说明记录当时未验证，不代表今天仍未部署，也不能因代码存在宣布今天已验收。
- 文档正文出现冲突时，核对代码后直接修正错误条目；不要只在开头加“以新说明为准”却保留相反的操作步骤。

## 文档使用约定

- 一项持续演进的业务保留一份当前说明；后续阶段更新同一业务时优先更新该说明，不再新增平行的“二期规则”文档。
- 当前说明写业务规则、关键状态变化、代码入口、同步边界和未验收事项。长篇推演、历史测试输出和创作过程放到规划或归档材料。
- 规划、旧验收结论和资源预览都应标明日期及状态；被取代的材料移入 `docs/archive/` 并链接到现行说明。
- 修改持久字段前按项目 `AGENTS.md` 确认同步范围；无需同步的字段在说明中写明原因。
- 业务流程指引与界面提示同步：若美食制作、炼金制作、迷宫探索等业务流程规则、准入条件、分支判定或多轮循环逻辑发生变动，除更新后端逻辑与当前业务说明文档外，必须同步维护前端流程说明配置文件 `frontend_react/src/components/AgentWorld/decisionProcessGuides.ts`，同时维护 `DecisionProcessInfo.tsx`、`DecisionProcessSteps.tsx` 和按领域拆分的 `decisionGuides/`。每次模型决策必须单列步骤，列明当前输入、合法选项、跳过条件、循环与失败恢复；说明须与实际调用和业务提交顺序一致。
