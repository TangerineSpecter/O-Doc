# Agent 武道大会

2026-10-22：一期已接入，隔离后端测试、完整快照重复恢复和本地浏览器验收已通过；正式数据库迁移、真实决策连接和双设备 WebDAV 仍需分别验收。

## 适用范围与当前规则

同一账号下，已有战斗档案且未归档的居民自动参赛，包括初始职业，不占用生活日程。跟随本机「世界自动运行」开关；关闭时暂停抽签、比赛和发奖。首次启用登记下一个周日，不创建历史赛事。

- 北京时间周日 14:00 锁定名单、随机抽签；不足两人记为未开赛，不发奖。
- 超过64人时当天连续预选，直到不超过64人；周一开始每天14:00一轮，人数少时提前结束，最多周六决赛。
- 每轮重新配对；奇数轮空，优先从累计轮空次数最少的居民中随机选一位。
- 四人半决赛的两位败者在决赛日争季军；三人晋级两人时，唯一败者直接获季军。两人参赛没有季军。
- 锁定名单后新增居民下周参赛。归档、删除、战斗档案缺失按弃权处理，不补人；空缺名次不发奖。
- 服务器错过时间后，按计划时间顺序补完已创建赛事；每场读取实际执行时的当前配置，同时记录计划与实际时间。不凭当前名单补造错过的历史周赛。

## 对战与战报

每场直接读取当前职业、等级、技能和穿戴装备，无报名装备副本。双方使用真实数值、满血满蓝、空临时状态，统一均衡风格，每回合随机先后手；后台直接计算，无需打开页面。

比赛状态独立于探索，不写实际血蓝、冷却、体力，不使用美食或消耗品，不发经验或魔物掉落。普通上限200回合，按剩余生命比例判胜；相同则进入最多50回合禁止生命恢复的加赛，最后仍相同则随机判胜。生命恢复限制同时覆盖主动治疗、持续治疗、被动生命恢复；法力恢复保留。双倒地随机判胜。

战报保存稳定居民 ID、当场职业/属性/技能/装备依据、逐回合行动和血蓝、胜负原因。它是已经发生的事实，不用于锁定下一场配置。战斗与模型请求在数据库事务外运行，提交时复核本机许可、赛事状态及是否退出。

## 奖励与处置

| 名次 | 奖励 |
| --- | --- |
| 冠军 | 一件金装，决策模型选择部位 |
| 亚军 | 一件蓝装，决策模型选择部位 |
| 季军 | 愈合、灵思、铁壁、狂暴、再生药剂中独立等概率随机三瓶，全一星，允许重复 |

装备先按获奖者当前等级±5，在1～99边界内等概率抽等级，再从现有启用目录找该等级可生成的部位。合法 Boss 专属模板也在奖池；不扩充目录，不按居民职业、精通过滤。

「武道大会奖励部位」结构化决策场景只输入当前穿戴的部位与金/蓝/白品质或空槽，以及奖励品质、合法部位；不带角色长文本、具体属性、评分、背包。戒指两个槽分别展示。唯一候选直接确定；未配置连接、场景关闭、非法输出或模型故障时由代码随机选择合法部位，不调用普通文本模型。类型、词条与数值由代码复用装备生成器随机产生。

各名次独立生成和发放。等级与候选先存检查点，生成结果在入库前固定；重复调度、重启与同步恢复不重抽、不重复发奖。奖品不绑定、不自动穿戴，可出售、交易，不能穿戴也照常发放，不自动出售。药水不扣材料或体力，不增加炼金经验，按现有一星规则价值写入背包价格批次。

## 持久数据与 WebDAV

已确认全部业务事实同步：`Tournament`、`TournamentRound`、`TournamentMatch`、`TournamentReward`、`TournamentIntegrity`。赛事按账号和周日日期唯一，轮次、比赛、名次奖品使用稳定业务键。赛后可变的决战配图关联使用独立 `TournamentIllustration`，不改写对阵、战报及赛事事实指纹。

- 同步协议 `tournament_schema_version=2`、赛事清单与赛事摘要验证名单、抽签、轮次、战报、名次、奖励来源和对应资产链；配图关联与图片 Asset、生图任务和参考图一起同步，校验赛事归属及已应用图片资源。旧版本 1 快照可读取；所有同步设备须升级后才能读取版本 2 快照。
- 战斗协议升至11：新增 `CombatFact.kind=tournament_reward`，固化奖励装备属性与穿戴条件。不能只导入装备行而缺少获奖与发放事实。奖励出售和市场转移继续使用原事实链。
- 季军发放事实纳入炼金资产指纹；药水沿用 `elixir.<recipeId>`、`source.stars=1` 和库存价格批次，不伪造炼金制作经验。
- 同一比赛或奖品在两端生成不同结果时拒绝逐行拼接，须选择整份设备快照；不重新发奖修复。旧快照无大会数据表示没有历史赛事。
- `TournamentRuntime` 的日历起点、租约和本机执行状态不参与同步，因为它们只协调本机工作；恢复清空执行租约，世界自动运行仍由本机授权。同一世界只在一台设备执行，WebDAV 不提供离线设备实时互斥。

升级前备份数据库与媒体，执行 Django migration `0088_tournaments`；参与同步的所有设备需先升级到支持战斗协议11的版本。迁移不创建历史赛事、不修改居民现有装备和成长。

## 界面与接口

Agent 世界工具栏「武道大会」打开当前赛事、赛程、奖品、历届记录；比赛详情按需加载文字战报。没有新增像素对战动画。`(i)` 展示完整流程，世界决策设置可单独排除奖励部位场景。

已结束赛事的「决战纪念图」可上传 PNG/JPEG/WebP，或者选择支持参考图的生图模型，预览后手动应用。生成从决赛战报中提取双方当时职业和装备及一次真实命中攻击；默认选最高伤害，也可选择具体回合行动。身份参考采用双方目前已上传的全身图或头像，可另传画风参考图；历史外貌可能与比赛时不同。无有效战报的赛事只能上传。任务状态保留、恢复时查询同一任务，不自动重复提交；提交状态不明时用户可主动放弃等待，重新生成可能再次计费。

实际接口前缀为 `/api/settings/agent-world/tournaments/`，提供 `current/`、分页列表、`<id>/`、`<id>/matches/<match_id>/`。全部要求登录并按账号隔离，GET 不建档、不抽签、不发奖。页面隐藏停止轮询，失败退避刷新。

晋级图的自动适配先保证每列卡片和连线留有间距；弹窗宽度不足以容纳当前轮次时，自动使用局部横向滚动的大图，避免相邻轮次卡片相互遮挡。用户仍可手动固定为大图模式。

赛程采用浅灰框架与白色内容面板。晋级图保留透明动漫金色奖杯贴图和浅色选手卡，左右向中央冠军汇合的紧凑布局，默认展示参赛人数不超过32人的已生成正赛轮次；可展开全部轮次。选手位置从末轮按晋级关系回溯排列，避免跨侧连线；连线依据相邻轮次实际胜者身份，不假设固定签位（每轮重新抽签）。预选、每日轮次表及季军战报保留；奖励详情默认折叠。每日轮次表左侧选择轮次，右侧以紧凑双列对阵行展示；窄屏改为单列，选手双方相邻排列。战报使用独立居中弹窗，不插入页面顶部。屏宽不超过 1100px 时首次进入默认显示每日轮次表，仍可切换到晋级图并局部横向滚动。晋级图节点文字保持固定字号，不随 SVG 连线画布缩小；冠军路径以橙色标识。

## 代码入口

- 后端：`system_settings/agent_world/tournament_{models,rules,service,battle,rewards,decision,runner,queries,views,sync}.py`。
- 调度：`world_cycle.tick` 分派独立大会后台线程，使用本机租约及提交许可复核。
- 资产：`combat/facts.py`、`combat/sync.py`、`alchemy_integrity.py`、共用 `inventory_stock.py`；同步总入口 `utils/sync_manager.py`。
- 前端：`components/Tournament/`、`hooks/useTournament.ts`、`api/tournament.ts`、`types/api/tournament.ts`；流程配置在 `decisionProcessGuides.ts` 和 `DecisionProcessInfo.tsx`。
- 决战纪念图：`tournament_art_prompt.py`、`tournament_art_views.py`、`api/tournamentArt.ts`、`components/Tournament/TournamentArtDialog.tsx`；数据库迁移 `0097_tournament_illustration`。
- Local 模式样例：`mocks/agentWorld/tournament.ts` 与 `routes.ts` 提供当前八十人赛（含预选与三人半决赛轮空）、历届四人赛、金蓝装备、一星药水和文字战报；沿用顶部样例、空数据、加载中、接口错误场景，不请求后端。
- 自动化：`system_settings/agent_world/test_tournaments.py`；测试必须使用隔离数据库、模拟外部服务。
