# 居民钓鱼说明

核对日期：2026-10-22。本文描述居民钓鱼首版的当前实现；正式数据库迁移、真实决策连接与双设备 WebDAV 仍需在目标环境验收。

## 入口与范围

世界管理 → 钓鱼，默认关闭，沿用统一生活参与居民。居民活动 → 钓鱼查看当前出钓、经验及历史；世界图鉴 → 钓鱼图鉴查看钓点、鱼种、鱼饵和捕获纪录。

钓鱼能力任务仅所属账号可查询，通用任务接口禁止删除该内置任务，能力开关在世界管理中修改。

参与范围为空或参与者全部归档时，能力任务刷新正常跳过，账户的其他维护流程继续；重新选择可参与居民后再刷新能力任务。归属冲突仍按原校验拒绝处理。

居民钓鱼观察面板沿用采集手册样式：桌面左侧为钓手成长卡，右侧展示当前出钓与返程档案；等级、经验、携带鱼饵、收获和鱼王胜负分层展示。空状态使用像素鱼插画，出钓过程采用带事件图标的逐竿记录；窄屏合并为纵向内容区。

居民属性同时展示钓鱼等级、累计经验与当前等级的经验进度。属性接口按账号批量读取钓鱼档案，沿用钓鱼升级规则，未有档案时显示 1 级、0 经验；查询不创建档案。该展示是既有同步经验的只读投影，不增加持久字段或同步数据。

钓鱼入口使用鱼形 SVG。图鉴采用浅纸色与青绿色的采集手册样式，使用鱼种编号、分段收集进度、像素标本区及鱼王金色标识；布局为固定宽度的紧凑鱼种列表与摘要式详情分栏，鱼饵以并排小卡展示，支持按钓点、收集状态和鱼名筛选，以及个人/全体纪录切换；窄屏横向选择鱼种、纵向阅读详情。鱼种与五种鱼饵沿用药剂图标的 32×32 Canvas 像素绘制方式，缓存为透明 PNG 并清晰缩放；图鉴、市场补给卡片、详情与背包物品共用对应图标，用户自定义图标仍优先。鱼王带像素皇冠标识；这些展示资源不参与业务结算或同步。

钓鱼是统一生活中的普通活动，不另建独立行动频率。整日日程仍由现有文本模型安排；钓鱼领域内部的地点、时长、携带鱼饵和鱼王出拳只使用决策连接，无普通文本回退。先启用世界结构化决策及四个钓鱼场景。

首版三个钓点分别在 1、10、20 级解锁，每处四种普通鱼和一条专属鱼王；五种鱼饵为蚯蚓、面团、玉米、小鱼饵、鲜虾。完整内容位于 `system_settings/agent_world/fishing/catalog.py`，版本为 `fishing-1.0.0`。

## 商店与鱼饵

- 商店独立固定一个鱼饵位，每个上海小时批次等概率抽取一种，报价写入原 MarketBatch.supplies；已生成批次不重新随机，不补历史批次。
- 无限供应，沿用市场通用单次参数范围，无鱼饵专属限购，不占随机商品位或居民每批两个商品格额度。
- 保留真实余额、市场预算、其他日程资金预留及旧报价校验，稳定请求键防止重复扣款。
- 日市场规划和小时预检支持鱼饵采购目标。十二竿作为一次出钓的缺口参考，仅影响自动规划候选，不作为商店购买限制。
- 鱼饵 SKU 为 `bait.*`，存入共用背包，保留采购价格批次；不可挂牌和回收。出钓准备不临时采购。

## 准备与持续执行

规划先过滤未启用、决策连接缺失、体力不足、没有库存鱼饵、等级或时间窗口不允许的情况；输入仅提供有界状态摘要。

准备按钓点 → 时长 → 鱼饵进行。时长从 30／60／120 分钟中按剩余生活活动窗口过滤。鱼饵最多三轮，第一轮必须选择一种，第二、三轮可选择不再携带。候选仅包含库存大于零、尚未选过、本次钓点和时间内有适用鱼种的鱼饵；输入包含名称、数量及代码计算的鱼种偏好、出没时间。唯一候选不请求供应商。

每步选择随出钓记录保存；故障继续原步骤。出发时复核最新条件，将所选种类全部现有库存移入携带物资，不询问数量。准备取消不扣鱼饵。

后台独立五秒轮询，实际每五分钟抛一竿。每竿消费一份鱼饵和两点体力，按选择顺序轮换，耗尽或当前时段不适用的鱼饵跳过。空竿、垃圾、脱钩均消耗物资。垃圾仅记录名称，不入背包、不增加收益或经验。

垂钓期间居民与旅行、探索、市场及其他生活活动互斥，后续安排沿用统一忙碌顺延机制；等待不持有世界全局执行位。页面仅观察，不决定结算。

时间到、饵用尽、体力不足、无适用饵或主动召回时返回，剩余物资按原批次返还。正常最后一竿允许五秒轮询容差；长期停机不批量补竿，截止时间仍有效。重启或同步恢复后继续正在垂钓的出钓，保留原下一竿的最早时间，不因重新授权缩短五分钟间隔；原时间已过时只推进一竿，再从实际抛竿时间计算后续间隔。

## 普通鱼与成长

每竿空竿概率 15%、垃圾 20%；适用鱼王使用偏好饵时出现概率 1%，可接受饵为三分之一；剩余为普通鱼。普通鱼候选由钓点、实际上海时间和鱼饵先过滤，再按基础权重和偏好权重抽取，偏好权重为可接受的三倍。跨午夜时间窗口按当时小时判断。

普通鱼咬钩后：

```
x = ln(2) + (居民钓鱼等级 - 鱼等级) / 10 + 钓竿加成
捕获率 = 5% + 90% × sigmoid(x)
```

同级约 65%，低鱼十级约 43%，高鱼十级约 81%，范围 5%～95%。当前固定普通钓竿，加成为零，不购买、不掉落、不选择、不设置承重。后续铁匠铺可通过加成参数扩展。钓点等级限制进入，鱼等级影响难度，钓竿不影响鱼种候选。

初始一级，首版五十级封顶；每级需求 `100 + 25 × (当前等级 - 1)`。普通鱼经验 `10 + 鱼等级 × 2`，脱钩两点，鱼王五倍，空竿和垃圾不给经验。下一竿使用升级后的等级。

捕获保存鱼种、重量、地点、时间、经验及目录版本，鱼类 SKU 为 `fish.*`，进入背包。重量用于个人与全体纪录，不改变回收单价。普通鱼支持回收、挂牌和自动处置标记，鱼王不进入自动处置，须由市场明确交易。售出不删除图鉴，图鉴与最大重量从不可变捕获事实派生。首版不接入菜谱。

## 鱼王对局与失败处理

鱼王出现暂停普通抛竿；居民每局只从锤子、剪刀、布中选择，鱼王代码独立等概率随机。当前局鱼王出拳在居民选定后才生成，不提前暴露给模型。

累计三胜直接捕获，累计三败逃脱，平局不计数；每轮无额外鱼饵和体力消耗，不再叠加普通捕获率。对局结束后有时间与资源则继续钓鱼；到返程时间先完成当前对局再返回。

每趟同一时刻最多一个推进线程，每次推进最多一局猜拳。决策故障保留选择和胜负，最多尝试三次，间隔一分钟和五分钟；仍失败暂停，用户可重试或提前返回。技术中断与主动放弃不伪造三败。

## 数据、同步与恢复

用户已确认全部业务数据纳入 WebDAV：FishingCatalog、FishingConfig、FishingProfile、FishingTrip、FishingEvent、FishingIntegrity，以及既有日程、背包、商店批次、交易与体力事实。

- 快照增加 `fishing_schema_version=1` 和账号清单，覆盖导出、来源、合并结果、导入、本地备份恢复与覆盖入口的对应校验。
- 不可变事件和相同版本目录两端不同内容时拒绝合并；核对成长经验、逐竿序列、体力事实、携带消耗返还及鱼类捕获、背包、托管、成交收支。
- 业务事务使用共用资产锁，逐竿、猜拳、返程以稳定操作键和状态版本保证幂等。模型请求在事务外，提交前检查授权和版本。
- 每趟固化完整规则，已有出钓和历史不会因目录更新重算。
- FishingRuntime 是本机执行许可、租约和互斥状态，明确不同步：其他设备恢复记录不代表允许发起模型请求。线程、轮询对象也不持久化到业务快照。
- 旧快照无钓鱼域按未启用兼容，不补造经验或收获；更高钓鱼版本拒绝读取。恢复撤销运行许可，并沿用统一生活的本机关闭策略，开启本机运行后在钓鱼面板继续。
- 迁移 `0087_fishing` 只创建结构，不修改既有居民资产；所有同步端升级并迁移后再交换新快照。
