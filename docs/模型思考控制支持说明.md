# 模型思考控制支持说明

核对日期：2026-10-10。以下针对 O-Doc 实际使用的 `/chat/completions` 接口，不把原生 API 或 Responses 参数直接混用。文档核对不等于使用真实账号逐个模型完成验收。

| 服务商 | 官方依据与实现范围 |
| --- | --- |
| DeepSeek | [Chat Completions 文档](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)明确列出 `deepseek-flash`、`deepseek-v4-pro`，支持 `thinking.type=enabled/disabled`。仅注册这些原生型号，不猜测别名。 |
| Qwen | [深度思考模型文档](https://www.alibabacloud.com/help/en/model-studio/deep-thinking)区分混合思考、固定思考及非思考型号。混合思考使用 `enable_thinking`；注册文档列举的具体型号及明示支持的后续快照。Thinking、QwQ、R1 等固定思考型号不显示开关；未知型号也不显示。文档说明部分百炼开源 Qwen3 型号开启思考只支持流式输出，当前普通 Agent 工具入口为非流式；本次保守隐藏开源数值尺寸型号的开关，待核实对应非流式兼容性或适配后再开放。 |
| SiliconFlow | [Chat Completions 文档](https://docs.siliconflow.cn/docs/api/chat-completions-post)提供 `enable_thinking`，并说明适用于大部分推理模型，不能据此认为所有模型都支持。本次限定已识别的混合 Qwen / DeepSeek V3.1、V3.2、V4 型号；R1、Thinking、Instruct、Coder 和未知型号不自动提供开关。 |
| Doubao | [深度思考文档](https://docs.volcengine.com/docs/ark/deep-thinking?lang=en)给出 Chat Completions 的 `thinking.type`。对 Seed 1.6、1.8、2.0、2.1 家族使用该参数；带 `thinking` 的固定思考型号不显示。部署端点 `ep-*` 无法从 ID 判断模型，暂不提供开关。 |
| Xiaomi | [MiMo 深度思考文档](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/other/deep-thinking)列出 MiMo V2.5、V2.5 Pro、V2.6 Flash、V2.6 Pro、V2.6 Pro Ultraspeed，使用 `thinking.type`。其他型号暂不注册。 |
| MiniMax | [OpenAI SDK 文档](https://platform.minimax.io/docs/api-reference/text-openai-api)规定 M3 开启使用 `adaptive`、关闭使用 `disabled`。M2.x 接受 disabled 但忽略，M3.1 Flash Preview 拒绝 disabled，因此两者都不显示开关。 |
| Google AI | [OpenAI 兼容文档](https://ai.google.dev/gemini-api/docs/openai)允许 Gemini 2.5 Flash / Flash Lite 用 `reasoning_effort=none` 关闭，开启使用 `medium`。Gemini 2.5 Pro 与 3 系列不能完全关闭，隐藏开关；原生 `thinkingBudget` 不直接用于当前请求路径。 |
| OpenAi | [GPT-5.1 发布说明](https://openai.com/index/gpt-5-1-for-developers/)及 [GPT-5.2 指南](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.2)确认 `reasoning_effort=none`。本次仅注册 GPT-5.1 / 5.2 的基础型号及日期快照；不外推到 Pro、Codex、旧 GPT-5 或更新型号。开启使用 medium；有界请求与模型连通性检测开启时共用兼容规则，省略不兼容的 temperature。 |
| Ollama | [思考能力](https://docs.ollama.com/capabilities/thinking)与 [OpenAI 兼容文档](https://docs.ollama.com/api/openai-compatibility)明确存在思考控制。读取本机 `/api/show` 的 `thinking.values`，只有同时声明关闭（false）及开启值的模型才显示开关。当前接口发送 `reasoning_effort=none` / 支持的开启强度；不把原生 `think` 误传到兼容接口。元数据缺失、仅强度档位或仅 false 均隐藏开关；不以模型名称推断。元数据缓存 60 秒，查询超时 3 秒，不执行推理。 |
| Grsai | 已查阅[官方 Chat 文档入口](https://grsai.com/zh/dashboard/documents/chat)，公开页面未取得可确认的模型思考控制契约。隐藏开关，不能据此断言服务不支持。 |
| NewAPI / custom | [NewAPI 官方文档入口](https://docs.newapi.pro/en)无法证明任意实例的实际路由及参数透传行为；custom 没有统一官方契约。因此不自动显示开关。用户按实际上游文档选择支持的协议后显示，属于用户声明的能力，仍需真实请求验证。 |

模型能力由 `utils/thinking_capabilities.py` 统一决定，API 校验、请求与前端能力预览共用，前端不维护另一份型号匹配规则。显式协议不能绕过已知原生供应商的限制；未确认 / 不支持的型号不发送任务默认的关闭参数。旧的错误开关配置可以在编辑时恢复默认或自动协议，不批量重写存量配置。

能力响应与 Ollama 元数据是只读派生数据，不新增同步字段。`thinking_mode` / `thinking_protocol` 仍沿用用户已确认的同步范围；新增 reasoning_effort 协议要求执行 `system_settings.0058`。全部同步设备先升级并迁移再交换新配置；本次没有执行正式数据库迁移或真实付费推理验收。
