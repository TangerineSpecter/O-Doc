当任务是评价一张照片时，按下面的顺序做。先拿到观察，再打分，最后提交。没有观察结果时不要打分，也不要编造画面。

## 工具

- 先调用照片 MCP 的 `observe_photo`，参数只有图片文集中的 `image_id`。
- 写完评语和分数后，调用同一 MCP 的 `submit_photo_review`。
- 不要用识图 MCP 的 `describe_image` 来评价照片。那条工具只说明画面里有什么。

## 怎么读观察

`observe_photo` 返回六段事实：画面内容、构图、光影、色彩、清晰范围、表达线索。这些是识图模型看见的内容，不是分数。

同一份结果里的标题、焦段、描述和作者名，是创建人自己写的。作者没写的项是空的，不要把空项当成画面里存在的事实。作者的说法可以和观察对照；两者不一致时，在评语里点出来。

照片送给识图模型前会缩到长边 1280。清晰范围写「看不出问题」时，不要把对焦写成原片精准，评语里说明这是缩小图上看不出问题。清晰范围写「整张明显发糊」或指出局部发糊时，按这段观察打对焦。写「无法判断」的项目不要打很高的分。

思想分只依据表达线索和作者自己的说明。观察没有给出拍摄者的意图。

## 分数

六项都要打：主题、构图、思想、光影、色彩、对焦。每项是 0 到 10，步进 0.5。提交时使用字段 `theme`、`composition`、`idea`、`light`、`color`、`focus`。

综合分由服务端用六项平均后再对齐到 0.5，不要自己另报一个不同的综合分。评语里如果提到分数，必须和提交的六项一致。

同一张照片再次提交会覆盖你上一次的评价。

## 评语

用你自己的性格和口吻写评语，可以尖锐，也可以温和。评语说明判断依据，不要写成中立的画面说明书。`commentary` 最多 2000 字。
